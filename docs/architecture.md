# BENNE — Architecture

> Terminology cleanup (2026-04-15): standardized system-level wording to `inventory` (including Bennescript/docs paths), while keeping `inventory item` only for single carried entries.

> **Speaking Text GUI (`speaking-text`)** (2026-05-04): The default **`say`** line overlay is authored as **`src/game/guis/speaking-text/speaking-text.gui.json`** with display **`name`** **Speaking Text** in the Inspector — distinct from the **`dialog`** choice-overlay GUI (**`guis/dialog/dialog.gui.json`** for **`B.dialog`…`start` / `stop`**). The technical **`guiId`** / folder id stays **`speaking-text`** everywhere scripts and paths refer to it.

> **Display Text GUI (`display-text`)** (2026-05-07): The default **`B.display`** narration overlay lives under **`src/game/guis/display-text/display-text.gui.json`** (typically **`nineSliceImage`** **`displayTextBg`** + **`text`** **`text`**). > **Sound (`B.sound`)** (2026-05-07): **SFX** and **music** use **`Phaser.Game#sound`** via **`SoundManager`** (**`src/engine/sound/SoundManager.ts`**, registry **`benneSoundManager`** in **`createBenneGame`**). Authors place files under **`src/game/assets/audio/sfx/<stem>.{wav,mp3,ogg,m4a}`** and **`src/game/assets/audio/music/<stem>.…`**; **`B.sound.play('stem')`** / **`playMusic('stem')`** take basename-only ids. **`getBenneAudioBootEntries`** (**`resolveGameAssetUrl.ts`**) feeds **`queueBenneAudioForBootLoader`** from **`BootScene`** when **`benneAudioScriptDisabled`** is unset (editor preview **`Phaser.Game`** instances set it in **`preBoot`** so previews stay silent). **`stopAllSfx`** runs on room-leave (**`RoomTransitionOrchestrator.prepareForLeave`**) and dialog session end (**`dialogSession.ts`**); music is intentionally **not** stopped on room change. Blocking **`B.sound.play`** is queued on the Bennescript **`interactionTail`** so it runs **after** **`walkToClicked`** / **`wait`** — use **`playAndWait`** when the next step should wait for the clip to finish.

> **Per-target game cursor (`activeCursorOverride`)** (2026-05-14): With **`game-config.json`** **`cursor.display.aseprite`** enabled, **`RoomScene.refreshCustomCursor`** picks the Aseprite clip for the **active verb** pointer state. **Priority:** (1) **active inventory** with a resolved **`cursorAnimation`** tag on that item’s sheet — unchanged; (2) else, when the sorted pointer hit stack resolves to a **room hotspot** (**`RoomHotspotData`** in **`*.room.json`** `hotspots[]`), a **clickable prop** (**`RoomPropInstance`** in `props[]`), or a **clickable NPC** (**`CharacterData`** on **`*.character.json`**), optional JSON **`activeCursorOverride`** (frame tag on the **game** cursor atlas under **`src/game/assets/images/cursor/`**) overrides **`cursor.activeAnimation`** for that hover only; (3) otherwise **`cursor.activeAnimation`**. GUI buttons and inventory rows still use the global active clip (no per-control override). Invalid / missing override tags fall back to **`activeAnimation`** (**DEV** warns once per tag per room load). **Inspector** (**`benne-editor`**): **Active cursor** on room **prop** (when **Clickable**) and **hotspot** cards; **Active cursor override** on standalone **Character** metadata (disabled when the definition is not clickable).

> **Drop policy clears the active verb too** (2026-05-01): when **`shouldDropActiveInventoryOnUse`** resolves to **drop** after a use-on-target click (combine on **`inventoryPanel`** rows **and** inventory-on-prop / hotspot / character), the runtime **active verb** is now cleared in lockstep with **`activeInventoryItemId`** so the verb HUD resets after the combine instead of leaving "Use …" armed. **`BenneScriptCore.subscribeInventoryUsedOnTargetEvents`** clears both after the handler tail; **`RoomScene`** prop / hotspot / character pointer handlers and **`buildGuiOverlay`** inventory-on-inventory clear both synchronously when dispatch was unhandled. **`whenInventoryUsedOn.doNotClear(...)`** still wins (both stay armed); items / global config with **`dropWhenUsed`** / **`dropWhenInventoryUsed: false`** also still keep both armed.

> **Inventory row “Use” / “Give” → active** (2026-04-23): The resolved **use** or **give** verb on an **`inventoryPanel`** row arms **`activeInventoryItemId`** after the interaction queue drains **without** requiring **`B.whenUse` / `B.whenGive`** in **`*.inventory.ts`**. Optional **`whenUse` / `whenGive`** handlers run **in addition**; **`…doNotActivate`** opts that verb out of arming when **all** handlers for that verb use it. **`trySyncActiveInventoryAfterInventoryUseOrGiveRowDispatch`** (`dispatchInventoryVerb.ts`) covers **JSON-only** items (no **`registerInventoryScript`**). **`RoomScene`** calls **`B.ensureDefaultInventoryUseAndGiveActivationAfterRegister()`** after each inventory script body.

> **Verb dispatch vs. in-progress walk** (2026-04-23): **`createBenneGame`** registers a module-level **`Phaser.Game`** handle (**`setActiveBenneGame` / `tryGetActiveBenneGame`**, `src/engine/gameState/activeBenneGame.ts`, cleared on game **destroy**) so verb dispatch can call **`interruptPlayerWalkForVerbInteraction`** (`src/engine/scenes/interruptPlayerWalkForVerbInteraction.ts`) → **`RoomScene.interruptPlayerWalk()`** before any interaction listeners run. That stops click-to-walk (and any script-queued walk tween) so **`say`**, fallbacks, and **`walkToClicked`** do not overlap movement to an older destination. Entry points: **`dispatchVerbInteraction`**, **`dispatchInventoryOnVerbTargetInteraction`**, **`dispatchInventoryOnInventoryItemInteraction`**, **`dispatchInventoryVerbInteraction`**. Editor preview **`Phaser.Game`** constructors that bypass **`createBenneGame`** do not set this handle unless extended.

> **Aseprite clip namespacing** (2026-04-25): Room props, GUI Aseprite controls, per-item inventory sheets, the shared **`inventory.json`** sheet, and the optional custom pointer all register clips via the scene **`AnimationManager`** (global keys). Identical **frame tag strings** on different atlases could **overwrite or mask** each other (e.g. a room prop tag **`Key`** stealing the inventory row clip). **`loadAsepriteAtlasData.ts`** prefixes **`meta.frameTags[].name`** when normalizing atlases (**`room:<roomId>:`**, **`gui:<guiId>:`**, **`invitem:<itemId>:`**, **`inventory:`** for shared — already the shared pattern, **`cursor:`** for the pointer). **`RoomScene`**, **`buildGuiOverlay.ts`**, **`inventoryPhaserAnimationKeyForTag`** (`inventoryAseprite.ts`), and **`asepritePhaserAnimationKeys.ts`** map **author-facing** short tags in JSON / Bennescript to those Phaser keys. Editor preview blob loads (**`buildPreviewManifest.ts`**, **`guiEditorMain.ts`**, **`inventoryEditorMain.ts`**) apply the same prefixes. **Character** sheets use **`sprite.anims.createFromAseprite`** (per-sprite scope), not this global collision class.

> **Room context + `moveTo` vs `walkTo`** (2026-04-25): **`GameStateManager`** snapshots optional **`currentRoom` / `lastRoom`** (legacy saves may omit them; load normalizes to **`""`** / **`null`**). Getters and setters exist on the manager and on **`B.state`**; updates emit **`gameState:roomContextChanged`** (`GAME_STATE_ROOM_CONTEXT_CHANGED_EVENT` in **`src/types/gameState.ts`**, payload **`GameStateRoomContextChangedPayload`). **`lastRoom` / `currentRoom`** are also driven by the **room transition** pipeline when changing rooms in-game (see **Room transitions** below). **Movement API:** **`B.player.walkTo` / `B.character(id).walkTo`** (and **`.now`**) use pathfinding + **Walk** tweens. **`moveTo` / `moveTo.now` / `moveToNow`** **teleport** the character’s **feet** to the resolved point (**`RoomScene.movePlayerToNow` / `moveCharacterToNow`**, clamping to the walkable mesh, then **Idle** facing). String targets resolve in the same order as **`walkTo`** (prop → hotspot → character → **`room.points`**) via **`RoomScene.resolveMovementTarget`**. **`moveTo`** can queue on the Bennescript interaction tail; **`moveTo.now`** and **`moveToNow`** skip the queue. See **§3 → Game state (v1)** and **§7 → API table**.

> **Character `movable` (JSON + Bennescript)** (2026-05-13): **`CharacterData`** in **`src/types/character.ts`** may set optional **`movable: false`** on **`*.character.json`** (default **movable** when omitted or non-`false`). **`B.player.movable`** and **`B.character(characterId).movable`** read the effective flag; the **setter** queues on the interaction tail and persists **`character:<characterId>:movable`** in **`GameStateManager.variables`**, overriding the JSON default for that definition id across rooms (same pattern as **`visible`**). When **not movable**, **`RoomScene`** skips pathfind **Walk**: **`walkTo`**, **`walkToClicked`**, empty-space **click-to-walk**, and verb flows that call **`walkPlayerTo`** / **`walkCharacterTo`** — all no-op (promise resolves immediately). **`moveTo` / `moveTo.now` / `moveToNow`**, **`face`**, **`say`**, and **`playAnimation`** are unchanged. On room load, the engine seeds a per-definition JSON default from the **first** **`characters[]`** spawn row for that id in the active room’s JSON (same “first wins” idea as visibility defaults). **`B.character('someId').movable`** for an id **not** present in the current room still reads **`movable`** from saved state if set, otherwise falls back to **`true`** (there is no live **`CharacterData`** row from this room). The VS Code **Inspector** character metadata grid includes a **movable** checkbox (cleared **`true`** omits the JSON field).

> **Character `startFacingCharacter` / `stopFacingCharacter` (Bennescript)** (2026-05-13): **`B.character(observerId).startFacingCharacter(targetId, minWaitSeconds?, maxWaitSeconds?)`** queues on the interaction tail and registers a per-room runtime lock in **`RoomScene`**: the observer’s **Idle** facing updates toward the target’s **world feet** after a **uniform random** delay in **`[minWaitSeconds, maxWaitSeconds]`** (defaults **0.2** / **0.4**) whenever **either** character’s feet move past a small epsilon; while feet keep changing every frame, the pending turn keeps sliding so the snap tends to happen after motion settles. **`stopFacingCharacter()`** clears the lock and cancels the timer. Not saved in **`GameStateManager`** — locks are cleared on **`RoomScene`** **`create`** / **shutdown**. Uses the same override-aware idle path as **`face`** (**`getCharacterAnimationOverrideTag`**: only **`facing`** data updates when an override clip is active). **`B.player`** does not expose these methods.

> **Character follow (`startFollowingCharacter` / `stopFollowingCharacter`)** (2026-05-13): **`B.character(followerId).startFollowingCharacter(targetId, options?)`** and **`B.player.startFollowingCharacter(…)`** queue on the interaction tail and persist to **`GameStateManager`**: keys `` `character:<followerId>:followingTarget` `` (string — any character definition id or the literal **`"player"`**, normalized from case-insensitive **`"player"`**) and `` `character:<followerId>:followOptions` `` (merged effective options object: **`minDistance`**, **`repathThreshold`**, **`offset`**, **`speedMultiplier`**, **`faceTargetWhenIdle`**, **`pauseDuringCutscene`** — see **`CharacterFollowOptions`** in **`src/types/characterFollow.ts`**). **`stopFollowingCharacter()`** clears both keys and stops a follow-initiated walk if one is active. **`isFollowing`** / **`followingTarget`** read saved state (or **`false`** / **`null`** when no manager). Cross-room: state survives room changes and save/load; the **live** follow driver runs only when **both** follower and resolved target are spawned in the **same** room — **`RoomScene.updateCharacterFollowers`** (after enter hooks and queue drain, **`RoomTransitionOrchestrator`** enables the driver with **`setCharacterFollowBehaviorEnabled(true)`** before fade-in). While **`pauseDuringCutscene`** is **true** (default) and **`RoomScene`** reports scripted-dialog or cutscene input suppression (**`isInputSuppressed()`**), the driver does not issue new follow walks. Self-follow or empty target: DEV warn + no-op (nothing persisted). Offset is applied in the target’s current facing frame (**`offsetWorldByCharacterFacing`**). Implementation: **`applyPersistedCharacterFollowFromScript`**, **`readSavedCharacterFollowingTarget`**, **`readSavedCharacterFollowEffectiveOptions`**, **`clearSavedCharacterFollowState`** in **`benneAnimationRuntime.ts`**; **`RoomScene.startCharacterFollowingCharacter`**, **`stopCharacterFollowingCharacter`**, **`updateCharacterFollowers`**.

See **§3 → Dialog system (choice topics)**.

> **Room regions — perspective character scale** (2026-05-03): **`RoomData.regions`** (**`RoomRegionData`**, **`src/types/room.ts`**) may set **`scaleTop`** / **`scaleBottom`** (default **`1`**) and optional **`scaleWalkSpeed`** (default **`false`**). > **Character perspective WebGL batch (retro texel snap)** (2026-05-13): Room **characters** (spawned **`Image`** / **`Sprite`**, including Aseprite-backed sprites) use a custom Phaser 4 render-node path so downscaled sprites keep **crisp, constant “full” source texels** instead of soft minification. **`RoomScene.create`** calls **`registerBenneCharacterPerspectiveBatch(this.game)`** (**`src/engine/rendering/benneCharacterPerspectiveBatch.ts`**, WeakSet-guarded); **`spawnCharacter`** / **`spawnAsepriteCharacter`** call **`attachBenneCharacterPerspectiveRenderNodes(sprite)`** so **`Submitter`** / **`BatchHandler`** roles use **`SubmitterBenneCharacterQuad`** / **`BatchHandlerBenneCharacterQuad`** (stock quad stack extended with **`inPerspMag`** in the vertex layout). **`inPerspMag`** is **`max(|scaleX|, |scaleY|)`** each draw (same scalar as region-driven **`setScale`**). Fragment path **`BenneCharacterPerspective`** runs **after** stock **`SmoothPixelArt`** in the addition order: when **`outPerspMag`** is near **1**, the smooth/blocky path applies unchanged; when scale is below a small epsilon of 1, UVs are rewritten by **`bennePerspectiveTexCoord`** using **`uMainResolution`** from **`GetTexRes`** — the batch keeps **`texRes`** effectively on so **`uMainResolution`** is always uploaded for that shader. Sampling uses **integer bucket widths** `floor(1/mag + 0.5)` so the snap grid **plateaus** while **`mag`** drifts (e.g. walking through **`scaleTop`** / **`scaleBottom`** gradients), plus a **canonical half-texel** round-trip so default **LINEAR** filtering stays sharp in motion. Shader sources mirror Phaser’s quad additions via **`src/engine/rendering/phaserQuadStandardShaderInline.ts`** (plain strings + factories) so the browser bundle never imports **`node_modules/phaser/src/**`** (CommonJS **`require`** breaks Vite). **Scope:** character quads only; props, GUI, cursor, **`gameConfig`**, and hi-DPI canvas policy are unchanged. If **`src/engine/rendering/benneCharacterPerspectiveBatch.ts`** or **`phaserQuadStandardShaderInline.ts`** changes, keep renderer parity per **`.cursor/rules/benne-preview-rendering-parity.mdc`** when any preview path also runs **`RoomScene`**.

> **Room regions — enter / exit Bennescript** (2026-05-09): **`registerRoomScript`** only — **`B.region('regionId').whenEnter` / `whenExit`** and flat **`B.whenEnterRegion` / `whenExitRegion`**. Each crossing emits on **`gameEvents`** with ids from **`roomRegionEnterEventId` / `roomRegionExitEventId`** (**`src/engine/events/regionEnterExitEvents.ts`**); **`BenneScript`** subscribes via the same **`subscribe`** path as verb handlers (interaction tail, optional payload). **`RoomScene.update`** (after **`syncIdleCharacterRegionScales`**) compares the **winning** region id at each character’s world feet (**`resolveWinningRoomRegionIdAtFeet`**, same overlap rule as scale) against the previous frame; **no** enter/exit fires on the initial seed pass so spawns already inside a polygon do not trigger **`whenEnter`**. Moving **between** two overlapping regions fires **`whenExit`** on the old id then **`whenEnter`** on the new. Payload **`RegionEnterExitContext`** (**`src/types/regionEnterExit.ts`**: **`roomId`**, **`regionId`**, **`characterId`**, **`isPlayer`**, **`feetX`**, **`feetY`**). Unlike **`whenEnterRoom`** / **`whenEnterRoomAfterFade`**, the engine does **not** auto-wrap region handlers in **`pushCutscene`** — use **`B.cutscene(…)`** when you want full pointer suppression for a scripted beat.

## 1. Overview

**BENNE** is a **web-based point-and-click adventure game engine** (LucasArts / PowerQuest–style): fixed-resolution pixel rooms, click-to-walk, and verb-style interactions on props and characters. The runtime is **Phaser 4** (RC), **TypeScript**, and **Vite**.

**Core design goals**

- **Data-first**: Rooms, characters, **GUIs** (overlay UI definitions), **inventory** definitions, **dialogs** (topic lines + choice options in JSON), and game tuning live in **JSON** (and Aseprite exports) under `src/game/`; TypeScript supplies **room** / **character** / **GUI** / **inventory** / **dialog** scripts and engine code, not hand-authored level blobs in code. Optional **`src/game/pdcs/<id>/<id>.pdc.json`** files store **designer-only puzzle flow charts** (Cytoscape JSON); they are **not** registered by **`registerGameContent`** and do not participate in runtime loading.
- **Separation**: **`src/engine/`** is reusable; **`src/game/`** is project-specific content and registration (`registerGameContent`).
- **Retro display**: Internal resolution defaults to **352×198** and remains the source of truth for gameplay + GUI coordinates. Runtime scaling uses a **hi-DPI canvas** strategy (`Scale.NONE`) instead of `FIT + MAX_ZOOM`: backing buffer targets **parent CSS size × device pixel ratio** (capped), `scale.zoom = 1 / dpr` keeps CSS sizing predictable, and the game frame is aspect-fit via `cameras.main.setViewport` + smooth (non-integer) zoom. Resize uses a two-phase path in `benneRuntimeHiDpiScale.ts`: per-frame cheap camera/CSS updates while dragging, plus a short debounced backing-store commit (`scale.resize`) to reduce flicker. Startup runs an unconditional commit burst across initial RAFs, and camera dedupe includes active-scene keys so scene changes (`BootScene` -> `RoomScene`) still force first-frame camera application. **Post-processing** is wired as a **camera hook** (`attachPostProcessingPlaceholder`) — currently a no-op, reserved for CRT / dissolve-style effects.
- **Scrolling rooms**: Rooms wider or taller than the viewport declare `size` in `RoomData` (e.g. `"size": { "width": 704, "height": 198 }`). `RoomScene` reads this and sets `cameras.main.setBounds` + `startFollow` on the player so the camera tracks movement within the room. An optional `scrollBounds` field further restricts how far the camera pans (PowerQuest-style).
- **Simplicity over frameworks**: One primary gameplay scene (`RoomScene`), a thin boot loader (`BootScene`), and a **global `EventBus`** for script-facing events instead of a heavy ECS.

## 3. Core Systems

### Scrolling room camera

- **Room size** (`RoomData.size`): the physical extent of the room in game-world pixels.  Controls camera bounds, walkable-area extent, and whether `startFollow` is activated.  The background image and Aseprite prop sheets render at their **own natural dimensions** — `size` does **not** scale the art.  Setting `size` smaller than the art restricts the camera to a sub-region of the art, which is valid (e.g. the art bleeds beyond the playable area).  Matches PowerQuest's "Room Bounds."

- **Scroll bounds** (`RoomData.scrollBounds`): optional `{ x, y, width, height }` in room space that restricts how far `cameras.main` may pan within the room.  When omitted the camera pans anywhere within `size`.  Making `scrollBounds` narrower than `size` keeps the camera away from room edges (the camera is "less eager" to scroll to the edge).  Making `scrollBounds` equal to `size` lets the camera pan all the way to the edge.  Implemented via `cameras.main.setBounds(scrollBounds)`.  Matches PowerQuest's "Scroll Bounds."
- **`RoomScene.setupRoomCamera`** (private): called at the end of `create` after characters spawn. Sets `cameras.main.setBounds` from `scrollBounds` (or room size). When the room is larger than the viewport and a player exists, **`applyPlayerCameraFollow`** calls `startFollow` with an offset derived from **`CharacterData.feet`** so the camera tracks the character’s **feet** (see **`src/engine/characterFeet.ts`**), not the sprite’s top-left.
- **`RoomScene.setEditorCameraMode(mode)`** (public): called by the editor's `RoomPolygonEditScene` whenever the toolbar mode changes. Stores the current mode so it can be re-applied on panel resize. Two behaviours: `'navigate'` — letterboxes the game's virtual resolution (352×198) inside the panel using `cameras.main.setViewport`, sets zoom to fill that box, and re-activates player follow + scroll bounds for game-accurate preview; `'edit'` — expands the camera to fill the entire panel (`setViewport(0,0,panelW,panelH)`), computes `zoom = min(panelW/roomW, panelH/roomH)` to fit the full room art, sets bounds to room bounds, and disables player follow so the authoring view is stable. The `scale.on('resize')` hook re-invokes `setEditorCameraMode` automatically when the VS Code panel is resized.
- **Runtime hi-DPI camera split** (`RoomScene` + `benneRuntimeHiDpiScale.ts`): runtime keeps world rendering on `cameras.main` (normal origin/follow math) and routes GUI / cursor through a dedicated UI camera (`ensureEditorUiCamera`, also used in preview). This avoids `scrollFactor: 0` HUD drift under zoomed/letterboxed viewports while preserving room-art alignment and click mapping.
- **Background and props** render at their **natural texture dimensions** — `room.size` does **not** call `setDisplaySize`. Art that extends beyond `room.size` is simply not scrolled into view.
- **Hotspot zones** are sized to `room.size` so polygon hit areas only cover the playable area.

### Scene / room system

- **`BootScene`**: Entry after game creation. Uses **`loadStartRoomData()`** — **`startingRoomId` in `game-config.json` overrides** `rooms.manifest.json` — resolves the room’s **`*.room.json`**. Shared helpers **`buildRoomSceneStartDataFromRoomData`** and **`queueRoomSceneAssetLoads`** (`roomSceneBootstrap.ts`) build **`RoomSceneStartData`** and queue the same class of assets; **`BootScene`** uses them, and **`RoomTransitionOrchestrator`** reuses that path for arbitrary **`roomId`** (via **`loadRoomDataById`** in `loadRoomData.ts`). Queues background image (optional), room Aseprite sheet, character assets, and registered **inventory** Aseprite sheets (shared `inventory.json` and/or per-item exports), then on loader complete calls **`startInitialRoomFromBoot`** ( **`setLastRoom(null)`**, registry **`'boot'`**, **`scene.start`**) so **`onRoomSceneCreateComplete`** runs **enter** hooks, **optional boot Play From**, **`waitForEnterPhaseBenneScriptQueues`**, **fade in**, and **after-fade** hooks (or the equivalent fallback if no orchestrator is registered).
- **`RoomScene`**: Single active gameplay view for that room. No second “room manager” type is used at runtime; the abstract **`Room`** class in `Room.ts` is a **placeholder** for future data-driven room types, not wired into Phaser yet. On **`create`**, it walks **`getAllGuiData()`** (all **`*.gui.json`** under **`src/game/guis/`**) and builds one overlay per GUI **except** **Speaking Text** (**`speaking-text`**, wired only to **`setDialogTextOverlay`** / **`say`**, starts hidden at boot regardless of JSON **`visible`**), **except** **Display Text** (**`display-text`**, wired only to **`setDisplayTextOverlay`** / **`display`**, starts hidden at boot), and **except** the ids returned by **`getRegisteredDialogChoiceGuiIds()`** (always **`dialog`**, plus each registered **`Dialog.guiId`**) — those choice-dialog overlays start hidden and are driven by **`benne:dialog:started`** / **`benne:dialog:stopped`** (see **§3 → Dialog system**). Every other GUI follows **`GuiData.visible`** (**`false`** hides at load; omitted / **`true`** shows). Stable **`id`** sort and spaced **`depth`** bands keep stacking predictable: generics first, then Speaking Text (**`speaking-text`**), then Display Text (**`display-text`**), then each reserved choice GUI (so topic lines + choice UI stack above the HUD), then a **screen-fade** rectangle (see the top-of-doc **Full-screen fade** note) above that stack and below the custom pointer.
- **Room switching**: In-game, **`B.room.changeTo('roomId')`** (or **`.now`**) is handled by **`RoomTransitionOrchestrator`**: leave hooks → fade out (unless **`.now`**) → load via **`loadRoomDataById`** + **`queueRoomSceneAssetLoads`** → **`setLastRoom` / `setCurrentRoom`** ( **`gameState:roomContextChanged`**) → **`scene.start('Room', …)`** with **`'transition'`** start kind on the registry ( **`RoomScene.create`** then runs **enter** hooks, **`waitForEnterPhaseBenneScriptQueues`**, **fade in**, **after-fade** hooks). The initial **`BootScene` → `RoomScene`** start uses the same start-data and loader helpers; **`startInitialRoomFromBoot`** sets **`lastRoom` to `null`**, registry **`'boot'`** — there are **no** **leave** hooks, and **enter** hook **`lastRoom`** is **`null`**. See the top-of-doc **Room transitions** callout, **§7** ( **`B.room`**, **fades**, **moveTo**, per-room and global room-transition hooks, API table), and **`loadRoomData.ts` / `RoomTransitionOrchestrator.ts`**. **VS Code** room preview uses **`'preview'`**; it does not run the full boot/orchestrator path.

**Boundaries**: Room **layout and flags** come from JSON; **reactions** for room-scoped content (props, hotspots, or room-scoped character verbs) typically live in **`registerRoomScript`** in `*.room.ts`. **Character-definition** reactions use **`registerCharacterScript('characterId', ({ B }) => { … })`** in `*.character.ts` with **self-only** verb sugar (`B.whenLookAt(() => …)` subscribes to **`verb:character:<id>:<verb>`** only). **`dispatchVerbInteraction`** still prefers **room-scoped** character handlers when present; character-file handlers are the **fallback**. Cross-entity wiring (verbs on other props/NPCs) stays in **`*.room.ts`**.

### Rendering system

- **Renderer**: Phaser **`WebGL`** (`gameConfig.ts` **`type: Phaser.WEBGL`**) with **`pixelArt`**, **`roundPixels`**, and **`antialias: false`** for crisp **`BitmapText`** and sprites (same settings across the GUI preview, room preview, character preview, inventory preview, and **BENNE Play**).
- **Internal size** from `game-config.json` `resolution`; shipped runtime uses Phaser **Scale.NONE** + `wireBenneRuntimeHiDpiCanvasScale` (`src/engine/benneRuntimeHiDpiScale.ts`) for hi-DPI backbuffer sizing and aspect-fit letterboxing on the main camera. During active browser resize the engine prioritizes visual stability (camera/CSS updates) and defers expensive buffer realloc to a short debounce window; once settled, a full `scale.resize` commit restores crisp final output. Camera dedupe is scene-aware so newly started scenes still receive main-camera viewport/zoom even when dimensions are unchanged. Preview surfaces that should fill their panel keep **Scale.RESIZE** (via `getEditorPhaserGameConfig`).
- **Layers**: Background image (optional, full-frame) → **room stack** (`RoomScene`): props, active hotspot zones, and spawned characters are **sorted every frame** into sequential Phaser depths (from `ROOM_STACK_DEPTH_BASE` in `src/engine/room/roomStackDrawOrder.ts` via **`sortRoomStackEntities`**). **Primary order** is authored **`zIndex`** (higher draws in front). **Optional `baseline`** on **`RoomPropInstance`** and **`RoomHotspotData`**: a **room-space Y** (pixels, y down). If a character’s **world feet Y** (from **`CharacterData.feet`** or the bottom-centre fallback) is **strictly greater** than that baseline, the character draws **in front** of that prop/hotspot even with a lower **`zIndex`**. **Character vs character** uses **feet Y** only (y-sort when feet differ, then **`zIndex`**). At the same **`zIndex`** when baseline/feet rules do not decide, draw order is **prop → hotspot → character** (then stable id / feet tie-breaks). If baseline exceptions and **`zIndex`** bands together would imply a **cycle**, that character is placed using **`zIndex` / kind / feet / sortKey only** (no baseline jumps) for that insertion so order stays **deterministic** when props change. **Debug** graphics and **GUI** overlays sit above this stack.
- **`PostEffects.ts`**: **`attachPostProcessingPlaceholder(this.cameras.main)`** — extension point for Phaser 4 camera filters; **no shaders shipped yet**.
- **Aseprite tags vs. Phaser animation keys (global `createFromAseprite`)**: When several atlases register clips on **`scene.anims`**, their **animation key** is the Aseprite tag name unless the engine rewrites tags at load (see the **Aseprite clip namespacing** note at the top of this doc). Keep using the **same short tag names** in **`*.room.json`** (prop **`tag`**, **`animations`** keys), **`*.gui.json`**, **`*.inventory.json`**, and **`game-config.json`** **`cursor.idleAnimation` / `activeAnimation`**; do not hand-author the **`room:`** / **`gui:`** / **`invitem:`** / **`cursor:`** prefixes in those files unless you intentionally match the normalized atlas.

### GUI BitmapText color and text outlines

`text` and `button` controls in `*.gui.json` support colour and outline fields:

**`color`** — hex string (e.g. `"#ff0000"`); default `#ffffff`. Applied to the main `BitmapText` via `applyGuiBitmapTextFillTint` in `guiTextOutline.ts`.

**`textOutline`** — `GuiTextOutline` object (`src/types/gui.ts`):

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `enabled` | `boolean` | — | Must be `true` for the outline to appear. |
| `color` | hex string | `#000000` | Outline colour. |
| `alpha` | 0–1 | `1` | Outline opacity. |
| `thickness` | integer ≥ 1 | `1` | Pixel distance of each offset copy. |
| `sides` | `GuiTextOutlineSides` | `allSides` | Which directions receive copies (see below). |

For `button` controls, text can also switch colour per button state:

**`textColorStates`** — `GuiButtonTextColorStates` object (`src/types/gui.ts`):

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `hover` | hex string | falls back to `textColor` | Applied while pointer is over the button. |
| `pressed` | hex string | falls back to `textColor` | Applied while pointer is down on the button. |
| `disabled` | hex string | falls back to `textColor` | Applied when `enabled: false`. |

**`GuiTextOutlineSides`** — `allSides` (full 8-direction stroke) or one of 8 directional shadow presets: `topLeft`, `top`, `topRight`, `left`, `right`, `bottomLeft`, `bottom`, `bottomRight`. For `allSides` with `thickness: 1` this produces 8 offset clones; with `thickness: 2` it produces 16 (each direction gets copies at 1 px and 2 px offset, deduplicated).

**Runtime (engine)**

- `createGuiBitmapTextOutlines` (`buildGuiOverlay.ts`) reads `resolveEffectiveGuiTextOutline` (from `guiTextOutline.ts`) which expands `sides` + `thickness` into a deduplicated `{ dx, dy }` offset list. One `BitmapText` clone is created per offset, at depth-ceiling − i × ε so clones stack below the main label in a predictable fixed order.
- `buildGuiButton` (`buildGuiOverlay.ts`) applies `textColorStates.hover` / `pressed` / `disabled` to button labels in the same pointer/event flow used for sprite `states.*` tag swaps, with per-state fallback to base `textColor`.
- Each clone has `BENNE_GUI_OUTLINE_DX_KEY` / `BENNE_GUI_OUTLINE_DY_KEY` (and outline fill keys when coloured) stored via `setData` for position sync and `syncOutlinedGuiBitmapTextAll`.
- `attachGuiBitmapTextOutlineList` stores the clone array on the main BitmapText via `setData(BENNE_GUI_BITMAP_TEXT_OUTLINE_KEY, ...)`.
- `syncOutlinedGuiBitmapTextAll(main, text)` (called by `GuiRuntime` whenever speaking-text / verb-line content changes) calls `setText` on main and each clone, then re-applies fill tints from the stored data keys so colours survive text updates.
- `syncOutlinedGuiBitmapTextPositions(main)` re-anchors clones after the main label moves (e.g. Speaking Text bottom-centre repositioning).

**WebGL tinting**

With **`Phaser.WEBGL`**, Phaser’s Tint component applies to `BitmapText`. **`applyGuiBitmapTextFillTint`** sets `setTint(tint)` + `setTintMode(Phaser.TintModes.FILL)` + explicit corner assignment, and stores the tint in `BENNE_GUI_BITMAP_TEXT_FILL_TINT_KEY` / `BENNE_GUI_OUTLINE_FILL_TINT_KEY` so `syncOutlinedGuiBitmapTextAll` can re-apply after `setText`. Outline clones are separate `BitmapText` instances offset by whole pixels (no Canvas pre-tinted atlas or prototype patch).

### Prop parallax

Room props may set **`parallaxDepth`** (`RoomPropInstance` in `src/types/room.ts`). Each frame, `RoomScene.updateParallaxProps` blends the prop’s authored position with the **top-left of the camera’s visible world rectangle** (`camera.worldView`), not raw `scrollX` / `scrollY` (those diverge from the visible corner when zoom ≠ 1, which breaks editor navigate mode):

```
worldX = parallaxDepth * baseX + (1 − parallaxDepth) * camera.worldView.x
worldY = parallaxDepth * baseY + (1 − parallaxDepth) * camera.worldView.y
```

(`baseX` / `baseY` are the prop’s authored `x` / `y` in room space.)

| `parallaxDepth` | Effect |
|-----------------|--------|
| `0` | Sprite position tracks camera scroll origin (moves fully with the camera). |
| `0–1` | Distant; moves slower than the camera. |
| `1` | No parallax (default if the field is omitted); world-fixed at authored position. |
| `>1` | Foreground; moves faster than the camera. |

**Example** — distant layer at half camera coupling:
```json
"parallaxDepth": 0.5
```

**Performance**: Props with `parallaxDepth === 1` or no `parallaxDepth` are not added to the parallax update list. The scene’s `update()` skips work when that list is empty.

### Input system

- **Custom pointer** (optional `game-config.json` **`cursor`**): when **`cursor.display.aseprite`** is **`true`** and `src/game/assets/images/cursor/cursor.{png,json}` are bundled, **`BootScene`** loads the sheet as **`aseprite:cursor`**; **`RoomScene`** hides the OS cursor, draws a screen-fixed **`Sprite`** that follows the pointer, and swaps clips named by **`idleAnimation`** vs **`activeAnimation`** (Aseprite frame tags / Phaser animation keys). Optional **`cursor.animations`** uses the same per-tag shape as **`CharacterData.animations`** (`loop`, `frameDuration`, `events`); **`applyCharacterAnimationClips`** applies it after **`createFromAseprite`**. Optional **`cursor.hotspot`** picks where the logical pointer tip sits on the art (**`top-left`** through **`bottom-right`** as Phaser `setOrigin` fractions, or **`custom`** with required **`cursor.hotspotPixel`** **`{ x, y }`** from the sprite’s top-left). Hover uses Phaser **`hitTestPointer`** over props (clickable colliders only), **`benneHotspot`** zones, clickable characters, GUI **`button`** hit targets (`buildGuiOverlay` sets **`benneGuiButton`** on button hit targets), and **occupied** GUI **`inventoryPanel`** slot containers (**`benneInventorySlot`** — same “active” cursor clip as over other clickables). The VS Code **room preview** queues the same asset via **`buildPreviewManifest`** (`queueGameCursorLoad`). **Active inventory item** (use-on-target, see **Game state** / **Inventory** below): when an item is armed and its **`InventoryItemData.cursorAnimation`** names a tag that exists on **that item’s** inventory Aseprite sheet, **`RoomScene`** plays that clip on the custom cursor regardless of hover target (it overrides idle/active while that item stays armed). If the field is omitted or the tag is missing, cursor behavior falls back to the normal idle / active-verb clips.
- **Walk**: **Left click** on empty space (no hit-test targets) moves the **player** character toward the click. **Right click** on empty space clears the runtime active verb (see **Verb system → Active verb** below). Clicks outside the mesh are **clamped** into **walkable regions** (`walkable.ts` — each **`WalkablePolygon`** is an outer ring minus optional **active** hole rings; union across polygons; point-in-polygon + closest-point clamping). Characters then **pathfind** around holes and concave parts of the mesh via `src/engine/pathfinding.ts` (see **Pathfinding** below).
- **Clickable targets** (props / hotspots / characters): **`pointerdown`** resolves through **`resolvePointerVerbForTarget`** (`src/engine/verbs/resolvePointerVerb.ts`) which considers the current **active verb** (runtime state on **`GameStateManager`**), the target's authored **`defaultVerb`**, and the effective **`inputProfile`**. Outcomes: dispatch a verb; walk to the target's stand point (when a slot resolves to the built-in `walkTo`); clear the active verb (right-click while one is set); or no-op. **Props** still dispatch immediately (no engine walk-to-before-verb). **Hotspots** use closed **`points`** polygons (≥3 vertices); optional **`onVerbFallback`** on the hotspot (and prop) JSON gates object-level fallback dispatch; per-verb handling is whatever **`*.room.ts`** registers on the **`EventBus`**. **Clickable characters** use a **polygon hit area** when **`CharacterData.collider.points`** has at least three vertices (coordinates in **sprite frame space**, origin top-left of the cel, consistent with **`feet`**); otherwise the **full sprite rectangle** is interactive.
- **GUI `inventoryPanel` (occupied slots)**: **`buildGuiOverlay`** gives each **filled** slot row a **`pointerdown`** handler that runs **`resolvePointerVerbForInventoryItem`** (`resolvePointerVerb.ts`), then **`dispatchInventoryVerbInteraction`** (`src/engine/verbs/dispatchInventoryVerb.ts`), then **`trySyncActiveInventoryAfterInventoryUseOrGiveRowDispatch`** (same module) when the row has **no** **`registerInventoryScript`** module — that synchronous path arms **`activeInventoryItemId`** for the effective **use** or **give** verb id only (**`resolveEffectiveUseVerbId`** / **`resolveEffectiveGiveVerbId`** in **`verbConfig.ts`**). **Active verb** and **left / right → `inputProfile`** match props/hotspots/characters, except (1) profile **`walkTo`** cannot mean “walk to a stand point” for a bag row — it is treated like **`defaultVerb`** on that item (**`InventoryItemData.defaultVerb`**, fallback **`look`**), and (2) when **`activeInventoryItemId`** is set, **`resolvePointerVerbForInventoryItem`** forces **`consumeActive: false`** on **`verb`** resolutions so the verb bar stays selected for **inventory-on-inventory** / **use-on-target** (**`shouldDispatchInventoryUsedOnVerbForGame`**); with **no** armed item, **`consumeActive`** matches **`resolvePointerVerbForTarget`**, and **`buildGuiOverlay`** **defers** **`clearActiveVerb`** with **`queueMicrotask`**: it **skips** the clear when **`activeInventoryItemId ===`** the clicked row (arming for combine / use-on-target after **`InventoryBenneScript`** **`afterInteractionTail`**, **`trySync`**, or any **`whenVerb`** that **`setActiveInventory`** for that row), otherwise clears like a room click. **`RoomScene`** supplies **`inventoryPanelPointerContext`** (current **`roomId`**, scripted-dialog suppression, dialog click-to-skip) on every in-game GUI overlay build; the VS Code **GUI preview** omits it, so preview inventory slots stay non-interactive and clicks still pass through like other non-button controls.
- **Context menu** disabled on mouse in `RoomScene`.

### Verb system

- **Config** (`src/game/game-config.json`, types **`src/types/game.ts`**): optional **`verbs`** (`{ id, label?, preposition? }` each — **`preposition`** is a short connector for composed verb + object UI, e.g. “Look **at** …”), optional **`inputProfile`** (flat **`primaryButtonVerb`** / **`secondaryButtonVerb`** — no `kind` field), optional **`defaultFallbackLine`** (used for **`verb:unhandled`**).
- **`inputProfile` slot grammar** — each slot accepts **any configured verb id** from **`verbs[]`**, or one of two reserved literal tokens:
  - **`"walkTo"`** — built-in universal walk verb (`WALK_TO_VERB_ID` in `verbs/verbConfig.ts`). Never authored in **`verbs[]`**, never shown as a verb chip in the Inspector. When a slot resolves to `walkTo` on a **room** clickable target, the engine walks the player to the target's stand point (prop `walkToPoint` / collider-closest / frame-center; hotspot `walkToPoint` / centroid; character `walkToPoint` / feet) — no verb dispatch for that click. On a **GUI `inventoryPanel`** occupied slot, there is no stand point: resolution uses **`resolvePointerVerbForInventoryItem`**, which substitutes the row item's **`defaultVerb`** (fallback **`look`**) and dispatches that verb. Empty-space clicks always walk, independent of slot configuration.
  - **`"defaultVerb"`** — substitute with the clicked target's authored **`defaultVerb`** field (per-prop / hotspot / character / inventory item). Falls back to **`"look"`** when the target omits the field. Shown in the Inspector as a "Default verb" dropdown on each clickable card (built from **`game-config.json`** `verbs`).
- **Defaults**: Omitting **`verbs`** implies ids **`look`** and **`use`**. Omitting **`inputProfile`** defaults to **left → `look`**, **right → `use`**. Typical 9-verb wiring: `primaryButtonVerb: "walkTo"`, `secondaryButtonVerb: "defaultVerb"` (paired with a verb GUI that calls `B.setActiveVerb(...)` per button).
- **Active verb** (runtime UI state on **`GameStateManager`**, not persisted in snapshots): a script-settable verb id that overrides the pointer resolution on the **next** target click.
  - **Bennescript**: **`B.setActiveVerb(verbId | null)`**, **`B.getActiveVerb()`**, **`B.clearActiveVerb()`** are available on every Bennescript facade (room / character / global / inventory / GUI) via the shared **`BenneScriptCore`**.
  - **Resolution rules — room clickables** (`resolvePointerVerbForTarget`):
    - Clickable + **left** click + active verb set → dispatch the active verb on the target; **clear** the active verb ( **`consumeActive`** ).
    - Clickable + **right** click + active verb set → clear the active verb (no dispatch).
    - Clickable + any button + no active verb → resolve the matching `inputProfile` slot (`walkTo` / `defaultVerb` / plain verb id).
    - Empty space + **right** click → clear the active verb (no dispatch, no walk).
  - **Resolution rules — GUI `inventoryPanel` rows** (`resolvePointerVerbForInventoryItem`): same active-verb / **`inputProfile`** / right-click clear semantics as above, plus **`walkTo` → item `defaultVerb` / `look`**. With **no** **`activeInventoryItemId`**, a left-click **`verb`** dispatch uses the same **`consumeActive`** as room clickables; **`buildGuiOverlay`** may clear the active verb on a **microtask** after dispatch unless the clicked row became **`activeInventoryItemId`** (any verb id that arms that row — built-in **use** / **give** tails, **`trySync`**, or **`setActiveInventory`** in **`whenVerb`**). When an item **is** armed, **`consumeActive`** is forced to **`false`** on **`verb`** resolutions so the selection stays for combine / use-on-target. If an inventory handler **queues** async work (`say`, **`wait`**, tweens) **before** arming on the same click, arm with **`setActiveInventory`** **synchronously** at handler start when the verb should combine; otherwise the deferred clear can run too early. The resolved **use** and **give** verb ids on a row arm **`activeInventoryItemId`** after the interaction queue drains by default (**`InventoryBenneScript`**, plus **`trySyncActiveInventoryAfterInventoryUseOrGiveRowDispatch`** for JSON-only items — see **Inventory System → Bennescript**). **`B.whenUse` / `B.whenGive`** add optional handler code **in addition**; **`B.whenUse.doNotActivate` / `B.whenGive.doNotActivate`** opt out of arming for that verb when **every** registered handler for that verb uses **`doNotActivate`**.
  - Event **`gameState:activeVerbChanged`** (`GAME_STATE_ACTIVE_VERB_CHANGED_EVENT`) fires on every change; handy for cursor / button-highlight wiring. **`applySnapshot`** also clears the active verb so loading a save never leaves a stray verb selected.
- **Per-object data**: **`RoomPropInstance`** and **`RoomHotspotData`** carry optional **`onVerbFallback`** (and **`defaultVerb`**) only; **`InventoryItemData`** may carry optional **`onVerb`** (verb id → **`true`**, authoring) plus **`onVerbFallback`**. **`CharacterData`** mirrors props/hotspots (no **`onVerb`**); optional **`onVerbFallback`** and **`defaultVerb`** behave like other clickables. **`defaultVerb`** controls what the `"defaultVerb"` slot substitutes in (omit to fall back to `"look"`); the Inspector shows it as a dropdown on each clickable card (the room-character card surfaces it read-only — edit from the character's own Inspector).
- **Dispatch** (`src/engine/verbs/dispatchVerb.ts`): **Before** emitting, **`interruptPlayerWalkForVerbInteraction`** runs (see **Game state → Active `Phaser.Game` handle**): if **`RoomScene`** is the active Phaser scene, **`RoomScene.interruptPlayerWalk()`** stops any in-progress **player** path tween, clears the live path / arrive callback, returns the player to **Idle**, and emits **`player:walk:stop`** (`PLAYER_WALK_STOP` in **`playerWalkEvents.ts`**) with **`reason: 'interrupted'`**. The same interrupt runs at the start of **`dispatchInventoryOnVerbTargetInteraction`**, **`dispatchInventoryOnInventoryItemInteraction`**, and **`dispatchInventoryVerbInteraction`** so inventory-on-world and **`inventoryPanel`** row verbs behave consistently. Superseding a walk by **starting another walk** still stops the prior tween inside **`RoomScene.movePlayerToward`**; this hook covers the case where the next interaction is **not** a new walk (e.g. **look** while crossing the room). **`RoomScene.tryBeginPropLook`** goes through **`dispatchVerbInteraction`**, so it participates in the same interrupt. **Emit order (listener-first)**: for **props** and **hotspots**, emit **`verb:room:<roomId>:<targetType>:<targetId>:<verbId>`** only when that channel has listeners; otherwise continue. For **characters**, try **`verb:room:<roomId>:character:<characterId>:<verbId>`** then **`verb:character:<characterId>:<verbId>`** the same way. If **`onVerbFallback`** is enabled on the target, try room-scoped then character-global fallback events **only when those channels have listeners**. Then **`verb:global:<verbId>`** (if listeners) → **`verb:global:fallback`** (if listeners) → **`verb:unhandled`**. In **Vite dev**, unhandled verbs also **`console.warn`**.
- **Payloads** (`propInteractionEvents.ts`): **`RoomPropInteractPayload`**, **`RoomHotspotInteractPayload`**, and **`CharacterVerbInteractPayload`** carry **`verbId`** and target ids; props also expose optional **`walkToPoint`** / **`lookAtPoint`** (room pixels). Characters may include optional **world** **`walkToPoint`** / **`talkPoint`** when the matching fields exist in **`CharacterData`** (converted from frame offsets at click time). Object fallback emissions add **`verbFallback: true`**.

### GUI verb status line (Bennescript)

LucasArts-style copy (**Walk to**, **Push pillar**, **Use item with …**) is authored as a normal **`text`** control plus **`registerGuiScript`**: subscribe to **`B.onVerbContextChanged`** (**`BENNE_VERB_CONTEXT_CHANGED_EVENT`**) inside **`onGuiBuilt`** and set **`control('…').text`** from **`B.activeVerb`**, **`B.activeInventory`**, **`B.currentHoverDescription`**, matching the pattern in **`src/game/guis/verbs/verbs.gui.ts`**. Helpers **`composeVerbLineText`**, **`resolveVerbLineDisplayLabel`**, and **`resolveVerbLineLeadingVerbWord`** in **`verbConfig.ts`** remain available when you prefer that exact string math in TS.

**Hover context for `B.currentHoverDescription`** — **`RoomScene`** walks Phaser **`hitTestPointer`** (sorted like dispatch) each **`pointermove`** and after **`gameState:inventoryChanged`**, skips GUI **`button`** hits, and publishes the short label plus structured **`B.currentHoverTarget`** (including optional authored **`defaultVerb`** when non-empty) through **`publishBenneVerbHoverContext`** (props/hotspots/clickable characters/occupied **`inventoryPanel`** rows). During **scripted dialog** input suppression (**`say`** lock), **`B.currentHoverDescription`** is cleared so HUD lines do not advertise room targets behind a blocking line.

### Character feet (walk / camera)

Optional **`feet`** on **`CharacterData`** (`src/types/character.ts`): **`{ "x", "y" }`** in **frame pixel space** from the cel’s **top-left** to the ground contact. The runtime places Aseprite sprites with **`origin (0,0)`** and offsets position so room spawn **`(x, y)`** is where the feet stand; walk tweens and camera follow use the same point. If **`feet`** is omitted, the engine uses the **bottom-centre** of the **current** frame (works best when cels share a consistent size). The VS Code **BENNE Character preview** webview (`npm run build:character-preview`) plays a default idle (prefers **`IdleD`**, then other **`Idle*`** tags), shows **Feet**, **Walk to**, and **Talk** handles plus the collider on one overlay, and **Save to JSON** writes **`feet`**, **`walkToPoint`**, **`talkPoint`**, and **`collider`** together via **`characterGeometryPatch.ts`**. In the preview, **Feet** and **collider** vertices are clamped to the cel; **Walk to** and **Talk** may be placed outside the sprite bounds (camera bounds grow to include them).

Optional **`walkToPoint`** on **`CharacterData`**: same **frame space** as **`feet`**; world stand = sprite position + offset. Used when **`RoomScene`** resolves script **`walkTo('<characterId>')`** to that character. If omitted, resolution uses the character’s **world feet** (same effective stand as when **`walkToPoint`** matches **`feet`**).

Optional **`talkPoint`** on **`CharacterData`**: same **frame space**; a script-facing **look / dialogue** hint. Verb payloads include **world** **`talkPoint`** when the field is set (like prop **`lookAtPoint`**, but stored per character in frame space).

**Click collider (authoring)** — Optional **`collider: { "points": [ { "x", "y" }, … ] }`** on **`CharacterData`**, same **frame space** as **`feet`**. The preview reuses **`PreviewPolygonOverlay`** with the same vertex / edge / Delete gestures as prop colliders; fewer than three points on save **removes** **`collider`** so the engine falls back to the full-sprite hit test. Verbs and scaffolding use **`CharacterVerbInteractPayload`** from **`propInteractionEvents.ts`**; **Create Character** and verb-handler insertion ensure that **import** is present in new **`*.character.ts`** files.

### Room regions (perspective character scale)

**Data** — **`regions`** on **`RoomData`** (`src/types/room.ts`, **`RoomRegionData`**): each entry is a closed **`points`** polygon in **room pixels** (same space as walkables and hotspots), with optional **`active`** (omit or non-**`false`** = used). Optional **`scaleTop`** and **`scaleBottom`** default to **`1`** (normal sprite size). **Top** means the **smaller** room **Y** (upper on screen); **bottom** means the **larger** **Y**. The runtime takes the axis-aligned **vertical span** of the polygon’s vertices (**min Y** … **max Y**) and linearly blends **`scaleTop` → `scaleBottom`** as the character’s **feet Y** moves down that span while the feet remain **inside** the polygon. Optional **`scaleWalkSpeed`** (default **`false`**) on the **winning** region: when **`true`**, the character’s **authored walk speed** is multiplied each frame by **`max(minWalkScale, pow(linearScale, walkScalePower))`**, where **`linearScale`** is that same vertical blend (and **`minWalkScale` / `walkScalePower`** come from **`game-config.json`** — see **`perspective`** below). Optional **`tint`** (**`#rrggbb`**) and **`tintAlpha`** (**0–1**, default **`1`**) on the **winning** region multiply-tint spawned character sprites while feet stay inside (see top-of-doc **Room regions — character tint** note).

**Runtime** — **`computeRoomRegionPerspective(feetX, feetY, regions, perspectiveSettings)`** (`src/engine/room/regionCharacterScale.ts`) walks **`regions`** in array order; each active polygon with ≥3 points that contains the feet updates **`characterScale`** (the linear value) and, if that region’s **`scaleWalkSpeed`** is **`true`**, **`walkSpeedMultiplier`** from the formula above; otherwise **`walkSpeedMultiplier`** is **`1`**. The same pass records **`winningRegion`** (the last matching **`RoomRegionData`**) for tint and diagnostics. **`computeRoomRegionCharacterScale`** remains a thin wrapper that returns only **`characterScale`** (for callers that do not need walk tuning). Outside every region, both outputs are **`1`** and **`winningRegion`** is **`null`**. Later entries **win** when polygons overlap. **`resolveWinningRoomRegionIdAtFeet`** / **`resolveWinningRoomRegionDataAtFeet`** return that winner’s **`id`** or data (**`null`** outside) using the identical containment / ordering rules — shared by **`RoomScene.syncCharacterRegionEnterExit`** for **`B.region`…`whenEnter` / `whenExit`**. **`RoomScene`** applies **`characterScale`** and **region character tint** (via **`packedTintFromWinningRegion`**) inside **`applyFeetWorldWithRegionScale`**: on spawn, on idle **`update`** (characters not in a walk tween), and along **walk legs** (interpolated feet). **Walk legs** advance **`u`** with **`u += (walkSpeed * walkSpeedMultiplier * dt) / legLength`**, then place feet and recompute scale + tint.

**Rendering (crisp downscale on screen)** — The **`characterScale`** math above drives **`sprite.setScale`**. How scaled character **sprites** stay **blocky / sharp** in the WebGL pipeline (custom quad batch, **`inPerspMag`**, texel bucketing while **`mag`** drifts) is separate; see the top-of-document **Character perspective WebGL batch (retro texel snap)** note and **`src/engine/rendering/benneCharacterPerspectiveBatch.ts`**.

**Enter / exit hooks (Bennescript)** — Room scripts only: **`B.region('<regions[].id>').whenEnter(handler)`** / **`whenExit`**, or **`B.whenEnterRegion` / `whenExitRegion`** as flat sugar. Handlers register through **`BenneScript.subscribe`** (same queued interaction semantics as **`whenLookAt`**). The scene compares winning region ids **every frame** for all spawned characters (including mid-walk feet positions); the first frame after **`create`** seeds prior membership without firing events so **`whenEnterRoom`** + **`moveToNow`** into a zone does not double-trigger unless the feet **later** leave and re-enter.

**Game config** — **`GameSettings.perspective`** (`src/types/game.ts`): optional **`minWalkScale`** (default **`0.3`**) and **`walkScalePower`** (default **`0.8`**). Merged by **`getPerspectiveSettings()`** in **`ConfigManager.ts`** (validated at load when the block is present).

**Feet / camera** — **`characterFeet.ts`** treats world feet as **`sprite.x + feetLocalX * scaleX`** (and **Y**), and **`placeSpriteByFeet`** backs out the same when positioning the top-left origin. The module-level **`getFeetFollowOffset`** used for **`cameras.main.startFollow`** scales the offset so follow still targets the feet when **`scale` ≠ 1**.

**Authoring** — **Add Region** (**`runAddRoomRegionWizard`**) still scaffolds a default square; edit the polygon in the **room preview** (**region polygon** mode). In the **Inspector**, region cards expose **Scale top** / **Scale bottom** (patch **`regionScale`**, **`updateRegionScaleFields`**), **Scale walk speed** (checkbox, patch **`regionScaleWalkSpeed`**, **`updateRegionScaleWalkSpeed`**), **Character tint** / **Tint alpha** (patch **`regionTint`**, **`updateRegionTintFields`**), or hand-edit **`*.room.json`**. Rebuild **`benne-editor/media/inspector/inspector.js`** after Inspector TS changes (**`npm run compile`** or **`npm run watch`** under **`benne-editor/`**).

**Limits (v1)** — Mapping is by the polygon’s **bounding Y extent**, not a custom “depth” axis through the floor. **`flipX`** on characters is separate from **`setScale`** (no negative scale for mirroring).

### Character directional animation (facing)

Directional clips use **Aseprite frame-tag names** built as **`<base><facing>`** (e.g. `IdleL`, `WalkDR`, `TalkUL`). Implementation lives in **`src/engine/directionalCharacterAnimation.ts`**; types for room JSON use **`CharacterFacingLetter`** in **`src/types/character.ts`**.

**Facings (eight-way)** — left, right, up, down, and diagonals: **`L`**, **`R`**, **`U`**, **`D`**, **`UL`**, **`UR`**, **`DL`**, **`DR`**. World space matches the rest of the engine (**y increases downward** on screen).

**Choosing facing from movement** — **`facingFromWorldDelta(dx, dy)`** normalizes the walk (or look) vector and picks the facing whose **unit direction** has the **largest dot product** with that vector, so purely horizontal or vertical motion maps to a **cardinal** (e.g. straight down → **`D`**), and diagonal motion maps to a **diagonal** when both components matter. A **zero** delta defaults to **`D`**.

**Playing a clip when some facings are missing** — **`playDirectionalAnimation(sprite, baseName, facing)`** first tries **`${baseName}${facing}`**. If that Phaser animation does not exist (or has no frames), it walks **other facings in order of smallest angular distance** from the requested facing, and for each candidate tries:

1. The **unflipped** tag for that facing.
2. If a **horizontal mirror partner** exists — **`L`↔`R`**, **`UL`↔`UR`**, **`DL`↔`DR`** — the partner’s tag with **`flipX`**, so a character can ship only **`WalkDL`** and still satisfy a **`DR`** request. **`U`** and **`D`** have **no** mirror pair in this scheme.

The sprite’s **`facing`** data stores the **logical** facing the gameplay asked for (walk end, look-at, spawn), not necessarily the suffix of the clip that ended up playing.

**Spawn and idle defaults** — **`resolveSpawnIdleFacing`** honors **`initialFacing`** on room character instances when it is one of the eight letters; otherwise it falls back like **`resolveInitialIdleFacing`**, which prefers an existing **`Idle*`** in a default order (**cardinals** `R`, `D`, `L`, `U`, then **diagonals** `DR`, `DL`, `UR`, `UL`), and finally **`D`** if nothing matches.

**RoomScene** uses this for **player walk**, **idle after walk**, and **NPC spawn** animation bases (`Idle`, `Walk`, etc.).

### Scripting / interaction system

- **Canonical scoped event ids** are emitted by **`dispatchVerbInteraction`** from runtime target context; JSON no longer stores ad-hoc event-id strings. Props/hotspots/room-scoped characters use `verb:room:...`, character-global uses `verb:character:...` (props still dispatch immediately; no engine **walk-to-then-verb** queue — but an **in-progress** player walk from empty space or **`walkTo`** resolution is **cancelled** when a verb dispatches; see **Verb system → Dispatch** and **Game state → Active `Phaser.Game` handle**).
- **`registerGameContent()`** (called before `createBenneGame`) **lazily** registers **`./rooms/**/*.room.ts`** (factories only — no module execution) and **eagerly** loads **`./characters/**/*.character.ts`**, **`./guis/**/*.gui.ts`**, **`./inventory/**/*.inventory.ts`**, **`./dialogs/**/*.dialog.ts`**, and **`./globalScript.ts`** so side-effect registrations run; it also registers **`./inventory/**/*.inventory.json`** and **`./dialogs/**/*.dialog.json`**. Room modules are executed on demand by **`ensureRoomScriptLoaded(roomId)`** (`src/engine/scripting/registerRoomScript.ts`), which is awaited in **`BootScene`** (after the Phaser asset loader completes, before `startInitialRoomFromBoot`) and in **`RoomTransitionOrchestrator`** (in parallel with `awaitLoaderComplete` during `changeTo`). Callbacks registered via **`registerRoomScript`** are stored in a **per-roomId map**; `RoomScene.create` calls **`getCallbacksForRoom(roomId)`** to run only that room's handlers with a fresh context. **`wireBenneGlobalScripts(game, gameEvents)`** runs immediately after **`createBenneGame`**, always constructs **`RoomTransitionHookRegistry` + `RoomTransitionOrchestrator`**, and (when at least one **`registerGlobalScript`** callback was recorded) runs those callbacks with **`GlobalBenneScript`** and **`setGlobalBenneScriptForRoomTransitions`** — enabling **`B.whenGlobalFallback`**, **`B.whenLeaveAnyRoom`**, **`B.whenEnterAnyRoom`**, etc. There is **no** exported `register*Script(events)` loader path.
- **Payloads**: Typed payloads for prop interaction (`propInteractionEvents.ts`), player walk start/stop, etc.
- **`BenneScript` movement — walk vs teleport**: **`B.player.walkTo(target)`** and **`B.character(id).walkTo(target)`** (and **`.now`**) use **`RoomScene`** pathfinding + **Walk** animation to a resolved room-space point — **unless** **`movable`** is **`false`** for that walker (**`CharacterData.movable`** / **`B.player.movable`** / **`B.character(id).movable`**), in which case the walk is a **no-op** (see top-of-doc **Character `movable`**). **`B.player.moveTo` / `moveTo.now` / `moveToNow`** and **`B.character(id).moveTo` / …** **do not** pathfind: they call **`movePlayerToNow` / `moveCharacterToNow`** (feet **teleport** with walkable **clamp** and **Idle** facing) and are **not** gated by **`movable`**. The **same** resolution rules apply to **`Point2`** and string targets (first match): **prop** in the room → **hotspot** → **character** → **`room.points`**; props use **`walkToPoint`**, else closest point in/on the **collider** to the walker, else the prop frame **center**; hotspots use **`walkToPoint`** or polygon **centroid**; characters use **`CharacterData.walkToPoint`** or **feet** world position. Public **`RoomScene.resolveMovementTarget(target, walkerFeet)`** returns the room-space feet goal for any scripting use. Unknown ids **`console.warn`** once per id and fall back to the walker’s current feet (no move / no teleport offset). **`B.character(id)`** is implemented on **`BenneScriptCore`** (shared with room / character / inventory / **global / GUI / dialog** scripts): each call resolves the active **`RoomScene`** via the same hook as **`B.player`** (room-scoped facades pass **`() => this.roomScene`**; dialog / global / GUI pass **`game.scene.getScene(SCENE_ROOM)`**).
- **NPC track-facing**: **`B.character(observer).startFacingCharacter(targetId, minWaitSeconds?, maxWaitSeconds?)`** and **`stopFacingCharacter()`** (NPC-only; see top-of-doc **Character `startFacingCharacter` / `stopFacingCharacter`**) queue on **`BenneScriptCore`**’s tail and drive **`RoomScene.startCharacterFacingCharacter` / `stopCharacterFacingCharacter`** — runtime **Idle** facing toward the other character’s feet with delayed re-aim when either moves.
- **Character follow (persisted)**: **`B.character(follower).startFollowingCharacter(targetId, options?)`** / **`stopFollowingCharacter()`** and the **`B.player`** equivalents (see top-of-doc **Character follow**) persist to **`GameStateManager`** and drive **`RoomScene.updateCharacterFollowers`** when both sprites exist in the room; distinct from **`startFacingCharacter`** (not saved).
- **`BenneScript` verb sugar** (**`whenLookAt`**, **`whenUse`**, **`whenPickUp`**, **`whenPush`**, **`whenPull`**, **`whenOpen`**, **`whenClose`**, **`whenVerb`**, **`whenTalkTo`**) registers handlers using the same **prop → hotspot → character** rule for the string id (room **`props`** / **`hotspots`** / spawned **`CharacterData.id`**). **`B.onProp`** and **`B.prop`** stay **prop-only**; **`whenGive`** remains **prop-only** for the recipient id.
- **`B.region(regionId)`** (**`whenEnter`**, **`whenExit`**) and **`whenEnterRegion` / `whenExitRegion`** — room JSON **`regions[].id`** only; see **Room regions → Enter / exit hooks** above. **`RegionEnterExitContext`** payload; **`gameEvents`** ids **`roomRegionEnterEventId` / `roomRegionExitEventId`**.
- **`B.hotspot(hotspotId).active`** — room JSON **`hotspots[].id`** only; persisted **`active`** override with live polygon zone mount/remove (see top-of-doc **Room hotspots — `active` Bennescript** and **`docs/bennescript-api.md`**).
- **Tagged dialogue (`B.say`)**: On every **`BenneScriptCore`** facade (**`BenneScript`**, **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, **`GuiBenneScript`**, **`DialogBenneScript`**), **`B.say`**…`` / **`B.say.now`**…``. Each non-blank line is **`Speaker: text`** (trimmed); **`Player`** in any case maps to **`startingPlayerCharacter`** in **`game-config.json`**. Other labels match a **spawned** character definition id **case-insensitively** (resolved to the room’s canonical id) or **`parseDialogueLines`** throws with a short hint list. Blank lines and **`//`** line or trailing comments are skipped. **`B.say`**…`` lines are chained on the Bennescript interaction tail in order. **`B.say.now`**…``: a **single** line does not use the tail (same as **`B.player.say.now('…')`**); **multiple** lines still play **in order** but off the tail so later **`wait`** / **`walkTo`** steps in the same handler are not blocked. **`B.player.say`**…`` / **`B.character('id').say`**…`` scope plain lines to that speaker; a mismatched **`Name:`** prefix throws. String **`B.player.say('…')`** and optional **`{ clickToSkip }`** on those calls are unchanged. When there is **no** active **`RoomScene`**, **`B.say`** / **`B.character`** calls no-op with a **DEV** one-time **`console.warn`** (same pattern as **`B.player`** in those contexts).
- **Boundary**: Scenes should not embed game-specific puzzle logic; they **emit** and **listen** only through agreed event names and small shared types.

### Asset management / loading

- **Room & character JSON** for Aseprite: **eager globs** in `loadAsepriteAtlasData.ts` (and friends); **normalized** for Phaser frame indices (`normalizeAsepriteJson.ts`).
- **Binary assets**: **`resolveGameAssetUrl` / `resolveGameAssetJsonUrl` / `resolveGameAssetXmlUrl`** map paths under `src/game/assets/**` to **Vite-built URLs** (images, JSON, BMFont XML for GUI bitmap fonts). **Audio** uses additional globs on **`./assets/audio/sfx/**`** and **`./assets/audio/music/**`** (.mp3 / .ogg / .wav / .m4a); **`getBenneAudioBootEntries()`** groups stems + URLs for **`queueBenneAudioForBootLoader`** (Phaser **`load.audio`** keys **`benne:sfx:<stem>`** / **`benne:music:<stem>`** via **`benneAudioCacheKeys.ts`**).
- **Boot-time loading only** in `BootScene` (Phaser loader); **no streaming** or mid-room asset packs yet.

### Audio system

**Goals**

- **`Phaser.Game#sound` only** (`SoundManager` never uses `scene.sound`) so playback survives **`RoomScene`** teardown — **music** can continue across **`B.room.changeTo`** without restarting.
- **Volumes**: **`applyBootAudioSettings`** (**`BootScene`**) sets the Phaser sound manager cap from **`game-config.json`** **`audio.masterVolume`**. Per-call playback multiplies **`getEffectiveSfxVolume`** / **`getEffectiveMusicVolume`** (**`applyAudioFromSettings.ts`**) with optional **`SoundPlayOptions.volume`** / **`MusicPlayOptions.volume`** (0–1) and with **`SoundManager`** session multipliers set by **`B.sound.setSfxVolume`** / **`setMusicVolume`** (runtime-only scalars; reapplied to active instances when changed).

**Asset discovery**

- **`registerGameContent`** does **not** glob audio; **`resolveGameAssetUrl.ts`** holds **`import.meta.glob`** tables for **`assets/audio/sfx/**`** and **`assets/audio/music/**`**. **`getBenneAudioBootEntries()`** returns one boot row per **stem** (filename without extension); multiple formats for the same stem become a **fallback URL array** for **`load.audio`**.
- **`queueBenneAudioForBootLoader`** runs from **`BootScene.create`** only when **`game.registry`** **`benneAudioScriptDisabled`** is **not** `true` (VS Code **room / GUI / inventory / character** previews set **`benneAudioScriptDisabled`** in **`Phaser.Game` `callbacks.preBoot`**).

**Runtime**

- **`SoundManager`** (**`src/engine/sound/SoundManager.ts`**) — **`playSfx` / `playSfxAndWait`**, **`playMusic`**, **`stopSfx`**, **`stopAllSfx`**, **`stopMusic`**, **`destroy`**. **SFX** instances are tracked until **`complete`** / **`destroy`** or **`stop`**; **`playAndWait`** resolves when the sound finishes or is stopped.
- **Registry** — **`benneSoundRegistry.ts`**: **`BENNE_SOUND_MANAGER_KEY`**, **`tryGetBenneSoundManager`**, **`setBenneSoundManager`**; **`BENNE_AUDIO_SCRIPT_DISABLED_KEY`** (**`benneAudioScriptDisabled`**).
- **`Game.ts`** — constructs **`SoundManager`** after **`new Phaser.Game`**, registers it, **`destroy()`** on **`Phaser.Core.Events.DESTROY`** and removes the registry entry.

**Bennescript**

- **`createBenneScriptSoundFacade`** (**`benneScriptSoundApi.ts`**) wires **`B.sound`** on **`BenneScriptCore`** and exposes the **same object** on **`B.player.sound`**, **`B.character('…').sound`**, **`B.prop('…').sound`**.
- **Blocking `B.sound.play`** appends to **`interactionTail`** so it orders **after** **`walkToClicked`**, **`wait`**, etc.; **`B.sound.play.now`** plays immediately without tail sequencing. **`playAndWait`** chains **`SoundManager.playSfxAndWait`**; **`playAndWait.now`** starts playback without waiting on prior tail steps (same spirit as **`wait.now`**).
- **Author ids**: **`^[a-zA-Z0-9_-]+$`** map to loader keys **`benne:sfx:id`** / **`benne:music:id`**.

**Lifecycle**

| Event | SFX | Music |
|-------|-----|--------|
| **`RoomTransitionOrchestrator.prepareForLeave`** | **`stopAllSfx()`** (also calls **`roomScene.flushRuntimeStateToGameState()`** first — see **§3 → Game state**) | unchanged |
| **`endDialogSessionIfMatches`** (**`dialogSession.ts`**) | **`stopAllSfx()`** after dialog **`dispose`** | unchanged |
| **`Phaser.Game` destroy** | **`SoundManager.destroy()`** stops all | stopped |

**Helpers**

- **`getEffectiveDialogueVolume`** remains for future spoken-line mixing; dialogue playback is not routed through **`SoundManager`** in v1.

### Game state (v1)

- **Active `Phaser.Game` handle (engine bridge)** — not part of the saveable snapshot; complements **`game.registry`** + **`GameStateManager`** when APIs need the **game** or **active room scene** but only receive **`gameEvents`** (or other bus-only entry points). **`createBenneGame`** calls **`setActiveBenneGame(game)`** (`src/engine/gameState/activeBenneGame.ts`); the game’s **destroy** lifecycle clears it with **`setActiveBenneGame(null)`**. **`tryGetActiveBenneGame()`** returns **`null`** before boot or after destroy. **Primary use today**: **`interruptPlayerWalkForVerbInteraction`** (`src/engine/scenes/interruptPlayerWalkForVerbInteraction.ts`) resolves **`game.scene.getScene(SCENE_ROOM)`** (see **`SCENE_ROOM`** in **`src/game/constants.ts`**) and, when that scene **`scene.isActive()`**, invokes **`RoomScene.interruptPlayerWalk()`** so verb and inventory-interaction dispatch does not run on top of an unfinished empty-space or **`walkTo`**-target move. **VS Code preview** bundles that build **`Phaser.Game`** without **`createBenneGame`** do not register this handle unless preview boot is updated — interrupt is then a no-op and preview walk + verb stacking may still occur.
- **`GameStateManager`** (`src/engine/gameState/GameStateManager.ts`): in-memory **flags** (`Record<string, boolean | number | string>`), **variables** (`Record<string, unknown>`), and **inventory** (**`Record<string, number>`** — item id → quantity). Constructed in **`createBenneGame`** (`src/engine/Game.ts`) and stored on **`Phaser.Game.registry`** under **`benneGameState`** (`BENNE_GAME_STATE_REGISTRY_KEY`) so the same instance survives **`RoomScene`** teardown. **`applySnapshot` / `importSnapshotJson`** accept legacy snapshots whose **`inventory`** was a **`string[]`** (each id becomes quantity **1**). **`getSnapshot()` runs `runSnapshotFlushHooks()` first** so any **lazily-saved runtime state** (today: character feet positions and prop authoring positions on the active **`RoomScene`** — see **§7 → Sprite animation & persistence**) gets pulled into **`variables`** before the snapshot is cloned; this is what makes **`saveToLocalStorage`**, **`exportSnapshotJson`**, **`B.state.saveToBrowser`**, and **`B.state.exportJson`** capture positions without extra wiring. **Bennescript sprite animation** also uses **`variables`** for reserved keys (see **§7 → Sprite animation & persistence**): `` `room:<roomId>:prop:<propId>:animation` `` (base prop tag), `` `character:<characterId>:animation` `` (character override), and **inventory** GUI/cursor tags `` `inventory:<itemId>:defaultAnimation` `` / `` `inventory:<itemId>:cursorAnimation` `` (override JSON **`defaultAnimation`** / **`cursorAnimation`**); **`playAnimation`** does not write these. **Per-room visit counter** — `` `room:<roomId>:visitCount` `` (non-negative integer; engine-maintained via **`roomVisitState.ts`**, surfaced as **`B.room.visitCount`**, **`B.room.isFirstVisit`**, and **`RoomTransitionContext.visitCount`**). **Per-room positions (lazily flushed)** — `` `room:<roomId>:character:<characterId>:position` `` (feet world coords) and `` `room:<roomId>:prop:<propId>:position` `` (authoring coords); see **§7 → Sprite animation & persistence → Snapshot flush hooks**. **Dialog options** persist via **`variables`** keys `` `dialog:<dialogId>:option:<optionId>:enabled` `` and `` `:used` `` (see **`dialogOptionVariables.ts`**); **`B.dialog(…).optionOn` / `optionOff`** write **`:enabled`**; picking a row sets **`:used`** and **`RoomScene`** refreshes the overlay on **`gameState:variableChanged`** for those keys and for **`__benne_active_dialog_id`**.
- **Room context (persisted, not a variable bag entry):** optional **`currentRoom` / `lastRoom`** on **`SerializableBenneGameState`** (`src/types/gameState.ts`) — **`""`** and **`null`** when absent from JSON. **`getCurrentRoom` / `getLastRoom` / `setCurrentRoom` / `setLastRoom`**; **`B.state`** and **`B.room.current` / `B.room.last`** expose the same values. A cold **`createBenneGame`** leaves **`currentRoom` empty and **`lastRoom` null**; **`startInitialRoomFromBoot`** in **`BootScene`** sets **`lastRoom` to `null`** again before the first **`RoomScene`** (ensures a clean first **enter** context). Changes emit **`gameState:roomContextChanged`**; **`applySnapshot`** emits when loaded values differ from the previous in-memory pair. This is **separate** from the generic **`gameState:variableChanged`** stream. **`GameStateManager`**’s constructor accepts an optional slice that can seed these fields (`GameStateInitialSlice`); **`createBenneGame`** today only merges flags / variables / inventory from **`game-config.json`**. In-game **room loads** are driven by **`B.room.changeTo`** and **`RoomTransitionOrchestrator`** (not by mutating **`currentRoom` / `lastRoom`** alone — those fields track state for saves and hook context; see the top **Room transitions** callout and **§3**).
- **Runtime “selection” UI state (verbs + use-on-target)**:
  - **Active verb** — see **Verb system → Active verb** (not part of save snapshots; cleared on **`applySnapshot`**).
  - **Active inventory item** (**`activeInventoryItemId`**, optional on **`SerializableBenneGameState`**): the item id “armed” for **use-on-target** clicks on room props / hotspots / characters. Persisted in **`getSnapshot` / `applySnapshot`** / **`exportSnapshotJson`**. Set/cleared with **`B.setActiveInventory` / `B.clearActiveInventory`** on room, character, global, and inventory Bennescript facades (**`GameStateManager.setActiveInventoryItem`**). Emits **`gameState:activeInventoryItemChanged`** (`GAME_STATE_ACTIVE_INVENTORY_ITEM_CHANGED_EVENT`). **`InventoryBenneScript`** arms the row after the interaction queue drains when the resolved **use** or **give** verb fires on that item — **without** requiring **`B.whenUse` / `B.whenGive`**. Optional **`B.whenUse` / `B.whenGive`** handlers run first, then the same **`afterTail`** activation unless **all** handlers for that verb used **`doNotActivate`**.
  - **Console**: the manager logs descriptive **`[Benne] …`** **`console.log`** lines when the active verb or active inventory item becomes active, inactive, or is overwritten by snapshot load (inventory lines include **display names** from **`inventoryDefinitionRegistry`** when available).
- **Data-first bootstrap**: optional **`initialGameState`** on **`game-config.json`** (merged at startup; validated in **`ConfigManager.ts`**). **`initialGameState.inventory`** may be a **unique id list** (legacy) or a **quantity map**.
- **EventBus**: incremental changes emit **`gameState:flagChanged`**, **`gameState:variableChanged`**, **`gameState:inventoryChanged`**; **room context** changes emit **`gameState:roomContextChanged`**; wholesale replace (**`applySnapshot`**, successful browser load) emits **`gameState:replaced`** only. Scripts listen with **`B.raw.on(...)`** (payload types in **`src/types/gameState.ts`**).
- **Bennescript**: **`B.state`** (set/get/has/clear flag and variable, **`getCurrentRoom` / `getLastRoom` / `setCurrentRoom` / `setLastRoom`**, **`saveToBrowser` / `loadFromBrowser` / `clearBrowserSave`**, **`exportJson` / `importJson`**, **`flush`** — pulls lazily-saved runtime state into **`variables`**; runs automatically inside **`getSnapshot`** and **`prepareForLeave`**) and **`B.inventory`** — quantity helpers: **`add` / `remove`** are **`BlockingWithNow`** (queue on each script facade’s **`interactionTail`** when **`createBenneScriptInventoryNamespace`** receives **`chain`**; **`.now`** applies immediately), plus **`has`**, **`quantityOf`**, **`items`**, and **`clearInventory`** (still synchronous). **`B.inventory(itemId).animation`** / **`.cursorAnimation`** (**getters** return the effective tags used by the GUI cursor row and armed custom pointer; **setters queue** on the same tail as other blocking APIs; **`animationNow`** / **`cursorAnimationNow`** apply immediately; same **`variables`** keys as §7) on **`BenneScript`**, **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, and **`DialogBenneScript`** (during an open dialog session). **`GuiBenneScript`** has no `game` handle at registration time — no **`B.state`** / **`B.inventory`** there yet.
- **Persistence v1**: **`localStorage`** keys **`benne-save-<slot>`** (default slot **`0`**); **`exportSnapshotJson` / `importSnapshotJson`** on the manager are the extension point for future file-based saves.

### Inventory System

- **Authoring layout**: Under **`src/game/inventory/<inventoryId>/`**, each inventory entry has **`<inventoryId>.inventory.json`** (source of truth, **`InventoryItemData`** in **`src/types/inventory.ts`**) and **`<inventoryId>.inventory.ts`** with top-level **`registerInventoryScript('inventoryId', ({ B }) => { … })`** from **`@engine/scripting`** (side effects only, mirroring characters). Optional **`defaultVerb`** on **`InventoryItemData`** is used when the player's click on that row in a GUI **`inventoryPanel`** resolves the effective **`inputProfile`** slot to **`"defaultVerb"`** or **`"walkTo"`** (both map to authored **`defaultVerb`**, else **`look`**). Plain verb ids in the profile (e.g. **`use`**) dispatch that verb on the item. Optional **`dropWhenUsed`** (boolean) overrides the global **`dropWhenInventoryUsed`** policy for this item only — see **Use-on-target (inventory × world) → Drop policy**. Optional **`cursorAnimation`** (string, Aseprite tag on **that item’s** sheet) drives the **optional** custom-game-cursor clip whenever this item is the **active inventory selection** — see **Input system → Custom pointer**; omit it to keep default cursor behavior only; at runtime **`B.inventory(itemId).cursorAnimation`** reads the **effective** tag (JSON ± **`GameStateManager`** override via **`inventory:<itemId>:cursorAnimation`** — see **`bennescript-api.md`** and §7 persistence).
- **Use-on-target (inventory × world)**: With **`activeInventoryItemId`** set, **`RoomScene`** may route the next qualifying **left** click on a prop, hotspot, or clickable character to **inventory-on-target** dispatch (**`dispatchInventoryOnVerbTargetInteraction`**, events in **`inventoryOnVerbEvents.ts`**) instead of normal verb dispatch when **`shouldDispatchInventoryUsedOnVerbForGame`** is true (resolved verb is the configured **use** verb id **or** matches the current **active verb**). Room and character Bennescript register **`B.whenInventoryUsedOn('targetId', (payload) => { … })`**: in **room** scripts **`targetId`** is the prop id, hotspot id, or **character definition id**; in **character** scripts **`targetId`** must equal that character’s **`id`** (otherwise the handler is not registered). Handlers run through the usual interaction tail. A payload handler may **`return false`** to re-emit **`verb:global:inventoryOnVerbTarget:unhandled`** so **`B.whenInventoryOnVerbTargetUnhandled`** in **`globalScript.ts`** runs instead of inlining a fallback; in that case **`subscribeInventoryUsedOnTargetEvents`** does **not** apply drop-after-tail for the room callback—the global listener’s tail does.
- **Drop policy (“stay armed vs. drop after use”)**: whether the active inventory selection is “dropped” (active inventory + active verb both cleared) after a use-on-target click follows a layered policy resolved by **`shouldDropActiveInventoryOnUse`** (`src/engine/verbs/dispatchInventoryOnVerbTarget.ts`):
  1. Script-level **`B.whenInventoryUsedOn.doNotClear(...)`** (or **`{ doNotClear: true }`**) — hard per-handler opt-out; inventory stays armed.
  2. Per-item **`dropWhenUsed`** on **`*.inventory.json`** (**`InventoryItemData`**) — when present, wins.
  3. Global **`dropWhenInventoryUsed`** on **`game-config.json`** (**`GameSettings`**).
  4. Default **`false`** — inventory stays armed so the player can use the same item on several targets in a row (classic modern adventure behavior). Set the global or per-item flag to **`true`** for classic PowerQuest-style “drop after use”.

  When the policy resolves to **drop** **and** the **`whenInventoryUsedOn`** payload handler did **not** **`return false`**, **`BenneScriptCore.subscribeInventoryUsedOnTargetEvents`** clears **both** the active inventory and the runtime **active verb** after the handler’s queued steps so the verb HUD resets to idle (no stale "Use …" armed). **`RoomScene`** prop / hotspot / character pointer handlers and **`buildGuiOverlay`** inventory-on-inventory synchronously clear both when **`dispatchInventoryOnVerbTargetInteraction`** / **`dispatchInventoryOnInventoryItemInteraction`** is unhandled and **`shouldDropActiveInventoryOnUse`** is true. **`payload.verbId`** is captured at dispatch time, so handler bodies still see the verb that fired even after the post-tail clear. When the policy resolves to **don’t drop**, both the armed item **and** the active verb stay set across the click; clear them manually with **`B.clearActiveInventory()` / `B.clearActiveVerb()`**, verb GUI buttons, or right-click while armed.
- **Right-click / empty-space clears while armed**: whenever **`activeInventoryItemId`** is set, a **right**-click on **anything** (prop, hotspot, clickable character, inventory row, or empty space) clears **both** the active inventory and the active verb. A **left**-click on empty space while armed also clears both instead of walking — the player must re-arm before the empty-space click walks again (`RoomScene.handleRoomPointerDown` + `resolution.kind === 'clearActive'` branches in the prop / hotspot / character pointer handlers and in **`buildGuiOverlay`** inventory rows).
- **Registry**: **`registerInventoryDefinitionsFromGame()`** (from **`registerGameContent`**) eager-loads **`./inventory/**/*.inventory.json`** into **`inventoryDefinitionRegistry`** so **`GameStateManager`** can read **`stackable`** when applying **`add` / `remove`**, and **`BootScene`** knows which Aseprite sheets to queue. JSON validation preserves optional fields such as **`cursorAnimation`**.
- **Shared Aseprite (PowerQuest-style)**: One export at **`src/game/assets/images/inventory/inventory.png`** + **`inventory.json`**. Each **frame tag** on the sheet is an inventory clip (and default animation name); entry-specific variants should use a root naming convention like **`<root>-*`** (for example **`lantern-glow`**, **`lantern-open`** for root **`lantern`**). The engine normalizes JSON for Phaser, then prefixes Phaser animation keys as **`inventory:<tag>`** so tags stay namespaced on a single texture (**`aseprite:inventory:shared`**). In JSON, set **`display.aseprite`** to **`"shared"`**. Optional **`defaultAnimation`** is the Aseprite frame tag used as the default clip in UI/cursor; when omitted, the inventory **`id`** is used (so the tag name normally matches the folder / inventory id).
- **Per-inventory-entry Aseprite**: **`display.aseprite: true`** loads **`images/inventory/<id>/<id>.png`** + **`.json`** (same pattern as characters). Animation keys are the raw Aseprite tag names on that sheet (texture key **`aseprite:inventory:<id>`**). The **same soft `<root>-*` convention** as the shared sheet applies in tooling: roots are the inventory **`id`** plus optional **`defaultAnimation`**; a sheet tag is grouped with the entry when it equals a root or starts with **`root-`** (literal hyphen). The Inspector derives suggested animation rows from the per-item export the same way it does for **`"shared"`**; authored **`animations`** in JSON remains authoritative.
- **Bennescript**: **`InventoryBenneScript`** exposes the same **`B.player` / `B.character` / `B.state` / `B.inventory`** surface as character scripts, plus inventory-entry-scoped **`whenLookAt`**, **`whenUse`**, **`whenGive`**, … that subscribe to **`verb:room:<roomId>:inventory:<inventoryId>:<verbId>`** and **`verb:inventory:<inventoryId>:<verbId>`**. **`dispatchInventoryVerbInteraction`** ( **`src/engine/verbs/dispatchInventoryVerb.ts`** ) mirrors character precedence for inventory-authored handlers: emit **room-scoped** if that channel has listeners, else **global** if that channel has listeners, else the same global verb chain as **`dispatchVerbInteraction`** (**`verb:global:<verbId>`** → **`verb:global:fallback`** → **`verb:unhandled`**) so **`globalScript.ts`** fallbacks apply when no **`whenLookAt`** / **`whenVerb`** handler exists for that row. **`RoomScene`** runs every **`registerInventoryScript`** callback on each room load (inventory is not “spawned” like characters), then **`B.ensureDefaultInventoryUseAndGiveActivationAfterRegister()`** so empty scripts still subscribe the default **use** / **give** → **`setActiveInventory(thisId)`** path ( **`afterTail`**, same interaction tail as handler **`say` / `walkTo`**). **`B.whenUse` / `B.whenGive`** merge into that subscription — avoid redundant **`B.setActiveInventory(thisId)`** in the handler body unless you need activation **before** queued steps. **`trySyncActiveInventoryAfterInventoryUseOrGiveRowDispatch`** runs from **`buildGuiOverlay`** after dispatch for items with **no** **`registerInventoryScript`** module (JSON-only definitions). Room / character / global / inventory scripts may also use **`B.inventory(itemId)`** with **`animation`** / **`cursorAnimation`** to override **`defaultAnimation`** / **`cursorAnimation`** at runtime (**setters** queue on **`interactionTail`**; **`animationNow`** / **`cursorAnimationNow`** apply immediately — see **§7 → Sprite animation & persistence**), and **`B.inventory.add` / `remove`** (**`BlockingWithNow`**) for quantity changes in the same order as other tail steps.
- **VS Code extension**: Main tree **Inventory** group (with **Rooms**, **Characters**, **GUIs**, **Dialogs**). Tree selection opens **`*.inventory.json`** in the primary editor column and **`openBenneInventoryTypeScript`** (**`roomScriptNavigation.ts`**) for the companion **`*.inventory.ts`** in the Benne script row. Commands **`benne-editor.createInventoryItem`** (wizard: id + name → folder, minimal JSON with **`"aseprite": "shared"`**, stub **`.inventory.ts`**) and **`benne-editor.importInventoryItemsFromAsepriteTags`** (reads **`inventory.json`**, multi-select tags, writes/updates **`.inventory.json`** per tag and optionally **`.inventory.ts`**). **Inventory-on-target** authoring from the **room / character Inspectors** uses **`benne-editor.addRoomInventoryUsedOnStub`** / **`addCharacterInventoryUsedOnStub`** (see **Inspector view** and the dated note at the top of this doc). In the Inspector, **both** **`display.aseprite: "shared"`** and **`display.aseprite: true`** entries derive animation cards from the relevant sheet using item-scoped roots (item **`id`** plus optional **`defaultAnimation`**) and only include matching tags (**`root`** and **`root-*`**); editing a derived row materializes that row into the entry JSON under **`animations`**. Tags outside that family can still be added manually in JSON (soft convention). Context menus follow the same pattern as **Characters** / **GUIs** (create on group/workspace; import from group or entry context where applicable).

### Dialog system (choice topics)

- **Authoring layout**: Under **`src/game/dialogs/<dialogId>/`**, each dialog has **`<dialogId>.dialog.json`** (**`Dialog`** in **`src/types/dialogue.ts`**: **`id`**, optional **`displayName`**, optional **`guiId`** defaulting to **`dialog`**, **`options[]`**) and **`<dialogId>.dialog.ts`** with top-level **`registerDialogScript('dialogId', ({ B }) => { … })`** from **`@engine/scripting`**. Each **`DialogOption`** has **`id`**, **`text`**, optional **`enabled`** (omit or **`true`** → option visible), optional **`used`** (authoring default **`false`**; runtime may persist **`true`** after the player picks that row), and optional **`say`** (omit or **`true`** → **`DialogBenneScript`** queues **`B.player.say`** with that option’s **`text`** before the matching **`whenChoice`** handler; **`false`** skips the automatic player line). Array **order** is the on-screen order; the Inspector can reorder rows (see **§2 → Dialogs**). The default choice GUI is **`guis/dialog/dialog.gui.json`** ( **`Option-Grid`**, **`scrollUp`**, **`scrollDown`**, template **`Dialog-Option`** / **`Bullet`** rows — the runtime hides templates and injects synthetic rows per option).

- **Registry**: **`registerDialogDefinitionsFromGame()`** (from **`registerGameContent`**) eager-loads **`./dialogs/**/*.dialog.json`** into **`dialogDefinitionRegistry`** (**`dialogDefinitionRegistry.ts`**). **`getRegisteredDialogChoiceGuiIds()`** returns **`'dialog'`** union every definition’s **`guiId`** so **`RoomScene`** can reserve those overlays from the generic GUI walk.

## 4. Data Flow

1. **Bootstrap**: `game-config.json` → resolution, start room id, **verbs / input profile / fallback line**, audio caps, debug flags, optional **`initialGameState`** for **`GameStateManager`**.
2. **Boot**: Manifest + glob pick **`RoomData`** → **`BootScene`** builds load list → loader completes → **`startInitialRoomFromBoot`** ( **`setLastRoom(null)`**, start kind **`'boot'`**) → **`RoomSceneStartData`** into **`RoomScene.create`**.
3. **Frame loop**: Phaser updates tweens / anims; **input** → hit tests → background **walk** on empty space, or **prop/hotspot/character** hit → **`dispatchVerbInteraction`** (stops an in-progress **player** walk first when applicable) → **`gameEvents.emit`** on the chosen event id.
4. **Scripts**: **`*.room.ts`** / **`*.character.ts`** / **`*.gui.ts`** / **`*.inventory.ts`** / **`*.dialog.ts`** / **`globalScript.ts`** register on **`gameEvents`** (or receive **`B`** from `@engine/scripting`) and run side effects when their lifecycle runs (per room load for room + character + inventory Bennescript; **`registerDialogScript`** bodies run when **`B.dialog(id).start`** / **`.start.now`** opens that dialog’s session via **`openDialogSessionForId`**; after game create for global; at content registration for GUI).

JSON + Aseprite  →  BootScene (Loader)  →  RoomScene (display + input)

Pointer / keys ──────────────────────────────┤
                                              ▼

                                              ▲
registerGameContent (*.room.ts factories [lazy], *.character.ts, *.gui.ts, *.inventory.ts, *.dialog.ts, globalScript)─┘

## 5. Key Design Decisions

| Decision | Why | Tradeoff |
|----------|-----|----------|
| **One `RoomScene` + boot + transition loader** | Keeps a single Phaser **room** scene; startup and in-room handoffs use the same **`RoomSceneStartData`** + loader queue helpers (`roomSceneBootstrap.ts`). | Each **`B.room.changeTo`** / **`changeToNow`** ( **`RoomTransitionOrchestrator`**) **restarts** **`RoomScene`** with a new start payload. **Cross-room data** (flags / variables / inventory) stay on **`GameStateManager`**. **Teleport** helpers **`moveTo`** are unrelated (same room). |
| **Global `gameEvents` singleton** | Fast to wire; matches stringly event ids from JSON. | Global coupling; tests need discipline or indirection later. |
| **JSON string event ids** | Editable in data; matches classic adventure “verb” naming. | Typos fail at runtime; editor/tooling (e.g. VS Code extension) helps. |
| **Central verb dispatch** | One precedence chain (scoped per-verb listeners → object fallback → global → unhandled) and one place for future 9-verb / coin UIs to plug in. | Handlers must register **`verb:global:*`** if they rely on global overrides; listener counts drive whether each tier runs. |
| **Vite glob for assets** | Correct hashed URLs and tree-shaking. | **Editor preview** must use a **separate fetch/Webview path** (`src/editor/preview/`) — two loading strategies. |
| **Walkable polygons in JSON + visibility-graph pathfinding** | Designer-controlled navmesh; shortest-path routing around holes and concavities via reflex-vertex visibility graph + A\* (classical approach for polygons with holes; matches LucasArts feel). | No auto navmesh; bad polygons break movement visually (mitigated by debug draw of mesh + live path polyline). O(N²) visibility build per walk query — fine for hand-authored rooms, would need caching / triangulation for very large meshes. |
| **Aseprite tags = props / anims** | Single sheet per room/character, industry-standard tool. | Untagged cels are invisible to the engine; tag discipline required. |

## 6. Constraints and Rules

- **Engine vs game**: Do not put **game-specific narrative or room logic** under `src/engine/` except through **generic hooks** (events, helpers). Put reactions in **`src/game/`** (`*.room.ts`, future modules).
- **Config**: **`game-config.json`** is the **single source** for resolution, default character, start room override, **verbs**, **inputProfile**, **defaultFallbackLine**, audio, debug flags, optional **`initialGameState`** — read via **`getGameSettings()`**, not duplicated literals. Optional **`cursor`** (custom pointer) adds **`idleAnimation`** / **`activeAnimation`** (Aseprite tag names), optional **`cursor.animations`** (same per-tag shape as **`CharacterData.animations`**), and optional **`cursor.hotspot`** / **`cursor.hotspotPixel`** for pointer-tip placement.
- **Room data**: Follow **`RoomData`** / **`RoomPropInstance`** in **`src/types/room.ts`**; **`collider`** is required for **`clickable`** props. **`walkToPoint`** / **`lookAtPoint`** are optional script hints (not applied by the engine on click). Interactions are **`registerRoomScript`** listeners; optional **`onVerbFallback`** on a prop/hotspot enables fallback **`EventBus`** dispatch when no per-verb listener handled the verb. Optional **`defaultVerb`** (string verb id) feeds the `inputProfile` `"defaultVerb"` token (fallback `"look"`). **Room prop sheet placement**: **`spritePlacement`** defaults to **`"canvas"`** (authored `x`/`y` map to logical cel/sheet origin, full-canvas workflow); set **`"tight"`** when authoring against trimmed visible pixels (runtime uses `spriteSourceSize` and keeps placement synced across animated frames). Room-level **`points`** (**`RoomPointData[]`**, named **`x` / `y`**) are used by **`RoomScene`** when **`BenneScript`** resolves **`walkTo('pointId')`**; **`regions`** (**`RoomRegionData[]`**, closed polygons + **`active`**) remain **authoring / future-system** for gameplay that opts in. **Hotspot** polygons are separate **`hotspots[].points`**.
- **Room prop clip families (soft convention)**: Optional **`RoomPropInstance.defaultAnimation`** adds a second **root** alongside **`id`** for editor/Inspector grouping of tags on the room Aseprite sheet: a tag is suggested for that prop when it **equals** a root or matches **`root-*`** (literal hyphen after the root). **`RoomScene`** still uses **`tag`** for which clip is drawn; **`animations`** maps Aseprite tag names to optional **`loop`** / **`frameDuration`** overrides (same shape as character clip config). The Inspector merges **`meta.frameTags`** with **`animations`** using those roots; JSON stays the source of truth and arbitrary tags remain valid if added manually.
- **Character data**: Follow **`CharacterData`** in **`src/types/character.ts`**. Optional **`collider`** (≥3 **`points`** in frame space) restricts **click** hit-testing for **`clickable`** characters; omit it or save fewer than three points in the preview to use the **full sprite** bounds. Optional **`defaultVerb`** (string) feeds the `inputProfile` `"defaultVerb"` token for clicks on this character (fallback `"look"`). Optional **`onVerbFallback`** enables character-level fallback dispatch when no per-verb listener handled the click.
- **GUI data**: Follow **`GuiData`** in **`src/types/gui.ts`**. Optional **`controls`** describe screen-space widgets (**`text`**, **`inventoryPanel`**, **`image`**, **`nineSliceImage`**, **`button`**, **`trigger`**, **`grid`**). Optional top-level **`x`** / **`y`** set the initial screen-space offset of the packed **`gui.root`** (e.g. **`"y": -34`** to park a dropdown bar offscreen; fixed controls are not offset). Optional **`fixedControls`** is a string array of control **`id`** values: those controls are **not** parented under **`gui.root`**, so **`gui.root.tweenTo`** (and future whole-overlay moves) slide the rest of the HUD without moving them. Aseprite sheets use **`images/guis/<guiId>/<guiId>.png`** and **`.json`** when **`display.aseprite`** is true (same export pattern as characters). On **`image`** controls, **`tag`** and **`backgroundAnchor`** live on the control object (parallel to **`backgroundTag`** / **`backgroundAnchor`** on **`inventoryPanel`** and **`button`**); the GUI root **`display`** block is only for overlay-level options such as **`aseprite`**. **Trim-aware sheet placement**: `buildGuiOverlay` uses Aseprite trim metadata (`spriteSourceSize`) so both workflows are valid — **full-canvas** (`backgroundAnchor: "screen"`) and **trimmed-cel** (`top-left` / `center`). For grid-placed images, **`gridPlacement.align: "center"`** centers using visible packed frame size (`cutWidth`/`cutHeight`) rather than untrimmed source canvas size. **Bitmap fonts** for text controls: PNG atlas + BMFont **`.xml`** under **`src/game/assets/fonts/`**, logical ids and paths in **`fonts/fonts.json`** (Phaser **`load.bitmapFont`** key = id = GUI control **`font`**). **`RoomScene`** builds **one overlay per `*.gui.json`** (not a hard-coded id list): Speaking Text (**`speaking-text`**) is reserved for **`setDialogTextOverlay`** / **`say`**; ids in **`getRegisteredDialogChoiceGuiIds()`** are reserved for **`B.dialog`…`start` / `stop`** (built after Speaking Text (**`speaking-text`**), start hidden). Every other GUI is shown at room load unless **`"visible": false`**. The **GUI preview** uses the same **`buildGuiOverlay`** path for the selected GUI. **`nineSliceImage`** controls draw a tag from the GUI sheet using **`meta.slices`** (Aseprite slice names mapped per 3×3 cell in **`sliceNames`**) and nine cropped quads so panels scale on Canvas (see **`buildGuiOverlay`** / **`guiNineSliceImage.ts`**).
- **Walkable mesh**: **`walkable.polygons[]`** entries support optional **`holes[]`** (inner rings subtracted when **`active`** is not **`false`**). Each polygon and hole may set **`active`**; omitted or non-**`false`** means included in tests and debug draw. See **`walkable.ts`** and **`RoomScene`** debug overlays (outer vs hole stroke colors).
- **Registration**: New room scripts live under **`src/game/rooms/`** as **`*.room.ts`** with top-level **`registerRoomScript(({ B }) => { … })`**. Character scripts use **`registerCharacterScript('id', ({ B }) => { … })`** under **`src/game/characters/`**. GUI scripts use **`registerGuiScript('id', ({ B }) => { … })`** under **`src/game/guis/<id>/`**. Inventory scripts use **`registerInventoryScript('id', ({ B }) => { … })`** under **`src/game/inventory/<id>/`**. Dialog scripts use **`registerDialogScript('id', ({ B }) => { … })`** under **`src/game/dialogs/<id>/`**. Global hooks use **`registerGlobalScript(({ B, game }) => { … })`** in **`src/game/globalScript.ts`**. All are side-effect-only (no **`export function register*Script`**).
- **Strict TypeScript**: Project uses **strict** compiler options; new code should preserve typings for payloads and JSON-shaped types.

## 7. Scripting / interaction system (Bennescript)

BENNE uses a **two-layer scripting architecture** that keeps the engine data-first while giving authors a clean, modern, PowerQuest-inspired authoring experience.

**Layer 1 – Engine Core (unchanged)**  
- Verb dispatch still emits canonical scoped event IDs via `dispatchVerbInteraction` (`verb:room:office:prop:desk:look`, etc.).
- Raw `EventBus` (`gameEvents`) and typed payloads (`RoomPropInteractPayload`, etc.) remain the foundation.

**Layer 2 – Bennescript Facade (new authoring surface)**

Authors now write against a clean, discoverable facade. Handlers are **ordinary sync functions**; the engine registers `async` listeners and, for queued actions, awaits an internal **interaction tail** built from `Promise`s so linear scripts work **without** author `async`/`await` (see **Blocking interaction queue vs `.now`** below).

```ts
import { registerRoomScript } from '@engine/scripting';

// Sugar verbs (`whenLookAt`, `whenUse`, `whenTalkTo`, …) use one string id: `props[]` → `hotspots[]` → character in room.
// `walkTo('…')` pathfinds; `moveTo('…')` / `moveToNow('…')` teleports (same id / `{x,y}` resolution).
// `walkTo` / `moveTo` resolve prop → hotspot → character → `points[]`.
// `walkToClicked` / `walkToClicked.now` (also on `B.player`) walk to the clicked prop/hotspot/character id from the verb payload (same resolution as `walkTo` for that id), then face like `faceClicked` when the walk finishes.
// `faceClicked` / `faceClicked.now` alone use `lookAtPoint` from the room JSON when present; for NPCs, face their feet (`RoomScene.facePlayerTowardClicked`).
registerRoomScript(({ B }) => {
  B.whenLookAt('desk', () => {
    B.walkToClicked();
    B.player.say('Looks like an ordinary desk with some paperwork…');
  });

  B.whenUse('desk', () => {
    B.player.say("I don't know what to do with that yet.");
  });
});
```

Character definition scripts use the same `B` movement/dialog primitives on the active `RoomScene`, but **self-only** verb sugar (no target id string — subscribes to `verb:character:<id>:<verb>` only):

```ts
import { registerCharacterScript } from '@engine/scripting';

registerCharacterScript('hank', ({ B }) => {
  B.whenLookAt(() => {
    B.player.say('Hank stares back.');
  });
});
```

**Blocking interaction queue vs `.now` (core Bennescript behavior)**  

Room and character verb handlers are written as **ordinary synchronous functions**, but several `B` methods represent **time** (movement tweens, short `say` pacing delays, `wait`, etc.). Those methods participate in an **internal interaction queue** (`interactionTail` in `BenneScriptCore`): each step is a `Promise` that must finish before the **next** queued step **starts**. That makes linear scripts read top-to-bottom while still driving real async engine work (e.g. `RoomScene.walkPlayerTo` resolves when the walk tween completes). The same queue backs **`BenneScript`** (room), **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, and **`GuiBenneScript`**. **`B.inventory.add` / `B.inventory.remove`** ( **`BlockingWithNow`**) and **`B.inventory(itemId).animation`** / **`.cursorAnimation`** setters on room, character, inventory, global, and dialog-session facades append through that tail (**`createBenneScriptInventoryNamespace`** in **`benneScriptGameStateApi.ts`** passes each script’s **`chain`**). **`GuiBenneScript`** has no **`B.inventory`** surface.

**`walkToClicked` / `walkToClicked.now`**: While a handler registered through `BenneScriptCore.subscribe` or `subscribeAfterInteractionTail` runs, the engine pushes a short-lived walk target derived from the event payload (`propId` / `hotspotId` / `characterId`, including global verbs and inventory use-on-target). `B.walkToClicked()` (room and global scripts) or `B.player.walkToClicked()` (character and inventory scripts) calls `RoomScene.walkPlayerTo` with that id so movement uses the same string resolution as `B.player.walkTo`, then applies `RoomScene.facePlayerTowardClicked` when the walk Promise settles — equivalent to chaining `faceClicked` after the walk (snapshot from the handler’s payload taken when `walkToClicked` runs). Pure inventory-row verbs (`dispatchInventoryVerbInteraction`) carry no world target — a one-time dev `console.warn` applies if authors call `walkToClicked` there anyway. Misuse outside any verb handler is also warned once in dev.

**`faceClicked` / `faceClicked.now`**: Uses the same payload-derived context stack. Facing prefers **`lookAtPoint`** from the verb payload (props, hotspots, global handlers — emitted from room JSON / `VerbInteractTarget`). **Characters** do not use `lookAtPoint`; the player faces the clicked character’s **feet** in room space. If there is no `lookAtPoint` and the target is not a character, facing falls back to the same stand/centroid point as **`walkToClicked`**. When the feet→target vector is ~0, facing is left unchanged (so the player does not snap to “down”). Same dev warnings as `walkToClicked` when there is no world target or no room scene.

**Important implementation detail:** queued steps are registered with **lazy factories** (`() => Promise<…>`), not pre-created promises. If the queue were fed eager promises, every `walkTo` / `say` in one handler body would **start immediately** in the same synchronous tick; only **completion** order would be serialized. Lazy registration ensures the **next** walk (or delay) does not begin until the previous step’s promise has settled.

**Methods that use the queue today (blocking by default)**  

These schedule work on the queue when called from a handler (or any code path using the same `BenneScript` instance). Not every facade method is queued; only ones that need ordering relative to time or prior steps. **Teleport** **`moveTo`** is queued the same way as **`walkTo`** (synchronous **`movePlayerToNow` / `moveCharacterToNow`** inside the tail step); **`moveTo.now`** / **`moveToNow`** fire immediately, like **`walkTo.now`**.

| API | Blocking call | Non-blocking (same effect, no queue) |
|-----|----------------|--------------------------------------|
| `B.player` / `B.character(id)` — walk | `walkTo(target)` | `walkTo.now(target)` |
| `B.player` / `B.character(id)` — feet teleport (not a walk) | `moveTo(target)` | `moveTo.now(target)` or `moveToNow(target)` |
| `B.player` / `B.character(id)` — line | `say(text)` | `say.now(text)` |
| `B.player` / `B.character(id)` — clip | `playAnimation(tag)` | `playAnimation.now(tag)` |
| `B.player` / `B.character(id)` — facing | `face(dir)` | `face.now(dir)` |
| `B.character(id)` — script visibility | `hide()` / `show()` / `visible = …` (queued) | `hide.now()` / `show.now()` / `visibleNow(…)` |
| `B.prop(id)` — persisted **base** Aseprite tag | `B.prop('x').animation = tag` (queued) | `B.prop('x').animationNow(tag)` |
| `B.prop(id)` — script visibility | `hide()` / `show()` / `visible = …` (queued) | `hide.now()` / `show.now()` / `visibleNow(…)` |
| `B.prop(id)` / `B.character(id)` — sprite alpha tween | `fade(fromAlpha, toAlpha, durationSeconds)` | `fade.now(fromAlpha, toAlpha, durationSeconds)` |
| `B.player` / `B.character(id)` — persisted **override** (`null` clears) | `… .animation = tag` / `null` (queued) | `… .animationNow(tag)` / `null` |
| `B.inventory` — add / remove rows | `add(id, qty?)`, `remove(id, qty?)` | `add.now(…)`, `remove.now(…)` |
| `B.inventory(itemId)` — icon / armed-cursor tags | get **`animation`** / **`cursorAnimation`** (effective tags); **`animation = tag`**, **`cursorAnimation = tag`** (queued setters) | `animationNow(tag)`, `cursorAnimationNow(tag)` |
| Room pacing | `B.wait(seconds)` | `B.wait.now(seconds)` |
| `B.room` — read **`GameStateManager`** (same values as **`B.state.getCurrentRoom` / `getLastRoom`**) | `current` (getter), `last` (getter) | — |
| `B.room` — persisted **visit** counter for **`current`** (key `` `room:<roomId>:visitCount` ``) | `visitCount` (getter), `isFirstVisit` (getter) | — |
| `B.room` — change room (queued **leave** path; **`.now` / `changeToNow`** skip the **leave** fade) | `changeTo(roomId)` | `changeTo.now(roomId)` or **`changeToNow(roomId)`** |
| `B.fadeOut` / `B.fadeIn` — full-screen overlay ( **`RoomScene`**; see top **Full-screen fade** note) | `fadeOut(duration?, color?)`, `fadeIn(duration?, color?)` | `fadeOut.now(…)`, `fadeIn.now(…)` |
| **`B.sound`** — one-shot SFX | `play(key, opts?)` — **queued** after prior tail steps | `play.now(key, opts?)` |
| **`B.sound`** — SFX until end / stop | `playAndWait(key, opts?)` | `playAndWait.now(…)` — starts without waiting on prior tail; does not block following lines on sound end |
| **`B.sound`** — background music (single slot; new track replaces old) | `playMusic(key, opts?)` | `playMusic.now(…)` |
| **`B.sound`** — stop SFX (all or one stem) / stop music | `stop(key?)`, `stopMusic()` | `stop.now(…)`, `stopMusic.now()` |

**`.now` semantics**  

- **`.now`** runs the **same** underlying behavior (walk tween, `delayedCall` for `say` / `wait`, sync animation or facing).  
- It does **not** append to `interactionTail`; later **blocking** lines in the same handler still run in source order, but **without waiting** for the `.now` action to finish.  
- Return type is **`void`** (same as the blocking form); the engine does not surface promises to authors for the default API.  
- TypeScript models blocking methods as **`BlockingWithNow<…>`** — the callable plus a **`now`** property with the same parameters (good autocomplete).

**Sprite animation & persistence (PowerQuest-style `Animation` vs `PlayAnimation`)**  

Bennescript separates a **saved** “what should this prop/character show by default?” from a **temporary** scripted clip (inventory row clips use **saved** overrides only — no **`playAnimation`** on **`B.inventory(id)`**):

- **`B.prop(id)`** (`BenneScriptPropFacade` in `src/engine/scripting/benneScriptFacades.ts`): **`animation`** get/set is the prop’s **base** Aseprite tag (JSON `tag` until a save overrides it). The **setter** is **queued** on the same **`interactionTail`** as **`walkTo`**, **`say`**, and **`playAnimation`**; **`animationNow(tag)`** writes game state and updates the sprite **immediately** (skips the tail). **`playAnimation` / `.now`** plays a tag once, then restores that persisted base clip. Room props register clips with **`scene.anims.createFromAseprite`** (global keys on the scene AnimationManager).

- **`B.player`** / **`B.character('id')`**: **`get animation`** returns the **effective** key (persisted **override** if any, else the live directional idle / walk / talk tag). **`set animation`** / **`animationNow`** accept **`string | null`** (`null` clears the override). **`stopAnimation()`** clears the saved override and returns to directional idle (always immediate — no **`.now`** variant). While an override is active, **`RoomScene`** avoids swapping to automatic directional **Idle / Walk / Talk** (movement tweens still run; **facing** data updates so that when the override ends, idle matches the current facing). **`BenneScriptCore.applySayLineDirectionalBase`** skips directional **Talk** when an override is active and restores via **`applyCharacterEffectiveAnimation`** after each line.

- **Character movability — `B.player.movable` / `B.character(id).movable`**: **`get movable`** returns whether pathfind walking is allowed (**`readSavedCharacterMovable`** vs **`CharacterData.movable`** default from the room’s first spawn row for that definition id). **`set movable`** queues like **`visible`** and persists to **`GameStateManager`** (see **Persistence**). When **`movable`** is **`false`**, **`RoomScene.movePlayerToward`**, **`walkPlayerToWorldPoint`**, **`walkCharacterTo`**, and **`walkCharacterToWorldPoint`** return without starting tweens ( **`walkTo`**, **`walkToClicked`**, click-to-walk, verb **`walkPlayerTo`** paths). **`movePlayerToNow` / `moveCharacterToNow`** still run.

- **Character follow — `B.player` / `B.character(id).startFollowingCharacter` / `stopFollowingCharacter`**: Persistent **trail** behavior (not the same as **`startFacingCharacter`**, which is runtime-only idle facing). **`startFollowingCharacter(targetId, options?)`** is idempotent for the same target (re-call updates saved options). **`stopFollowingCharacter()`** clears persisted keys and interrupts a walk that was started by the follow driver (sprite **`setData`** purpose **`benneFollowWalkPurpose`**). Follow walks apply **`benneFollowWalkSpeedMult`** on the sprite so **`beginPlayerWalkLeg` / `beginNpcWalkLeg`** multiply base **`walkSpeed`**. When **`faceTargetWhenIdle`** is **true** (default) and the follower is not walking and has no **`startFacingCharacter`** lock, **`RoomScene`** turns idle facing toward the target’s feet. **`B.player`** exposes the same API so the starting player can follow an NPC if authored.

- **`playAnimation`**: never touches **`GameStateManager`**; for **looping** clips (`loop: true` in `CharacterData.animations` → Phaser **`repeat: -1`**), completion is approximated by **one full cycle** (**`Animation.duration`**, with a frame-based fallback) before revert, so the interaction tail does not settle in the same tick as the play call. Character sheets use **`sprite.anims.createFromAseprite`**, so clips are **sprite-local**; **`promiseWhenSpriteAnimationFinishes`** (in `src/engine/benneAnimationRuntime.ts`) resolves completion using **`sprite.anims`** first, then **`scene.anims`** (props), and reads **`repeat`** from the resolved **`Animation`**.

- **`B.inventory('itemId')`** (`BenneScriptInventoryItemFacade`): **`animation`** / **`cursorAnimation`** get/set the effective **GUI icon** and **armed cursor** Aseprite tags (JSON defaults when no override; **`cursorAnimation`** getter is **`''`** when the armed pointer would fall back to the verb / global cursor). **Setters** are **queued** on the same **`interactionTail`** as **`walkTo`**, **`say`**, **`wait`**, and **`B.player.animation`** when used from **`BenneScript`**, **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, or **`DialogBenneScript`**; **`animationNow(tag)`** / **`cursorAnimationNow(tag)`** write **`GameStateManager`** variables and refresh the active room scene **immediately** (skip the tail). Setter **empty string** clears that field’s variable so JSON applies again. **`RoomScene`** validates tags when a room is active; **`buildGuiOverlay`** / custom cursor read effective values (`src/engine/inventory/inventoryScriptingAnimations.ts`).

- **Sprite alpha fade — `B.prop(id).fade` / `B.character(id).fade`** (room scripts for props; room + character scripts for characters): **`fade(fromAlpha, toAlpha, durationSeconds)`** tweens the prop/character sprite's `alpha` from **`fromAlpha`** to **`toAlpha`** over **`durationSeconds`** using a `Linear` ease. Both alphas clamp to `[0, 1]` and `durationSeconds` clamps to `>= 0` (a duration of `0` snaps to `toAlpha` synchronously). Each call **`tweens.killTweensOf`** the sprite first so back-to-back fades don't stack, then sets `alpha = fromAlpha` before the tween starts (so `fade(0, 1, 0.5)` always begins fully transparent regardless of prior state). The **blocking** form queues on the script's **`interactionTail`** and waits for the tween to complete; **`fade.now`** starts the same tween immediately without blocking subsequent script lines (later **blocking** lines still serialize through the tail behind any previously-queued steps). The **`toAlpha`** is **persisted to `GameStateManager`** the moment the call runs (room-scoped key for props, global per-character-id key for characters — see **Persistence** below) so saving mid-fade or reloading the room restores the **intended final** alpha rather than mid-tween state. Backed by **`RoomScene.fadePropScriptAlpha`** and **`RoomScene.fadeCharacterScriptAlpha`** (`src/engine/scenes/RoomScene.ts`).

- **Prop visibility — `B.prop(id).hide` / `show` / `visible = …` / `visibleNow(…)`**: Each setter call **persists** the boolean to **`GameStateManager`** (room-scoped key — see **Persistence**) and updates the live sprite. Spawn re-reads the saved value via **`readSavedPropVisible`** so a hidden prop stays hidden across **`B.room.changeTo`** and browser save/load. **`B.prop(id).visible`** getter prefers the live sprite when one is present (so it reflects what is on screen right now); when the prop is not yet spawned, it falls back to the saved value, then to the JSON default.

- **Character visibility — `B.character(id).hide` / `show` / `visible = …` / `visibleNow(…)`**: Same pattern as props, but the key is **global per character definition id** (see **Persistence**). Spawn re-applies via **`readSavedCharacterVisible`**. When there is no active **`RoomScene`**, setters still persist through **`writeSavedCharacterVisible`** if a **`GameStateManager`** is active (mirrors **`fadeCharacterScriptAlpha`** reachability from global / GUI scripts).

- **Prop position — `B.prop(id).moveTo` / `moveTo.now` / `moveToNow`**: Teleport the prop's **authoring** origin to a `Point2` in room space (no tween, no string-id resolution — props don't have feet / stand-points the way characters do). The **blocking** form queues on the script's **`interactionTail`** (same ordering as **`B.prop(id).visible`** / **`animation`**); **`.now`** / **`moveToNow`** apply immediately. Backed by **`RoomScene.movePropToNow`**, which routes the new origin to whichever placement model the prop uses: **tight** (`spritePlacement: "tight"`) updates **`benneRoomPropAuthoredX/Y`** then re-syncs via **`syncBenneRoomPropTightWorldPosition`**; **parallax** (`parallaxDepth !== 1`) updates the entry's **`baseX / baseY`** (the next parallax tick repositions the sprite); plain canvas placement sets **`sprite.x / y`** directly. Position is **not** eagerly persisted on the call — it goes to game state on the next snapshot flush (room-leave, **`getSnapshot`**, or **`B.state.flush`**), matching how character positions are tracked.

- **Character + prop position persistence (lazy)** — character feet (after walk / teleport) and prop authoring origin do **not** write to **`GameStateManager`** per-tick. Instead, **`RoomScene.create`** registers a **snapshot flush hook** (via **`registerSnapshotFlushHook`** in **`src/engine/gameState/snapshotFlushHooks.ts`**) that walks **`characterSpritesByDefId`** (writing **`getCharacterWorldFeet(sprite)`** to `` `room:<roomId>:character:<characterId>:position` ``) and **`propSpritesById`** (writing each prop's authoring position — tight → parallax `baseX/Y` → live `sprite.x/y` — to `` `room:<roomId>:prop:<propId>:position` ``). The hook fires from three trigger points: **`GameStateManager.getSnapshot`**, **`RoomTransitionOrchestrator.prepareForLeave`**, and **`B.state.flush`**. The hook is unregistered on **`Phaser.Scenes.Events.SHUTDOWN`** so torn-down rooms (and editor preview **`Phaser.Game`** instances that don't run `RoomScene.create`) never hold stale references. See **Persistence → Snapshot flush hooks** below.

**Persistence** ( **`GameStateManager` variables** — same snapshot pipe as other `B.state` keys):

- **Room visits** (room-scoped):
  - `` `room:<roomId>:visitCount` `` — integer **`>= 0`**; the engine increments this **once per room load** (before **`whenEnterRoom`** / **`whenEnterAnyRoom`**) and exposes it on **`B.room.visitCount`**, **`B.room.isFirstVisit`** (`visitCount === 1`), and **`RoomTransitionContext.visitCount`**. Survives **`exportJson` / `importJson`** / save slots like any other **`variables`** entry.
- **Props** (room-scoped):
  - `` `room:<roomId>:prop:<propId>:animation` `` — base tag string. Applied when **`RoomScene`** spawns props (after merged Aseprite clip setup).
  - `` `room:<roomId>:prop:<propId>:visible` `` — boolean override for **`B.prop(id).hide` / `show` / `visible = …` / `visibleNow(…)`**; spawn applies via **`readSavedPropVisible`** (JSON `RoomPropInstance.visible` is the fallback default).
  - `` `room:<roomId>:prop:<propId>:alpha` `` — number `[0, 1]`; written as **`toAlpha`** by **`B.prop(id).fade(...)`** and **`fade.now`**; spawn applies via **`readSavedPropAlpha`** (JSON `RoomPropInstance.alpha` ?? `1` is the fallback default).
  - `` `room:<roomId>:prop:<propId>:position` `` — `{ x, y }` authoring world coords. **Lazily** written by the snapshot flush hook installed in **`RoomScene.create`** (see **Snapshot flush hooks** below) — written on **room-leave**, **`getSnapshot`**, and **`B.state.flush`**, never per-tick. Source is the prop's **authoring** position, not its live `sprite.x / y`: tight-placement uses `benneRoomPropAuthoredX/Y`; parallax uses the entry's **`baseX / baseY`**; otherwise the live sprite position. Spawn applies via **`readSavedPropPosition`** by overriding `RoomPropSpawn.x / y` before `add.sprite`, so tight + parallax + plain placement all round-trip. Authors mutate this through **`B.prop(id).moveTo` / `moveTo.now` / `moveToNow`** (see [bennescript-api.md → `B.prop(propId)`](bennescript-api.md#bproppropid-bennescriptpropfacade)).
- **Characters** (global, follows the definition id across rooms):
  - `` `character:<characterId>:animation` `` — override tag; cleared by **`stopAnimation()`** or **`animation = null`** / **`animationNow(null)`**.
  - `` `character:<characterId>:visible` `` — boolean override for **`B.character(id).hide` / `show` / `visible = …` / `visibleNow(…)`**; spawn applies via **`readSavedCharacterVisible`** (first **`RoomCharacterInstance.visible`** fold in the room JSON is the fallback default, same “first wins” rule as the sprite map for duplicate definition ids).
  - `` `character:<characterId>:movable` `` — boolean override for **`B.player.movable`** / **`B.character(id).movable`**; effective value via **`readSavedCharacterMovable`** (JSON **`CharacterData.movable`** from the first spawn row for that id in the active room is the fallback default — **`true`** when the field is omitted or anything other than **`false`**).
  - `` `character:<characterId>:followingTarget` `` — non-empty string when **`B.character(id).startFollowingCharacter`** / **`B.player.startFollowingCharacter`** is active: a character definition id or the literal **`"player"`** (resolved at runtime to **`game-config.json`** **`startingPlayerCharacter`**). Cleared by **`stopFollowingCharacter()`**.
  - `` `character:<characterId>:followOptions` `` — plain object with merged follow tuning (**`minDistance`**, **`repathThreshold`**, **`offset` `{ x, y }`**, **`speedMultiplier`**, **`faceTargetWhenIdle`**, **`pauseDuringCutscene`**); written whenever follow starts or options change. Read via **`readSavedCharacterFollowEffectiveOptions`** (defaults applied when missing or partial).
  - `` `character:<characterId>:alpha` `` — number `[0, 1]`; written as **`toAlpha`** by **`B.character(id).fade(...)`** and **`fade.now`**; spawn applies via **`readSavedCharacterAlpha`** to both image-only and Aseprite character spawn paths (default `1`).
  - `` `room:<roomId>:character:<characterId>:position` `` — `{ x, y }` **feet world** coords (matches **`getCharacterWorldFeet`**). **Per-room** (so the same character id appearing in two rooms never clobbers across rooms) and **lazily** written by the same snapshot flush hook as prop positions; source is the live sprite's feet, walked or teleported during gameplay. Spawn (image and Aseprite paths) applies via **`readSavedCharacterPosition`** by overriding the `RoomCharacterSpawn` `x / y` fed to **`applyFeetWorldWithRegionScale`**. Rooms with a `whenEnterRoom` that calls **`B.player.moveTo.now('entry-point')`** still work — spawn applies the saved feet, the enter hook teleports the player to the entry, and the next flush records the new spot.
- **Inventory** (per item id, global): `` `inventory:<itemId>:defaultAnimation` `` and `` `inventory:<itemId>:cursorAnimation` `` — optional overrides for **`InventoryItemData.defaultAnimation`** / **`cursorAnimation`** (see **Inventory System**).

**Snapshot flush hooks** ( **`src/engine/gameState/snapshotFlushHooks.ts`** ): a small registry — **`registerSnapshotFlushHook(fn)`** returns an unregister fn; **`runSnapshotFlushHooks()`** invokes every hook in registration order with per-hook **`try / catch`** (a buggy hook can never break **`getSnapshot`** — saves are sacred). Used as a **pull-up** for state that is too noisy to write eagerly per-tick (today: **character feet positions** and **prop authoring positions**; everything else — visibility, alpha, animation overrides, flags, variables, inventory — is still written eagerly on every change). **Trigger points** (all funnel into the same hook): (1) **`GameStateManager.getSnapshot`** runs hooks **before** cloning state, so **`saveToLocalStorage`**, **`exportSnapshotJson`**, **`B.state.saveToBrowser`**, and **`B.state.exportJson`** automatically pick everything up; (2) **`RoomTransitionOrchestrator.prepareForLeave`** calls **`roomScene.flushRuntimeStateToGameState()`** as its first step before the scene tears down; (3) **`B.state.flush()`** for explicit script save points. **`RoomScene.create`** registers the flush hook and stores the unregister fn in **`snapshotFlushHookUnregister`**, called on **`Phaser.Scenes.Events.SHUTDOWN`** so editor previews and torn-down rooms never hold stale hooks. The **scene method** **`flushRuntimeStateToGameState`** walks **`characterSpritesByDefId`** + **`propSpritesById`**; the prop helper **`getPropAuthoringPosition`** picks tight authored coords → parallax `baseX/Y` → live `sprite.x / y` in that order so values round-trip across spawn.

**Runtime wiring**  
- Room scripts run **after** props, characters, the player, and the camera are set up in `RoomScene.create()` (so `B.prop` / `B.player` resolve real scene objects).  
- Character scripts for a given id run in the same phase **only if** that character is spawned in the room; each gets its own `CharacterBenneScript` and `B.dispose()` on scene shutdown.  
- **`registerDialogScript`** callbacks run **when** a matching dialog session opens (**`openDialogSessionForId`** after **`B.dialog(id).start`** / **`.start.now`**); **`endDialogSessionIfMatches`** calls **`dispose()`** on that session’s **`DialogBenneScript`** so **`whenChoice`** and other subscriptions clear when the dialog stops or another dialog replaces it.  
- On scene shutdown, each room/character `B.dispose()` removes listeners that instance registered (avoids duplicate handlers if the room scene is recreated).  
- Optional payload-typed handlers use `(p: any)` for unified **`when*`** methods (runtime shape depends on prop vs hotspot vs character), or import specific payload types from `propInteractionEvents.ts` when wiring **`onProp`** / raw events.

**Key Design Decisions**  
- Single `B.` namespace → excellent Cursor IntelliSense and discoverability (better than multiple `C.`, `H.`, `P.` prefixes for a modern TS codebase).  
- `registerRoomScript(({ B }) => { ... })` → natural, minimal boilerplate; **blocking** timing is internal (`async` listener + `await` on the tail after the sync handler body); **`.now`** opts out per call.  
- Side-effect registration via module-level array → works reliably with Vite `import.meta.glob` (avoids marker propagation issues).  
- All real work still flows through the existing `EventBus` and verb dispatch system — zero runtime cost for the facade.

**Multi-room note:** every `registerRoomScript` callback runs once per room load with that room’s `ctx`. Scripts meant for a single room should guard with `if (ctx.roomId !== 'myRoom') return` at the top until a tighter binding exists. **Room changes** at runtime: **`B.room.changeTo` / `changeToNow`**; **first** room from **`BootScene`**: **`startInitialRoomFromBoot`** (see the API table, **`RoomTransitionOrchestrator`**, and the top **Room transitions** callout). Per-room **`whenLeaveRoom`**, **`whenEnterRoom`**, **`whenEnterRoomAfterFade`** in **`registerRoomScript`**, and global **`whenLeaveAnyRoom`**, **`whenEnterAnyRoom`**, **`whenEnterAnyRoomAfterFade`** in **`registerGlobalScript`**, receive **`RoomTransitionContext`**.

**Future extensions** (easy to add under `B.`):  
- `B.sequence(...)` for parallel/cutscene actions on top of the existing queue and **`B.room`**
- Richer branching on top of **`B.dialog`…`start` / `stop`**, **`B.whenChoice`**, and persisted **`:enabled` / `:used`** option state (see **§3 → Dialog system**)

This layer turns BENNE from "wiring events" into "telling a story" while keeping the engine clean and data-driven.

### Per-frame hooks — `B.onUpdate`

PowerQuest-style **`void Update()`** continuous logic: **`B.onUpdate((ctx: UpdateContext) => { … })`** on **room** and **global** script facades only (**`registerRoomScript`**, **`registerGlobalScript`**). **`UpdateContext`** (**`src/engine/scripting/types.ts`**) exposes **`deltaSeconds`** (Phaser **`game.loop.delta / 1000`**) and **`roomId`** (active **`RoomData.id`**). The engine invokes handlers from **`RoomScene.update`** **after** snap/follow/region/parallax/stack/path work, **not** on the **`interactionTail`**; **room** callbacks run **before** **global** callbacks. Handlers **still run** while **`cutsceneDepth > 0`**. Per-handler failures log to **`console.error`** without skipping later handlers. Wiring: **`BenneScriptCore.onUpdate`** + subclass **`acquireOnUpdateSubscription`**, **`RoomScene.registerBenneScriptOnUpdateHandler`**, **`benneScriptOnUpdateRegistry.ts`** for globals (**`runGlobalBenneScriptOnUpdateHandlers`**, cleared on **`Phaser.Core.Events.DESTROY`** from **`wireBenneGlobalScripts`**). See **`docs/bennescript-api.md` → Per-frame hook — `B.onUpdate`**.

### Cutscene mode

BENNE supports **PowerQuest-style uncancelable sequences** that suppress all player input for the duration of a scripted sequence.

**Automatic activation** — the following handlers are always wrapped in a cutscene block with no author changes required:

| Handler | When active |
|---------|-------------|
| `B.whenEnterRoom(…)` | Before fade-in; covers the enter-phase queue drain |
| `B.whenEnterRoomAfterFade(…)` | After fade-in; typical walk-in / scripted intro |
| `B.whenEnterAnyRoom(…)` | Same timing as `whenEnterRoom` (global script) |
| `B.whenEnterAnyRoomAfterFade(…)` | Same timing as `whenEnterRoomAfterFade` (global script) |
| `B.whenChoice(optionId, …)` | Full `say` + interaction-tail drain after the player picks an option |

**Explicit API** — `B.cutscene(callback)` / `B.cutscene.now(callback)` is available on every Bennescript surface (room, character, inventory, global, GUI, dialog):

```ts
B.cutscene(() => {
  B.walkToClicked();
  B.player.say('I'll do it!');
  B.wait(0.5);
  B.character('guard').say('Stop right there.');
});
```

- **Blocking form**: waits for any previously-queued steps to drain, pushes the cutscene flag, runs `callback` synchronously (which may queue further `B.*` steps), then pops after all those steps complete.
- **`.now` form**: pushes the cutscene flag immediately, runs the callback, then pops after any steps the callback queued finish.

Both forms use the interaction tail so they chain correctly with `walkTo`, `say`, `wait`, fades, etc.

**What is suppressed** — push/pop are reference-counted so nested cutscenes are safe:

| Input | During cutscene | During `say`-line only |
|-------|:---------------:|:----------------------:|
| Background empty-floor walks | ✗ | ✗ |
| Prop / hotspot / character clicks | ✗ | ✗ |
| Inventory row clicks | ✗ | ✗ |
| GUI button clicks | ✗ | **✓ live** |
| Hover descriptions (`B.currentHoverDescription`) | suppressed (null) | suppressed (null) |
| Click-to-skip scripted `say` lines | **✓ always live** | ✓ live |

**Walk promise contract** — inside a cutscene, if a scripted walk is interrupted (e.g. a new `walkTo` starts before the prior one finishes), the pending `walkPlayerTo` promise resolves immediately so the interaction chain does not hang. Outside cutscene mode, interrupting a walk drops the arrive callback (existing behaviour).

**Custom cursor** — when the Aseprite cursor is enabled, `game-config.json`'s `cursor.busyAnimation` controls the appearance during a cutscene:

- Non-empty string and the animation key exists → cursor plays that tag.
- Missing, blank, or clip not found → cursor sprite is hidden entirely (classic PowerQuest style).

Both `idle` and `active` animations are fully restored when the cutscene ends.

**`B.state.isCutsceneActive`** — read-only `boolean` on every `B.state`, true while any cutscene block is active on the current `RoomScene`. Safe to read from GUI / global scripts.

**Key modules:** `src/engine/scenes/RoomScene.ts` (`pushCutscene` / `popCutscene` / `isCutsceneActive`), `src/engine/scripting/BenneScriptCore.ts` (`cutscene` / `cutscene.now`), `src/engine/scenes/RoomTransitionOrchestrator.ts` (automatic enter / after-fade wrapping + queue drain), `src/engine/scripting/DialogBenneScript.ts` (automatic `whenChoice` wrapping), `src/engine/gui/buildGuiOverlay.ts` (`isButtonClickSuppressed` callback), `src/engine/scripting/benneScriptGameStateApi.ts` (`B.state.isCutsceneActive`), `src/types/game.ts` (`GameSettingsCursor.busyAnimation`).

### GUI behavior runtime (`GuiRuntime`, `B.onGuiBuilt`)

After **`buildGuiOverlay`** composes a GUI in **`RoomScene`**, the engine constructs a **`GuiRuntime`** for that overlay and invokes every **`B.onGuiBuilt((gui) => { … })`** callback registered in the matching **`registerGuiScript('guiId', …)`** facade. The same path runs for the reserved Speaking Text (**`speaking-text`**) overlay. Authors use this for **low-level, composable** UI behavior (slide panels, fades, hover bands, etc.) without adding opinionated helpers to the engine core.

- **`gui.root`** — **`ControlFacade`** for the **`Phaser.GameObjects.Container`** that parents every authored control **except** those whose **`id`** appears in **`fixedControls`** on the GUI JSON. **`gui.root.tweenTo`** / **`setY`**, etc. move or fade only that packed subtree (same Bennescript interaction queue as per-control facades). Fixed controls keep their own scene objects; tween them via **`gui.getControl(id)`** if needed. **`GuiOverlayHandle.gameObjects`** lists the packed container **plus** each fixed control’s top-level object(s) so editor UI-camera routing stays correct. Optional **`GuiData.x`** / **`GuiData.y`** set the **initial** position of the packed root at build time — e.g. **`"y": -34`** parks a dropdown bar just offscreen so a **`tweenTo({ y: 0 })`** in **`onGuiBuilt`** reveals it without any setup call. Fixed controls ignore **`GuiData.x`/`y`** (that is the whole point — keep the reveal trigger pinned in screen space while the rest slides).
- **`gui.getControl(controlId)`** returns **`ControlFacade | null`** — use when a control may be absent and you branch. **`gui.getControlOrThrow(controlId)`** returns **`ControlFacade`** and throws with **`guiId`** + control id if missing; **prefer this** when a missing id means bad JSON so TypeScript stays strict without local guards. Controls need a stable **`id`** in **`*.gui.json`** (`text`, **`button`** `id`, **`inventoryPanel`** optional `id`, **`image`** optional `id`, **`trigger`** `id`). Each facade exposes **`gameObject`**, immediate setters (**`setY`**, **`setVisible`**, **`setAlpha`**, …), **`setVisualState`** on **`button`** hits ( **`'normal'`** / **`'hover'`** / **`'pressed'`** / **`'disabled'`** — drives **`states.*`** + **`textColorStates`**, **`'normal'`** re-enables pointer-driven chrome), and **`tweenTo(props, duration?, easing?)`** / **`tweenTo.now(...)`** — tweens use the **same interaction queue** as other Bennescript (`say`, **`B.wait`**, …) on that GUI’s **`GuiBenneScript`** instance.
- **Pointer hover events**: **`B.whenMouseEnter(controlId, handler)`** / **`B.whenMouseLeave(controlId, handler)`** fire when the pointer enters / leaves any GUI control with that **`id`**. They work uniformly for **`button`** (while enabled, via Phaser's native `pointerover` / `pointerout` since buttons already need `setInteractive` for clicks) and for **`image`**, **`inventoryPanel`**, **`text`**, and **`trigger`** — all of which use a **non-blocking scene-level `pointermove` observer** (**`installGuiControlPointerHoverObserver`**) that tests the pointer against the control's current world bounds without calling `setInteractive`. Events emit on `gameEvents` as **`gui:<guiId>:control:<controlId>:mouseenter` / `:mouseleave`** (see **`guiControlHoverEvents.ts`**). **The observer is critical to keep HUD overlays from eating room clicks**: because non-button GUI controls are not hit-tested by Phaser, the `RoomScene` pointer pipeline (prop / hotspot / character `pointerdown`, and the walk-on-empty-space path that calls `hitTestPointer`) still receives events for pixels covered by an `inventoryBar` backdrop or `image` control.
- **`trigger` control** — **`GuiTriggerControl`** in **`src/types/gui.ts`** (fields: **`id` / `name?` / `x` / `y` / `width` / `height` / `active?` / `visible?`**). It is **never drawn** (a `debug.showGuiOutlines` overlay still traces it for layout). Triggers use the same non-blocking observer as the other non-button controls. Multiple overlapping triggers all fire independently (each is its own rect-containment test). When **`active: false`** no events emit; hiding the rect flushes a synthetic **`mouseleave`** so subscribers always see a clean exit. Authored via the **Add Control** wizard in the Inspector as **“Trigger”**.
- **Dropdown / slide-in HUD pattern**: combine **`GuiData.y`** for the parked position with **two triggers** — a small reveal rect at the top of the screen plus a larger keep-alive rect covering the bar footprint, both listed in **`fixedControls`** so they stay in place while **`gui.root`** slides. Wire reveal on **`whenMouseEnter('hoverZone')`** and hide on **`whenMouseLeave('hideZone')`**. Because triggers are non-blocking, moving the pointer from the reveal zone down onto a button inside the bar keeps **`hideZone`** "inside" and the bar stays open while the click is processed; see **`src/game/guis/inventoryBar/inventoryBar.gui.json`** + **`.gui.ts`** for the canonical example.

```ts
B.onGuiBuilt((gui) => {
  const root = gui.root;

  B.whenMouseEnter('hoverZone', () => {
    root.tweenTo({ y: 0 }, 300, 'Sine.easeOut');
  });

  B.whenMouseLeave('hideZone', () => {
    root.tweenTo({ y: -34 }, 250, 'Sine.easeIn');
  });
});
```

- **Teardown**: **`GuiRuntime.dispose`** (from overlay **`destroy`**) kills tweens on **`gui.root`** and per-control facades; **`buildGuiOverlay`** destroys the packed content container **and** any **`fixedControls`** scene objects, and detaches every hover-forwarder listener it installed. **`GuiBenneScript`** subscriptions (button click, mouseenter/leave) remain on **`gameEvents`** for the next room load; **`onGuiBuilt`** handlers run again whenever the overlay is rebuilt.

Core modules: **`src/engine/scripting/GuiRuntime.ts`**, **`GuiBenneScript.ts`**, and **`buildGuiOverlay`** (`BuiltGuiOverlay` / **`createGuiRuntime`**).

### BENNE Play (full runtime `WebviewPanel`)

**Purpose** — Run the **shipped** engine bootstrap inside VS Code so gameplay (verbs, **`buildGuiOverlay`**, inventory, dialogs, **`registerGameContent`** scripts, room transitions) matches the browser build, without repurposing the **room preview** authoring surface.

### High-DPI editor overlay

The editor preview uses **`Scale.RESIZE`** (not `Scale.FIT`) so the Phaser canvas always fills the VS Code panel. **Navigate mode** simulates the exact in-game view by computing `scale = min(panelW/gameW, panelH/gameH)` and using `cameras.main.setViewport(centreX, centreY, gameW*scale, gameH*scale)` — the viewport box is letterboxed inside the panel using the game background colour. **Edit mode** expands the viewport to the full panel (`setViewport(0,0,panelW,panelH)`), zooms to fit the room art, and enables mouse-wheel zoom (around the cursor) and middle-mouse pan. Pressing **F** resets to the fit-room zoom. The camera re-applies its mode automatically via `scale.on('resize')`. The DOM overlay canvas is sized to fill the full panel in both modes; all handle drawing uses `worldToCanvasCss(p, cam)` which accounts for the active camera zoom, scroll, and viewport origin (`cam.x`, `cam.y`). **Pointer capture** on the overlay handles drags; **`pointer-events: none`** in Navigate so `RoomScene` receives clicks. **Zoom formula** (Phaser 4-accurate): `scrollX = worldX - originX - (screenX - originX - cam.x) / newZoom` keeps the world point under the cursor fixed across zoom steps.

**Editor UI camera** (`RoomScene.ensureEditorUiCamera`): because the editor main camera uses `setZoom(scale)` while the shipped game keeps `cameras.main.zoom = 1`, Phaser 4's origin-aware zoom math pushes `scrollFactor: 0` overlays off the viewport by `origin × (1 − zoom)` pixels (hundreds of px at typical editor scales) — this is why the first "Show GUIs" attempt produced no visible pixels even with `visible: true` and correct bounds. `RoomScene` creates a second camera (`name: 'editor-ui'`) with the same viewport + zoom as `cameras.main` but `origin = (0, 0)` and `scroll = (0, 0)`, so GUI overlays render at `(x × zoom, y × zoom)` relative to the viewport top-left — matching the runtime placement. `GuiOverlayHandle.gameObjects` enumerates each overlay's top-level objects so the main camera can `ignore` them and the UI camera can `ignore` everything else; a `Phaser.Scenes.Events.ADDED_TO_SCENE` listener keeps the split correct for objects added after scene boot (tween sprites, debug overlays). The UI camera is torn down on `Phaser.Scenes.Events.SHUTDOWN`. The shipped game never calls `setEditorCameraMode`, so this camera is editor-only and has **zero** runtime cost.

### Pathfinding (engine)

- **`src/engine/pathfinding.ts`** — `findWalkPath(start, goal, polygons) -> Point2[]` returns an ordered polyline of waypoints (goal last) routing the character around **holes** and **concave** parts of the walkable union. Used by both the player and NPCs.
- **Algorithm**: classical **reduced visibility graph + A\***, the canonical shortest-path approach for *simple polygons with holes* and what most modern 2D adventure engines use under the hood (Adventure Creator, Wintermute-family, PowerQuest polygon mode). Result is the **exact Euclidean shortest path** — a polyline that bends only at polygon corners, giving the classic LucasArts "walk around the obstacle" look.
- **Graph nodes**:
  - **Reflex** outer-ring vertices of each **active** polygon (convex outer corners are never on a shortest path and are omitted).
  - **All** vertices of each **active** hole ring (holes poke into the walkable region, so every hole vertex is reflex as seen from the walk side).
  - Each node is offset **~1 px inward along the interior angle bisector** so waypoints sit just inside the mesh rather than exactly on the boundary pixel. This both matches the classic LucasArts corner-radius feel and keeps segment-midpoint-in-walkable tests numerically robust at vertices.
- **Edges**: two points are connected iff the straight segment between them lies entirely inside the walkable region. Tested by (1) sampling the segment at t = 0.25 / 0.5 / 0.75 and checking each is in the walkable union, plus (2) a proper-crossing test against every ring edge (outer + active hole) that ignores shared-endpoint touches and collinear overlap.
- **Start / goal**:
  - Goal is first clamped to the walkable union (reuses `clampWalkDestinationTowardClick`).
  - If the **start** point is outside the walkable region (spawn / cutscene placement off the mesh), pathfinding is skipped and a **direct line** to the clamped goal is returned — preserves the pre-pathfinding behavior where off-mesh characters glide to the floor.
  - If start and goal are in **disconnected components** of the walkable union, A\* returns no path and the engine falls back to a direct line to the clamped goal.
  - If the straight segment from start to clamped goal is already inside the mesh, `findWalkPath` short-circuits to `[goal]` without running A\* (common case: clicking nearby open floor).
- **Complexity**: O((N+2)²) visibility edges per query, where N is the number of candidate nodes (typically tens for hand-authored rooms). Each visibility test is O(E) across all ring edges. Cheap in practice; invoked once per walk command (click-to-walk, `B.player.walkTo(…)`, or `B.character(id).walkTo(…)`), not per frame. No cross-query caching yet — future work if rooms ever grow to hundreds of vertices.
- **Integration in `RoomScene`**:
  - `walkPlayerToWorldPoint` / `walkCharacterToWorldPoint` (and the empty-space click handler) call `findWalkPath` and then chain **one Phaser tween per path leg** via `beginPlayerWalkLeg` / `beginNpcWalkLeg`. Facing is recomputed per leg with `facingFromWorldDelta` so the sprite turns into each new direction (`Walk` base animation swaps accordingly); `Idle` plays on final leg completion.
  - `PLAYER_WALK_START` fires **once** with the final clamped target; `PLAYER_WALK_STOP` fires **once** on `complete` (final leg) or `interrupted` (new walk pre-empts the chain, scene shuts down, etc.). Leg boundaries themselves do not emit events.
  - `stopPlayerMoveTween(emitStop)` cancels the current leg and clears `currentPlayerPath`; in-flight `onComplete` guards against advancing a superseded chain by comparing tween identity with `playerMoveTween`.

| **`npm run set-template -- <name>`** | Save the **current** live tree (bootstrap + template sync-down), then **replace** **`src/game/`** with a fresh copy of **`_bootstrap/`** + **`game-templates/<name>/`**. Shorthands: **`npm run set-template:2-click`**, **`npm run set-template:9-verb`**. |

Each mirror builds a **plan** (new / modified / unchanged / orphan deletes), prints a summary, and asks for confirmation unless **`--yes`** / **`-y`** is passed (e.g. **`npm run set-template:9-verb -- --yes`**).

**What counts as “bootstrap” vs “template”**

- **Bootstrap**: every **top-level regular file** in **`src/game/`** **except** **`game-config.json`** and **`globalScript.ts`** (subdirectories never count). New engine helpers added alongside those two are synced automatically — the script does **not** read **`game-templates/_bootstrap/`** to discover names.
- **Template**: **`game-config.json`**, **`globalScript.ts`**, and **everything under subdirectories** (rooms, assets, dialogs, …).

**Special cases the script handles**

- **`.gitkeep`** under template folders is ignored by the mirror so empty directories can stay in git without being deleted when **`src/game/`** has no matching file.
- **Editor / OS duplicate names** are ignored and dropped as orphans on sync (never copied into templates): e.g. **`game-config copy.json`**, Windows **`… - Copy.ext`**, Explorer **`… (1).ext`**, **`.DS_Store`**, Office **`~$…`** lockfiles.

**Authoring pitfall**

Empty templates still need a **`src/game/rooms/rooms.manifest.json`** (and usually manifest **room entries**) because **`loadStartRoom.ts`** imports the manifest statically; the **Create New Room** wizard only **appends** to an existing manifest — it does not create the file if missing.

## 10. Future Considerations

- **Room transitions (extensions)**: The shipped path **restarts `RoomScene`** with new **`RoomSceneStartData`** via **`RoomTransitionOrchestrator`**. Deeper work might add **preloading**, **shared caches**, or **non-black cutscene transitions**; **global narrative state** should remain on **`GameStateManager`** unless a game explicitly resets it.
- **Post-processing**: `PostEffects.ts` is ready for **camera filter** composition (CRT, dither, etc.).
- **Audio**: **`B.sound`** covers **SFX + music** from authored assets and **`BlockingWithNow`** sequencing; further work might add **spatial audio**, **voice/dialogue bus mixing**, or **event-driven triggers** outside scripts.
- **Dialogue / inventory UI**: **`say`** shows the **Speaking Text** overlay (**`speaking-text`**). **`inventoryPanel`** GUIs render a carried-items grid with optional **paged scroll** (`scrollDirection`, `backButton`, `forwardButton` in **`*.gui.json`**) and **reactive rebuild** on **`gameState:inventoryChanged`** / **`gameState:replaced`** when scroll is configured. **Richer dialogue** (choices, portraits) and **full inventory UX** (drag-reorder, cursor) remain **future work** — **`B.inventory`** is available for wiring.
- **Editor**: VS Code extension + **`build:room-preview`** ship a **live `RoomScene` preview** in a webview with **polygon editing** (walkable, prop colliders, **hotspots**, **regions**, and **room points**) via **`RoomPolygonEditScene`**. **`build:character-preview`** adds a separate webview for **feet** + **click collider** polygons. **`build:benne-play`** ships the **BENNE Play** full-runtime panel (same boot as **`main.ts`**, not the preview loader) — see **§8**.
- **HMR script registry hygiene:** During dev hot reload, side-effect `register*Script` calls can accumulate stale handlers (e.g. room enter hooks) if registries are append-only. Add HMR-safe registry reset/dedupe behavior (`import.meta.hot.dispose` and/or module-keyed maps) to prevent duplicate/stale hook execution without requiring full page reloads.
