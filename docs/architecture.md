# BENNE — Architecture

## 1. Overview

**BENNE** is a **web-based point-and-click adventure game engine** (LucasArts SCUMM / AGS / PowerQuest): fixed-resolution pixel rooms, click-to-walk, and verb-style interactions on props and characters. The runtime is **Phaser 4** (RC), **TypeScript**, and **Vite**.

**Core design goals**

- **Data-first**: Rooms, characters, **GUIs** (overlay UI definitions), **inventory** definitions, **dialogs** (topic lines + choice options in JSON), and game tuning live in **JSON** (and Aseprite exports) under `src/game/`; TypeScript supplies **room** / **character** / **GUI** / **inventory** / **dialog** scripts and engine code, not hand-authored level blobs in code. Optional **`src/game/pdcs/<id>/<id>.pdc.json`** files store **designer-only puzzle flow charts** (Cytoscape JSON); they are **not** registered by **`registerGameContent`** and do not participate in runtime loading.
- **Separation**: **`src/engine/`** is reusable; **`src/game/`** is project-specific content and registration (`registerGameContent`).
- **Retro display**: Internal resolution defaults to **352×198** and remains the source of truth for gameplay + GUI coordinates. Runtime scaling uses a **hi-DPI canvas** strategy (`Scale.NONE`) instead of `FIT + MAX_ZOOM`: backing buffer targets **parent CSS size × device pixel ratio** (capped), `scale.zoom = 1 / dpr` keeps CSS sizing predictable, and the game frame is aspect-fit via `cameras.main.setViewport` + smooth (non-integer) zoom. Resize uses a two-phase path in `benneRuntimeHiDpiScale.ts`: per-frame cheap camera/CSS updates while dragging, plus a short debounced backing-store commit (`scale.resize`) to reduce flicker. Startup runs an unconditional commit burst across initial RAFs, and camera dedupe includes active-scene keys so scene changes (`BootScene` -> `RoomScene`) still force first-frame camera application. **Post-processing** is wired as a **camera hook** (`attachPostProcessingPlaceholder`) — currently a no-op, reserved for CRT / dissolve-style effects.
- **Scrolling rooms**: Rooms wider or taller than the viewport declare `size` in `RoomData` (e.g. `"size": { "width": 704, "height": 198 }`). `RoomScene` reads this and sets `cameras.main.setBounds` + `startFollow` on the player so the camera tracks movement within the room. An optional `scrollBounds` field further restricts how far the camera pans.
- **Simplicity over frameworks**: One primary gameplay scene (`RoomScene`), a thin boot loader (`BootScene`), and a **global `EventBus`** for script-facing events instead of a heavy ECS.

## 2. High-Level Architecture

**Major pieces**

| Area | Role |
|------|------|
| **`main.ts` + `Game.ts`** | DOM mount, `Phaser.Game` with **`BootScene` + `RoomScene`** wired in `Game.ts` (keeping the scene imports out of `gameConfig.ts` so previews don't transitively pull them). **`createBenneGame`** registers **`GameStateManager`** on **`game.registry`**, publishes **`setActiveBenneGame(game)`** for engine code that needs the live **`Phaser.Game`** without a handle (cleared with **`setActiveBenneGame(null)`** on game **destroy** — see **Game state → Active `Phaser.Game` handle**). |
| **`gameConfig.ts`** | **Side-effect free** Phaser config helpers: resolution from JSON, scale, **`getBenneRendererConfigFields()`** ( **`Phaser.WEBGL`**, `pixelArt`, `roundPixels`, `antialias`, `backgroundColor`, `render.powerPreference`), and **`getEditorPhaserGameConfig()`** for room-style previews that need **`Scale.RESIZE`**. Every preview and **BENNE Play** spread the same renderer fields (see `.cursor/rules/benne-preview-rendering-parity.mdc`). Scenes are **not** imported here; doing so would transitively pull `resolveGameAssetUrl.ts` (which `import.meta.glob`'s every asset PNG) into preview bundles. |
| **`ConfigManager.ts`** | Reads bundled `game-config.json` (`getGameSettings`). |
| **`src/engine/content/`** | The only engine code that reads **`src/game/`**: the `import.meta.glob` tables (root-absolute, e.g. `/src/game/rooms/**/*.room.json`), the `game-config.json` and `fonts.json` imports, and the loaders and path/texture-key helpers built on them (`registerGameContent`, `loadRoomData`, `resolveGameAssetUrl`, …). An ESLint rule rejects game imports anywhere else in `src/engine/`. Its files stay small and separate so a preview bundle pulls in only the globs it uses. |
| **`BootScene`** | Loads assets for the **start room** (manifest + globbed JSON), then **`startInitialRoomFromBoot`** ( **`setLastRoom(null)`**, registry **`'boot'`**, `scene.start(Room, startData)`) or the same state + **`scene.start`** if no orchestrator. |
| **`RoomScene`** | Renders one room: background, Aseprite props, hotspots, characters, player walk, prop/character hit tests, debug overlays, and **every** screen-space GUI from **`./guis/**/*.gui.json`** (via **`buildGuiOverlay`**), except **Speaking Text** (**`speaking-text`**, reserved for **`say`**) and **choice-dialog GUI ids** (reserved for **`dialogs.x.start()` / `dialog.end()`** — see **§3 → Dialog system**). |
| **`EventBus` (`gameEvents`)`** | `Phaser.Events.EventEmitter` — verb dispatch is **listener-first** (room-scoped per-verb events, then character-global, then object **`onVerbFallback`**, then globals / **`verb:unhandled`**). Props and hotspots wire handlers only in **`*.room.ts`**; **`InventoryItemData`** may still carry optional **`onVerb`** / **`onVerbFallback`** for tooling; **`CharacterData`** mirrors props/hotspots (**`onVerbFallback`** only, no **`onVerb`**). |
| **`registerGameContent`** | **Discovery** pass for all game script modules. `*.room.ts` files are registered as **lazy** Vite dynamic-import factories (not executed here) via **`registerRoomModuleLoaders`** (`scenes/roomScriptModules.ts`). All other script types (**`*.character.ts`**, **`*.gui.ts`**, **`*.inventory.ts`**, **`./dialogs/**/*.dialog.ts`**, **`globalScript.ts`**) load eagerly through `import.meta.glob`, so their top-level BenneScript registrations run at once. Also registers **`*.inventory.json`** and **`./dialogs/**/*.dialog.json`** (`registerInventoryDefinitionsFromGame`, `registerDialogDefinitionsFromGame`). Room script modules are executed on demand by **`ensureRoomScriptLoaded`** (called by `BootScene` and `RoomTransitionOrchestrator`); their handlers go into that room's handler table, which `RoomScene` attaches on `create` (see **§7**). **`wireRoomTransitions(game, gameEvents)`** in `main.ts` (after `createBenneGame`) constructs **`RoomTransitionHookRegistry`** + **`RoomTransitionOrchestrator`** and attaches the any-room hooks (`game.onEnterAnyRoom` & co.) that registered while the scripts loaded. |
| **Generated handle modules** (`src/game/game.ids.ts` as **`@game`**; `rooms/`, `dialogs/`, `guis/<id>/<id>.ids.ts`) | **Build-time** TypeScript modules with a typed handle for every room, prop, hotspot, character, point, region, walkable polygon, item, dialog option, GUI control, sound, music track, video and verb, generated from **`src/game/`** by **`scripts/generate-game-ids.mjs`** (`scripts/lib/generateGameHandles.mjs`). Gitignored (`src/game/**/*.ids.ts`); regenerated on **`npm run dev`**, **`build`** and **`typecheck`**, and when the BENNE Editor changes game JSON. See **§7 → Generated handles**. |
| **`src/game/assets/`** | Images + Aseprite JSON; URLs resolved at build time via Vite `import.meta.glob` (`src/engine/content/resolveGameAssetUrl.ts`). |

**Editor (out of runtime path)**  
The **VS Code extension** (`benne-editor/`) and **`src/editor/preview/`** build **bundled Phaser previews** (room, character, GUI, inventory) that fetch game assets via webview URIs — tooling only, not part of the shipped game loop. The room preview reuses **`RoomScene`** with editor-only loader/scenes (**`createRoomPreviewGame.ts`**, **`RoomPolygonEditScene`**). **BENNE Play** is different: a **full runtime** panel (**`bennePlayPanel.ts`**, **`benne-play`**) that runs the same **`BootScene` + `RoomScene`** stack as **`main.ts`**, from a **separate Vite bundle** under **`benne-editor/media/benne-play/`** — use it to verify verbs, inventory, GUIs, and room transitions without replacing the authoring canvas (you can keep both panels open). **Play From** (**`playFrom(name, fn)`** in **`*.room.ts`**, optional **`__BENNE_PLAY_FROM_NAME`** + room preview **Play from** dropdown) loads arbitrary scripted starting state on boot without touching the shipped browser entry. **Dialogs** have **no** dedicated Phaser preview bundle; authoring is **Inspector** (**`*.dialog.json`**) plus **`*.dialog.ts`** in the editor (see **Dialogs** under **Inspector view** below).

**BENNE — Actions view** (`benne-editor`): Verb rows use **`game-config.json`** `verbs` (same order and defaults as the engine if `verbs` is omitted).

**BENNE — Inspector view** (`benne-editor`): A **WebviewView** (**Inspector**) in its own **BENNE Inspector** view container in the **Secondary Side Bar** (`contributes.viewsContainers.secondarySidebar`, which needs VS Code 1.106, the extension's minimum), across the window from the BENNE activity bar container (**BENNE** tree, **Actions**, **State**). The editor layouts in **`benneEditorLayout.ts`** (two-row preview/script and single-column dialog) end by revealing it through **`InspectorWebviewViewProvider.reveal`**, which **`extension.ts`** registers with **`setBenneInspectorRevealer`**. **`WebviewView.show(true)`** opens the Secondary Side Bar and selects the Inspector's container without taking focus; before the view has been resolved there is no `WebviewView`, so it opens the container and focuses the active editor group again. Setting **`benneEditor.layout.revealInspector`** (default on) turns this off. When the main tree selection is a **room** or **any item under a room** (walkable polygon or hole under **Walkable areas**, prop, hotspot, point, region, spawned character), the Inspector edits that room’s **`*.room.json`**. When the selection is a **puzzle dependency chart**, the Inspector shows only a placeholder message (the chart is edited in the **PDC Editor** panel, not in the Inspector webview). When the selection is a **dialog**, the Inspector edits that dialog’s **`*.dialog.json`** and the extension keeps **`*.dialog.ts`** as the only BENNE-staged editor document (single-column layout — no Phaser preview tab). The webview is styled with **VS Code theme variables** (inputs, buttons, panel borders) so it matches the host. **Room metadata** and **Walkable areas** are top-level **accordions** (`<details>`). Metadata uses a **property grid** for **Display name** and **Room ID** (read-only badge), a **Fit to background** action, and compact **dimension grids**: one row for **room size** (**W** / **H**), and a **2×2** grid for **scroll bounds** (**X**, **Y** on the first row; **W**, **H** on the second). Walkable polygons and holes stay in a table with **active** toggles, per-row **Edit** (opens the room preview in **walkable** edit mode for that polygon or hole), add-polygon / add-hole controls, and **Edit in Preview** links under **room size** and **scroll bounds** in metadata (those jump straight into **room size** / **scroll bounds** rect edit modes in the preview — no top-bar mode dropdown). **Hotspots**, **Props**, **Spawned characters**, **Points**, and **Regions** each sit in their own accordion, with a **vertical list of flat cards** inside. Optional field groups within a card use a nested **card subsection** (`<details class="benne-card-subsection">`, rendered by **`renderInspectorCardSubsection`** in **`inspectorCardSubsection.ts`**) — e.g. **Animations** on room **prop** cards and grouped **Sheet** / **Grid placement** / **Animations** (and similar) on **GUI** control cards; open state keys are **`parentEntity` + parent id + subsection id** (`guiControl`, `prop`, …). Cards carry **`data-entity` / `data-id`** for tooling; tree focus is mirrored in the payload as **`expanded`**, which **scrolls the matching card into view** and opens its section. **Prop** cards keep **Visible** in the header; **zIndex**, **baseline Y**, **Parallax**, **Alpha**, and **Clickable** use the property grid, with **Description** and a **Verbs** label above **verb chips** (same defined vs add behaviour as **Actions**). **Inv** appears after verb rows when the row is hit-testable for use-on-target authoring (**clickable** props, **active** hotspots, spawned characters whose definition is **clickable**, and on standalone **character** definitions that are **clickable**): it runs **`benne-editor.addRoomInventoryUsedOnStub`** or **`benne-editor.addCharacterInventoryUsedOnStub`**, appending an **`x.onAnyItem(() => { Player: "That doesn't work." })`** handler to **`*.room.ts`** or **`*.character.ts`** (any item handler already on the target, such as **`x.onUseItem(items.key, …)`**, counts as present). **Clickable** props get a subtle tint. All props get an **Edit in Preview** button: clickable props open collider / walk / look / baseline editing; non-clickable props open **baseline** editing only (same drag-line as clickable). **Hotspot** cards use **Active** (JSON **`active`**) in the header and a property row for **zIndex**. **Character** cards keep **Visible** in the header; **X** / **Y** use the dimension-grid row, then a property grid for read-only **Clickable**, **zIndex**, **Facing**, and **Animation**. **Edit in Preview** on props, hotspots, **points**, and **regions** drives the **BENNE Room preview** the same way as selecting that entity in the main tree; **Edit** on walkable rows and **Edit in Preview** for **room size** / **scroll bounds** do the same for those geometry tools. **`RoomPreviewPanelController.focusInspectorGeometry`** folds a one-shot target into the next **`loadRoom`** so the preview opens in the correct **`polygonEditBridge`** mode (**spawned characters** do not use **Edit in Preview** here). Selecting a **walkable polygon** or **hole** under **Walkable areas** in the main tree sets **`EditorSelection.roomPanel`** to **`walkable`** and loads the preview in **walkable** mode directly. **`*.room.json` remains the source of truth**; edits persist with **Save** and field **blur**, and **Open raw JSON** opens the file. **Actions** stays the compact verb-centric list; the Inspector is the full-room surface. Implementation: **`benne-editor/src/inspector/inspectorMain.ts`** bundles to **`benne-editor/media/inspector/inspector.js`**; shared shell CSS lives in **`inspectorWebviewViewProvider.ts`** (run **`npm run compile`** or **`npm run watch`** under `benne-editor/` after UI changes). After changing **`src/editor/preview/roomEditorMain.ts`** (or other room preview entry code), rebuild from the repo root: **`npm run build:room-preview`**. Selecting a standalone **character** or **inventory** definition opens the character or inventory Inspector; selecting a **GUI** opens the GUI Inspector for **`*.gui.json`** (see **GUIs** below).

- **Props** (selected under a room): Verb chips and **Inv** are shown only when the prop is **`clickable: true`** (matches the engine). Non-clickable props get **Make clickable** first (`clickable` in room JSON); authors still add a **collider** (≥3 points) in the preview or JSON. Non-clickable props can still author **`baseline`** in the room preview (same drag-line as clickable props). Verb handlers live in **`*.room.ts`** (`door.onLook(…)`); adding a verb appends a BenneScript handler there. Inspector / Actions highlight defined verbs by reading **`*.room.ts`** with the extension's ScriptModel (§9 of the design doc), not room JSON.

- **Hotspots**: Same verb / add-verb flow when a hotspot is selected; handlers in **`*.room.ts`**. Inactive hotspots show a reminder that they are not hit-tested.

- **Characters**: When a character is selected, **`clickable: true`** is required before verb rows (same as the engine). **Make clickable** updates **`*.character.json`**. Verbs add **`jensen.onLook(…)`** handlers (imported from **`./jensen.ids`**) to **`*.character.ts`** (they apply wherever the character is spawned) or room-scoped **`jensen.onLook(…)`** handlers to **`*.room.ts`** (the room's handler wins). For **precise clicks** on sprites with transparent padding, authors add **`collider`** (≥3 points in **frame space**, like **`feet`**) in **`*.character.json`** or in the **BENNE Character preview** (polygon editor, same interaction model as **prop colliders**). Optional **`walkToPoint`** / **`talkPoint`** (frame space, same origin as **`feet`**) tune **`walkTo('…')`** resolution and script-facing **world** hints on verb clicks. Optional **`movable: false`** disables pathfind walking for that definition by default ( **`moveTo`** still teleports); scripts may override with **`jensen.movable`** / **`player.movable`** (see **§7 → Sprite animation & persistence**). The **Actions** view may remind you to add a collider when the character is clickable but none is defined.

- **GUIs**: **Main tree** lists **`src/game/guis/<id>/<id>.gui.json`** under a **GUIs** group (below **Characters**); expanding a GUI lists **`controls[]`** entries (same **`type:id:index`** keys as the GUI Inspector), and selecting a control scrolls that card into view (**`EditorSelection.guiPanel`** → **`InspectorGuiState.expanded`**). **Create GUI** scaffolds **`*.gui.json`**, **`*.gui.ts`** (a commented BenneScript example), and **`src/game/assets/images/guis/<id>/`** (Aseprite export target). The GUI **Inspector**'s **Controls** section has an **Add Control** button that opens a **Quick Pick** (Text / Text Input / Inventory Panel / Image / Button / Checkbox / Slider / Trigger / Grid), then runs **`runAddGuiControlWizard`** (**`benne-editor/src/guiScaffolding.ts`**) — prompts for an optional control id (defaults such as `text1` / `inventoryPanel1` / `image1` / `grid1`; skipped if left blank where allowed), appends a kind-specific default entry to **`controls[]`** in **`*.gui.json`**, and refreshes the Inspector (same pattern as **Add Hotspot** / **Add Prop** / **Add Point** / **Add Region** in the room Inspector). Selecting a GUI opens the **two-row** layout with **BENNE GUI preview** on top (internal resolution from **`game-config.json`**) and the companion **`*.gui.ts`** in the Benne **script row**; the **`*.gui.json`** is edited in the **Inspector** (or any open editor tab), not as a second tab stacked with the script in the bottom row. **Runtime** (**`RoomScene`**): every matching **`*.gui.json`** is composed with **`buildGuiOverlay`** (screen-fixed **`scrollFactor` 0**), **except** overlays whose id is Speaking Text (**`speaking-text`**) or appears in **`getRegisteredDialogChoiceGuiIds()`** (those follow the reserved paths in **§3 → Scene / room system** and **Dialog system**). Supported **`controls`** are **`text`** (Phaser **`BitmapText`**), **`textInput`** (color-driven BitmapText input), **`inventoryPanel`** (player inventory grid), **`image`** (Aseprite tag from this GUI’s sheet), **`button`**, **`checkbox`** (sheet toggle), **`slider`** (sheet range control), **`trigger`**, and **`grid`** (layout container: other controls use **`gridPlacement`** to sit in a cell and move with the grid). Verb-style status lines are implemented with a **`text`** control set from **`pointer.sentence`** in the GUI's script (see **`src/game/guis/verbs/verbs.gui.ts`**). Bitmap fonts for **`text`** live in **`src/game/assets/fonts/fonts.json`** (PNG + BMFont XML) and **`BootScene`** calls **`load.bitmapFont`**. Speech lines (`Hank: "…"`, `jensen.say(…)`) drive only the reserved Speaking Text (**`speaking-text`**) GUI via **`setDialogTextOverlay`**; **`dialogs.x.start()` / `dialog.end()`** drive reserved **choice-dialog** overlays (dynamic **`Option-Grid`** rows, scroll, **`options.x.onChoose`**). All other GUI ids are ordinary HUD layers—there is **no** per-id whitelist beyond those reservations. **`GuiData.visible`**: for ordinary GUIs, **`false`** hides the overlay at room load; omitted or **`true`** shows it. Speaking Text (**`speaking-text`**) and choice-dialog ids ignore initial **`visible`** for authored “show at load” (the engine shows/hides them for speech and topic UI). GUI overlays are sorted by **`id`**, assigned spaced base **`depth`** values; Speaking Text (**`speaking-text`**) and choice GUIs are ordered so line-at-a-time speech sits under the topic grid when both are active. **GUI Aseprite sheets** (`display.aseprite: true`): unlike rooms or characters, there is **no** “import animations from tags” command for GUIs. Only tags **explicitly bound** on a control (Inspector **Animations** section, or the same fields in JSON) are played or shown; unreferenced tags on the export are ignored. **`image`** controls and **`inventoryPanel`** slot/backdrop/highlight layers use a per-sprite **`anchor`**: **`top-left`** (default) aligns the sprite’s top-left to the control origin; **`center`** aligns the sprite’s center to the authored **`x`/`y`**; **`screen`** draws at canvas **(0,0)** in internal resolution (ignores the control’s **`x`/`y`** for placement—full-frame HUD art) while **`x`/`y`/size** remain available for layout and future clipping. The VS Code **GUI preview** uses **`buildGuiOverlay`** (same compositor as **`RoomScene`**). **`letterSpacing`** may be set per **`text`** control in **`*.gui.json`**, otherwise per-font **`defaultLetterSpacing`** in **`fonts/fonts.json`**. Wrapped text uses an even **`wordWrapWidth`** (snapped down by one pixel when odd) to reduce sub-pixel centering artifacts from Phaser **`BitmapText`**. **`gameConfig.ts`**, **BENNE Play**, and every Phaser preview use the same renderer fields from **`getBenneRendererConfigFields()`** (**`Phaser.WEBGL`**, **`pixelArt`**, **`roundPixels`**) so **`BitmapText`** and sprites stay aligned. After changing **`src/editor/preview/guiEditorMain.ts`** (or related preview entry), rebuild **`npm run build:gui-preview`** from the repo root so **`benne-editor/media/gui-preview/`** stays current.

- **Dialogs**: **Main tree** lists **`src/game/dialogs/<id>/<id>.dialog.json`** under a **Dialogs** group (**`mainTreeProvider.ts`**, **`gameDiscovery.ts`**). **Create Dialog** (**`benne-editor.createDialog`**, **`runCreateDialogWizard`** in **`dialogScaffolding.ts`**) scaffolds **`src/game/dialogs/<id>/`**, **`*.dialog.json`**, and a **`*.dialog.ts`** holding a commented BenneScript example. Selecting a dialog runs **`applyBenneSingleColumnEditorLayout`** (**`benneEditorLayout.ts`**) and **`openBenneDialogTypeScript`** (**`roomScriptNavigation.ts`**): other BENNE preview/script tabs close so authors work in **Inspector + dialog script** only (contrast the **two-row** room / character / GUI / inventory flows). The **Inspector** (**`inspectorMain.ts`** → bundled **`media/inspector/inspector.js`**) edits **metadata** (display name, optional **`guiId`**) and each **option** in a card: **id**, **text**, **enabled**, **used (JSON)** (authoring default before runtime persistence), **say line** (default **on** — when checked, the player **says that row’s `text` before the option's `onChoose` handler runs**; uncheck to omit **`say`** in JSON or set **`say`: false**), **Script…**, and **Remove**. A **drag handle** (**⋮⋮**) on each row reorders **`options[]`** in **`*.dialog.json`** (**`dialogReorderOption`** patch in **`inspectorMutations.ts`**). **Metadata** and option fields **auto-save on blur / checkbox change** (same idea as other Inspector panels); **Save** still writes the full dialog, and **Open raw JSON** opens **`*.dialog.json`**. **Add option** appends a row. **Script…** posts **`dialogEnsureWhenChoice`** so **`ensureDialogWhenChoiceHandlerAndReveal`** (**`dialogChoiceScaffolding.ts`**) inserts or reveals **`options.<name>.onChoose(…)`** in **`*.dialog.ts`** (either `onChoose` or `onChooseOnce` counts as present). Patches flow through **`inspectorWebviewViewProvider.ts`**. **`benne-editor.rebuildDialogPreview`** runs **`runBenneEditorWebpackCompile`** on the extension (same class of rebuild as the final step of **`benne-editor.rebuildEditorPreviewBundles`**), not **`npm run build:*-preview`** — use it after changing Inspector webview code (or **`npm run compile`** / **`npm run watch`** under **`benne-editor/`**). Completions for **`dialogs.x.start()`** and every other handle come from TypeScript over the generated modules (§7). **Actions** when a dialog is focused (**`actionsTreeProvider.ts`**): open JSON, open script. **Delete** supports dialog folders (**`deleteTarget.ts`**, **`deleteService.ts`**).

- **Puzzle Dependency Charts (PDC)** — designer planning only; **no** companion **`.ts`**, **no** engine loader. **Main tree**: **`src/game/pdcs/<id>/<id>.pdc.json`** under **Puzzle Dependency Charts** (**`listPdcDefinitions`** in **`gameDiscovery.ts`**). **Create Puzzle Chart** (**`benne-editor.createPdc`**, **`runCreatePdcWizard`** in **`pdcScaffolding.ts`**) writes JSON with **`id`**, **`name`**, and **`elements`** (empty array initially). Selecting a chart sets **`EditorSelection`** to **`pdc`**, resets Phaser previews, and opens the **PDC Editor** **`WebviewPanel`** (**`bennePdcEditor`**): **Cytoscape.js** graph (**add/move nodes**, **edge links**, **labels**, **delete selection**, **`Fit`**); changes **debounced-write** back to **`*.pdc.json`**. **Actions**: open raw JSON plus a usage hint. **Delete** removes **`src/game/pdcs/<id>/`**. Rebuild the webview bundle with **`npm run compile`** under **`benne-editor/`** (third webpack entry; output **`media/pdc-editor/pdc-editor.js`**). Details: **§8 → Puzzle Dependency Charts (PDC editor)**.

**Add Prop / Hotspot / Point / Region** and **Import Props from Aseprite Tags** appear only when the **room** node or a **category** row (Props, Hotspots, Points, Regions) is selected; they are hidden when a specific prop, hotspot, point, or region item is selected.

**BENNE — State view** (`benne-editor`): a **WebviewView** (**`benne-editor.state`**) under the BENNE activity bar, below **Actions**. It shows the flags and vars of the first BENNE game's **`src/game/state.ts`** (§4.7 of the BenneScript design doc) as two tables (**name**, **default**) and edits that file. **`bennescript/stateFile.ts`** (pure; no `vscode`) parses the **`defineFlags({…})`** / **`defineVars({…})`** object literals with the bundled TypeScript and edits them by splicing text, so comments and order survive. It reads `true`/`false` and **`flag(default, { saveKey })`** flags and JSON-literal vars (looking past **`as T`**); other entries are shown read-only. **`bennescript/stateNames.ts`** validates names and is shared with the webview. **`StateWebviewViewProvider`** (**`stateWebviewViewProvider.ts`**) applies each edit as a **`WorkspaceEdit`** on the document, one at a time per file (**`enqueueJsonFileWork`**), and saves it unless it already had unsaved changes. It creates **`state.ts`** when it is missing and runs **`generate:game-ids`**, since **`@game`** only re-exports **`flags`** / **`vars`** once the file exists. **Rename** uses **`vscode.executeDocumentRenameProvider`** at the declaration, which follows the property through **`defineFlags`**' mapped type into every script. **Delete** counts **`vscode.executeReferenceProvider`** results and asks first when scripts use the name. While TypeScript is still loading the project it answers both from its syntax server with only some files, so the provider retries (up to 10 s) until the answer covers the **`flags.name`** / **`vars.name`** uses found by a text search of the game. The view refreshes on document changes and a **`state.ts`** file watcher. ## 3. Core Systems

### Scrolling room camera

- **Room size** (`RoomData.size`): the physical extent of the room in game-world pixels.  Controls camera bounds, walkable-area extent, and whether `startFollow` is activated.  The background image and Aseprite prop sheets render at their **own natural dimensions** — `size` does **not** scale the art.  Setting `size` smaller than the art restricts the camera to a sub-region of the art, which is valid (e.g. the art bleeds beyond the playable area).

- **Scroll bounds** (`RoomData.scrollBounds`): optional `{ x, y, width, height }` in room space that restricts how far `cameras.main` may pan within the room.  When omitted the camera pans anywhere within `size`.  Making `scrollBounds` narrower than `size` keeps the camera away from room edges (the camera is "less eager" to scroll to the edge).  Making `scrollBounds` equal to `size` lets the camera pan all the way to the edge.  Implemented via `cameras.main.setBounds(scrollBounds)`.
- **`RoomScene.setupRoomCamera`** (private): called at the end of `create` after characters spawn. Sets `cameras.main.setBounds` from `scrollBounds` (or room size). When the room is larger than the viewport and a player exists, **`applyPlayerCameraFollow`** calls `startFollow` with an offset derived from **`CharacterData.feet`** so the camera tracks the character’s **feet** (see **`src/engine/characterFeet.ts`**), not the sprite’s top-left.
- **`RoomScene.setEditorCameraMode(mode)`** (public): called by the editor's `RoomPolygonEditScene` whenever the toolbar mode changes. Stores the current mode so it can be re-applied on panel resize. Two behaviours: `'navigate'` — letterboxes the game's virtual resolution (352×198) inside the panel using `cameras.main.setViewport`, sets zoom to fill that box, and re-activates player follow + scroll bounds for game-accurate preview; `'edit'` — expands the camera to fill the entire panel (`setViewport(0,0,panelW,panelH)`), computes `zoom = min(panelW/roomW, panelH/roomH)` to fit the full room art, sets bounds to room bounds, and disables player follow so the authoring view is stable. The `scale.on('resize')` hook re-invokes `setEditorCameraMode` automatically when the VS Code panel is resized.
- **Runtime hi-DPI camera split** (`RoomScene` + `benneRuntimeHiDpiScale.ts`): runtime keeps world rendering on `cameras.main` (normal origin/follow math) and routes GUI / cursor through a dedicated UI camera (`ensureEditorUiCamera`, also used in preview). This avoids `scrollFactor: 0` HUD drift under zoomed/letterboxed viewports while preserving room-art alignment and click mapping.
- **Script camera (`camera`)** — Runtime-only overrides on `RoomScene`: a focus flag (suspends `startFollow` until `camera.reset()`) and a gameplay zoom multiplier (`1.0` = room default). State is **not** persisted; room transitions and save/load restart `RoomScene` and restore default follow. Gameplay zoom composes as **`displayZoom × scriptGameplayZoom`** (display zoom from hi-DPI letterbox or editor navigate mode; script zoom from `camera.zoom` / `camera.zoomTo`). String focus targets use **`resolveCameraFocusTarget`** (prop → hotspot → character → room point): props/hotspots prefer **`lookAtPoint`**; characters prefer **`talkPoint`**, else feet — not **`walkToPoint`**. Config defaults and limits: `game-config.json` **`camera`** (`minZoom`, `maxZoom`, `shake`, …) via **`getCameraSettings()`**. `camera.shake` doesn't wait; the moves and zooms are timed actions (`.now` to not wait).
- **Background and props** render at their **natural texture dimensions** — `room.size` does **not** call `setDisplaySize`. Art that extends beyond `room.size` is simply not scrolled into view.
- **Hotspot zones** are sized to `room.size` so polygon hit areas only cover the playable area.

### Scene / room system

- **`BootScene`**: Entry after game creation. Uses **`loadStartRoomData()`** — **`startingRoomId` in `game-config.json` overrides** `rooms.manifest.json` — resolves the room’s **`*.room.json`**. Shared helpers **`buildRoomSceneStartDataFromRoomData`** and **`queueRoomSceneAssetLoads`** (`roomSceneBootstrap.ts`) build **`RoomSceneStartData`** and queue the same class of assets; **`BootScene`** uses them, and **`RoomTransitionOrchestrator`** reuses that path for arbitrary **`roomId`** (via **`loadRoomDataById`** in `loadRoomData.ts`). Queues background image (optional), room Aseprite sheet, character assets, and registered **inventory** Aseprite sheets (shared `inventory.json` and/or per-item exports), then on loader complete calls **`startInitialRoomFromBoot`** ( **`setLastRoom(null)`**, registry **`'boot'`**, **`scene.start`**) so **`onRoomSceneCreateComplete`** runs **enter** hooks, **optional boot Play From**, **`waitForEnterPhaseBenneScriptQueues`**, **fade in**, and **after-fade** hooks (or the equivalent fallback if no orchestrator is registered).
- **`RoomScene`**: Single active gameplay view for that room. No second “room manager” type is used at runtime; the abstract **`Room`** class in `Room.ts` is a **placeholder** for future data-driven room types, not wired into Phaser yet. On **`create`**, it walks **`getAllGuiData()`** (all **`*.gui.json`** under **`src/game/guis/`**) and builds one overlay per GUI **except** **Speaking Text** (**`speaking-text`**, wired only to **`setDialogTextOverlay`** / **`say`**, starts hidden at boot regardless of JSON **`visible`**), **except** **Display Text** (**`display-text`**, wired only to **`setDisplayTextOverlay`** / **`display`**, starts hidden at boot), and **except** the ids returned by **`getRegisteredDialogChoiceGuiIds()`** (always **`dialog`**, plus each registered **`Dialog.guiId`**) — those choice-dialog overlays start hidden and are driven by **`benne:dialog:started`** / **`benne:dialog:stopped`** (see **§3 → Dialog system**). Every other GUI follows **`GuiData.visible`** (**`false`** hides at load; omitted / **`true`** shows) as its initial state; scripts may then toggle full overlays at runtime via **`guis.x.show()`** / **`hide()`**. Stable **`id`** sort and spaced **`depth`** bands keep stacking predictable: generics first, then Speaking Text (**`speaking-text`**), then Display Text (**`display-text`**), then each reserved choice GUI (so topic lines + choice UI stack above the HUD), then a **screen-fade** rectangle (see **Screen fade** below) above that stack and below the custom pointer.
- **Reserved text overlays**: **`src/game/guis/speaking-text/speaking-text.gui.json`** is the line-at-a-time **Speaking Text** surface for **`say`**; it is distinct from the **`dialog`** choice overlay used by **`dialogs.x.start()`**. **`src/game/guis/display-text/display-text.gui.json`** is the narration surface for **`display(…)`**, normally a wrapped `BitmapText` named **`text`** over a `nineSliceImage` named **`displayTextBg`**. `setDisplayTextOverlay` and `GuiOverlayHandle.setDisplayTextLayout` resize that panel to its wrapped text. **`display(…)`** / **`display.now(…)`** use scripted-dialog input suppression and click-to-dismiss like `say`, but have no line timer.
- **Screen fade**: after GUI composition, `RoomScene.create` adds a screen-fixed full-viewport rectangle at **`BENNE_SCREEN_FADE_OVERLAY_DEPTH`**, above every GUI/text overlay and below the optional custom cursor. **`fadeOut()`** / **`fadeIn()`** run `queueScreenFadeToAlpha` as timed actions (the script waits; `.now` doesn't). Defaults are **0.35 seconds** and **`0x000000`**. Global and GUI scripts resolve the active room through `tryGetActiveBenneGame`; the room preview registers the rectangle with its UI camera. The layer is recreated with each `RoomScene`.
- **Room switching**: In-game, **`rooms.x.goTo()`** (which ends the calling handler) is handled by **`RoomTransitionOrchestrator`**: leave hooks → fade out → load room JSON, its lazily registered script, and assets → **`setLastRoom` / `setCurrentRoom`** (emitting **`gameState:roomContextChanged`**) → restart `RoomScene` with the **`transition`** start kind. `RoomScene.create` increments the persisted visit count before hooks, runs global then room-local enter hooks with per-handler isolation, optionally runs a named **Play From** setup on `boot`/`preview`, waits for the enter handlers to finish, fades in, then runs global and room-local after-fade hooks. Save-load starts run global then local **loaded** hooks and skip enter/after-fade hooks. Tearing down the old room flushes positions into the game state, clears the armed verb and item, and cancels every running BenneScript handler (`cancelAllInteractions`). The initial **`BootScene` → `RoomScene`** start uses **`boot`**, sets `lastRoom` to `null`, and has no leave hooks. **`RoomTransitionContext`** carries `roomId`, `lastRoom`, session-only `isFirstEnter`, and persisted `visitCount`. VS Code room preview uses **`preview`** and does not run the full leave/load orchestrator.

**Boundaries**: Room **layout and flags** come from JSON; **reactions** for room-scoped content (props, hotspots, or room-scoped character verbs) live in `*.room.ts` (`battery.onLook(…)`). **Character-definition** reactions live in `*.character.ts` (`characters.jensen.onLook(…)`) and apply in every room that spawns the character; verb dispatch prefers the **room-scoped** handler when there is one, and the character-script handler is the **fallback**. Cross-entity wiring (verbs on other props/NPCs) stays in **`*.room.ts`**.

### Rendering system

- **Renderer**: Phaser **`WebGL`** (`gameConfig.ts` **`type: Phaser.WEBGL`**) with **`pixelArt`**, **`roundPixels`**, and **`antialias: false`** for crisp **`BitmapText`** and sprites (same settings across the GUI preview, room preview, character preview, inventory preview, and **BENNE Play**).
- **Internal size** from `game-config.json` `resolution`; shipped runtime uses Phaser **Scale.NONE** + `wireBenneRuntimeHiDpiCanvasScale` (`src/engine/benneRuntimeHiDpiScale.ts`) for hi-DPI backbuffer sizing and aspect-fit letterboxing on the main camera. During active browser resize the engine prioritizes visual stability (camera/CSS updates) and defers expensive buffer realloc to a short debounce window; once settled, a full `scale.resize` commit restores crisp final output. Camera dedupe is scene-aware so newly started scenes still receive main-camera viewport/zoom even when dimensions are unchanged. Preview surfaces that should fill their panel keep **Scale.RESIZE** (via `getEditorPhaserGameConfig`).
- **Layers**: Background image (optional, full-frame) → **room stack** (`RoomScene`): props, active hotspot zones, and spawned characters are **sorted every frame** into sequential Phaser depths (from `ROOM_STACK_DEPTH_BASE` in `src/engine/room/roomStackDrawOrder.ts` via **`sortRoomStackEntities`**). **Primary order** is authored **`zIndex`** (higher draws in front). **Optional `baseline`** on **`RoomPropInstance`** and **`RoomHotspotData`**: a **room-space Y** (pixels, y down). If a character’s **world feet Y** (from **`CharacterData.feet`** or the bottom-centre fallback) is **strictly greater** than that baseline, the character draws **in front** of that prop/hotspot even with a lower **`zIndex`**. **Character vs character** uses **feet Y** only (y-sort when feet differ, then **`zIndex`**). At the same **`zIndex`** when baseline/feet rules do not decide, draw order is **prop → hotspot → character** (then stable id / feet tie-breaks). If baseline exceptions and **`zIndex`** bands together would imply a **cycle**, that character is placed using **`zIndex` / kind / feet / sortKey only** (no baseline jumps) for that insertion so order stays **deterministic** when props change. **Debug** graphics, the optional **cinematic video layer** (`video.x.play()`, **`ROOM_VIDEO_LAYER_DEPTH = 24_000`**), and **GUI** overlays sit above this stack — the video draws above room art but **below** every GUI (so Speaking Text / Display Text stay visible over playing cinematics).
- **`PostEffects.ts`**: **`attachPostProcessingPlaceholder(this.cameras.main)`** — extension point for Phaser 4 camera filters; **no shaders shipped yet**.
- **Aseprite animation-key namespacing**: props, GUI controls, inventory sheets, and the custom pointer register clips on the scene-global `AnimationManager`, so `loadAsepriteAtlasData.ts` prefixes normalized frame-tag names with **`room:<roomId>:`**, **`gui:<guiId>:`**, **`invitem:<itemId>:`**, **`inventory:`**, or **`cursor:`**. Runtime helpers and editor preview blob loaders map author-facing short tags to those keys. Authors should continue using short Aseprite tag names in room, GUI, inventory, and cursor JSON; character clips are exempt because `sprite.anims.createFromAseprite` is sprite-local.
- **Perspective-scaled character batch**: `registerBenneCharacterPerspectiveBatch` installs a Phaser 4 custom quad path and character spawns attach it with `attachBenneCharacterPerspectiveRenderNodes`. The extended vertex layout passes **`inPerspMag = max(|scaleX|, |scaleY|)`**. For scales below 1, the `BenneCharacterPerspective` fragment addition snaps UVs to integer texel buckets (`floor(1 / mag + 0.5)`) using `uMainResolution`, after Phaser's `SmoothPixelArt` addition. This keeps source texels crisp while region scale changes continuously. The implementation mirrors Phaser shader source in `phaserQuadStandardShaderInline.ts` to avoid importing CommonJS files from `node_modules/phaser/src/**` into Vite. The batch applies only to character quads; props, GUI, cursor, and renderer configuration are unchanged.

### GUI BitmapText color and text outlines

`text` and `button` controls in `*.gui.json` support colour and outline fields:

**`color`** — hex string (e.g. `"#ff0000"`); default `#ffffff`. Applied to the main `BitmapText` via `applyGuiBitmapTextFillTint` in `guiTextOutline.ts`.

**`textOutline`** — `GuiTextOutline` object (`src/types/gui.ts`):

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `enabled` | `boolean` | — | Must be `true` for the outline to appear. |
| `color` | hex string | `#000000` | Outline colour. |
| `alpha` | 0–1 | `1` | Outline opacity. |
| `thickness` | integer ≥ 1 | `1` | Pixel distance of each offset copy. |
| `sides` | `GuiTextOutlineSides` | `allSides` | Which directions receive copies (see below). |

For `button` controls, text can also switch colour per button state:

**`textColorStates`** — `GuiButtonTextColorStates` object (`src/types/gui.ts`):

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `hover` | hex string | falls back to `textColor` | Applied while pointer is over the button. |
| `pressed` | hex string | falls back to `textColor` | Applied while pointer is down on the button. |
| `disabled` | hex string | falls back to `textColor` | Applied when `enabled: false`. |

**`GuiTextOutlineSides`** — `allSides` (full 8-direction stroke) or one of 8 directional shadow presets: `topLeft`, `top`, `topRight`, `left`, `right`, `bottomLeft`, `bottom`, `bottomRight`. For `allSides` with `thickness: 1` this produces 8 offset clones; with `thickness: 2` it produces 16 (each direction gets copies at 1 px and 2 px offset, deduplicated).

**Runtime (engine)**

- `createGuiBitmapTextOutlines` (`buildGuiOverlay.ts`) reads `resolveEffectiveGuiTextOutline` (from `guiTextOutline.ts`) which expands `sides` + `thickness` into a deduplicated `{ dx, dy }` offset list. One `BitmapText` clone is created per offset, at depth-ceiling − i × ε so clones stack below the main label in a predictable fixed order.
- `buildGuiButton` (`buildGuiOverlay.ts`) applies `textColorStates.hover` / `pressed` / `disabled` to button labels in the same pointer/event flow used for sprite `states.*` tag swaps, with per-state fallback to base `textColor`.
- Each clone has `BENNE_GUI_OUTLINE_DX_KEY` / `BENNE_GUI_OUTLINE_DY_KEY` (and outline fill keys when coloured) stored via `setData` for position sync and `syncOutlinedGuiBitmapTextAll`.
- `attachGuiBitmapTextOutlineList` stores the clone array on the main BitmapText via `setData(BENNE_GUI_BITMAP_TEXT_OUTLINE_KEY, ...)`.
- `syncOutlinedGuiBitmapTextAll(main, text)` (called by `GuiRuntime` whenever speaking-text / verb-line content changes) calls `setText` on main and each clone, then re-applies fill tints from the stored data keys so colours survive text updates.
- `syncOutlinedGuiBitmapTextPositions(main)` re-anchors clones after the main label moves (e.g. Speaking Text bottom-centre repositioning).

**WebGL tinting**

With **`Phaser.WEBGL`**, Phaser’s Tint component applies to `BitmapText`. **`applyGuiBitmapTextFillTint`** sets `setTint(tint)` + `setTintMode(Phaser.TintModes.FILL)` + explicit corner assignment, and stores the tint in `BENNE_GUI_BITMAP_TEXT_FILL_TINT_KEY` / `BENNE_GUI_OUTLINE_FILL_TINT_KEY` so `syncOutlinedGuiBitmapTextAll` can re-apply after `setText`. Outline clones are separate `BitmapText` instances offset by whole pixels (no Canvas pre-tinted atlas or prototype patch).

### GUI interactive controls

- **`checkbox`**: a sheet-backed toggle built by `buildGuiCheckbox`. `tag` is the unchecked clip; `states.uncheckedHover`, `checked`, `checkedHover`, `disabled`, and `disabledChecked` supply the remaining chrome. Pointer toggles emit **`gui:<guiId>:checkbox:<id>:check|uncheck`**. The Inspector scaffolds the `onChange` handler.

### Prop parallax

Room props may set **`parallaxDepth`** (`RoomPropInstance` in `src/types/room.ts`). Each frame, `RoomScene.updateParallaxProps` blends the prop’s authored position with the **top-left of the camera’s visible world rectangle** (`camera.worldView`), not raw `scrollX` / `scrollY` (those diverge from the visible corner when zoom ≠ 1, which breaks editor navigate mode):

```
worldX = parallaxDepth * baseX + (1 − parallaxDepth) * camera.worldView.x
worldY = parallaxDepth * baseY + (1 − parallaxDepth) * camera.worldView.y
```

(`baseX` / `baseY` are the prop’s authored `x` / `y` in room space.)

| `parallaxDepth` | Effect |
|-----------------|--------|
| `0` | Sprite position tracks camera scroll origin (moves fully with the camera). |
| `0–1` | Distant; moves slower than the camera. |
| `1` | No parallax (default if the field is omitted); world-fixed at authored position. |
| `>1` | Foreground; moves faster than the camera. |

**Example** — distant layer at half camera coupling:
```json
"parallaxDepth": 0.5
```

**Performance**: Props with `parallaxDepth === 1` or no `parallaxDepth` are not added to the parallax update list. The scene’s `update()` skips work when that list is empty.

### Input system

- **Custom pointer** (optional `game-config.json` **`cursor`**): when **`cursor.display.aseprite`** is **`true`** and `src/game/assets/images/cursor/cursor.{png,json}` are bundled, **`BootScene`** loads the sheet as **`aseprite:cursor`**; **`RoomScene`** hides the OS cursor, draws a screen-fixed **`Sprite`** that follows the pointer, and swaps clips named by **`idleAnimation`** vs **`activeAnimation`** (Aseprite frame tags / Phaser animation keys). Optional **`cursor.animations`** uses the same per-tag shape as **`CharacterData.animations`** (`loop`, `frameDuration`, `events`); **`applyCharacterAnimationClips`** applies it after **`createFromAseprite`**. Optional **`cursor.hotspot`** picks where the logical pointer tip sits on the art (**`top-left`** through **`bottom-right`** as Phaser `setOrigin` fractions, or **`custom`** with required **`cursor.hotspotPixel`** **`{ x, y }`** from the sprite’s top-left). Hover uses Phaser **`hitTestPointer`** over props (clickable colliders only), **`benneHotspot`** zones, clickable characters, GUI **`button`** hit targets (`buildGuiOverlay` sets **`benneGuiButton`** on button hit targets), and **occupied** GUI **`inventoryPanel`** slot containers (**`benneInventorySlot`** — same “active” cursor clip as over other clickables). The VS Code **room preview** queues the same asset via **`buildPreviewManifest`** (`queueGameCursorLoad`). Cursor clip priority is: (1) an armed inventory item's valid `cursorAnimation`; (2) the sorted hovered room target's optional **`activeCursorOverride`** on a hotspot, clickable prop, or clickable character; (3) global `cursor.activeAnimation`; otherwise `cursor.idleAnimation`. Per-target overrides name tags on the game cursor atlas, apply only to room targets (not GUI buttons or inventory rows), and fall back to `activeAnimation` with a once-per-tag DEV warning when invalid. The Inspector exposes the override only while the target is hit-testable.
- **Walk**: **Left click** on empty space (no hit-test targets) moves the **player** character toward the click. **Right click** on empty space clears the runtime active verb (see **Verb system → Active verb** below). Clicks outside the mesh are **clamped** into **walkable regions** (`walkable.ts` — each **`WalkablePolygon`** is an outer ring minus optional **active** hole rings; union across polygons; point-in-polygon + closest-point clamping). Characters then **pathfind** around holes and concave parts of the mesh via `src/engine/pathfinding.ts` (see **Pathfinding** below).
- **Clickable targets** (props / hotspots / characters): **`pointerdown`** resolves through **`resolvePointerVerbForTarget`** (`src/engine/verbs/resolvePointerVerb.ts`) which considers the current **active verb** (runtime state on **`GameStateManager`**), the target's authored **`defaultVerb`**, and the effective **`inputProfile`**. Outcomes: dispatch a verb; walk to the target's stand point (when a slot resolves to the built-in `walkTo`); clear the active verb (right-click while one is set); or no-op. **Props** still dispatch immediately (no engine walk-to-before-verb). **Hotspots** use closed **`points`** polygons (≥3 vertices); optional **`onVerbFallback`** on the hotspot (and prop) JSON gates object-level fallback dispatch; per-verb handling is whatever **`*.room.ts`** registers on the **`EventBus`**. **Clickable characters** use a **polygon hit area** when **`CharacterData.collider.points`** has at least three vertices (coordinates in **sprite frame space**, origin top-left of the cel, consistent with **`feet`**); otherwise the **full sprite rectangle** is interactive.
- **GUI `inventoryPanel` (occupied slots)**: **`buildGuiOverlay`** gives each **filled** slot row a **`pointerdown`** handler that runs **`resolvePointerVerbForInventoryItem`** (`resolvePointerVerb.ts`), then **`dispatchInventoryVerbInteraction`** (`src/engine/verbs/dispatchInventoryVerb.ts`), which runs the item's handler for that verb (room-scoped, then the item script's) or, when there is none, arms **`activeInventoryItemId`** for an item verb (**`usesItem`**) and sends any other verb to the global fallbacks. BenneScript item handlers for an item verb arm the item after the handler (unless registered with **`.doNotActivate`**). **Active verb** and **left / right → `inputProfile`** match props/hotspots/characters, except (1) profile **`walkTo`** cannot mean “walk to a stand point” for a bag row — it is treated like **`defaultVerb`** on that item (**`InventoryItemData.defaultVerb`**, fallback **`look`**), and (2) when **`activeInventoryItemId`** is set, **`resolvePointerVerbForInventoryItem`** forces **`consumeActive: false`** on **`verb`** resolutions so the verb bar stays selected for **inventory-on-inventory** / **use-on-target** (**`shouldDispatchInventoryUsedOnVerbForGame`**); with **no** armed item, **`consumeActive`** matches **`resolvePointerVerbForTarget`**, and **`buildGuiOverlay`** **defers** **`clearActiveVerb`** with **`queueMicrotask`**: it **skips** the clear when **`activeInventoryItemId ===`** the clicked row (arming for combine / use-on-target by the engine, by an item handler, or by a script setting **`pointer.item`**), otherwise clears like a room click. **`RoomScene`** supplies **`inventoryPanelPointerContext`** (current **`roomId`**, scripted-dialog suppression, dialog click-to-skip) on every in-game GUI overlay build; the VS Code **GUI preview** omits it, so preview inventory slots stay non-interactive and clicks still pass through like other non-button controls.
- **Context menu** disabled on mouse in `RoomScene`.

### Verb system

- **Config** (`src/game/game-config.json`, types **`src/types/game.ts`**): optional **`verbs`** (`{ id, label?, preposition? }` each — **`preposition`** is a short connector for composed verb + object UI, e.g. “Look **at** …”), optional **`inputProfile`** (flat **`primaryButtonVerb`** / **`secondaryButtonVerb`** — no `kind` field), optional **`defaultFallbackLine`** (used for **`verb:unhandled`**).
- **`inputProfile` slot grammar** — each slot accepts **any configured verb id** from **`verbs[]`**, or one of two reserved literal tokens:
  - **`"walkTo"`** — built-in universal walk verb (`WALK_TO_VERB_ID` in `verbs/verbConfig.ts`). Never authored in **`verbs[]`**, never shown as a verb chip in the Inspector. When a slot resolves to `walkTo` on a **room** clickable target, the engine walks the player to the target's stand point (prop `walkToPoint` / collider-closest / frame-center; hotspot `walkToPoint` / centroid; character `walkToPoint` / feet) — no verb dispatch for that click. On a **GUI `inventoryPanel`** occupied slot, there is no stand point: resolution uses **`resolvePointerVerbForInventoryItem`**, which substitutes the row item's **`defaultVerb`** (fallback **`look`**) and dispatches that verb. Empty-space clicks always walk, independent of slot configuration.
  - **`"defaultVerb"`** — substitute with the clicked target's authored **`defaultVerb`** field (per-prop / hotspot / character / inventory item). Falls back to **`"look"`** when the target omits the field. Shown in the Inspector as a "Default verb" dropdown on each clickable card (built from **`game-config.json`** `verbs`).
- **Defaults**: Omitting **`verbs`** implies ids **`look`** and **`use`**. Omitting **`inputProfile`** defaults to **left → `look`**, **right → `use`**. Typical 9-verb wiring: `primaryButtonVerb: "walkTo"`, `secondaryButtonVerb: "defaultVerb"` (paired with a verb GUI whose buttons call `verbs.x.select()`). The game-level **`defaultVerb`** (default: `look` when the game has it, else the first verb) stands in for a clickable without its own **`defaultVerb`**; **`usesItem`** (default: true when the verb has a `preposition`) marks the verbs that use an inventory item on a target (**`isItemVerb`**, **`resolveGameDefaultVerbId`**, **`resolveDefaultItemVerbId`** in **`verbConfig.ts`**).
- **Active verb** (runtime UI state on **`GameStateManager`**, not persisted in snapshots): a script-settable verb id that overrides the pointer resolution on the **next** target click.
  - **BenneScript**: **`pointer.verb`** reads the armed verb as a `verbs.x` handle; setting it (`pointer.verb = verbs.look`, or `null`) arms or clears it, as does **`verbs.x.select()`**. **`pointer.item`** does the same for the armed inventory item.
  - **Resolution rules — room clickables** (`resolvePointerVerbForTarget`):
    - Clickable + **left** click + active verb set → dispatch the active verb on the target; **clear** the active verb ( **`consumeActive`** ).
    - Clickable + **right** click + active verb set → clear the active verb (no dispatch).
    - Clickable + any button + no active verb → resolve the matching `inputProfile` slot (`walkTo` / `defaultVerb` / plain verb id).
    - Empty space + **right** click → clear the active verb (no dispatch, no walk).
  - **Resolution rules — GUI `inventoryPanel` rows** (`resolvePointerVerbForInventoryItem`): same active-verb / **`inputProfile`** / right-click clear semantics as above, plus **`walkTo` → item `defaultVerb` / `look`**. With **no** **`activeInventoryItemId`**, a left-click **`verb`** dispatch uses the same **`consumeActive`** as room clickables; **`buildGuiOverlay`** may clear the active verb on a **microtask** after dispatch unless the clicked row became **`activeInventoryItemId`** (any verb that arms that row: the engine's arming for an item verb without a handler, a BenneScript item handler's arming afterwards, or a script setting **`pointer.item`**). When an item **is** armed, **`consumeActive`** is forced to **`false`** on **`verb`** resolutions so the selection stays for combine / use-on-target. Every item verb (**`usesItem`**) on a row arms **`activeInventoryItemId`**: at once when the item has no handler for that verb, else after its BenneScript handler finishes (`items.x.onUse(…)` adds code **in addition**). **`items.x.onUse.doNotActivate(…)`** registers a handler that does not arm. See **Inventory System → BenneScript**.
  - Event **`gameState:activeVerbChanged`** (`GAME_STATE_ACTIVE_VERB_CHANGED_EVENT`) fires on every change; handy for cursor / button-highlight wiring. **`applySnapshot`** also clears the active verb so loading a save never leaves a stray verb selected.
- **Per-object data**: **`RoomPropInstance`** and **`RoomHotspotData`** carry optional **`onVerbFallback`** (and **`defaultVerb`**) only; **`InventoryItemData`** may carry optional **`onVerb`** (verb id → **`true`**, authoring) plus **`onVerbFallback`**. **`CharacterData`** mirrors props/hotspots (no **`onVerb`**); optional **`onVerbFallback`** and **`defaultVerb`** behave like other clickables. **`defaultVerb`** controls what the `"defaultVerb"` slot substitutes in (omit to fall back to `"look"`); the Inspector shows it as a dropdown on each clickable card (the room-character card surfaces it read-only — edit from the character's own Inspector).
- **Dispatch** (`src/engine/verbs/dispatchVerb.ts`): **Before** emitting, **`interruptPlayerWalkForVerbInteraction`** runs (see **Game state → Active `Phaser.Game` handle**): if **`RoomScene`** is the active Phaser scene, **`RoomScene.interruptPlayerWalk()`** stops any in-progress **player** path tween, clears the live path / arrive callback, returns the player to **Idle**, and emits **`player:walk:stop`** (`PLAYER_WALK_STOP` in **`playerWalkEvents.ts`**) with **`reason: 'interrupted'`**. The same interrupt runs at the start of **`dispatchInventoryOnVerbTargetInteraction`**, **`dispatchInventoryOnInventoryItemInteraction`**, and **`dispatchInventoryVerbInteraction`** so inventory-on-world and **`inventoryPanel`** row verbs behave consistently. Superseding a walk by **starting another walk** still stops the prior tween inside **`RoomScene.movePlayerToward`**; this hook covers the case where the next interaction is **not** a new walk (e.g. **look** while crossing the room). **`RoomScene.tryBeginPropLook`** goes through **`dispatchVerbInteraction`**, so it participates in the same interrupt. **Emit order (listener-first)**: for **props** and **hotspots**, emit **`verb:room:<roomId>:<targetType>:<targetId>:<verbId>`** only when that channel has listeners; otherwise continue. For **characters**, try **`verb:room:<roomId>:character:<characterId>:<verbId>`** then **`verb:character:<characterId>:<verbId>`** the same way. If **`onVerbFallback`** is enabled on the target, try room-scoped then character-global fallback events **only when those channels have listeners**. Then **`verb:global:<verbId>`** (if listeners) → **`verb:global:fallback`** (if listeners) → **`verb:unhandled`**. In **Vite dev**, unhandled verbs also **`console.warn`**.
- **Payloads** (`propInteractionEvents.ts`): **`RoomPropInteractPayload`**, **`RoomHotspotInteractPayload`**, and **`CharacterVerbInteractPayload`** carry **`verbId`** and target ids; props also expose optional **`walkToPoint`** / **`lookAtPoint`** (room pixels). Characters may include optional **world** **`walkToPoint`** / **`talkPoint`** when the matching fields exist in **`CharacterData`** (converted from frame offsets at click time). Object fallback emissions add **`verbFallback: true`**.

### GUI verb status line (BenneScript)

LucasArts-style copy (**Walk to**, **Push pillar**, **Use item with …**) is authored as a normal **`text`** control set from the GUI's script: **`pointer.onContextChange(refresh)`** (the persistent **`BENNE_VERB_CONTEXT_CHANGED_PERSISTENT_EVENT`**, so the handler survives room changes) and **`gui.onBuilt(refresh)`**, where `refresh` sets **`verbLineText.text = pointer.sentence`**, matching **`src/game/guis/verbs/verbs.gui.ts`**. **`pointer.sentence`** is the engine's **`composeVerbLineText`** (`verbConfig.ts`) over the armed verb, the armed item and the hover description, except while a clicked verb runs: the verb dispatchers record that action's line (**`verbs/actionSentence.ts`**), and it stays until no gameplay interaction is running (decision 57); **`resolveVerbLineDisplayLabel`** and **`resolveVerbLineLeadingVerbWord`** remain available for a custom line.

**Hover context for `pointer.hover`** — **`RoomScene`** walks Phaser **`hitTestPointer`** (sorted like dispatch) each **`pointermove`** and after **`gameState:inventoryChanged`**, skips GUI **`button`** hits, and publishes the short label plus a structured hover target (including optional authored **`defaultVerb`** when non-empty) through **`publishBenneVerbHoverContext`** (props/hotspots/clickable characters/occupied **`inventoryPanel`** rows). Scripts read it as **`pointer.hover`** (`{ kind, id, description, defaultVerb }`, with `defaultVerb` a `verbs.x` handle). During **scripted dialog** input suppression (the speech-line lock), the hover description is cleared so HUD lines do not advertise room targets behind a blocking line.

### Character feet (walk / camera)

Optional **`feet`** on **`CharacterData`** (`src/types/character.ts`): **`{ "x", "y" }`** in **frame pixel space** from the cel’s **top-left** to the ground contact. The runtime places Aseprite sprites with **`origin (0,0)`** and offsets position so room spawn **`(x, y)`** is where the feet stand; walk tweens and camera follow use the same point. If **`feet`** is omitted, the engine uses the **bottom-centre** of the **current** frame (works best when cels share a consistent size). The VS Code **BENNE Character preview** webview (`npm run build:character-preview`) plays a default idle (prefers **`IdleD`**, then other **`Idle*`** tags), shows **Feet**, **Walk to**, and **Talk** handles plus the collider on one overlay, and **Save to JSON** writes **`feet`**, **`walkToPoint`**, **`talkPoint`**, and **`collider`** together via **`characterGeometryPatch.ts`**. In the preview, **Feet** and **collider** vertices are clamped to the cel; **Walk to** and **Talk** may be placed outside the sprite bounds (camera bounds grow to include them).

Optional **`walkToPoint`** on **`CharacterData`**: same **frame space** as **`feet`**; world stand = sprite position + offset. Used when **`RoomScene`** resolves script **`walkTo('<characterId>')`** to that character. If omitted, resolution uses the character’s **world feet** (same effective stand as when **`walkToPoint`** matches **`feet`**).

Optional **`talkPoint`** on **`CharacterData`**: same **frame space**; a script-facing **look / dialogue** hint. Verb payloads include **world** **`talkPoint`** when the field is set (like prop **`lookAtPoint`**, but stored per character in frame space).

**Click collider (authoring)** — Optional **`collider: { "points": [ { "x", "y" }, … ] }`** on **`CharacterData`**, same **frame space** as **`feet`**. The preview reuses **`PreviewPolygonOverlay`** with the same vertex / edge / Delete gestures as prop colliders; fewer than three points on save **removes** **`collider`** so the engine falls back to the full-sprite hit test. Verbs and scaffolding use **`CharacterVerbInteractPayload`** from **`propInteractionEvents.ts`**; **Create Character** and verb-handler insertion ensure that **import** is present in new **`*.character.ts`** files.

### Room regions (perspective character scale)

**Data** — **`regions`** on **`RoomData`** (`src/types/room.ts`, **`RoomRegionData`**): each entry is a closed **`points`** polygon in **room pixels** (same space as walkables and hotspots), with optional **`active`** (omit or non-**`false`** = used). Optional **`scaleEnabled`** (omit or not **`true`** = this region does not scale). When **`scaleEnabled`** is **`true`**, optional **`scaleTop`** and **`scaleBottom`** default to **`1`** (normal sprite size). **Top** means the **smaller** room **Y** (upper on screen); **bottom** means the **larger** **Y**. The runtime takes the axis-aligned **vertical span** of the polygon’s vertices (**min Y** … **max Y**) and linearly blends **`scaleTop` → `scaleBottom`** as the character’s **feet Y** moves down that span while the feet remain **inside** the polygon. Optional **`scaleWalkSpeed`** (default **`false`**) on that **scale winner**: when **`true`**, the character’s **authored walk speed** is multiplied each frame by **`max(minWalkScale, pow(linearScale, walkScalePower))`**, where **`linearScale`** is that same vertical blend (and **`minWalkScale` / `walkScalePower`** come from **`game-config.json`** — see **`perspective`** below). Optional **`tintEnabled`** (omit or not **`true`** = this region does not tint). When **`tintEnabled`** is **`true`**, optional **`tint`** (**`#rrggbb`**) and **`tintAlpha`** (**0–1**, default **`1`**) multiply-tint spawned character sprites while feet stay inside (applied by **`RoomScene.applyFeetWorldWithRegionScale`**). A missing or invalid hex, or **`tintAlpha`** **`0`**, clears tint for that tint winner.

**Runtime** — **`computeRoomRegionPerspective(feetX, feetY, regions, perspectiveSettings)`** (`src/engine/room/regionCharacterScale.ts`) walks **`regions`** in array order. Each active polygon with ≥3 points that contains the feet becomes **`winningRegion`** (last match — enter/exit only). Scale and tint are separate: only a region with **`scaleEnabled: true`** updates **`characterScale`** and, if that region’s **`scaleWalkSpeed`** is **`true`**, **`walkSpeedMultiplier`**; only a region with **`tintEnabled: true`** becomes **`tintRegion`**. A later region with the feature off does not reset an earlier scale or tint. If no containing region has scale enabled, **`characterScale`** and **`walkSpeedMultiplier`** stay **`1`**. If none has tint enabled, **`tintRegion`** is **`null`** (no tint). **`computeRoomRegionCharacterScale`** remains a thin wrapper that returns only **`characterScale`**. **`resolveWinningRoomRegionIdAtFeet`** / **`resolveWinningRoomRegionDataAtFeet`** return the enter/exit winner’s **`id`** or data (**`null`** outside) — shared by **`RoomScene.syncCharacterRegionEnterExit`** for **`regions.x.onEnter` / `onExit`**, and independent of **`scaleEnabled`** / **`tintEnabled`**. **`RoomScene`** applies **`characterScale`** and **region character tint** (via **`packedTintFromWinningRegion`** on **`tintRegion`**) inside **`applyFeetWorldWithRegionScale`**: on spawn, on idle **`update`** (characters not in a walk tween), and along **walk legs** (interpolated feet). **Walk legs** advance **`u`** with **`u += (walkSpeed * walkSpeedMultiplier * dt) / legLength`**, then place feet and recompute scale + tint.

**Rendering (crisp downscale on screen)** — The **`characterScale`** math above drives **`sprite.setScale`**. How scaled character **sprites** stay **blocky / sharp** in the WebGL pipeline (custom quad batch, **`inPerspMag`**, texel bucketing while **`mag`** drifts) is separate; see **§3 → Rendering system → Perspective-scaled character batch** and **`src/engine/rendering/benneCharacterPerspectiveBatch.ts`**.

**Enter / exit hooks (BenneScript)** — Room scripts only: **`regions.x.onEnter((who) => …)`** / **`onExit`**, where `who` is the room module's handle for the character (so `who === hank` works; `who.isPlayer` tells the player apart). Region handlers are gameplay handlers: they take the interaction lock, so one that only sends an NPC somewhere uses `jensen.walkTo.now(…)`. After idle region scale/tint synchronization, the scene compares winning region ids every frame for all spawned characters, including mid-walk feet positions. The first frame after `create` seeds membership without emitting; when overlap priority changes, exit for the old winner emits before enter for the new winner. **`RegionEnterExitContext`** carries `roomId`, `regionId`, `characterId`, `isPlayer`, `feetX`, and `feetY`. Region handlers are not automatically cutscenes; wrap work in **`cutscene(…)`** when world clicks should be ignored throughout.

**Game config** — **`GameSettings.perspective`** (`src/types/game.ts`): optional **`minWalkScale`** (default **`0.3`**) and **`walkScalePower`** (default **`0.8`**). Merged by **`getPerspectiveSettings()`** in **`ConfigManager.ts`** (validated at load when the block is present).

**Feet / camera** — **`characterFeet.ts`** treats world feet as **`sprite.x + feetLocalX * scaleX`** (and **Y**), and **`placeSpriteByFeet`** backs out the same when positioning the top-left origin. The module-level **`getFeetFollowOffset`** used for **`cameras.main.startFollow`** scales the offset so follow still targets the feet when **`scale` ≠ 1**.

**Authoring** — **Add Region** (**`runAddRoomRegionWizard`**) still scaffolds a default square; edit the polygon in the **room preview** (**region polygon** mode). New regions omit **`scaleEnabled`** and **`tintEnabled`**, so both Inspector checkboxes start unchecked. In the **Inspector**, region cards expose **Scale** (checkbox, patch **`regionScaleEnabled`**, **`updateRegionScaleEnabled`**; checked writes **`true`**, unchecked deletes the key), **Scale top** / **Scale bottom** (patch **`regionScale`**, **`updateRegionScaleFields`**), **Scale walk speed** (checkbox, patch **`regionScaleWalkSpeed`**, **`updateRegionScaleWalkSpeed`**), **Tint** (checkbox, patch **`regionTintEnabled`**, **`updateRegionTintEnabled`**; same write/delete pattern), **Character tint** / **Tint alpha** (patch **`regionTint`**, **`updateRegionTintFields`**), or hand-edit **`*.room.json`**. The numeric and color fields stay editable while the feature checkboxes are off. Rebuild **`benne-editor/media/inspector/inspector.js`** after Inspector TS changes (**`npm run compile`** or **`npm run watch`** under **`benne-editor/`**).

**Limits (v1)** — Mapping is by the polygon’s **bounding Y extent**, not a custom “depth” axis through the floor. **`flipX`** on characters is separate from **`setScale`** (no negative scale for mirroring).

### Character directional animation (facing)

Directional clips use **Aseprite frame-tag names** built as **`<base><facing>`** (e.g. `IdleL`, `WalkDR`, `TalkUL`). Implementation lives in **`src/engine/directionalCharacterAnimation.ts`**; types for room JSON use **`CharacterFacingLetter`** in **`src/types/character.ts`**.

**Facings (eight-way)** — left, right, up, down, and diagonals: **`L`**, **`R`**, **`U`**, **`D`**, **`UL`**, **`UR`**, **`DL`**, **`DR`**. World space matches the rest of the engine (**y increases downward** on screen).

**Choosing facing from movement** — **`facingFromWorldDelta(dx, dy)`** normalizes the walk (or look) vector and picks the facing whose **unit direction** has the **largest dot product** with that vector, so purely horizontal or vertical motion maps to a **cardinal** (e.g. straight down → **`D`**), and diagonal motion maps to a **diagonal** when both components matter. A **zero** delta defaults to **`D`**.

**Playing a clip when some facings are missing** — **`playDirectionalAnimation(sprite, baseName, facing)`** first tries **`${baseName}${facing}`**. If that Phaser animation does not exist (or has no frames), it walks **other facings in order of smallest angular distance** from the requested facing, and for each candidate tries:

1. The **unflipped** tag for that facing.
2. If a **horizontal mirror partner** exists — **`L`↔`R`**, **`UL`↔`UR`**, **`DL`↔`DR`** — the partner’s tag with **`flipX`**, so a character can ship only **`WalkDL`** and still satisfy a **`DR`** request. **`U`** and **`D`** have **no** mirror pair in this scheme.

The sprite’s **`facing`** data stores the **logical** facing the gameplay asked for (walk end, look-at, spawn), not necessarily the suffix of the clip that ended up playing.

**Spawn and idle defaults** — **`resolveSpawnIdleFacing`** honors **`initialFacing`** on room character instances when it is one of the eight letters; otherwise it falls back like **`resolveInitialIdleFacing`**, which prefers an existing **`Idle*`** in a default order (**cardinals** `R`, `D`, `L`, `U`, then **diagonals** `DR`, `DL`, `UR`, `UL`), and finally **`D`** if nothing matches.

**RoomScene** uses this for **player walk**, **idle after walk**, and **NPC spawn** animation bases (`Idle`, `Walk`, etc.).

### Scripting / interaction system

- **Canonical scoped event ids** are emitted by **`dispatchVerbInteraction`** (`src/engine/verbs/dispatchVerb.ts`) from runtime target context; JSON stores no event-id strings. Props/hotspots/room-scoped characters use `verb:room:...`, character-global uses `verb:character:...`, then `verb:global:<verbId>` → `verb:global:fallback` → `verb:unhandled`. An **in-progress** player walk from empty space or **`walkTo`** resolution is **cancelled** when a verb dispatches; see **Verb system → Dispatch** and **Game state → Active `Phaser.Game` handle**.
- **BenneScript** (§7) subscribes to those channels. Room script modules load lazily per room (**`ensureRoomScriptLoaded`**, `scenes/roomScriptModules.ts`, awaited in **`BootScene`** and in **`RoomTransitionOrchestrator`** alongside the asset loader); their top-level registrations fill that room's handler table, which **`RoomScene.create`** attaches and room leave detaches. Character, inventory, dialog, GUI and global scripts load at startup (**`registerGameContent`**) and register once on the global channels.
- **Payloads**: Typed payloads for prop interaction (`propInteractionEvents.ts`), player walk start/stop, region enter/exit, inventory-on-target, etc. BenneScript handlers don't see them: the runtime turns them into the clicked target (`walkToClicked()`), the item (`onAnyItem((item) => …)`) or the character (`regions.x.onEnter((who) => …)`).
- **Movement: walk vs teleport**: **`player.walkTo(target)`** and **`jensen.walkTo(target)`** (and **`.now`**) use **`RoomScene`** pathfinding + **Walk** animation to a resolved room-space point, **unless** **`movable`** is **`false`** for that walker (**`CharacterData.movable`** / **`jensen.movable`**), in which case the walk is a **no-op** (see **§7 → Persistence**). **`moveTo`** does **not** pathfind: it calls **`movePlayerToNow` / `moveCharacterToNow`** (feet **teleport** with walkable **clamp** and **Idle** facing) and is **not** gated by **`movable`**. A target is a handle (`points.x`, a prop, hotspot or character), a string id or a **`Point2`**; string and handle targets resolve in this order: **prop** in the room → **hotspot** → **character** → **`room.points`**. Props use **`walkToPoint`**, else the closest point in/on the **collider** to the walker, else the prop frame **center**; hotspots use **`walkToPoint`** or polygon **centroid**; characters use **`CharacterData.walkToPoint`** or **feet** world position. Public **`RoomScene.resolveMovementTarget(target, walkerFeet)`** returns the room-space feet goal. Unknown ids **`console.warn`** once per id and fall back to the walker’s current feet.
- **NPC track-facing**: **`henry.startFacing(target?, { minWait, maxWait })`** / **`stopFacing()`** (`RoomScene.startCharacterFacingCharacter`). The observer's Idle facing re-aims toward the target's world feet (the player by default) after a uniform random delay (defaults **0.2–0.4 seconds**) when either character moves; continued movement postpones the turn until motion settles. Locks are per-room runtime state, are not saved, and update logical facing without replacing an active animation override.
- **Character follow (persisted)**: **`jensen.startFollowing(target?, options?)`** / **`stopFollowing()`** and the **`player`** equivalents persist the target plus merged `CharacterFollowOptions` (`minDistance`, `repathThreshold`, facing-relative `offset`, `speedMultiplier`, `faceTargetWhenIdle`, `pauseDuringCutscene`); **`isFollowing`** / **`followingTarget`** read it back. The live driver runs only while both sprites are in the same room and normally pauses new walks during input-suppressed cutscenes. The saved target `"player"` resolves to the active player. Stopping clears state and interrupts only follow-initiated movement.
- **Verb handlers** are generated per configured verb (`door.onLook(…)`, `battery.onClean(…)`; §7 and §8 of the design doc) on **prop**, **hotspot** and **character** handles; one target id belongs to one kind, so there is no string-id resolution. Armed-inventory use on props, hotspots or characters goes through **`on<Verb>Item(item, …)`**, **`onItem`** and **`onAnyItem`** on the same handles.
- **Regions**: **`regions.x.onEnter` / `onExit`** (room JSON **`regions[].id`**); see **Room regions → Enter / exit hooks** above. **`gameEvents`** ids **`roomRegionEnterEventId` / `roomRegionExitEventId`**.
- **Hotspots**: **`battery.active`** persists under `room:<roomId>:hotspot:<hotspotId>:active` and mounts/destroys the live polygon zone so inactive hotspots are not hit-tested; **`clickable`** is an alias. **`battery.description`** is the hover / verb-line label; persists under `room:<roomId>:hotspot:<hotspotId>:description`.
- **Walkable polygons**: **`walkables.x.active`**, room JSON **`walkable.polygons[].id`** only. Persists under `` `room:<roomId>:walkable:<walkableId>:active` `` and writes the live polygon’s **`active`** so walk tests, clamping, and pathfinding ignore that polygon (and its holes) without a room reload. A walk already in progress keeps its current path. JSON **`active: false`** is the authoring default; the saved override is re-applied in **`RoomScene.create`**. Hole rings are not separate script handles: toggle the owning polygon, or set **`holes[].active`** in JSON.
- **Speech**: `Hank: "…"` labels (resolved to a character id at build time), `` say`…` `` blocks and `jensen.say(…)` all end in **`sayTask`** (`bennescript/actions.ts`), which drives the Speaking Text overlay through **`RoomScene`**. **`Player`** in any case maps to `GameStateManager.activePlayerCharacterId`. Block lines are **`Speaker: text`**; blank lines and `//` comments are skipped. A leading **`|number|`** voice id is removed from visible text and resolves the voice stem described under **Audio system**. Line timing, click-to-skip, `showText`, and `defaultTalkOffset` use **`readEffectiveSpeechSettings(manager)`** (`settings.speech.*` in scripts). Without an active `RoomScene`, speech warns once in DEV and does nothing.
- **Boundary**: Scenes should not embed game-specific puzzle logic; they **emit** and **listen** only through agreed event names and small shared types.

### Asset management / loading

- **Room & character JSON** for Aseprite: **eager globs** in `loadAsepriteAtlasData.ts` (and friends); **normalized** for Phaser frame indices (`normalizeAsepriteJson.ts`).
- **Binary assets**: **`resolveGameAssetUrl` / `resolveGameAssetJsonUrl` / `resolveGameAssetXmlUrl`** map paths under `src/game/assets/**` to **Vite-built URLs** (images, JSON, BMFont XML for GUI bitmap fonts). **Audio** uses additional globs on **`./assets/audio/sfx/**`**, **`./assets/audio/music/**`**, and **`./assets/audio/voice/**`** (.mp3 / .ogg / .wav / .m4a); **`getBenneAudioBootEntries()`** groups stems + URLs for **`queueBenneAudioForBootLoader`** (Phaser **`load.audio`** keys **`benne:sfx:<stem>`** / **`benne:music:<stem>`** / **`benne:voice:<stem>`** via **`benneAudioCacheKeys.ts`**).
- **Boot-time loading only** in `BootScene` (Phaser loader); **no streaming** or mid-room asset packs yet.

### Audio system

**Goals**

- **`Phaser.Game#sound` only** (`SoundManager` never uses `scene.sound`) so playback survives **`RoomScene`** teardown — **music** can continue across room changes (**`rooms.x.goTo()`**) without restarting.
- **Volumes**: **`applyBootAudioSettings`** (**`BootScene`**) sets the Phaser sound manager cap from **`game-config.json`** **`audio.masterVolume`**. Per-call playback multiplies **`getEffectiveSfxVolume`** / **`getEffectiveMusicVolume`** (**`applyAudioFromSettings.ts`**) with optional **`SoundPlayOptions.volume`** / **`MusicPlayOptions.volume`** (0–1) and with **`SoundManager`** session multipliers set by **`settings.sfxVolume`** / **`settings.musicVolume`** (persisted under **`settings:sfxVolume`** / **`settings:musicVolume`** in save snapshots via **`audioGameState.ts`**; **`applyPersistedAudioSessionVolumes`** on boot and **`GAME_STATE_REPLACED`**; **`applySnapshot`** preserves those keys when an incoming snapshot omits them unless **`initialGameState.variables`** seeds them). **Current music track** — **`settings:currentMusicId`** (stem or cleared on **`stopMusic`**); **`applyPersistedMusicTrack`** on boot and **`GAME_STATE_REPLACED`**; same merge/preserve rules via **`mergePreserveAudioVolumeVariables`** ( **`PERSISTED_AUDIO_STATE_VARIABLE_KEYS`** ). Playback position is **not** persisted. **Dialog prefs** use the same snapshot path for **`dialog:*`** variables via **`dialogGameState.ts`** (see **§3 → Dialog system**).

**Asset discovery**

- **`registerGameContent`** does **not** glob audio; **`resolveGameAssetUrl.ts`** holds **`import.meta.glob`** tables for **`assets/audio/sfx/**`**, **`assets/audio/music/**`**, and **`assets/audio/voice/**`**. **`getBenneAudioBootEntries()`** returns one boot row per **stem** (filename without extension); multiple formats for the same stem become a **fallback URL array** for **`load.audio`**.
- **`queueBenneAudioForBootLoader`** runs from **`BootScene.create`** only when **`game.registry`** **`benneAudioScriptDisabled`** is **not** `true` (VS Code **room / GUI / inventory / character** previews set **`benneAudioScriptDisabled`** in **`Phaser.Game` `callbacks.preBoot`**).

**Runtime**

- **`SoundManager`** (**`src/engine/sound/SoundManager.ts`**) — **`playSfx` / `playSfxAndWait`**, **`playMusic`** (instant replace by default; optional **`fadeSeconds`** crossfade with **`sync`** alignment), **`stopSfx`**, **`stopAllSfx`**, **`stopMusic`**, **`destroy`**. **SFX** instances are tracked until **`complete`** / **`destroy`** or **`stop`**; **`playAndWait`** resolves when the sound finishes or is stopped.
- **Registry** — **`benneSoundRegistry.ts`**: **`BENNE_SOUND_MANAGER_KEY`**, **`tryGetBenneSoundManager`**, **`setBenneSoundManager`**; **`BENNE_AUDIO_SCRIPT_DISABLED_KEY`** (**`benneAudioScriptDisabled`**).
- **`Game.ts`** — constructs **`SoundManager`** after **`new Phaser.Game`**, registers it, **`applyPersistedAudioSessionVolumes`** + **`applyPersistedMusicTrack`**, **`wireBenneAudioGameState`** ( **`GAME_STATE_REPLACED`** ), **`destroy()`** on **`Phaser.Core.Events.DESTROY`** and removes the registry entry.

**BenneScript**

- **BenneScript**: the generated **`sfx.<name>`** / **`music.<name>`** handles (**`SfxHandle`** / **`MusicHandle`** in `bennescript/handles.ts`) call **`SoundManager`** through **`tryGetBenneSoundManager`**. `@game` builds **`sfx`** with **`withSfxControls`** (`stopAll`) and **`music`** with **`withMusicControls`** (`stop`, `isPlaying`, `current`); the generator reserves those names.
- **`sfx.x.play()`** and **`music.x.play()`** start playback at that line and never wait (no `.now` needed). **`sfx.x.playAndWait()`** is a timed action over **`SoundManager.playSfxAndWait`** (`.now` starts it without waiting). During a skipped cutscene, one-shot sounds don't play and **`music.x.play()`** switches track without the crossfade.
- **Author ids**: **`^[a-zA-Z0-9_-]+$`** map to loader keys **`benne:sfx:id`** / **`benne:music:id`**.
- **Voiced `say` lines** use this same manager rather than a separate dialogue API. BenneScript's speech path (**`sayTask`**, `bennescript/actions.ts` → `bennescript/speech.ts`) recognizes a leading **`|number|`** marker in a line's text, removes it before logging/display, derives the stem **`<speakerId><number>`**, and plays `src/game/assets/audio/voice/<stem>.{mp3,ogg,wav,m4a}` at **`audio.dialogueVolume`**. The line's `Task` still owns the script waiting on it, `.now`, Speaking Text visibility, Talk/Idle animation, and click-to-skip; skipping or tearing down the line stops its retained voice instance.

**Lifecycle**

| Event | SFX | Music |
|-------|-----|--------|
| **`RoomTransitionOrchestrator.prepareForLeave`** | **`stopAllSfx()`** (also calls **`roomScene.flushRuntimeStateToGameState()`** first — see **§3 → Game state**) | unchanged |
| **`endDialogSessionIfMatches`** (**`dialogSession.ts`**) | **`stopAllSfx()`** after dialog **`dispose`** | unchanged |
| **`Phaser.Game` destroy** | **`SoundManager.destroy()`** stops all | stopped |

**Helpers**

- **`getEffectiveDialogueVolume`** combines the authored dialogue level with the active audio settings for voiced `say` playback.

### Video system

- **Ownership and loading**: cinematic playback is a single hidden Phaser `Video` plus black letterbox backdrop owned by `RoomScene`, not by a game-scoped manager. Videos live under **`src/game/assets/videos/<stem>.{mp4,webm}`**, and each stem becomes a generated **`video.<name>`** handle. `resolveGameAssetUrl.ts` discovers them, `getBenneVideoBootEntries` groups formats, and `BootScene` calls `queueBenneVideoForBootLoader`. Preview games set **`benneVideoScriptDisabled`** in `preBoot` so authoring surfaces never start cinematics.
- **Composition**: the video is screen-fixed at **`ROOM_VIDEO_LAYER_DEPTH = 24_000`**, above room art and below the GUI band. It is letterboxed to internal resolution, registered with the runtime/editor UI camera, and forced to `FilterMode.NEAREST` when playback starts. Speaking Text and Display Text remain above it. Other HUD overlays and the dialog choice band are snapshot-hidden for playback and restored independently of dialog visibility snapshots when playback ends, stops, or tears down.
- **BenneScript**: the generated **`video.<name>`** handles (**`VideoHandle`**) resolve the active `RoomScene`; missing-scene calls DEV-warn once. `video.x.play()` starts the video and the script goes on, so later speech, fades, and character actions can run over the movie; `video.x.playAndWait()` waits until end/stop. A room shows one video at a time, so `video.pause()`, `resume()`, `seek(s)`, `stop()`, `isPlaying` and `current` (**`withVideoControls`**) act on whichever plays. Completion invokes `options.onComplete` and emits **`benne:video:ended`**.
- **Input and lifecycle**: active video suppresses gameplay/GUI input and uses the cursor's busy state. Escape stops playback (or skips the enclosing cutscene when the video plays inside a skippable one); primary click/tap stops only when `clickToSkip` is true (default false). Room leave stops playback, scene shutdown destroys the objects, and video state is not saved. Volume is `audio.masterVolume × VideoPlayOptions.volume`.
- **VS Code codec caveat**: BENNE Play uses VS Code's webview browser, whose codec support differs from Chrome/Edge. MP4/H.264 with AAC may show frames but produce no sound. For editor testing, use a webview-supported audio codec (for example `ffmpeg -i Intro.mp4 -c:v copy -c:a libmp3lame -b:a 192k -movflags +faststart Intro-vscode.mp4`). When both MP4 and WebM exist, Phaser chooses one by container support and does not verify that the selected container's audio codec is decodable.

### Game state (v2)

- **Active `Phaser.Game` handle (engine bridge)** — not part of the saveable snapshot; complements **`game.registry`** + **`GameStateManager`** when APIs need the **game** or **active room scene** but only receive **`gameEvents`** (or other bus-only entry points). **`createBenneGame`** calls **`setActiveBenneGame(game)`** (`src/engine/gameState/activeBenneGame.ts`); the game’s **destroy** lifecycle clears it with **`setActiveBenneGame(null)`**. **`tryGetActiveBenneGame()`** returns **`null`** before boot or after destroy. **Primary use today**: **`interruptPlayerWalkForVerbInteraction`** (`src/engine/scenes/interruptPlayerWalkForVerbInteraction.ts`) resolves **`game.scene.getScene(SCENE_ROOM)`** (see **`SCENE_ROOM`** in **`src/engine/content/constants.ts`**) and, when that scene **`scene.isActive()`**, invokes **`RoomScene.interruptPlayerWalk()`** so verb and inventory-interaction dispatch does not run on top of an unfinished empty-space or **`walkTo`**-target move. **VS Code preview** bundles that build **`Phaser.Game`** without **`createBenneGame`** do not register this handle unless preview boot is updated — interrupt is then a no-op and preview walk + verb stacking may still occur.
- **`GameStateManager`** (`src/engine/gameState/GameStateManager.ts`): in-memory **flags** (`Record<string, boolean | number | string>`), **variables** (`Record<string, unknown>`), **`inventoryByCharacter`** (**`Record<string, Record<string, number>>`** — character definition id → item id → quantity), and **`activePlayerCharacterId`** (who **`inventory`** and default **`inventoryPanel`** rows target). Constructed in **`createBenneGame`** (`src/engine/Game.ts`) and stored on **`Phaser.Game.registry`** under **`benneGameState`** (`BENNE_GAME_STATE_REGISTRY_KEY`) so the same instance survives **`RoomScene`** teardown. **`getSnapshot` / `exportSnapshotJson`** emit **version 2** JSON. **`applySnapshot` / `importSnapshotJson`** accept **version 1** (flat **`inventory`** → starting player's bag) and **version 2**; v1 **`inventory`** arrays normalize to quantity maps (each id → **1**). **`getSnapshot()` runs `runSnapshotFlushHooks()` first** (unless `runFlushHooks: false`) so any **lazily-saved runtime state** (today: character feet positions and prop authoring positions on the active **`RoomScene`** — see **§7 → Sprite animation & persistence**) gets pulled into **`variables`** before the snapshot is cloned; this is what makes **`save`**, **`exportSnapshotJson`**, and **`saves.export()`** capture positions without extra wiring. **`applySnapshot`** (including **`saves.load(…)`**) emits **`gameState:replaced`** with **`getSnapshot({ runFlushHooks: false })`** so the still-active pre-load scene does not overwrite restored position variables with the player's current feet before **`transitionToLoadedRoom`** restarts the room. **Runtime dialog settings** (**`settings.dialog.*`**) use **`variables`** keys **`dialog:*`** (eight persisted prefs — see **`dialogGameState.ts`**); writes are **eager** (not flush hooks). **`applySnapshot`** merges **`dialog:*`** like **`settings:sfxVolume`** / **`settings:musicVolume`**: omitted incoming keys keep prior in-memory values unless **`initialGameState.variables`** seeded them. **BenneScript sprite animation** also uses **`variables`** for reserved keys (see **§7 → Sprite animation & persistence**): `` `room:<roomId>:prop:<propId>:animation` `` (base prop tag), `` `character:<characterId>:animation` `` (character override), and **inventory** GUI/cursor tags `` `inventory:<itemId>:defaultAnimation` `` / `` `inventory:<itemId>:cursorAnimation` `` (override JSON **`defaultAnimation`** / **`cursorAnimation`**); one-shot **`play(…)`** does not write these. **Per-room visit counter** — `` `room:<roomId>:visitCount` `` (non-negative integer; engine-maintained via **`roomVisitState.ts`**, surfaced as **`room.visitCount`** (settable, for Play From), **`room.isFirstVisit`**, and **`RoomTransitionContext.visitCount`**). **Per-room positions (lazily flushed)** — `` `room:<roomId>:character:<characterId>:position` `` (feet world coords) and `` `room:<roomId>:prop:<propId>:position` `` (authoring coords); see **§7 → Sprite animation & persistence → Snapshot flush hooks**. **Dialog options** persist via **`variables`** keys `` `dialog:<dialogId>:option:<optionId>:enabled` `` and `` `:used` `` (see **`dialogOptionVariables.ts`**); **`options.x.on()` / `off()`** write **`:enabled`**; picking a row sets **`:used`** and **`RoomScene`** refreshes the overlay on **`gameState:variableChanged`** for those keys and for **`__benne_active_dialog_id`**.
- **Active player and character switching**: `activePlayerCharacterId` defaults to `startingPlayerCharacter` and persists in v2 snapshots. **`player.id`** reads it; **`player.switchTo(character)`** persists it, rebind `RoomScene.player`, refresh camera follow, and repaint inventory panels that follow the active player. Speech labels and `say` block lines named **`Player:`** and character-follow targets named **`"player"`** resolve to this active id.
- **Room context (persisted, not a variable bag entry):** optional **`currentRoom` / `lastRoom`** on **`SerializableBenneGameState`** (`src/types/gameState.ts`) — **`""`** and **`null`** when absent from JSON. **`getCurrentRoom` / `getLastRoom` / `setCurrentRoom` / `setLastRoom`**; Scripts read them as **`game.currentRoom`** and **`room.last`** / **`room.cameFrom(rooms.x)`** (`room.last` is settable for Play From). A cold **`createBenneGame`** leaves **`currentRoom` empty and **`lastRoom` null**; **`startInitialRoomFromBoot`** in **`BootScene`** sets **`lastRoom` to `null`** again before the first **`RoomScene`** (ensures a clean first **enter** context). Changes emit **`gameState:roomContextChanged`**; **`applySnapshot`** emits when loaded values differ from the previous in-memory pair. This is **separate** from the generic **`gameState:variableChanged`** stream. **`GameStateManager`**’s constructor accepts an optional slice that can seed these fields (`GameStateInitialSlice`); **`createBenneGame`** today only merges flags / variables / inventory from **`game-config.json`**. In-game **room loads** are driven by **`rooms.x.goTo()`** and **`RoomTransitionOrchestrator`** (not by mutating **`currentRoom` / `lastRoom`** alone — those fields track state for saves and hook context; see **§3 → Scene / room system → Room switching**).
- **Runtime “selection” UI state (verbs + use-on-target)**:
  - **Active verb** — see **Verb system → Active verb** (not part of save snapshots; cleared on **`applySnapshot`**).
  - **Active inventory item** (**`activeInventoryItemId`**, optional on **`SerializableBenneGameState`**): the item id “armed” for **use-on-target** clicks on room props / hotspots / characters. Persisted in **`getSnapshot` / `applySnapshot`** / **`exportSnapshotJson`**. Set/cleared by scripts with **`pointer.item = items.x`** / **`pointer.item = null`** (**`GameStateManager.setActiveInventoryItem`**). Emits **`gameState:activeInventoryItemChanged`** (`GAME_STATE_ACTIVE_INVENTORY_ITEM_CHANGED_EVENT`). Every item verb (**`usesItem`**) on an inventory row arms that item: the engine does it at once when the item has no handler for the verb, and BenneScript after the item's handler (`items.x.onUse(…)`) finishes, unless the handler was registered with **`items.x.onUse.doNotActivate(…)`**. After an item handler on a target, the drop policy (**`dropWhenUsed`** / **`dropWhenInventoryUsed`**) clears it unless the handler passed **`{ doNotClear: true }`**.
  - **Console**: the manager logs descriptive **`[Benne] …`** **`console.log`** lines when the active verb or active inventory item becomes active, inactive, or is overwritten by snapshot load (inventory lines include **display names** from **`inventoryDefinitionRegistry`** when available).
- **Data-first bootstrap**: optional **`initialGameState`** on **`game-config.json`** (merged at startup; validated in **`ConfigManager.ts`**). **`initialGameState.inventory`** (legacy) seeds the **starting player character** bag only (unique id list or quantity map). **`initialGameState.inventoryByCharacter`** seeds multiple bags (character id → list or quantity map).
- **EventBus**: incremental changes emit **`gameState:flagChanged`**, **`gameState:variableChanged`**, **`gameState:inventoryChanged`**; **room context** changes emit **`gameState:roomContextChanged`**; wholesale replace (**`applySnapshot`**, successful browser load) emits **`gameState:replaced`** only. Scripts listen with **`events.on(…)`** (payload types in **`src/types/gameState.ts`**); in a room script the listener is live only while that room is active.
- **BenneScript**: **`flags`** / **`vars`** are declared with **`defineFlags`** / **`defineVars`** in `src/game/state.ts` (re-exported by `@game`); each read and write goes straight to **`GameStateManager`** at that line (a flag may store under a different **`saveKey`**). **`saves`** (`bennescript/saves.ts`) wraps the named / slot save APIs: **`save`** (refused while **`canSaveNow`** is false), **`load`** / **`import`** (cancel every running handler, load, restart the saved room via **`transitionToLoadedRoom`**, and end the calling handler), **`list`**, **`get`**, **`delete`**, **`rename`**, **`export`**. **`inventory`** is the active player's bag (`add`, `remove`, `has`, `count`, `clear`, `items`; all instant), and **`jensen.inventory`** a specific character's. **`items.x.animation`** / **`cursorAnimation`** / **`description`** get the effective values used by the GUI row and the armed custom pointer and set the same **`variables`** keys as §7 (through the active room when there is one, so the GUI refreshes). There is no flush call: saves and room changes run the snapshot flush hooks themselves.
- **Persistence v1**: legacy slot snapshots stay at **`localStorage`** keys **`benne-save-<slot>`** (default slot **`0`**). Named saves are manifest-backed with **`benne-saves-manifest-v1`** and payload keys **`benne-save-v1-<sanitized-name>`**. `getSaveList()` migrates/merges legacy slot entries into the manifest view without breaking numbered-slot compatibility. **`exportSnapshotJson` / `importSnapshotJson`** remain the extension point for future file-based saves.

### Inventory System

- **Authoring layout**: Under **`src/game/inventory/<inventoryId>/`**, each inventory entry has **`<inventoryId>.inventory.json`** (source of truth, **`InventoryItemData`** in **`src/types/inventory.ts`**) and an optional **`<inventoryId>.inventory.ts`** with top-level BenneScript handlers on **`items.<inventoryId>`** (`items.magnet.onLook(…)`, `items.magnet.onCombine(items.antenna, …)`). Optional **`defaultVerb`** on **`InventoryItemData`** is used when the player's click on that row in a GUI **`inventoryPanel`** resolves the effective **`inputProfile`** slot to **`"defaultVerb"`** or **`"walkTo"`** (both map to authored **`defaultVerb`**, else **`look`**). Plain verb ids in the profile (e.g. **`use`**) dispatch that verb on the item. Optional **`dropWhenUsed`** (boolean) overrides the global **`dropWhenInventoryUsed`** policy for this item only — see **Use-on-target (inventory × world) → Drop policy**. Optional **`cursorAnimation`** (string, Aseprite tag on **that item’s** sheet) drives the **optional** custom-game-cursor clip whenever this item is the **active inventory selection** — see **Input system → Custom pointer**; omit it to keep default cursor behavior only; at runtime **`items.x.cursorAnimation`** reads the **effective** tag (JSON ± **`GameStateManager`** override via **`inventory:<itemId>:cursorAnimation`** — see **`bennescript-api.md`** and §7 persistence).
- **Per-character bags**: `inventory` targets the active player's bag; `jensen.inventory` (or `characters.jensen.inventory`) targets that character's. An `inventoryPanel` may set `characterId` to pin the displayed bag, or omit it to follow the active player and repaint after `player.switchTo(…)`. Legacy flat inventory saves and `initialGameState.inventory` belong to the starting player's bag; `initialGameState.inventoryByCharacter` bootstraps multiple bags.
- **Use-on-target (inventory × world)**: With **`activeInventoryItemId`** set, **`RoomScene`** may route the next qualifying **left** click on a prop, hotspot, or clickable character to **inventory-on-target** dispatch (**`dispatchInventoryOnVerbTargetInteraction`**, events in **`inventoryOnVerbEvents.ts`**) instead of normal verb dispatch when **`shouldDispatchInventoryUsedOnVerbForGame`** is true (resolved verb is the game's default item verb (**`resolveDefaultItemVerbId`**) **or** matches the current **active verb**). BenneScript handles it with **`on<Verb>Item(item, …)`**, **`onItem(item, …)`** and **`onAnyItem((item, verb) => …)`** on the target's handle, in room scripts and character scripts (`characters.x.onAnyItem` listens on the character's global any-item tier, `registerCharacterAnyItemHandler`). Precedence: the room's per-item handler → the room's any-item handler → the character script's / item script's per-item handler → that target's global any-item handler → **`fallbacks.on<Verb>Item`** → **`fallbacks.onItemUnhandled`** (the `verb:global:inventoryOnVerbTarget:unhandled` channel). A handler that calls **`unhandled()`** hands the click to the next tier (**`continueInventoryOnDispatchAfterRoom`** / **`AfterGlobal`**).
- **Drop policy (“stay armed vs. drop after use”)**: whether the active inventory selection is “dropped” (active inventory + active verb both cleared) after a use-on-target click follows a layered policy resolved by **`shouldDropActiveInventoryOnUse`** (`src/engine/verbs/dispatchInventoryOnVerbTarget.ts`):
  1. Script-level **`{ doNotClear: true }`** as the last argument of an item handler (`door.onUseItem(items.key, fn, { doNotClear: true })`) — hard per-handler opt-out; inventory stays armed.
  2. Per-item **`dropWhenUsed`** on **`*.inventory.json`** (**`InventoryItemData`**) — when present, wins.
  3. Global **`dropWhenInventoryUsed`** on **`game-config.json`** (**`GameSettings`**).
  4. Default **`false`** — inventory stays armed so the player can use the same item on several targets in a row (classic modern adventure behavior). Set the global or per-item flag to **`true`** for classic “drop after use”.

  When the policy resolves to **drop** **and** the item handler finished (or ended) rather than calling **`unhandled()`** or being cancelled, **`applyInventoryDropPolicy`** (`bennescript/globalHandlers.ts`) clears **both** the active inventory and the runtime **active verb** after the handler's last step so the verb HUD resets to idle (no stale "Use …" armed). **`RoomScene`** prop / hotspot / character pointer handlers and **`buildGuiOverlay`** inventory-on-inventory synchronously clear both when **`dispatchInventoryOnVerbTargetInteraction`** / **`dispatchInventoryOnInventoryItemInteraction`** is unhandled and **`shouldDropActiveInventoryOnUse`** is true. The verb is captured at dispatch time, so `onAnyItem((item, verb) => …)` still sees the verb that fired. When the policy resolves to **don’t drop**, both the armed item **and** the active verb stay set across the click; clear them manually with **`pointer.item = null`** / **`pointer.verb = null`**, verb GUI buttons, or right-click while armed.
- **Removal disarms depleted selections**: `GameStateManager.removeFromInventory` clears both `activeInventoryItemId` and the active verb when the removed id is armed and its quantity reaches zero, including non-stackable removal and stack depletion. This is independent of the post-use drop policy.
- **Right-click / empty-space clears while armed**: whenever **`activeInventoryItemId`** is set, a **right**-click on **anything** (prop, hotspot, clickable character, inventory row, or empty space) clears **both** the active inventory and the active verb. A **left**-click on empty space while armed also clears both instead of walking — the player must re-arm before the empty-space click walks again (`RoomScene.handleRoomPointerDown` + `resolution.kind === 'clearActive'` branches in the prop / hotspot / character pointer handlers and in **`buildGuiOverlay`** inventory rows).
- **Registry**: **`registerInventoryDefinitionsFromGame()`** (from **`registerGameContent`**) eager-loads **`./inventory/**/*.inventory.json`** into **`inventoryDefinitionRegistry`** so **`GameStateManager`** can read **`stackable`** when applying **`add` / `remove`**, and **`BootScene`** knows which Aseprite sheets to queue. JSON validation preserves optional fields such as **`cursorAnimation`**.
- **Shared Aseprite (PowerQuest-style)**: One export at **`src/game/assets/images/inventory/inventory.png`** + **`inventory.json`**. Each **frame tag** on the sheet is an inventory clip (and default animation name); entry-specific variants should use a root naming convention like **`<root>-*`** (for example **`lantern-glow`**, **`lantern-open`** for root **`lantern`**). The engine normalizes JSON for Phaser, then prefixes Phaser animation keys as **`inventory:<tag>`** so tags stay namespaced on a single texture (**`aseprite:inventory:shared`**). In JSON, set **`display.aseprite`** to **`"shared"`**. Optional **`defaultAnimation`** is the Aseprite frame tag used as the default clip in UI/cursor; when omitted, the inventory **`id`** is used (so the tag name normally matches the folder / inventory id).
- **Per-inventory-entry Aseprite**: **`display.aseprite: true`** loads **`images/inventory/<id>/<id>.png`** + **`.json`** (same pattern as characters). Authoring continues to use raw tag names, while normalized Phaser animation keys are namespaced as **`invitem:<itemId>:<tag>`** on texture **`aseprite:inventory:<id>`**. The **same soft `<root>-*` convention** as the shared sheet applies in tooling: roots are the inventory **`id`** plus optional **`defaultAnimation`**; a sheet tag is grouped with the entry when it equals a root or starts with **`root-`** (literal hyphen). The Inspector derives suggested animation rows from the per-item export the same way it does for **`"shared"`**; authored **`animations`** in JSON remains authoritative.
- **BenneScript**: an inventory script registers verb handlers on its item's row (`items.magnet.onLook(…)`, generated per configured verb) on **`verb:inventory:<inventoryId>:<verbId>`**; a room script may register the same on **`verb:room:<roomId>:inventory:<inventoryId>:<verbId>`**. **`dispatchInventoryVerbInteraction`** (**`src/engine/verbs/dispatchInventoryVerb.ts`**) emits **room-scoped** if that channel has listeners, else **global** if it has listeners; else an item verb (**`usesItem`**) arms the item at once, and any other verb goes to the same global chain as **`dispatchVerbInteraction`** (**`verb:global:<verbId>`** → **`verb:global:fallback`** → **`verb:unhandled`**), so **`globalScript.ts`** fallbacks apply when the row has no handler. A BenneScript handler for an item verb arms the item after it finishes, unless it was registered with **`.doNotActivate`**; this is the same rule for every item, scripted or JSON-only. **`items.x.animation`** / **`cursorAnimation`** / **`description`** override **`defaultAnimation`** / **`cursorAnimation`** / **`description`** at runtime (instant, saved — see **§7 → Persistence**); **`inventory.add` / `remove`** change quantities at that line.
- **VS Code extension**: Main tree **Inventory** group (with **Rooms**, **Characters**, **GUIs**, **Dialogs**). Tree selection opens **`*.inventory.json`** in the primary editor column and **`openBenneInventoryTypeScript`** (**`roomScriptNavigation.ts`**) for the companion **`*.inventory.ts`** in the Benne script row. Commands **`benne-editor.createInventoryItem`** (wizard: id + name → folder, minimal JSON with **`"aseprite": "shared"`**, stub **`.inventory.ts`**) and **`benne-editor.importInventoryItemsFromAsepriteTags`** (reads **`inventory.json`**, multi-select tags, writes/updates **`.inventory.json`** per tag and optionally **`.inventory.ts`**). **Inventory-on-target** authoring from the **room / character Inspectors** uses **`benne-editor.addRoomInventoryUsedOnStub`** / **`addCharacterInventoryUsedOnStub`** (see **§2 → BENNE — Inspector view**). In the Inspector, **both** **`display.aseprite: "shared"`** and **`display.aseprite: true`** entries derive animation cards from the relevant sheet using item-scoped roots (item **`id`** plus optional **`defaultAnimation`**) and only include matching tags (**`root`** and **`root-*`**); editing a derived row materializes that row into the entry JSON under **`animations`**. Tags outside that family can still be added manually in JSON (soft convention). Context menus follow the same pattern as **Characters** / **GUIs** (create on group/workspace; import from group or entry context where applicable).

### Dialog system (choice topics)

- **Authoring layout**: Under **`src/game/dialogs/<dialogId>/`**, each dialog has **`<dialogId>.dialog.json`** (**`Dialog`** in **`src/types/dialogue.ts`**: **`id`**, optional **`displayName`**, optional **`guiId`** defaulting to **`dialog`**, **`options[]`**) and **`<dialogId>.dialog.ts`** with top-level BenneScript handlers on the dialog's options (`options.greeting.onChoose(…)`). Each **`DialogOption`** has **`id`**, **`text`**, optional **`enabled`** (omit or **`true`** → option visible), optional **`used`** (authoring default **`false`**; runtime may persist **`true`** after the player picks that row), and optional **`say`** (omit or **`true`** → the player says that option’s **`text`** before the matching **`onChoose`** handler runs; **`false`** skips the automatic player line). Array **order** is the on-screen order; the Inspector can reorder rows (see **§2 → Dialogs**). The default choice GUI is **`guis/dialog/dialog.gui.json`** ( **`Option-Grid`**, **`scrollUp`**, **`scrollDown`**, template **`Dialog-Option`** / **`Bullet`** rows — the runtime hides templates and injects synthetic rows per option).

- **Registry**: **`registerDialogDefinitionsFromGame()`** (from **`registerGameContent`**) eager-loads **`./dialogs/**/*.dialog.json`** into **`dialogDefinitionRegistry`** (**`dialogDefinitionRegistry.ts`**). **`getRegisteredDialogChoiceGuiIds()`** returns **`'dialog'`** union every definition’s **`guiId`** so **`RoomScene`** can reserve those overlays from the generic GUI walk.

- **Runtime (`RoomScene`)**: Reserved choice GUIs are built **after** Speaking Text (**`speaking-text`**) at a higher depth band. **`wireDialogChoiceUi`** listens for **`benne:dialog:started`** / **`benne:dialog:stopped`** (**`DIALOG_STARTED_EVENT`**, **`DIALOG_STOPPED_EVENT`**), **`benne:dialog:optionEnabledChanged`**, **`gameState:variableChanged`** (**`GAME_STATE_VARIABLE_CHANGED_EVENT`**), per-GUI **`guiAllButtonsClickEventId`**, and **`guiButtonClickEventId`** for **`scrollUp` / `scrollDown`**. **`dialogChoiceGuiRuntime.ts`** owns **`DialogChoiceDynamicRowState`** (**`refresh`**, **`layoutDialogChoiceViewportSegments`**, **`getDialogChoiceAvailableHeightPx`**, **`DIALOG_CHOICE_GRID_ID`**). **`benne:dialog:started`** shows the overlay, calls **`pushScriptedDialogInputSuppression`** (same **`say`** line-lock path), and **`refresh`** fills the grid; **`benne:dialog:stopped`** hides it and **`popScriptedDialogInputSuppression`** when the session matches (**`dialogChoiceInputSuppressionActive`** guards double-pop). Each synthetic row is a real **`buildGuiButton`** hit target whose **`pointerup`** emits **`guiButtonClickEventId(guiId, dc__…)`** and **`guiAllButtonsClickEventId`**; **`RoomScene`**’s catch-all handler marks **`:used`**, then **`refresh`** applies **used** styling to picked rows — either tinting with **`dialog.usedColor`** from **`game-config.json`** (hex, e.g. `#888888`) or falling back to `setAlpha(0.45)` when omitted (BenneScript choice handlers, **`options.x.onChoose`**, run from the per-button emit). Scroll buttons page within **`Option-Grid`** by **viewport-sized pages** ( **`advanceDialogChoiceScrollTopPx`** / **`computeDialogChoiceScrollPageStarts`** — typically two pages when content slightly exceeds the cap); each page shows as much text as fits, including **partial** rows at the edges; bullets appear only when an option **starts** at the top of the slice (**`clipTopPx === 0`**). **`layoutDialogChoiceViewportSegments`** + **`getDialogChoiceScrollButtonState`** drive layout and arrow visibility. **`clearStateForRoomTransition`** and shutdown paths end orphan dialog sessions and end suppression if still active.
- **Choice options viewport height**: By default, how many option rows may stack is **`internalHeight − Option-Grid top − 4px`** (options grow toward the bottom of the canvas — fine for bottom bars). For **top strips** or other compact HUDs, cap stacking with optional **`choiceOptionsViewportHeightPx`** (pixels downward from **`Option-Grid`** top): **`game-config.json`** → **`dialog.choiceOptionsViewportHeightPx`**, or per choice GUI root in **`*.gui.json`** (GUI wins over game-config). Omitted = legacy behavior. Runtime: **`resolveDialogChoiceViewportHeightPx`** → **`getDialogChoiceAvailableHeightPx(..., maxViewportHeightPx)`** uses **`min(toScreenBottom, cap)`** when a cap is set. Example: 55px top strip with **`Option-Grid`** at **`y: 4`** → about **`47`** (`55 − 4 − 4` margin).
- **Used option color**: Optional **`usedColor`** in **`game-config.json`** → **`dialog.usedColor`** (hex string, e.g. **`"#888888"`**). When set, dialog options the player has already picked are tinted to this color (bullet sprite, label, label outlines, and background) instead of the legacy **`setAlpha(0.45)`** dimming. Omitted = legacy alpha behavior. Overridable at runtime via **`settings.dialog.usedColor`** (persisted under **`dialog:usedColor`** in **`GameStateManager`** variables; **`undefined`** clears override). Runtime: **`DialogChoiceDynamicRowState.refresh`** resolves the effective color from **`getDialogSettings(manager)`** and applies **`setTint`** / **`applyGuiBitmapTextFillTint`** on each sub-element when the option is **`used`** and `usedColor` is present.

- **BenneScript**: **`dialogs.x.start()`** opens a conversation and waits until it ends (`.now` doesn't wait); **`dialog.end()`** closes it and ends the calling handler; **`options.x.on()` / `off()` / `enabled`** read and write **`:enabled`**; **`options.x.onChoose(fn)`** / **`onChooseOnce(fn)`** register on **`guiButtonClickEventId(dialogGuiId, dialogChoiceSyntheticButtonId(optionId))`**, and **`dialog.onStart(fn)`** runs each time the conversation opens. `bennescript/dialogs.ts` keeps a **stack** on top of the engine's single dialog session (**`dialog/dialogSession.ts`**: open, end, active session): starting a dialog from a choice handler suspends the parent, and the parent reopens once that choice handler has finished. Choice handlers are not cutscenes (a cutscene held while a choice waits on a sub-dialog would block its buttons); scripts wrap long choices in **`cutscene(…)`** for ESC. A handler waiting on `start()` is marked as waiting for the player, so idle detection sees the dialog rather than a busy script. A dialog script changes the room the conversation is in by importing that room's handles (`import { jensen } from '../../rooms/hallway/hallway.ids'`).

- **Events / variables**: Session helpers live in **`dialogSession.ts`**; **`dialogEvents.ts`** defines **`DIALOG_STARTED`**, **`DIALOG_STOPPED`**, **`dialogChoiceSyntheticButtonId`**, etc. Active dialog id is stored under **`BENNE_ACTIVE_DIALOG_ID_VARIABLE`** (**`__benne_active_dialog_id`**) for persistence and UI refresh.

- **Loading**: **`src/engine/content/registerDialogDefinitions.ts`** registers every **`*.dialog.json`**, and **`registerGameContent`** loads the **`*.dialog.ts`** scripts.

- **VS Code extension**: **Dialogs** in the main tree, **Create Dialog**, Inspector + **Script…** workflow, and the BenneScript editor support are documented under **§2 → BENNE — Inspector** (Dialogs bullet) and **§8**. Reserved Speaking Text (**`speaking-text`**) and choice-dialog **`*.gui.json`** / **`*.gui.ts`** authoring unchanged from the **GUIs** bullet above.

## 4. Data Flow

1. **Bootstrap**: `game-config.json` → resolution, start room id, **verbs / input profile / fallback line**, audio caps, debug flags, optional **`initialGameState`** for **`GameStateManager`**.
2. **Boot**: Manifest + glob pick **`RoomData`** → **`BootScene`** builds load list → loader completes → **`startInitialRoomFromBoot`** ( **`setLastRoom(null)`**, start kind **`'boot'`**) → **`RoomSceneStartData`** into **`RoomScene.create`**.
3. **Frame loop**: Phaser updates tweens / anims; **input** → hit tests → background **walk** on empty space, or **prop/hotspot/character** hit → **`dispatchVerbInteraction`** (stops an in-progress **player** walk first when applicable) → **`gameEvents.emit`** on the chosen event id.
4. **Scripts**: BenneScript handlers (**`*.room.ts`** / **`*.character.ts`** / **`*.gui.ts`** / **`*.inventory.ts`** / **`*.dialog.ts`** / **`globalScript.ts`**) are registered at module top level, on **`gameEvents`** channels through the handler tables in `src/engine/bennescript/` (room handlers attach per room; the others once, at startup), and each event they receive runs as a sequenced interaction (§7).

**Diagram (simplified)**

```
JSON + Aseprite  →  BootScene (Loader)  →  RoomScene (display + input)
                                              │
Pointer / keys ──────────────────────────────┤
                                              ▼
                                    gameEvents (EventBus)
                                              ▲
registerGameContent (*.room.ts factories [lazy], *.character.ts, *.gui.ts, *.inventory.ts, *.dialog.ts, globalScript)─┘
```

## 5. Key Design Decisions

| Decision | Why | Tradeoff |
|----------|-----|----------|
| **One `RoomScene` + boot + transition loader** | Keeps a single Phaser **room** scene; startup and in-room handoffs use the same **`RoomSceneStartData`** + loader queue helpers (`roomSceneBootstrap.ts`). | Each **`rooms.x.goTo()`** (**`RoomTransitionOrchestrator.changeTo`**) **restarts** **`RoomScene`** with a new start payload. **Cross-room data** (flags / variables / per-character **`inventoryByCharacter`**) stay on **`GameStateManager`**. **Teleport** helpers **`moveTo`** are unrelated (same room). |
| **Global `gameEvents` singleton** | Fast to wire; matches stringly event ids from JSON. | Global coupling; tests need discipline or indirection later. |
| **JSON string event ids** | Editable in data; matches classic adventure “verb” naming. | Typos fail at runtime; editor/tooling (e.g. VS Code extension) helps. |
| **Central verb dispatch** | One precedence chain (scoped per-verb listeners → object fallback → global → unhandled) and one place for future 9-verb / coin UIs to plug in. | Handlers must register **`verb:global:*`** if they rely on global overrides; listener counts drive whether each tier runs. |
| **Vite glob for assets** | Correct hashed URLs and tree-shaking. | **Editor preview** must use a **separate fetch/Webview path** (`src/editor/preview/`) — two loading strategies. |
| **Walkable polygons in JSON + visibility-graph pathfinding** | Designer-controlled navmesh; shortest-path routing around holes and concavities via reflex-vertex visibility graph + A\* (classical approach for polygons with holes; matches LucasArts feel). | No auto navmesh; bad polygons break movement visually (mitigated by debug draw of mesh + live path polyline). O(N²) visibility build per walk query — fine for hand-authored rooms, would need caching / triangulation for very large meshes. |
| **Aseprite tags = props / anims** | Single sheet per room/character, industry-standard tool. | Untagged cels are invisible to the engine; tag discipline required. |

## 6. Constraints and Rules

- **Engine vs game**: Do not put **game-specific narrative or room logic** under `src/engine/` except through **generic hooks** (events, helpers). Put reactions in **`src/game/`** (`*.room.ts`, future modules).
- **Config**: **`game-config.json`** is the **single source** for resolution, default character, start room override, **verbs**, **inputProfile**, **defaultFallbackLine**, audio, debug flags, optional **`initialGameState`** — read via **`getGameSettings()`**, not duplicated literals. Optional **`cursor`** (custom pointer) adds **`idleAnimation`** / **`activeAnimation`** (Aseprite tag names), optional **`cursor.animations`** (same per-tag shape as **`CharacterData.animations`**), and optional **`cursor.hotspot`** / **`cursor.hotspotPixel`** for pointer-tip placement.
- **Room data**: Follow **`RoomData`** / **`RoomPropInstance`** in **`src/types/room.ts`**; **`collider`** is required for **`clickable`** props. **`walkToPoint`** / **`lookAtPoint`** are optional script hints (not applied by the engine on click). Interactions are BenneScript handlers in **`*.room.ts`**; optional **`onVerbFallback`** on a prop/hotspot enables fallback **`EventBus`** dispatch when no per-verb listener handled the verb. Optional **`defaultVerb`** (string verb id) feeds the `inputProfile` `"defaultVerb"` token (fallback `"look"`). **Room prop sheet placement**: **`spritePlacement`** defaults to **`"canvas"`** (authored `x`/`y` map to logical cel/sheet origin, full-canvas workflow); set **`"tight"`** when authoring against trimmed visible pixels (runtime uses `spriteSourceSize` and keeps placement synced across animated frames). In development, trim metadata that reports `trimmed: true` without `spriteSourceSize` produces a one-time warning so non-standard Aseprite exports are visible. Room-level **`points`** (**`RoomPointData[]`**, named **`x` / `y`**) are used by **`RoomScene`** when BenneScript walks to **`points.x`**. **`regions`** (**`RoomRegionData[]`**, closed polygons + `active`) drive perspective scale, optional walk-speed scaling, character tint, and enter/exit hooks. **Hotspot** polygons are separate **`hotspots[].points`**.
- **Room prop clip families (soft convention)**: Optional **`RoomPropInstance.defaultAnimation`** adds a second **root** alongside **`id`** for editor/Inspector grouping of tags on the room Aseprite sheet: a tag is suggested for that prop when it **equals** a root or matches **`root-*`** (literal hyphen after the root). **`RoomScene`** still uses **`tag`** for which clip is drawn; **`animations`** maps Aseprite tag names to optional **`loop`** / **`frameDuration`** overrides (same shape as character clip config). The Inspector merges **`meta.frameTags`** with **`animations`** using those roots; JSON stays the source of truth and arbitrary tags remain valid if added manually.
- **Character data**: Follow **`CharacterData`** in **`src/types/character.ts`**. Optional **`collider`** (≥3 **`points`** in frame space) restricts **click** hit-testing for **`clickable`** characters; omit it or save fewer than three points in the preview to use the **full sprite** bounds. Optional **`defaultVerb`** (string) feeds the `inputProfile` `"defaultVerb"` token for clicks on this character (fallback `"look"`). Optional **`onVerbFallback`** enables character-level fallback dispatch when no per-verb listener handled the click.
- **GUI data**: Follow **`GuiData`** in **`src/types/gui.ts`**. Optional **`controls`** describe screen-space widgets (**`text`**, **`inventoryPanel`**, **`image`**, **`nineSliceImage`**, **`button`**, **`trigger`**, **`grid`**). Optional top-level **`x`** / **`y`** set the initial screen-space offset of the packed **`gui.root`** (e.g. **`"y": -34`** to park a dropdown bar offscreen; fixed controls are not offset). Optional **`fixedControls`** is a string array of control **`id`** values: those controls are **not** parented under **`gui.root`**, so **`gui.root.tweenTo`** (and future whole-overlay moves) slide the rest of the HUD without moving them. Optional **`zIndex`** (default **0**) sets **overlay stack order** among all **`*.gui.json`** files (lower = behind); ties break on **`id`**. Distinct from per-control **`zIndex`** in **`controls[]`**, which only layers widgets inside one GUI. **`RoomScene`** assigns Phaser depth from **`sortGuisForOverlayStack`** (`src/engine/gui/guiStackOrder.ts`). Optional **`modal`** (default **`false`**) installs a full-screen invisible pointer catcher while the overlay is visible, blocking room input and any GUI with a **lower** overlay depth. The VS Code GUI Inspector exposes **`zIndex`** and **modal** in **GUI metadata**. Aseprite sheets use **`images/guis/<guiId>/<guiId>.png`** and **`.json`** when **`display.aseprite`** is true (same export pattern as characters). On **`image`** controls, **`tag`** and **`backgroundAnchor`** live on the control object (parallel to **`backgroundTag`** / **`backgroundAnchor`** on **`inventoryPanel`** and **`button`**); the GUI root **`display`** block is only for overlay-level options such as **`aseprite`**. **Trim-aware sheet placement**: `buildGuiOverlay` uses Aseprite trim metadata (`spriteSourceSize`) so both workflows are valid — **full-canvas** (`backgroundAnchor: "screen"`) and **trimmed-cel** (`top-left` / `center`). For grid-placed images, **`gridPlacement.align: "center"`** centers using visible packed frame size (`cutWidth`/`cutHeight`) rather than untrimmed source canvas size. **Bitmap fonts** for text controls: PNG atlas + BMFont **`.xml`** under **`src/game/assets/fonts/`**, logical ids and paths in **`fonts/fonts.json`** (Phaser **`load.bitmapFont`** key = id = GUI control **`font`**). **`RoomScene`** builds **one overlay per `*.gui.json`** (not a hard-coded id list), stacked by **`GuiData.zIndex`** then **`id`**: Speaking Text (**`speaking-text`**) is reserved for **`setDialogTextOverlay`** / **`say`** (starts hidden at boot); ids in **`getRegisteredDialogChoiceGuiIds()`** are reserved for **`dialogs.x.start()` / `dialog.end()`** (start hidden). Every other GUI is shown at room load unless **`"visible": false`**. The **GUI preview** uses the same **`buildGuiOverlay`** path for the selected GUI. **`nineSliceImage`** controls draw a tag from the GUI sheet using **`meta.slices`** (Aseprite slice names mapped per 3×3 cell in **`sliceNames`**) and nine cropped quads so panels scale on Canvas (see **`buildGuiOverlay`** / **`guiNineSliceImage.ts`**).
- **Walkable mesh**: **`walkable.polygons[]`** entries support optional **`holes[]`** (inner rings subtracted when **`active`** is not **`false`**). Each polygon and hole may set **`active`**; omitted or non-**`false`** means included in tests and debug draw. Scripts toggle a polygon with **`walkables.x.active`** (persisted; see **§3 → Scripting / interaction system**). See **`walkable.ts`** and **`RoomScene`** debug overlays (outer vs hole stroke colors; the walkable stroke redraws when a script changes **`active`** and **`debug.showWalkable`** is on).
- **Registration**: Script files register BenneScript handlers at their top level; there is no `register*` wrapper. Room scripts: **`src/game/rooms/<id>/<id>.room.ts`**. Character scripts: **`src/game/characters/<id>/<id>.character.ts`**. GUI scripts: **`src/game/guis/<id>/<id>.gui.ts`**. Inventory scripts: **`src/game/inventory/<id>/<id>.inventory.ts`**. Dialog scripts: **`src/game/dialogs/<id>/<id>.dialog.ts`**. Fallbacks and any-room hooks: **`src/game/globalScript.ts`**. Flags and variables: **`src/game/state.ts`**. A script file with nothing in it can be deleted. See **§7**.
- **Strict TypeScript**: Project uses **strict** compiler options; new code should preserve typings for payloads and JSON-shaped types.

## 7. Scripting / interaction system (BenneScript)

Game logic is written in **BenneScript**: TypeScript script files in which each statement waits for the one above it, every content reference is a generated, typed handle, and `Hank: "…"` labels are speech lines. The engine stays data-first: verb dispatch still emits canonical scoped event ids on `gameEvents` (`verb:room:office:prop:desk:look`, …), and BenneScript is the layer that subscribes to them.

- **Authoring guide**: [`docs/public/bennescript.md`](public/bennescript.md). **API reference** (generated from the JSDoc by `npm run docs:api`): [`docs/bennescript-api.md`](bennescript-api.md). **Design and decisions**: [`docs/bennescript-ergonomics-refactor.md`](bennescript-ergonomics-refactor.md) (§5 sequencing rules, §6 the transform, §13 every decision).

```ts
// AI Apocalypse: rooms/club/club.room.ts
import { inventory, unhandled, wait, walkToClicked } from '@benne/script'
import { dialogs, flags, items, sfx } from '@game'
import { battery } from './club.ids'

battery.onUseItem(items.soda, () => {
  if (!flags.askedAboutBattery) unhandled()
  walkToClicked()
  Hank: "I hope this works."
  inventory.remove(items.soda)
  sfx.sodaPour.play()
  wait(0.75)
  dialogs.driver.options.wrench.on()
  flags.batteryClean = true
})
```

### Three pieces

```
 content JSON + assets ──► (1) handle generator ──► <room>.ids.ts, @game (typed handles)
                                                          │ imported by
 *.room.ts / *.dialog.ts / … ──► (2) Vite transform ──► async code: awaited steps + say()
                                                          │ runs on
                                 (3) step runtime: Task, InteractionContext, cancellation,
                                     skip, interaction lock, handler tables → gameEvents
```

1. **Handle generator** (`scripts/generate-game-ids.mjs` → `scripts/lib/generateGameHandles.mjs`). Writes `src/game/game.ids.ts` (aliased **`@game`**) and `rooms|dialogs|guis/<id>/<id>.ids.ts` from the content JSON, the audio / video folders and `game-config.json`.
2. **Build transform** (`vite-plugin-bennescript.ts` → `scripts/lib/bennescriptTransform.mjs`). Rewrites script files so that each statement is awaited.
3. **Step runtime and handle API** (`src/engine/bennescript/`, exported as **`@benne/script`** from `index.ts`). Runs each handler as an `InteractionContext`, waits on `Task`s, and registers handlers in tables that subscribe to the engine's events.

### Generated handles

- **Output**: real TypeScript modules (runtime objects plus types) next to the content, starting with a generated marker; gitignored (`src/game/**/*.ids.ts`). Only files carrying the marker are ever deleted, and files are written only when their text changes, so the dev watcher (which ignores `*.ids.ts`) doesn't loop.
- **When**: `npm run generate:game-ids`, run by `predev`, `prebuild`, `pretypecheck` and every `prebuild:*-preview`; the BENNE Editor runs it after content edits; the Vite plugin in `vite-plugin-bennegame-ids.ts` regenerates on JSON changes during dev (a failed run shows in the error overlay and keeps the previous modules). `npm run check:generated` fails on collisions, reserved verb ids and bad `scriptName`s.
- **`@game`**: `rooms`, `characters`, `items`, `dialogs` (with `options`), `guis` (with `controls`), `sfx` (`withSfxControls`), `music` (`withMusicControls`), `video` (`withVideoControls`), `verbs`, `fallbacks`, and `flags` / `vars` re-exported from `src/game/state.ts`. It also declares `VerbId`, `ItemVerbId` and the `VerbMethods` / `ItemVerbMethods` / `FallbackVerbMethods` interfaces from the configured verbs, and exports an internal `__withVerbs` that the room modules call.
- **Room modules**: `room` (= `rooms.<id>`), the room's props, hotspots and spawned characters as flat exports, plus `points`, `regions`, `walkables`. Character modules (`characters/<id>/<id>.ids.ts`): the character, flat, for its own character script (`jensen`, the same object as `characters.jensen`). Dialog modules: `dialog`, `options`. GUI modules: `gui` and its controls (flat). One object per thing: `dialogs.x.options.y` is `options.y`; a room's `jensen` is a separate handle from `characters.jensen` (different registration scope, §4.9).
- **Handles are generic over the game's verbs.** The engine classes (`PropHandle<VerbId, Anim>`, `HotspotHandle<VerbId>`, `CharacterHandle<VerbId, Anim>`, `ItemHandle<VerbId, Anim>`) contain no verb names; **`withVerbMethods`** attaches `on<Verb>` / `on<Verb>Item` (and `on<Verb>.doNotActivate` for item verbs on items) from the generated `VerbSpec` list, so the method names come from one place. Animation tags are string-literal unions read from the Aseprite JSON.
- **Naming**: camelCase IDs, the room id and kind word stripped in room modules (`club-hotspot-battery` → `battery`), collisions are errors that ask for a `"scriptName"`, reserved names in flat scopes get a trailing `_` and a warning, browser globals only warn. Full rules: design doc §7.2 and decision 24; speaker labels: `scripts/lib/benneSpeakers.mjs` (shared by the generator and the transform).

### The build transform

- **Where**: `vite.config.ts` registers the plugin once (`enforce: 'pre'`, before TypeScript is stripped); BENNE Play and the four editor previews merge that config. (Vitest's config is separate; the transform's unit tests call `transformBenneScript` directly.) It applies to `*.room.ts`, `*.character.ts`, `*.inventory.ts`, `*.dialog.ts`, `*.gui.ts`, `*.script.ts` and `globalScript.ts`. It parses with Oxc (Vite's `parseAst`), edits with `magic-string`, keeps every statement on its source line, and emits source maps, so breakpoints and stack traces land on the author's lines.
- **Step functions** become `async` and take the interaction context on entry (`const __$ = __bs.ctx()`): callbacks passed to any `x.on…(…)` / `x.once(…)` method except `onUpdate`, to `x.onY.doNotActivate(…)`, and to `playFrom`, `cutscene`, `background`, `together`, `withInputDisabled`; functions declared at a script file's top level; functions exported from `*.script.ts`.
- **Statements** inside step functions become `await __$.step(() => call)`. The call runs inside `step` with the context as ambient state, which is how `walkToClicked()` finds the clicked target and how a player walk is attributed to its interaction, without passing a context around. `x.now(…)` and `background(…)` in expression position are wrapped in `__$.run(…)` so they start with the handler's context.
- **Speech labels**: a labelled expression whose label resolves to `Player` or exactly one character (by id or display name, normalised) becomes `__bs.say("<id>", expr)`; `` say`…` `` blocks become `` say.__withSpeakers({…})`…` `` with their speakers resolved at build time. Unknown or ambiguous labels in front of a string, speech outside a step function, a step function passed to `forEach` & co., and a step-function call nested inside another call are build errors with a hint.
- **Errors**: authoring mistakes throw `BenneScriptTransformError` with a source position (unknown speaker, speech outside a step function, a step function passed to a callback); a parse error at `() => Hank: "…"` is reworded to say to add braces. Step-function detection lives in `scripts/lib/bennescriptSteps.mjs`, shared with the ESLint rules.
- **Lint**: `scripts/lib/eslint-plugin-bennescript.mjs` (`no-unwaited-timed-call`, `no-await-in-step`) catches timed actions where nothing waits and `await` in handlers, by type; `gameScriptsConfig(…)` is the block for `src/game/**/*.ts`, used by this repository's `eslint.config.mjs` and by new games' (design doc §6.3, decision 53).
- Full rules and the emitted shape: design doc §6.

### The step runtime

- **`Task`** (`task.ts`): a timed action that has started. Every timed action is written once with **`timed(start)`**: the blocking form returns `task.wait()` (a `TaskWait` marker), `.now` returns the bare `Task`. `$.step` waits on markers and on step-function promises only, so `jensen.walkTo.now(…)` as a statement doesn't wait, and `walk.wait()` later does. A `Task` has `finishNow()` (cutscene skip: apply the end state) and `cancel()`.
- **`InteractionContext`** (`interactionContext.ts`): one per dispatched event. `step()` checks cancellation before running the next statement, races the awaited task against the context's cancel signal, and in skip mode calls `finishNow()` on the task (registering it with `RoomScene.registerCutsceneSkipFinisher` while it runs, so an ESC mid-step finishes it). `goTo()`, `saves.load()` / `import()`, `game.newGame()` and `dialog.end()` throw `END_HANDLER` after scheduling their effect; `unhandled()` throws its own marker so the dispatcher can fall through to the next tier. The dispatcher (`runHandler`) swallows both and reports the outcome (`finished`, `ended`, `unhandled`, `cancelled`).
- **Cancellation**: a room change cancels every running context (`cancelAllInteractions()` in `RoomTransitionOrchestrator.prepareForLeave`), and so does any snapshot replacement (`gameState:replaced`: a load or new game). The handler that called `saves.load()` ends instead of being cancelled.
- **Blocks** (`blocks.ts`): `cutscene(fn, options?)` pushes a cutscene on the room for its body; `together(...fns)` runs step functions in parallel and waits for all; `background(fn)` starts a separate context that keeps the click payload but takes no lock, isn't "busy" for idle detection, doesn't block saving, and stops on a room change or load; `withInputDisabled(fn)` and `input.disabled` drive the room's user-input lock.
- **Interaction activity** (`src/engine/interaction/interactionActivity.ts`, engine-level, no BenneScript import): each context reports from start to end (`beginInteractionActivity`, with a `gameplay` flag) and runs its steps inside `runInInteraction`, so a player walk it starts belongs to it. The dev/test hooks' idle check and the save policy read this registry.
- **Interrupt policy**: the room asks **`admitGameplayClick()`** before a click starts a walk or an interaction (background walk, verb or item on a prop / hotspot / character, verb on an inventory row). While a gameplay handler is still on its **opening walk** (its first timed step is a walk of the active player), the click cancels it; after that, world clicks are dropped until it ends; inside a cutscene they are always dropped. Clicks that only clear the armed verb or item are UI and always pass. A player walk dropped for another reason outside a cutscene cancels its handler (`abandon()`).
- **Save policy**: `saves.canSaveNow` is false while a gameplay activity runs (including one waiting on a dialog it started), while a dialog is open, and during a room transition. GUI, `onUpdate`, settings and pointer callbacks report `gameplay: false`. `saves.autosave()` defers instead of refusing: it saves on the first frame where `canSaveNow` is true (dropped by a load).
- Full rules: design doc §5 and §10.

### Registration and dispatch

Handlers are registered at module top level into tables; nothing runs per room except attaching and detaching the room's table.

| Module | Holds | Subscribes |
|---|---|---|
| `roomHandlers.ts` | Per-room tables: verb and item-verb handlers on that room's props / hotspots / characters, any-item handlers, region enter / exit, `onEnter` / `onEnterAfterFade` / `onLeave` / `onLoaded`, room-scoped `events.on`, `playFrom` | `attachRoomHandlers(roomId, scene, events)` from `RoomScene.create`; the returned detach runs on shutdown. A room module's registrations belong to the room whose module is loading (`getLoadingRoomScriptId()`). |
| `globalHandlers.ts` | Fallbacks (`fallbacks.on<Verb>`, `onAnyVerb`, `onUnhandled`, `on<Verb>Item`, `onItemUnhandled`), character-script handlers (`characters.x.on…`), any-room hooks (`game.onEnterAnyRoom` & co.), `onUpdate` | Once, at startup, on the global channels. Any-room hooks wait for the hook registry (`attachGlobalRoomHooks()` from `wireRoomTransitions`). |
| `itemHandlers.ts` | Item-row verbs (`items.x.onLook`), item-on-item (`onCombine`, `on<Verb>Item`, `onAnyItem`) and arming after item verbs | Once, at startup |
| `dialogs.ts` | Choice handlers, `dialog.onStart`, the dialog stack | Once, at startup |
| `guis.ts` | GUI lifecycle (`onBuilt` / `onShow` / `onHide`), control events, `gui.onAnyClick` | Once, at startup; `RoomScene` builds a `GuiRuntime` for every overlay and calls `notifyGuiBuilt` after each build |
| `registry.ts` | Handle lookups by id (rooms, items, verbs, room-scoped characters), so engine payloads become handles (`who`, `item`, `pointer.verb`) | — |

- **Dispatch order** is the engine's (`dispatchVerb.ts`, `dispatchInventoryOnVerbTarget.ts`, `dispatchInventoryVerb.ts`): room-scoped handler → character script → object `onVerbFallback` channel → `verb:global:<verbId>` (`fallbacks.on<Verb>`) → `verb:global:fallback` (`onAnyVerb`) → `verb:unhandled` (`onUnhandled`). `unhandled()` resumes the chain after the tier that called it (`continueVerbDispatchAfterRoom` / `ToGlobal`, `continueInventoryOnDispatchAfterRoom` / `AfterGlobal`).
- **Item arming** (decisions 28, 44): every `usesItem` verb on an inventory row arms the item, at once when the item has no handler for it (engine) or after its BenneScript handler (unless registered with `.doNotActivate`). After an item handler on a target, `applyInventoryDropPolicy` applies the drop policy unless the handler passed `{ doNotClear: true }`.
- **Lifecycle hooks**: `RoomTransitionOrchestrator.onRoomSceneCreateComplete` runs global then room enter hooks inside one pushed cutscene per phase (skippable unless a hook passed `{ skippable: false }`), waits for their contexts, fades in, then runs the after-fade hooks the same way. A save load runs the loaded hooks instead (`game.onLoadedAnyRoom`, then `room.onLoaded`), not as a cutscene. Play From setups (`scenes/playFromRegistry.ts`) run before the enter hooks on `boot` / `preview` starts when BENNE Play names one.
- **Dialogs**: `bennescript/dialogs.ts` keeps a stack over the engine's single session (`dialog/dialogSession.ts`); see **§3 → Dialog system**.

### Sprite animation & persistence

BenneScript separates a **saved** "what should this prop / character / item show by default?" from a **temporary** one-shot clip:

- **Props** (`PropHandle`): **`animation`** get/set is the prop's **base** Aseprite tag (JSON `tag` until a script overrides it); setting it writes game state and updates the sprite at that line. **`play(tag)`** is a timed one-shot that returns to the base tag; it never writes game state. **`visible`** / **`show()`** / **`hide()`**, **`clickable`** (when false, `RoomScene` disables the sprite's input and skips it in hover, cursor and verb hit tests), **`description`** (the hover / verb-line name), **`fade(alpha, seconds)`** (timed; the end alpha is saved), **`moveTo(point)`** (teleport of the **authoring** origin; handles tight placement and parallax) and **`slideTo(point, seconds)`** (timed tween through `movePropToNow`).
- **Characters** (`CharacterHandle`, and `player` for the active one): **`animation`** reads the **effective** key (saved override, else the live directional idle / walk / talk tag) and sets the saved override; **`stopAnimation()`** clears it. **`play(tag)`** is a timed one-shot; looping clips (`loop: true` → Phaser `repeat: -1`) count one full cycle before reverting. **`visible`**, **`movable`** (when false, pathfind walks including click-to-walk are no-ops; `moveTo` still teleports), **`clickable`**, **`description`**, **`fade(alpha, seconds)`**, **`startFollowing`** / **`stopFollowing`** (persistent trail behavior; idempotent for the same target, which updates saved options), **`speechPosition`** / **`speechOffset`** / **`resetSpeechPosition()`**. Setters persist even without an active `RoomScene` when a `GameStateManager` is active.
- **Items** (`ItemHandle`): **`animation`** / **`cursorAnimation`** get/set the effective **GUI icon** and **armed cursor** tags (the `cursorAnimation` getter is `''` when the armed pointer would fall back to the verb / global cursor); **`description`** the hover name. Through the active room when there is one (which refreshes the inventory GUI and cursor), else straight into the game state.
- **Positions** (character feet after a walk or teleport, prop authoring origin) are **not** written per tick: `RoomScene.create` registers a **snapshot flush hook** that writes them on room leave and on every `getSnapshot` (so saves and `saves.export()` include them).

**Persistence** (**`GameStateManager` variables**, same snapshot pipe as `flags` / `vars`):

- **Room visits** (room-scoped): `` `room:<roomId>:visitCount` `` — integer **`>= 0`**; the engine increments it **once per room load**, before the enter hooks; exposed as **`room.visitCount`** (settable, for Play From), **`room.isFirstVisit`**, **`room.hasVisited`**, and **`RoomTransitionContext.visitCount`**.
- **Props** (room-scoped):
  - `` `room:<roomId>:prop:<propId>:animation` `` — base tag; applied when `RoomScene` spawns props.
  - `` `room:<roomId>:prop:<propId>:visible` `` — **`door.visible`** / `show()` / `hide()`; spawn applies via **`readSavedPropVisible`** (JSON `visible` is the default).
  - `` `room:<roomId>:prop:<propId>:clickable` `` — **`door.clickable`**; **`readSavedPropClickable`** (JSON `clickable === true` is the default).
  - `` `room:<roomId>:prop:<propId>:description` `` — **`door.description`** (including empty); **`readSavedPropDescription`**.
  - `` `room:<roomId>:prop:<propId>:alpha` `` — the end alpha of **`door.fade(…)`**; **`readSavedPropAlpha`** (JSON `alpha` ?? `1`).
  - `` `room:<roomId>:prop:<propId>:position` `` — `{ x, y }` authoring coords, **lazily** written by the flush hook; source is the prop's authoring position, not its live `sprite.x / y`.
- **Characters** (global per definition id):
  - `` `character:<characterId>:animation` `` — override tag; cleared by **`stopAnimation()`**.
  - `` `character:<characterId>:visible` `` / `:movable` / `:clickable` / `:description` — the matching properties; effective values via **`readSavedCharacterVisible`** / **`Movable`** / **`Clickable`** / **`Description`**, with the JSON (first spawn row for that id in the active room) as the default.
  - `` `character:<characterId>:followingTarget` `` — a character definition id or the literal **`"player"`** (resolved to the active player) while **`startFollowing`** is active; `` `:followOptions` `` — merged follow tuning (`minDistance`, `repathThreshold`, `offset`, `speedMultiplier`, `faceTargetWhenIdle`, `pauseDuringCutscene`), read via **`readSavedCharacterFollowEffectiveOptions`**.
  - `` `character:<characterId>:alpha` `` — the end alpha of **`jensen.fade(…)`**; applied on both image-only and Aseprite spawn paths.
  - `` `character:<characterId>:speechPosition` `` — `{ x, y }` room coords for the speaking-text GUI's bottom centre (**`jensen.speechPosition`**); `` `:speechOffset` `` — canvas-pixel offset (**`jensen.speechOffset`**). Both cleared by **`resetSpeechPosition()`**; read by **`RoomScene.resolveSpeechOverlayScreenPosition`** whenever a line opens.
  - `` `room:<roomId>:character:<characterId>:position` `` — `{ x, y }` **feet** coords, **per room**, lazily written by the flush hook.
- **Hotspots** (room-scoped): `` `room:<roomId>:hotspot:<hotspotId>:active` `` and `` `:description` `` — **`battery.active`** / **`battery.description`**.
- **Regions and walkables** (room-scoped): `` `room:<roomId>:region:<regionId>:active` ``, `` `room:<roomId>:walkable:<walkableId>:active` `` — **`regions.x.active`**, **`walkables.x.active`**.
- **Inventory** (per item id, global): `` `inventory:<itemId>:defaultAnimation` ``, `` `:cursorAnimation` ``, `` `:description` `` — **`items.x.animation`** / **`cursorAnimation`** / **`description`** (an empty description persists as empty; an empty tag clears the override).
- **Dialog options**: `` `dialog:<dialogId>:option:<optionId>:enabled` `` / `` `:used` `` (**`options.x.on()`** / **`off()`**; see **§3 → Dialog system**).
- **Flags and variables** declared in `state.ts`: the flag's name (or its **`saveKey`**) in **`flags`**, the variable's name in **`variables`**.

**Snapshot flush hooks** (`src/engine/gameState/snapshotFlushHooks.ts`): **`registerSnapshotFlushHook(fn)`** returns an unregister function; **`runSnapshotFlushHooks()`** runs every hook in order with a per-hook `try / catch`, so a failing hook never breaks `getSnapshot`. Wired into **`GameStateManager.getSnapshot`** and **`RoomTransitionOrchestrator.prepareForLeave`** (through **`RoomScene.flushRuntimeStateToGameState`**). Scripts never call it.

**Engine touchpoints**: `src/engine/benneAnimationRuntime.ts` (variable-key helpers, follow persistence and merge helpers, `promiseWhenSpriteAnimationFinishes`); `src/engine/inventory/inventoryScriptingAnimations.ts` (inventory animation and description keys); `RoomScene`'s `…Script…` methods (`getPropScriptBaseAnimationTag`, `setPropScriptBaseAnimationTag`, `playPropScriptAnimationOneShot`, `fadePropScriptAlpha`, `setPropScriptVisible`, `setPropScriptClickable`, `setPropScriptDescription`, `movePropToNow`, `setCharacterScriptAnimationOverride`, `playCharacterScriptAnimationOneShot`, `fadeCharacterScriptAlpha`, …), which the handles call through `characterOps` (`bennescript/actions.ts`) and `handles.ts`.

### Speech settings and character speech presentation

- **Runtime preferences**: `game-config.json` `speech` provides defaults; **`settings.speech.*`** (same names: `clickToSkip`, `showText`, `msPerCharacter`, `durationMultiplier`, `minDurationMs`, `maxDurationMs`, `defaultTalkOffset`) and the shortcuts **`settings.textSpeed`** / **`settings.clickToSkip`** read and write player overrides. `readEffectiveSpeechSettings(manager)` and `computeSpeechLineDurationMs` resolve override → config default. **`settings.dialog.choiceOptionsViewportHeightPx`** / **`usedColor`** do the same for the `dialog` section (`undefined` clears).
- **Persistence and events**: overrides are stored eagerly under **`speech:*`** / **`dialog:*`** variables (`speechGameState.ts`, `dialogGameState.ts`). Snapshot replacement preserves omitted keys unless `initialGameState.variables` seeded them, so they behave as player settings rather than save-slot state. Every setter emits **`benne:speechSettingsChanged`** (the room refreshes its overlays), then runs **`settings.onChange`** handlers. A per-line `player.say(…, { clickToSkip })` remains the highest-precedence override.
- **Character color**: optional `CharacterData.speechColor` tints the speaker's Speaking Text; `RoomScene` builds a first-wins color map by definition id and `setDialogTextOverlay` applies it through `GuiOverlayHandle.setPrimaryTextColor`.
- **Character position overrides**: absolute **`speechPosition`** (room coords) has the highest precedence and bypasses `talkPoint` and the global offset; otherwise **`speechOffset`** (canvas pixels) is added after the projected default anchor and `defaultTalkOffset`.

### Per-frame hooks: `onUpdate`

**`onUpdate((deltaSeconds) => { … })`** registers a global per-frame callback (`bennescript/onUpdateRegistry.ts`) for the whole game, wherever it is written; a room script that only wants its own room checks `game.currentRoom !== room`. `RoomScene.update` runs the handlers **after** snap / follow / region / parallax / stack / path work, also while a cutscene runs. They are **not** sequenced (the transform leaves the callback alone). They run in a **frame context** (`runFrameHandler` in `interactionContext.ts`): `timed()` checks it before starting any timed action, so a walk, line, `wait`, `face` or fade there throws **`TimedActionInUpdateError`** (design doc decision 53). A failing handler is logged once per message (not every frame) and doesn't stop the others; an ending call (`goTo`) just stops it. To start a sequence from a frame check, call `background(() => …)`, which gets its own context. `saves.autosave` uses the same registry to write a pending save on the first frame where saving is allowed.

### Cutscene mode

A cutscene ignores world clicks for its duration and is **skippable with ESC** (see **Skipping cutscenes**).

- **Automatic**: each room's enter phase (`game.onEnterAnyRoom` + `room.onEnter`) and after-fade phase (`game.onEnterAnyRoomAfterFade` + `room.onEnterAfterFade`) run inside one pushed cutscene per phase. Loaded hooks and dialog choice handlers are **not** cutscenes (decision 19); scripts wrap long choices in `cutscene(…)`.
- **Explicit**: **`cutscene(fn, options?)`** (`bennescript/blocks.ts`) pushes a cutscene on the room for its body and pops it when the body ends (not after a cancellation, which already emptied the room's stack). Push / pop are reference-counted, so nesting is safe. **`game.isCutsceneActive`** reads the state.

**What is suppressed**:

| Input | During cutscene | During a speech line only |
|-------|:---------------:|:----------------------:|
| Background empty-floor walks | ✗ | ✗ |
| Prop / hotspot / character clicks | ✗ | ✗ |
| Inventory row clicks | ✗ | ✗ |
| GUI button clicks | ✗ | **✓ live** |
| Hover descriptions (`pointer.hover`, `pointer.sentence`; a running clicked action's line still shows) | suppressed | suppressed |
| Click-to-skip on speech lines | **✓ always live** | ✓ live |

(Outside cutscenes, the interaction lock in **The step runtime** decides which world clicks a running handler admits.)

**Walk contract**: inside a cutscene, if a scripted walk is interrupted, its task settles at once so the handler doesn't hang; outside one, an interrupted opening walk cancels the handler (`abandon()`).

**Custom cursor**: with the Aseprite cursor enabled, `cursor.busyAnimation` plays during a cutscene (missing or blank hides the cursor); idle and active animations are restored afterwards.

#### Skipping cutscenes

Pressing **ESC** fast-forwards the cutscene; it never aborts it. Every remaining statement still runs, in order, with the same conditions; only the *time* is removed, so a skipped cutscene ends in exactly the state it would have produced (positions and facings, animations and alpha, flags and inventory, a room change, the camera).

`$.step` calls **`finishNow()`** on the task in flight when ESC is pressed (through `RoomScene.registerCutsceneSkipFinisher`) and on every later task until the cutscene ends (`RoomScene.isCutsceneSkipFastForwarding()`). The primitives' skipped behavior:

| Step | Skipped behavior |
|------|------------------|
| `wait(n)`, `waitForClick()` | Resolves immediately |
| Speech lines, `` say`…` ``, `display(…)` | No overlay, no voice; resolves immediately |
| `walkTo` / `walkToClicked` (player and NPC) | Teleports to the end of the pathfound route with the arrival facing; still emits the walk start / stop pair |
| `fadeIn` / `fadeOut`, prop / character `fade`, control `fadeTo` / `tweenTo`, prop `slideTo` | Jumps to the end value |
| `camera.*` moves | Applied with a zero-second transition |
| One-shot `play(…)` | Lands on the base / effective animation without playing the clip |
| `sfx.x.play()` / `playAndWait()` | Skipped (one-shot sounds leave no lasting state) |
| `music.x.play()` | Track still changes, without the crossfade |
| `video.x.play()` / `playAndWait()` | Video never starts; `onComplete` and `benne:video:ended` still fire |
| Flags, variables, inventory, `moveTo`, setters | Unchanged — already instant |

**Opting out**: `game-config.json` → `"cutscenesSkippable": false` for the whole game; `{ skippable: false }` on `cutscene(…)`, `room.onEnter` / `onEnterAfterFade` and `game.onEnterAnyRoom` / `onEnterAnyRoomAfterFade`. One unskippable entry anywhere on the cutscene stack locks the whole nest; for the enter / after-fade phases, one unskippable hook locks that phase.

**ESC and video**: ESC stops a standalone video. Inside a skippable cutscene, one ESC press skips the whole cutscene, video included.

**Key modules**: `RoomScene` (`pushCutscene` / `popCutscene` / `isCutsceneActive`, `canSkipActiveCutscene` / `requestCutsceneSkip` / `registerCutsceneSkipFinisher`, `onRoomKeyDown`), `bennescript/blocks.ts` (`cutscene`), `bennescript/interactionContext.ts` (skip in `step`), `RoomTransitionOrchestrator` (automatic enter / after-fade wrapping), `RoomTransitionHookRegistry` (per-hook `skippable`), `buildGuiOverlay` (`isButtonClickSuppressed`), `src/types/cutscene.ts` (`CutsceneOptions`), `src/types/game.ts` (`cutscenesSkippable`, `cursor.busyAnimation`).

### GUI behavior runtime (`GuiRuntime`)

After **`buildGuiOverlay`** composes a GUI in `RoomScene`, the room constructs a **`GuiRuntime`** (`src/engine/gui/GuiRuntime.ts`: immediate control operations only) for every overlay and calls **`notifyGuiBuilt(guiId)`**, which runs that GUI's **`gui.onBuilt`** handlers. Handles reach the live controls through `guiRuntime(guiId)` (`bennescript/guis.ts`), so a `GuiControlHandle` works from any script while its GUI is in the active room (else a one-time DEV warning). Authors build low-level, composable UI behavior (slide panels, fades, hover bands) on this, without engine-specific helpers.

- **`gui.onShow` / `gui.onHide`** run when a script shows or hides the overlay (`guis.x.show()` / `hide()` / `visible =`, `gui.fadeIn()` / `fadeOut()`); not for overlays that start visible at room load (initial sync belongs in `onBuilt`) or for engine-internal visibility changes (a dialog hiding the HUD). Use `onShow` to refresh live data on every open (`saves.list()`); `onBuilt` runs once per room build. Visibility set by scripts is runtime-only: the next room load restores `*.gui.json` `visible`. `setGuiVisible` routes through `GuiOverlayHandle.setVisible`, so modal blockers and fixed controls stay in sync.
- **`gui.root`** is the **packed** container of every control **except** those listed in **`fixedControls`**; tweening it (`gui.root.tweenTo({ y: 0 }, 0.3, 'Sine.easeOut')`) moves the HUD while fixed controls stay. Optional **`GuiData.x`** / **`y`** set its initial position, e.g. **`"y": -34`** to park a dropdown bar offscreen. `GuiOverlayHandle.gameObjects` lists the packed container plus each fixed control's objects, for editor camera routing.
- **Controls** (`GuiControlHandle` → `ControlFacade`): `text`, `alpha`, `visible`, `x`, `y`, `enabled` (buttons, text inputs, checkboxes: hit-testing plus disabled chrome), `value` (sliders; setting it doesn't emit the change event), `checked`, `selectedIndex`, `setRowText`, `rowCount`, `focused`, `visualState` (buttons: `'normal'` / `'hover'` / `'pressed'` / `'disabled'`; `'normal'` returns control to the pointer), and timed **`fadeTo`** / **`tweenTo`** (seconds; `{ clickToSkip }` lets a click finish them).
- **Events**: `onClick`, `onActivate` (list boxes), `onSubmit` (text inputs) and `gui.onAnyClick` are sequenced, **non-gameplay** handlers (they don't take the interaction lock, so menus work during cutscenes). `gui.onAnyClick` starts once the button's own `onClick` handlers are over, and not when one of them ended the interaction (`goTo`, `saves.load`, `dialog.end`) or was cancelled. `onChange`, `onSelect`, `onMouseEnter` / `onMouseLeave` run immediately (`runDetached`); like every detached callback, one still running stops on a room change or save load.
- **Pointer hover**: `onMouseEnter` / `onMouseLeave` fire for any control with that id. Buttons use Phaser's native `pointerover` / `pointerout`; **`image`**, **`inventoryPanel`**, **`text`** and **`trigger`** use a **non-blocking scene-level `pointermove` observer** (**`installGuiControlPointerHoverObserver`**) that tests the pointer against the control's world bounds without `setInteractive`, so HUD overlays don't eat room clicks. Events are **`gui:<guiId>:control:<controlId>:mouseenter` / `:mouseleave`** (`guiControlHoverEvents.ts`).
- **`trigger` control** — **`GuiTriggerControl`** in `src/types/gui.ts` (`id`, `name?`, `x`, `y`, `width`, `height`, `active?`, `visible?`): never drawn (`debug.showGuiOutlines` traces it), uses the same observer; overlapping triggers fire independently; `active: false` emits nothing, and hiding the rect flushes a synthetic `mouseleave`.
- **Dropdown / slide-in HUD pattern**: park the bar with **`GuiData.y`**, add **two triggers** listed in **`fixedControls`** (a small reveal rect at the screen edge and a larger keep-alive rect over the bar), and tween `gui.root` from their hover events. Because triggers don't block, moving from the reveal zone onto a button inside the bar keeps the keep-alive zone "inside" (from the 2-click template's `inventoryBar.gui.ts`):

```ts
hoverZone.onMouseEnter(() => {
  gui.root.tweenTo({ y: 0 }, 0.3, 'Sine.easeOut')
})

hideZone.onMouseLeave(() => {
  gui.root.tweenTo({ y: -33 }, 0.25, 'Sine.easeIn')
})
```

- **Teardown**: `GuiRuntime.dispose` (from the overlay's `destroy`) kills tweens on the root and controls; `buildGuiOverlay` destroys the packed container, the fixed controls and its hover listeners. BenneScript GUI registrations stay in `guis.ts` for the next room; `onBuilt` runs again on every rebuild.

### Events

**`events`** (`bennescript/events.ts`) is the script face of `gameEvents`: `events.on(name, fn)` / `once` / `off` / `emit`, for engine events (`gameState:*`, `benne:dialog:*`, `verb:unhandled`; the `EngineEventName` union, which the editor completes) and events scripts send each other. Listeners run as detached BenneScript handlers: their lines are sequenced, they don't take the interaction lock, and one still running stops on a room change or save load (§5 rule 7). In a room script, `events.on` goes into the room's table, so the listener is live only while that room is active.

### Editor support

The VS Code extension's BenneScript layer is `benne-editor/src/bennescript/` (no `vscode` imports, shared with the TS server plugin): a **ScriptModel** over the TypeScript AST (registrations, speech lines, handle references), resolved through the generated modules by **`IdsIndex`**, drives the Inspector's handler chips, "add handler" / "reveal handler", Play From discovery, voice ids and the speaking-text CSV; the **TS server plugin** adds speaker diagnostics and completions, quoted string-union completions, and go-to-definition from a handle to its JSON. See design doc §9 and **§8**.

### High-DPI editor overlay

The editor preview uses **`Scale.RESIZE`** (not `Scale.FIT`) so the Phaser canvas always fills the VS Code panel. **Navigate mode** simulates the exact in-game view by computing `scale = min(panelW/gameW, panelH/gameH)` and using `cameras.main.setViewport(centreX, centreY, gameW*scale, gameH*scale)` — the viewport box is letterboxed inside the panel using the game background colour. **Edit mode** expands the viewport to the full panel (`setViewport(0,0,panelW,panelH)`), zooms to fit the room art, and enables mouse-wheel zoom (around the cursor) and middle-mouse pan. Pressing **F** resets to the fit-room zoom. The camera re-applies its mode automatically via `scale.on('resize')`. The DOM overlay canvas is sized to fill the full panel in both modes; all handle drawing uses `worldToCanvasCss(p, cam)` which accounts for the active camera zoom, scroll, and viewport origin (`cam.x`, `cam.y`). **Pointer capture** on the overlay handles drags; **`pointer-events: none`** in Navigate so `RoomScene` receives clicks. **Zoom formula** (Phaser 4-accurate): `scrollX = worldX - originX - (screenX - originX - cam.x) / newZoom` keeps the world point under the cursor fixed across zoom steps.

**Editor UI camera** (`RoomScene.ensureEditorUiCamera`): because the editor main camera uses `setZoom(scale)` while the shipped game keeps `cameras.main.zoom = 1`, Phaser 4's origin-aware zoom math pushes `scrollFactor: 0` overlays off the viewport by `origin × (1 − zoom)` pixels (hundreds of px at typical editor scales) — this is why the first "Show GUIs" attempt produced no visible pixels even with `visible: true` and correct bounds. `RoomScene` creates a second camera (`name: 'editor-ui'`) with the same viewport + zoom as `cameras.main` but `origin = (0, 0)` and `scroll = (0, 0)`, so GUI overlays render at `(x × zoom, y × zoom)` relative to the viewport top-left — matching the runtime placement. `GuiOverlayHandle.gameObjects` enumerates each overlay's top-level objects so the main camera can `ignore` them and the UI camera can `ignore` everything else; a `Phaser.Scenes.Events.ADDED_TO_SCENE` listener keeps the split correct for objects added after scene boot (tween sprites, debug overlays). The UI camera is torn down on `Phaser.Scenes.Events.SHUTDOWN`. The shipped game never calls `setEditorCameraMode`, so this camera is editor-only and has **zero** runtime cost.

### Runtime walk mesh (engine)

- **`src/engine/walkable.ts`**: **`isPointInWalkablePolygon`** — inside **active** outer, not inside any **active** hole; **`isPointInWalkableArea`** unions polygons; **`clampWalkDestinationTowardClick`** uses holed closest-point logic (used as the goal-clamping step inside pathfinding, and as the fallback when no path is reachable).

- **`RoomScene`** debug **`showRegionOutlines`**: strokes **active** `regions[]` polygons in amber (distinct from walkable green, prop magenta, and path cyan).

### Pathfinding (engine)

- **`src/engine/pathfinding.ts`** — `findWalkPath(start, goal, polygons) -> Point2[]` returns an ordered polyline of waypoints (goal last) routing the character around **holes** and **concave** parts of the walkable union. Used by both the player and NPCs.
- **Algorithm**: classical **reduced visibility graph + A\***, the canonical shortest-path approach for *simple polygons with holes* and what most modern 2D adventure engines use under the hood (Adventure Creator, Wintermute-family, PowerQuest polygon mode). Result is the **exact Euclidean shortest path** — a polyline that bends only at polygon corners, giving the classic LucasArts "walk around the obstacle" look.
- **Graph nodes**:
  - **Reflex** outer-ring vertices of each **active** polygon (convex outer corners are never on a shortest path and are omitted).
  - **All** vertices of each **active** hole ring (holes poke into the walkable region, so every hole vertex is reflex as seen from the walk side).
  - Each node is offset **~1 px inward along the interior angle bisector** so waypoints sit just inside the mesh rather than exactly on the boundary pixel. This both matches the classic LucasArts corner-radius feel and keeps segment-midpoint-in-walkable tests numerically robust at vertices.
- **Edges**: two points are connected iff the straight segment between them lies entirely inside the walkable region. Tested by (1) sampling the segment at t = 0.25 / 0.5 / 0.75 and checking each is in the walkable union, plus (2) a proper-crossing test against every ring edge (outer + active hole) that ignores shared-endpoint touches and collinear overlap.
- **Start / goal**:
  - Goal is first clamped to the walkable union (reuses `clampWalkDestinationTowardClick`).
  - If the **start** point is outside the walkable region (spawn / cutscene placement off the mesh), pathfinding is skipped and a **direct line** to the clamped goal is returned — preserves the pre-pathfinding behavior where off-mesh characters glide to the floor.
  - If start and goal are in **disconnected components** of the walkable union, A\* returns no path and the engine falls back to a direct line to the clamped goal.
  - If the straight segment from start to clamped goal is already inside the mesh, `findWalkPath` short-circuits to `[goal]` without running A\* (common case: clicking nearby open floor).
- **Complexity**: O((N+2)²) visibility edges per query, where N is the number of candidate nodes (typically tens for hand-authored rooms). Each visibility test is O(E) across all ring edges. Cheap in practice; invoked once per walk command (click-to-walk, `player.walkTo(…)`, or `jensen.walkTo(…)`), not per frame. No cross-query caching yet — future work if rooms ever grow to hundreds of vertices.
- **Integration in `RoomScene`**:
  - `walkPlayerToWorldPoint` / `walkCharacterToWorldPoint` (and the empty-space click handler) call `findWalkPath` and then chain **one Phaser tween per path leg** via `beginPlayerWalkLeg` / `beginNpcWalkLeg`. Facing is recomputed per leg with `facingFromWorldDelta` so the sprite turns into each new direction (`Walk` base animation swaps accordingly); `Idle` plays on final leg completion.
  - `PLAYER_WALK_START` fires **once** with the final clamped target; `PLAYER_WALK_STOP` fires **once** on `complete` (final leg) or `interrupted` (new walk pre-empts the chain, scene shuts down, etc.). Leg boundaries themselves do not emit events.
  - `stopPlayerMoveTween(emitStop)` cancels the current leg and clears `currentPlayerPath`; in-flight `onComplete` guards against advancing a superseded chain by comparing tween identity with `playerMoveTween`.

## 9. Game content templates and switch script

The repo can hold **multiple authored game layouts** (e.g. a two-button verb game vs. a nine-verb SCUMM-style shell) while keeping **`src/engine/`** shared and **`src/game/`** as the **single live slot** Vite and the editor target.

**Layout**

| Path | Role |
|------|------|
| **`game-templates/<template-id>/`** | Complete template tree: `game-config.json`, `globalScript.ts`, `assets/`, `rooms/`, `characters/`, `guis/`, `inventory/`, etc. Each folder is one switchable template (**`2-click`**, **`9-verb`**, **`ai-apocalypse`**). |
| **`src/game/`** | Whatever template is active right now: `game-config.json` and `globalScript.ts` at the root alongside content folders — same shape as a shipped game folder. It holds only content; the code that loads it is the engine's (**`src/engine/content/`**). **Git tracks nothing in `src/game/`**, so switching templates leaves the working tree clean, and template edits reach git when **`sync-template-down`** (or **`set-template`**) copies them into **`game-templates/<name>/`**. **`git clean -x`** deletes unsynced edits there. |

**`game-config.json` → `name`**

Optional string field **`name`** on **`GameSettings`** ([`src/types/game.ts`](../src/types/game.ts)): **template id** used only by tooling. It must match the folder name under **`game-templates/<name>/`** so **`sync-template-down`** knows where to write. The engine does not branch on it.

**Script and npm commands**

Implementation: **[`scripts/switch-game-template.mjs`](../scripts/switch-game-template.mjs)** (Node ESM). Run from the **repo root** (expects **`src/game/`** and **`game-templates/`**).

| Command | Effect |
|---------|--------|
| **`npm run sync-template-down`** | Read **`name`** from **`src/game/game-config.json`**, then mirror **template** files from **`src/game/`** → **`game-templates/<name>/`**. |
| **`npm run set-template -- <name>`** | Save the **current** live tree (template sync-down), then **replace** everything in **`src/game/`** with the contents of **`game-templates/<name>/`**. Shorthands: **`npm run set-template:2-click`**, **`npm run set-template:9-verb`**, **`npm run set-template:ai-apocalypse`**. It finishes by rebuilding the editor preview bundles (**`build:previews`**) from the new game. After switching, **`npm run test:playthrough`** plays the new template's tests (`tests/playthrough/<name>/`). |
| **`npm run template:status`** | Show whether **`src/game/`** has edits not yet in **`game-templates/<name>/`** (exits 1 if so). **`npm run check`** runs it as a warning (**`check:template-sync`**). |
| **`ensure-template [name]`** | Run by **`npm install`** (**`postinstall`**): when **`src/game/`** holds no template (a fresh clone, CI), copy in **`ai-apocalypse`** (or **`name`**). Does nothing when one is loaded. |

Each mirror builds a **plan** (new / modified / unchanged / orphan deletes), prints a summary, and asks for confirmation unless **`--yes`** / **`-y`** is passed (e.g. **`npm run set-template:9-verb -- --yes`**).

**Release templates vs development templates**

Only the templates listed in **[`scripts/lib/releaseTemplates.mjs`](../scripts/lib/releaseTemplates.mjs)** (**`2-click`**, **`9-verb`**) ship: **`bundle:scaffold`** bundles just those into the VSIX's New Game picker, and **`test:artifacts`** fails if the scaffold holds anything else. **`ai-apocalypse`** (a complete game, with only the art it loads) stays in this repo as a development baseline: it swaps in with **`set-template`**, gets content validation like the others, and is played by the template tests.

**What counts as “template”**

Everything in **`src/game/`** — **`game-config.json`**, **`globalScript.ts`**, and all content subdirectories (rooms, assets, characters, guis, inventory, dialogs, pdcs, …) — except generated **`*.ids.ts`** handles.

**Special cases the script handles**

- **`.gitkeep`** under template folders is ignored by the mirror so empty directories can stay in git without being deleted when **`src/game/`** has no matching file.
- **Editor / OS duplicate names** are ignored and dropped as orphans on sync (never copied into templates): e.g. **`game-config copy.json`**, Windows **`… - Copy.ext`**, Explorer **`… (1).ext`**, **`.DS_Store`**, Office **`~$…`** lockfiles.

**Authoring pitfall**

Empty templates still need a **`src/game/rooms/rooms.manifest.json`** (and usually manifest **room entries**) because **`src/engine/content/loadStartRoom.ts`** imports the manifest statically; the **Create New Room** wizard only **appends** to an existing manifest — it does not create the file if missing.

For packaging, distribution, and VSIX publishing, see **[publishing.md](publishing.md)**.

## 10. Future Considerations

- **Room transitions (extensions)**: The shipped path **restarts `RoomScene`** with new **`RoomSceneStartData`** via **`RoomTransitionOrchestrator`**. Deeper work might add **preloading**, **shared caches**, or **non-black cutscene transitions**; **global narrative state** should remain on **`GameStateManager`** unless a game explicitly resets it.
- **Post-processing**: `PostEffects.ts` is ready for **camera filter** composition (CRT, dither, etc.).
- **Audio**: **`sfx`** / **`music`** cover **SFX + music** from authored assets (sound `play()` never waits; `playAndWait()` is a timed action); further work might add **spatial audio**, **voice/dialogue bus mixing**, or **event-driven triggers** outside scripts.
- **Dialogue / inventory UI**: **`say`** shows the **Speaking Text** overlay (**`speaking-text`**). **`inventoryPanel`** GUIs render a carried-items grid with optional **paged scroll** (`scrollDirection`, `backButton`, `forwardButton` in **`*.gui.json`**) and **reactive rebuild** on **`gameState:inventoryChanged`** / **`gameState:replaced`** when scroll is configured. **Richer dialogue** (choices, portraits) and **full inventory UX** (drag-reorder, cursor) remain **future work**; **`inventory`** and **`pointer.item`** are available for wiring.
- *(Resolved by the BenneScript refactor: give-on-target is `penny.onGiveItem(items.sandwich, …)` on any prop, hotspot or character, generated from the `give` verb's `usesItem`; see design doc §8.)*
- **Editor**: VS Code extension + **`build:room-preview`** ship a **live `RoomScene` preview** in a webview with **polygon editing** (walkable, prop colliders, **hotspots**, **regions**, and **room points**) via **`RoomPolygonEditScene`**. **`build:character-preview`** adds a separate webview for **feet** + **click collider** polygons. **`build:benne-play`** ships the **BENNE Play** full-runtime panel (same boot as **`main.ts`**, not the preview loader) — see **§8**.
- **HMR script registry hygiene:** During dev hot reload, side-effect `register*Script` calls can accumulate stale handlers (e.g. room enter hooks) if registries are append-only. Add HMR-safe registry reset/dedupe behavior (`import.meta.hot.dispose` and/or module-keyed maps) to prevent duplicate/stale hook execution without requiring full page reloads.
