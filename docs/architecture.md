# BENNE — Architecture

## 1. Overview

**BENNE** is a **web-based point-and-click adventure game engine** (LucasArts SCUMM / AGS / PowerQuest): fixed-resolution pixel rooms, click-to-walk, and verb-style interactions on props and characters. The runtime is **Phaser 4** (RC), **TypeScript**, and **Vite**.

**Core design goals**

- **Data-first**: Rooms, characters, **GUIs** (overlay UI definitions), **inventory** definitions, **dialogs** (topic lines + choice options in JSON), and game tuning live in **JSON** (and Aseprite exports) under `src/game/`; TypeScript supplies **room** / **character** / **GUI** / **inventory** / **dialog** scripts and engine code, not hand-authored level blobs in code. Optional **`src/game/pdcs/<id>/<id>.pdc.json`** files store **designer-only puzzle flow charts** (Cytoscape JSON); they are **not** registered by **`registerGameContent`** and do not participate in runtime loading.
- **Separation**: **`src/engine/`** is reusable; **`src/game/`** is project-specific content and registration (`registerGameContent`).
- **Retro display**: Internal resolution defaults to **352×198** and remains the source of truth for gameplay + GUI coordinates. Runtime scaling uses a **hi-DPI canvas** strategy (`Scale.NONE`) instead of `FIT + MAX_ZOOM`: backing buffer targets **parent CSS size × device pixel ratio** (capped), `scale.zoom = 1 / dpr` keeps CSS sizing predictable, and the game frame is aspect-fit via `cameras.main.setViewport` + smooth (non-integer) zoom. Resize uses a two-phase path in `benneRuntimeHiDpiScale.ts`: per-frame cheap camera/CSS updates while dragging, plus a short debounced backing-store commit (`scale.resize`) to reduce flicker. Startup runs an unconditional commit burst across initial RAFs, and camera dedupe includes active-scene keys so scene changes (`BootScene` -> `RoomScene`) still force first-frame camera application. **Post-processing** is wired as a **camera hook** (`attachPostProcessingPlaceholder`) — currently a no-op, reserved for CRT / dissolve-style effects.
- **Scrolling rooms**: Rooms wider or taller than the viewport declare `size` in `RoomData` (e.g. `"size": { "width": 704, "height": 198 }`). `RoomScene` reads this and sets `cameras.main.setBounds` + `startFollow` on the player so the camera tracks movement within the room. An optional `scrollBounds` field further restricts how far the camera pans.
- **Simplicity over frameworks**: One primary gameplay scene (`RoomScene`), a thin boot loader (`BootScene`), and a **global `EventBus`** for script-facing events instead of a heavy ECS.

## 2. High-Level Architecture

**Major pieces**

| Area | Role |

Every preview and **BENNE Play** spread the same renderer fields (see `.cursor/rules/benne-preview-rendering-parity.mdc`). Scenes are **not** imported here; doing so would transitively pull `resolveGameAssetUrl.ts` (which `import.meta.glob`'s every asset PNG) into preview bundles. |

| **`BootScene`** | Loads assets for the **start room** (manifest + globbed JSON), then **`startInitialRoomFromBoot`** ( **`setLastRoom(null)`**, registry **`'boot'`**, `scene.start(Room, startData)`) or the same state + **`scene.start`** if no orchestrator. |
| **`RoomScene`** | Renders one room: background, Aseprite props, hotspots, characters, player walk, prop/character hit tests, debug overlays, and **every** screen-space GUI from **`./guis/**/*.gui.json`** (via **`buildGuiOverlay`**), except **Speaking Text** (**`speaking-text`**, reserved for **`say`**) and **choice-dialog GUI ids** (reserved for **`B.dialog`…`start` / `stop`** — see **§3 → Dialog system**). |
| **`EventBus` (`gameEvents`)`** | `Phaser.Events.EventEmitter` — verb dispatch is **listener-first** (room-scoped per-verb events, then character-global, then object **`onVerbFallback`**, then globals / **`verb:unhandled`**). Props and hotspots wire handlers only in **`*.room.ts`**; **`InventoryItemData`** may still carry optional **`onVerb`** / **`onVerbFallback`** for tooling; **`CharacterData`** mirrors props/hotspots (**`onVerbFallback`** only, no **`onVerb`**). |
| **`registerGameContent`** | **Discovery** pass for all game script modules. `*.room.ts` files are registered as **lazy** Vite dynamic-import factories (not executed here) via **`registerRoomScriptModuleLoaders`**. All other script types (**`*.character.ts`**, **`*.gui.ts`**, **`*.inventory.ts`**, **`./dialogs/**/*.dialog.ts`**, **`globalScript.ts`**) still use eager `import.meta.glob` so their side-effect registrations run immediately. Also registers **`*.inventory.json`** and **`./dialogs/**/*.dialog.json`** (`registerInventoryDefinitionsFromGame`, `registerDialogDefinitionsFromGame`); runs GUI callbacks; records each **`GuiBenneScript`** instance per `guiId`. Room script modules are executed on demand by **`ensureRoomScriptLoaded`** (called by `BootScene` and `RoomTransitionOrchestrator`) so only the active room's handlers register when its `RoomScene` runs `create`. **`wireBenneGlobalScripts(game, gameEvents)`** in `main.ts` (after `createBenneGame`) always constructs **`RoomTransitionHookRegistry`** + **`RoomTransitionOrchestrator`**, and when a **`registerGlobalScript`** module exists, wires **`GlobalBenneScript`** and **`setGlobalBenneScriptForRoomTransitions`**. |
| **`src/types/generated/benne-game-ids.d.ts`** | **Build-time** literal unions for Bennescript string ids (`CharacterId`, `PropId`, `RoomId`, …). Scanned from **`src/game/`** by **`scripts/generate-game-ids.mjs`** (same folder conventions as **`benne-editor/src/gameDiscovery.ts`**). Regenerated on **`npm run build`**, **`npm run dev`**, and when the BENNE Editor changes game JSON. **Types only** — zero runtime cost. See **§7 → Generated game ID types**. |
| **`src/game/assets/`** | Images + Aseprite JSON; URLs resolved at build time via Vite `import.meta.glob` (`boot/resolveGameAssetUrl`). |

**Editor (out of runtime path)**  
The **VS Code extension** (`benne-editor/`) and **`src/editor/preview/`** build **bundled Phaser previews** (room, character, GUI, inventory) that fetch game assets via webview URIs — tooling only, not part of the shipped game loop. The room preview reuses **`RoomScene`** with editor-only loader/scenes (**`createRoomPreviewGame.ts`**, **`RoomPolygonEditScene`**). **BENNE Play** is different: a **full runtime** panel (**`bennePlayPanel.ts`**, **`benne-play`**) that runs the same **`BootScene` + `RoomScene`** stack as **`main.ts`**, from a **separate Vite bundle** under **`benne-editor/media/benne-play/`** — use it to verify verbs, inventory, GUIs, and room transitions without replacing the authoring canvas (you can keep both panels open). **Play From** (**`B.playFrom`** in **`*.room.ts`**, optional **`__BENNE_PLAY_FROM_NAME`** + room preview **Play from** dropdown) loads arbitrary scripted starting state on boot without touching the shipped browser entry. **Dialogs** have **no** dedicated Phaser preview bundle; authoring is **Inspector** (**`*.dialog.json`**) plus **`*.dialog.ts`** in the editor (see **Dialogs** under **Inspector view** below).

**BENNE — Actions view** (`benne-editor`): Verb rows use **`game-config.json`** `verbs` (same order and defaults as the engine if `verbs` is omitted).

**BENNE — Inspector view** (`benne-editor`): A third sidebar **WebviewView** (**Inspector**) under the same BENNE activity bar. When the main tree selection is a **room** or **any item under a room** (walkable polygon or hole under **Walkable areas**, prop, hotspot, point, region, spawned character), the Inspector edits that room’s **`*.room.json`**. When the selection is a **puzzle dependency chart**, the Inspector shows only a placeholder message (the chart is edited in the **PDC Editor** panel, not in the Inspector webview). When the selection is a **dialog**, the Inspector edits that dialog’s **`*.dialog.json`** and the extension keeps **`*.dialog.ts`** as the only BENNE-staged editor document (single-column layout — no Phaser preview tab). The webview is styled with **VS Code theme variables** (inputs, buttons, panel borders) so it matches the host. **Room metadata** and **Walkable areas** are top-level **accordions** (`<details>`). Metadata uses a **property grid** for **Display name** and **Room ID** (read-only badge), a **Fit to background** action, and compact **dimension grids**: one row for **room size** (**W** / **H**), and a **2×2** grid for **scroll bounds** (**X**, **Y** on the first row; **W**, **H** on the second). Walkable polygons and holes stay in a table with **active** toggles, per-row **Edit** (opens the room preview in **walkable** edit mode for that polygon or hole), add-polygon / add-hole controls, and **Edit in Preview** links under **room size** and **scroll bounds** in metadata (those jump straight into **room size** / **scroll bounds** rect edit modes in the preview — no top-bar mode dropdown). **Hotspots**, **Props**, **Spawned characters**, **Points**, and **Regions** each sit in their own accordion, with a **vertical list of flat cards** inside. Optional field groups within a card use a nested **card subsection** (`<details class="benne-card-subsection">`, rendered by **`renderInspectorCardSubsection`** in **`inspectorCardSubsection.ts`**) — e.g. **Animations** on room **prop** cards and grouped **Sheet** / **Grid placement** / **Animations** (and similar) on **GUI** control cards; open state keys are **`parentEntity` + parent id + subsection id** (`guiControl`, `prop`, …). Cards carry **`data-entity` / `data-id`** for tooling; tree focus is mirrored in the payload as **`expanded`**, which **scrolls the matching card into view** and opens its section. **Prop** cards keep **Visible** in the header; **zIndex**, **baseline Y**, **Parallax**, **Alpha**, and **Clickable** use the property grid, with **Description** and a **Verbs** label above **verb chips** (same defined vs add behaviour as **Actions**). **Inv** appears after verb rows when the row is hit-testable for use-on-target authoring (**clickable** props, **active** hotspots, spawned characters whose definition is **clickable**, and on standalone **character** definitions that are **clickable**): it runs **`benne-editor.addRoomInventoryUsedOnStub`** or **`benne-editor.addCharacterInventoryUsedOnStub`**, inserting **`B.whenInventoryUsedOn('…')`** into **`*.room.ts`** or **`*.character.ts`** with example **`if (payload.itemId === '…')`** branches for inventory ids discovered under **`src/game/inventory/`**. **Clickable** props get a subtle tint. All props get an **Edit in Preview** button: clickable props open collider / walk / look / baseline editing; non-clickable props open **baseline** editing only (same drag-line as clickable). **Hotspot** cards use **Active** (JSON **`active`**) in the header and a property row for **zIndex**. **Character** cards keep **Visible** in the header; **X** / **Y** use the dimension-grid row, then a property grid for read-only **Clickable**, **zIndex**, **Facing**, and **Animation**. **Edit in Preview** on props, hotspots, **points**, and **regions** drives the **BENNE Room preview** the same way as selecting that entity in the main tree; **Edit** on walkable rows and **Edit in Preview** for **room size** / **scroll bounds** do the same for those geometry tools. **`RoomPreviewPanelController.focusInspectorGeometry`** folds a one-shot target into the next **`loadRoom`** so the preview opens in the correct **`polygonEditBridge`** mode (**spawned characters** do not use **Edit in Preview** here). Selecting a **walkable polygon** or **hole** under **Walkable areas** in the main tree sets **`EditorSelection.roomPanel`** to **`walkable`** and loads the preview in **walkable** mode directly. **`*.room.json` remains the source of truth**; edits persist with **Save** and field **blur**, and **Open raw JSON** opens the file. **Actions** stays the compact verb-centric list; the Inspector is the full-room surface. Implementation: **`benne-editor/src/inspector/inspectorMain.ts`** bundles to **`benne-editor/media/inspector/inspector.js`**; shared shell CSS lives in **`inspectorWebviewViewProvider.ts`** (run **`npm run compile`** or **`npm run watch`** under `benne-editor/` after UI changes). After changing **`src/editor/preview/roomEditorMain.ts`** (or other room preview entry code), rebuild from the repo root: **`npm run build:room-preview`**. Selecting a standalone **character** or **inventory** definition opens the character or inventory Inspector; selecting a **GUI** opens the GUI Inspector for **`*.gui.json`** (see **GUIs** below).

- **Props** (selected under a room): Verb chips and **Inv** are shown only when the prop is **`clickable: true`** (matches the engine). Non-clickable props get **Make clickable** first (`clickable` in room JSON); authors still add a **collider** (≥3 points) in the preview or JSON. Non-clickable props can still author **`baseline`** in the room preview (same drag-line as clickable props). Verb handlers live in **`*.room.ts`** (`registerRoomScript`); adding a verb inserts a Bennescript stub there. Inspector / Actions highlight defined verbs by scanning **`*.room.ts`**, not room JSON.

- **Hotspots**: Same verb / add-verb flow when a hotspot is selected; handlers in **`*.room.ts`**. Inactive hotspots show a reminder that they are not hit-tested.

- **Characters**: When a character is selected, **`clickable: true`** is required before verb rows (same as the engine). **Make clickable** updates **`*.character.json`**. Verbs add stubs in **`registerCharacterScript('id', ({ B }) => { … })`** in **`*.character.ts`** or room-scoped handlers in **`*.room.ts`** (lazily loaded per-room by **`registerGameContent`**; **`RoomScene`** runs the callback when that character is spawned in the active room). For **precise clicks** on sprites with transparent padding, authors add **`collider`** (≥3 points in **frame space**, like **`feet`**) in **`*.character.json`** or in the **BENNE Character preview** (polygon editor, same interaction model as **prop colliders**). Optional **`walkToPoint`** / **`talkPoint`** (frame space, same origin as **`feet`**) tune **`walkTo('…')`** resolution and script-facing **world** hints on verb clicks. Optional **`movable: false`** disables pathfind walking for that definition by default ( **`moveTo`** still teleports); scripts may override with **`B.character(id).movable`** / **`B.player.movable`** (see **§7 → Sprite animation & persistence**). The **Actions** view may remind you to add a collider when the character is clickable but none is defined.

- **GUIs**: **Main tree** lists **`src/game/guis/<id>/<id>.gui.json`** under a **GUIs** group (below **Characters**); expanding a GUI lists **`controls[]`** entries (same **`type:id:index`** keys as the GUI Inspector), and selecting a control scrolls that card into view (**`EditorSelection.guiPanel`** → **`InspectorGuiState.expanded`**). **Create GUI** scaffolds **`*.gui.json`**, **`*.gui.ts`** (`registerGuiScript`), and **`src/game/assets/images/guis/<id>/`** (Aseprite export target). The GUI **Inspector**'s **Controls** section has an **Add Control** button that opens a **Quick Pick** (Text / Text Input / Inventory Panel / Image / Button / Checkbox / Slider / Trigger / Grid), then runs **`runAddGuiControlWizard`** (**`benne-editor/src/guiScaffolding.ts`**) — prompts for an optional control id (defaults such as `text1` / `inventoryPanel1` / `image1` / `grid1`; skipped if left blank where allowed), appends a kind-specific default entry to **`controls[]`** in **`*.gui.json`**, and refreshes the Inspector (same pattern as **Add Hotspot** / **Add Prop** / **Add Point** / **Add Region** in the room Inspector). Selecting a GUI opens the **two-row** layout with **BENNE GUI preview** on top (internal resolution from **`game-config.json`**) and the companion **`*.gui.ts`** in the Benne **script row**; the **`*.gui.json`** is edited in the **Inspector** (or any open editor tab), not as a second tab stacked with the script in the bottom row. **Runtime** (**`RoomScene`**): every matching **`*.gui.json`** is composed with **`buildGuiOverlay`** (screen-fixed **`scrollFactor` 0**), **except** overlays whose id is Speaking Text (**`speaking-text`**) or appears in **`getRegisteredDialogChoiceGuiIds()`** (those follow the reserved paths in **§3 → Scene / room system** and **Dialog system**). Supported **`controls`** are **`text`** (Phaser **`BitmapText`**), **`textInput`** (color-driven BitmapText input), **`inventoryPanel`** (player inventory grid), **`image`** (Aseprite tag from this GUI’s sheet), **`button`**, **`checkbox`** (sheet toggle), **`slider`** (sheet range control), **`trigger`**, and **`grid`** (layout container: other controls use **`gridPlacement`** to sit in a cell and move with the grid). Verb-style status lines are implemented with a **`text`** control plus **`registerGuiScript`** (see **`src/game/guis/verbs/verbs.gui.ts`**). Bitmap fonts for **`text`** live in **`src/game/assets/fonts/fonts.json`** (PNG + BMFont XML) and **`BootScene`** calls **`load.bitmapFont`**. **`B.player.say` / `B.character(…).say`** drive only the reserved Speaking Text (**`speaking-text`**) GUI via **`setDialogTextOverlay`**; **`B.dialog`…`start` / `stop`** drive reserved **choice-dialog** overlays (dynamic **`Option-Grid`** rows, scroll, **`whenChoice`**). All other GUI ids are ordinary HUD layers—there is **no** per-id whitelist beyond those reservations. **`GuiData.visible`**: for ordinary GUIs, **`false`** hides the overlay at room load; omitted or **`true`** shows it. Speaking Text (**`speaking-text`**) and choice-dialog ids ignore initial **`visible`** for authored “show at load” (the engine shows/hides them for speech and topic UI). GUI overlays are sorted by **`id`**, assigned spaced base **`depth`** values; Speaking Text (**`speaking-text`**) and choice GUIs are ordered so line-at-a-time speech sits under the topic grid when both are active. **GUI Aseprite sheets** (`display.aseprite: true`): unlike rooms or characters, there is **no** “import animations from tags” command for GUIs. Only tags **explicitly bound** on a control (Inspector **Animations** section, or the same fields in JSON) are played or shown; unreferenced tags on the export are ignored. **`image`** controls and **`inventoryPanel`** slot/backdrop/highlight layers use a per-sprite **`anchor`**: **`top-left`** (default) aligns the sprite’s top-left to the control origin; **`center`** aligns the sprite’s center to the authored **`x`/`y`**; **`screen`** draws at canvas **(0,0)** in internal resolution (ignores the control’s **`x`/`y`** for placement—full-frame HUD art) while **`x`/`y`/size** remain available for layout and future clipping. The VS Code **GUI preview** uses **`buildGuiOverlay`** (same compositor as **`RoomScene`**). **`letterSpacing`** may be set per **`text`** control in **`*.gui.json`**, otherwise per-font **`defaultLetterSpacing`** in **`fonts/fonts.json`**. Wrapped text uses an even **`wordWrapWidth`** (snapped down by one pixel when odd) to reduce sub-pixel centering artifacts from Phaser **`BitmapText`**. **`gameConfig.ts`**, **BENNE Play**, and every Phaser preview use the same renderer fields from **`getBenneRendererConfigFields()`** (**`Phaser.WEBGL`**, **`pixelArt`**, **`roundPixels`**) so **`BitmapText`** and sprites stay aligned. ## 3. Core Systems

### Scrolling room camera

- **Room size** (`RoomData.size`): the physical extent of the room in game-world pixels.  Controls camera bounds, walkable-area extent, and whether `startFollow` is activated.  The background image and Aseprite prop sheets render at their **own natural dimensions** — `size` does **not** scale the art.  Setting `size` smaller than the art restricts the camera to a sub-region of the art, which is valid (e.g. the art bleeds beyond the playable area).

- **Scroll bounds** (`RoomData.scrollBounds`): optional `{ x, y, width, height }` in room space that restricts how far `cameras.main` may pan within the room.  When omitted the camera pans anywhere within `size`.  Making `scrollBounds` narrower than `size` keeps the camera away from room edges (the camera is "less eager" to scroll to the edge).  Making `scrollBounds` equal to `size` lets the camera pan all the way to the edge.  Implemented via `cameras.main.setBounds(scrollBounds)`.
- **`RoomScene.setupRoomCamera`** (private): called at the end of `create` after characters spawn. Sets `cameras.main.setBounds` from `scrollBounds` (or room size). When the room is larger than the viewport and a player exists, **`applyPlayerCameraFollow`** calls `startFollow` with an offset derived from **`CharacterData.feet`** so the camera tracks the character’s **feet** (see **`src/engine/characterFeet.ts`**), not the sprite’s top-left.
- **`RoomScene.setEditorCameraMode(mode)`** (public): called by the editor's `RoomPolygonEditScene` whenever the toolbar mode changes. Stores the current mode so it can be re-applied on panel resize. Two behaviours: `'navigate'` — letterboxes the game's virtual resolution (352×198) inside the panel using `cameras.main.setViewport`, sets zoom to fill that box, and re-activates player follow + scroll bounds for game-accurate preview; `'edit'` — expands the camera to fill the entire panel (`setViewport(0,0,panelW,panelH)`), computes `zoom = min(panelW/roomW, panelH/roomH)` to fit the full room art, sets bounds to room bounds, and disables player follow so the authoring view is stable. The `scale.on('resize')` hook re-invokes `setEditorCameraMode` automatically when the VS Code panel is resized.
- **Runtime hi-DPI camera split** (`RoomScene` + `benneRuntimeHiDpiScale.ts`): runtime keeps world rendering on `cameras.main` (normal origin/follow math) and routes GUI / cursor through a dedicated UI camera (`ensureEditorUiCamera`, also used in preview). This avoids `scrollFactor: 0` HUD drift under zoomed/letterboxed viewports while preserving room-art alignment and click mapping.
- **Script camera (`B.camera`)** — Runtime-only overrides on `RoomScene`: a focus flag (suspends `startFollow` until `B.camera.reset()`) and a gameplay zoom multiplier (`1.0` = room default). State is **not** persisted; room transitions and save/load restart `RoomScene` and restore default follow. Gameplay zoom composes as **`displayZoom × scriptGameplayZoom`** (display zoom from hi-DPI letterbox or editor navigate mode; script zoom from `B.camera.setZoom` / `zoomTo`). String focus targets use **`resolveCameraFocusTarget`** (prop → hotspot → character → room point): props/hotspots prefer **`lookAtPoint`**; characters prefer **`talkPoint`**, else feet — not **`walkToPoint`**. Config defaults and limits: `game-config.json` **`camera`** (`minZoom`, `maxZoom`, `shake`, …) via **`getCameraSettings()`**. `B.camera.shake` is fire-and-forget (no interaction queue).
- **Background and props** render at their **natural texture dimensions** — `room.size` does **not** call `setDisplaySize`. Art that extends beyond `room.size` is simply not scrolled into view.
- **Hotspot zones** are sized to `room.size` so polygon hit areas only cover the playable area.

### Scene / room system

- **`BootScene`**: Entry after game creation. Uses **`loadStartRoomData()`** — **`startingRoomId` in `game-config.json` overrides** `rooms.manifest.json` — resolves the room’s **`*.room.json`**. Shared helpers **`buildRoomSceneStartDataFromRoomData`** and **`queueRoomSceneAssetLoads`** (`roomSceneBootstrap.ts`) build **`RoomSceneStartData`** and queue the same class of assets; **`BootScene`** uses them, and **`RoomTransitionOrchestrator`** reuses that path for arbitrary **`roomId`** (via **`loadRoomDataById`** in `loadRoomData.ts`). Queues background image (optional), room Aseprite sheet, character assets, and registered **inventory** Aseprite sheets (shared `inventory.json` and/or per-item exports), then on loader complete calls **`startInitialRoomFromBoot`** ( **`setLastRoom(null)`**, registry **`'boot'`**, **`scene.start`**) so **`onRoomSceneCreateComplete`** runs **enter** hooks, **optional boot Play From**, **`waitForEnterPhaseBenneScriptQueues`**, **fade in**, and **after-fade** hooks (or the equivalent fallback if no orchestrator is registered).
- **`RoomScene`**: Single active gameplay view for that room. No second “room manager” type is used at runtime; the abstract **`Room`** class in `Room.ts` is a **placeholder** for future data-driven room types, not wired into Phaser yet. On **`create`**, it walks **`getAllGuiData()`** (all **`*.gui.json`** under **`src/game/guis/`**) and builds one overlay per GUI **except** **Speaking Text** (**`speaking-text`**, wired only to **`setDialogTextOverlay`** / **`say`**, starts hidden at boot regardless of JSON **`visible`**), **except** **Display Text** (**`display-text`**, wired only to **`setDisplayTextOverlay`** / **`display`**, starts hidden at boot), and **except** the ids returned by **`getRegisteredDialogChoiceGuiIds()`** (always **`dialog`**, plus each registered **`Dialog.guiId`**) — those choice-dialog overlays start hidden and are driven by **`benne:dialog:started`** / **`benne:dialog:stopped`** (see **§3 → Dialog system**). Every other GUI follows **`GuiData.visible`** (**`false`** hides at load; omitted / **`true`** shows) as its initial state; scripts may then toggle full overlays at runtime via **`B.gui('guiId').show()`** / **`hide()`**. Stable **`id`** sort and spaced **`depth`** bands keep stacking predictable: generics first, then Speaking Text (**`speaking-text`**), then Display Text (**`display-text`**), then each reserved choice GUI (so topic lines + choice UI stack above the HUD), then a **screen-fade** rectangle (see **Screen fade** below) above that stack and below the custom pointer.
- **Reserved text overlays**: **`src/game/guis/speaking-text/speaking-text.gui.json`** is the line-at-a-time **Speaking Text** surface for **`say`**; it is distinct from the **`dialog`** choice overlay used by **`B.dialog`**. **`src/game/guis/display-text/display-text.gui.json`** is the narration surface for **`B.display`**, normally a wrapped `BitmapText` named **`text`** over a `nineSliceImage` named **`displayTextBg`**. `setDisplayTextOverlay` and `GuiOverlayHandle.setDisplayTextLayout` resize that panel to its wrapped text. **`B.display`** / **`.now`** use scripted-dialog input suppression and click-to-dismiss like `say`, but have no line timer.
- **Screen fade**: after GUI composition, `RoomScene.create` adds a screen-fixed full-viewport rectangle at **`BENNE_SCREEN_FADE_OVERLAY_DEPTH`**, above every GUI/text overlay and below the optional custom cursor. **`B.fadeOut`** / **`B.fadeIn`** queue `queueScreenFadeToAlpha` on the interaction tail; `.now` variants bypass the queue. Defaults are **0.35 seconds** and **`0x000000`**. Global and GUI scripts resolve the active room through `tryGetActiveBenneGame`; the room preview registers the rectangle with its UI camera. The layer is recreated with each `RoomScene`.
- **Room switching**: In-game, **`B.room.changeTo('roomId')`** (or **`.now`**) is handled by **`RoomTransitionOrchestrator`**: clear transient selection/dialog/timers/interaction tails → leave hooks → fade out (unless **`.now`**) → load room JSON, its lazily registered script, and assets → **`setLastRoom` / `setCurrentRoom`** (emitting **`gameState:roomContextChanged`**) → restart `RoomScene` with the **`transition`** start kind. `RoomScene.create` increments the persisted visit count before hooks, runs global then room-local enter hooks with per-handler isolation, optionally runs a named **Play From** setup on `boot`/`preview`, drains room and global interaction queues, fades in, then runs global and room-local after-fade hooks. Save-load starts run global then local **loaded** hooks and skip enter/after-fade hooks. The initial **`BootScene` → `RoomScene`** start uses **`boot`**, sets `lastRoom` to `null`, and has no leave hooks. **`RoomTransitionContext`** carries `roomId`, `lastRoom`, session-only `isFirstEnter`, and persisted `visitCount`. VS Code room preview uses **`preview`** and does not run the full leave/load orchestrator.

**Boundaries**: Room **layout and flags** come from JSON; **reactions** for room-scoped content (props, hotspots, or room-scoped character verbs) typically live in **`registerRoomScript`** in `*.room.ts`. **Character-definition** reactions use **`registerCharacterScript('characterId', ({ B }) => { … })`** in `*.character.ts` with **self-only** verb sugar (`B.whenLookAt(() => …)` subscribes to **`verb:character:<id>:<verb>`** only). **`dispatchVerbInteraction`** still prefers **room-scoped** character handlers when present; character-file handlers are the **fallback**. Cross-entity wiring (verbs on other props/NPCs) stays in **`*.room.ts`**.

### Rendering system

- **Renderer**: Phaser **`WebGL`** (`gameConfig.ts` **`type: Phaser.WEBGL`**) with **`pixelArt`**, **`roundPixels`**, and **`antialias: false`** for crisp **`BitmapText`** and sprites (same settings across the GUI preview, room preview, character preview, inventory preview, and **BENNE Play**).
- **Internal size** from `game-config.json` `resolution`; shipped runtime uses Phaser **Scale.NONE** + `wireBenneRuntimeHiDpiCanvasScale` (`src/engine/benneRuntimeHiDpiScale.ts`) for hi-DPI backbuffer sizing and aspect-fit letterboxing on the main camera. During active browser resize the engine prioritizes visual stability (camera/CSS updates) and defers expensive buffer realloc to a short debounce window; once settled, a full `scale.resize` commit restores crisp final output. Camera dedupe is scene-aware so newly started scenes still receive main-camera viewport/zoom even when dimensions are unchanged. Preview surfaces that should fill their panel keep **Scale.RESIZE** (via `getEditorPhaserGameConfig`).
- **Layers**: Background image (optional, full-frame) → **room stack** (`RoomScene`): props, active hotspot zones, and spawned characters are **sorted every frame** into sequential Phaser depths (from `ROOM_STACK_DEPTH_BASE` in `src/engine/room/roomStackDrawOrder.ts` via **`sortRoomStackEntities`**). **Primary order** is authored **`zIndex`** (higher draws in front). **Optional `baseline`** on **`RoomPropInstance`** and **`RoomHotspotData`**: a **room-space Y** (pixels, y down). If a character’s **world feet Y** (from **`CharacterData.feet`** or the bottom-centre fallback) is **strictly greater** than that baseline, the character draws **in front** of that prop/hotspot even with a lower **`zIndex`**. **Character vs character** uses **feet Y** only (y-sort when feet differ, then **`zIndex`**). At the same **`zIndex`** when baseline/feet rules do not decide, draw order is **prop → hotspot → character** (then stable id / feet tie-breaks). If baseline exceptions and **`zIndex`** bands together would imply a **cycle**, that character is placed using **`zIndex` / kind / feet / sortKey only** (no baseline jumps) for that insertion so order stays **deterministic** when props change. **Debug** graphics, the optional **cinematic video layer** (`B.video`, **`ROOM_VIDEO_LAYER_DEPTH = 24_000`**), and **GUI** overlays sit above this stack — the video draws above room art but **below** every GUI (so Speaking Text / Display Text stay visible over playing cinematics).
- **`PostEffects.ts`**: **`attachPostProcessingPlaceholder(this.cameras.main)`** — extension point for Phaser 4 camera filters; **no shaders shipped yet**.
- **Aseprite animation-key namespacing**: props, GUI controls, inventory sheets, and the custom pointer register clips on the scene-global `AnimationManager`, so `loadAsepriteAtlasData.ts` prefixes normalized frame-tag names with **`room:<roomId>:`**, **`gui:<guiId>:`**, **`invitem:<itemId>:`**, **`inventory:`**, or **`cursor:`**. Runtime helpers and editor preview blob loaders map author-facing short tags to those keys. Authors should continue using short Aseprite tag names in room, GUI, inventory, and cursor JSON; character clips are exempt because `sprite.anims.createFromAseprite` is sprite-local.
- **Perspective-scaled character batch**: `registerBenneCharacterPerspectiveBatch` installs a Phaser 4 custom quad path and character spawns attach it with `attachBenneCharacterPerspectiveRenderNodes`. The extended vertex layout passes **`inPerspMag = max(|scaleX|, |scaleY|)`**. For scales below 1, the `BenneCharacterPerspective` fragment addition snaps UVs to integer texel buckets (`floor(1 / mag + 0.5)`) using `uMainResolution`, after Phaser's `SmoothPixelArt` addition. This keeps source texels crisp while region scale changes continuously. The implementation mirrors Phaser shader source in `phaserQuadStandardShaderInline.ts` to avoid importing CommonJS files from `node_modules/phaser/src/**` into Vite. The batch applies only to character quads; props, GUI, cursor, and renderer configuration are unchanged.

### GUI BitmapText color and text outlines

`text` and `button` controls in `*.gui.json` support colour and outline fields:

**`color`** — hex string (e.g. `"#ff0000"`); default `#ffffff`. Applied to the main `BitmapText` via `applyGuiBitmapTextFillTint` in `guiTextOutline.ts`.

**`textOutline`** — `GuiTextOutline` object (`src/types/gui.ts`):

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `enabled` | `boolean` | — | Must be `true` for the outline to appear. |
| `color` | hex string | `#000000` | Outline colour. |
| `alpha` | 0–1 | `1` | Outline opacity. |
| `thickness` | integer ≥ 1 | `1` | Pixel distance of each offset copy. |
| `sides` | `GuiTextOutlineSides` | `allSides` | Which directions receive copies (see below). |

For `button` controls, text can also switch colour per button state:

**`textColorStates`** — `GuiButtonTextColorStates` object (`src/types/gui.ts`):

| Field | Type | Default | Notes |
|-------|------|---------|-------|
| `hover` | hex string | falls back to `textColor` | Applied while pointer is over the button. |
| `pressed` | hex string | falls back to `textColor` | Applied while pointer is down on the button. |
| `disabled` | hex string | falls back to `textColor` | Applied when `enabled: false`. |

**`GuiTextOutlineSides`** — `allSides` (full 8-direction stroke) or one of 8 directional shadow presets: `topLeft`, `top`, `topRight`, `left`, `right`, `bottomLeft`, `bottom`, `bottomRight`. For `allSides` with `thickness: 1` this produces 8 offset clones; with `thickness: 2` it produces 16 (each direction gets copies at 1 px and 2 px offset, deduplicated).

**Runtime (engine)**

- `createGuiBitmapTextOutlines` (`buildGuiOverlay.ts`) reads `resolveEffectiveGuiTextOutline` (from `guiTextOutline.ts`) which expands `sides` + `thickness` into a deduplicated `{ dx, dy }` offset list. One `BitmapText` clone is created per offset, at depth-ceiling − i × ε so clones stack below the main label in a predictable fixed order.
- `buildGuiButton` (`buildGuiOverlay.ts`) applies `textColorStates.hover` / `pressed` / `disabled` to button labels in the same pointer/event flow used for sprite `states.*` tag swaps, with per-state fallback to base `textColor`.
- Each clone has `BENNE_GUI_OUTLINE_DX_KEY` / `BENNE_GUI_OUTLINE_DY_KEY` (and outline fill keys when coloured) stored via `setData` for position sync and `syncOutlinedGuiBitmapTextAll`.
- `attachGuiBitmapTextOutlineList` stores the clone array on the main BitmapText via `setData(BENNE_GUI_BITMAP_TEXT_OUTLINE_KEY, ...)`.
- `syncOutlinedGuiBitmapTextAll(main, text)` (called by `GuiRuntime` whenever speaking-text / verb-line content changes) calls `setText` on main and each clone, then re-applies fill tints from the stored data keys so colours survive text updates.
- `syncOutlinedGuiBitmapTextPositions(main)` re-anchors clones after the main label moves (e.g. Speaking Text bottom-centre repositioning).

**WebGL tinting**

With **`Phaser.WEBGL`**, Phaser’s Tint component applies to `BitmapText`. **`applyGuiBitmapTextFillTint`** sets `setTint(tint)` + `setTintMode(Phaser.TintModes.FILL)` + explicit corner assignment, and stores the tint in `BENNE_GUI_BITMAP_TEXT_FILL_TINT_KEY` / `BENNE_GUI_OUTLINE_FILL_TINT_KEY` so `syncOutlinedGuiBitmapTextAll` can re-apply after `setText`. Outline clones are separate `BitmapText` instances offset by whole pixels (no Canvas pre-tinted atlas or prototype patch).

- **`checkbox`**: a sheet-backed toggle built by `buildGuiCheckbox`. `tag` is the unchecked clip; `states.uncheckedHover`, `checked`, `checkedHover`, `disabled`, and `disabledChecked` supply the remaining chrome. ### Prop parallax

Room props may set **`parallaxDepth`** (`RoomPropInstance` in `src/types/room.ts`). Each frame, `RoomScene.updateParallaxProps` blends the prop’s authored position with the **top-left of the camera’s visible world rectangle** (`camera.worldView`), not raw `scrollX` / `scrollY` (those diverge from the visible corner when zoom ≠ 1, which breaks editor navigate mode):

```
worldX = parallaxDepth * baseX + (1 − parallaxDepth) * camera.worldView.x
worldY = parallaxDepth * baseY + (1 − parallaxDepth) * camera.worldView.y
```

(`baseX` / `baseY` are the prop’s authored `x` / `y` in room space.)

| `parallaxDepth` | Effect |
|-----------------|--------|
| `0` | Sprite position tracks camera scroll origin (moves fully with the camera). |
| `0–1` | Distant; moves slower than the camera. |
| `1` | No parallax (default if the field is omitted); world-fixed at authored position. |
| `>1` | Foreground; moves faster than the camera. |

**Example** — distant layer at half camera coupling:
```json
"parallaxDepth": 0.5
```

**Performance**: Props with `parallaxDepth === 1` or no `parallaxDepth` are not added to the parallax update list. The scene’s `update()` skips work when that list is empty.

### Input system

- **Custom pointer** (optional `game-config.json` **`cursor`**): when **`cursor.display.aseprite`** is **`true`** and `src/game/assets/images/cursor/cursor.{png,json}` are bundled, **`BootScene`** loads the sheet as **`aseprite:cursor`**; **`RoomScene`** hides the OS cursor, draws a screen-fixed **`Sprite`** that follows the pointer, and swaps clips named by **`idleAnimation`** vs **`activeAnimation`** (Aseprite frame tags / Phaser animation keys). Optional **`cursor.animations`** uses the same per-tag shape as **`CharacterData.animations`** (`loop`, `frameDuration`, `events`); **`applyCharacterAnimationClips`** applies it after **`createFromAseprite`**. Optional **`cursor.hotspot`** picks where the logical pointer tip sits on the art (**`top-left`** through **`bottom-right`** as Phaser `setOrigin` fractions, or **`custom`** with required **`cursor.hotspotPixel`** **`{ x, y }`** from the sprite’s top-left). Hover uses Phaser **`hitTestPointer`** over props (clickable colliders only), **`benneHotspot`** zones, clickable characters, GUI **`button`** hit targets (`buildGuiOverlay` sets **`benneGuiButton`** on button hit targets), and **occupied** GUI **`inventoryPanel`** slot containers (**`benneInventorySlot`** — same “active” cursor clip as over other clickables). The VS Code **room preview** queues the same asset via **`buildPreviewManifest`** (`queueGameCursorLoad`). Cursor clip priority is: (1) an armed inventory item's valid `cursorAnimation`; (2) the sorted hovered room target's optional **`activeCursorOverride`** on a hotspot, clickable prop, or clickable character; (3) global `cursor.activeAnimation`; otherwise `cursor.idleAnimation`. Per-target overrides name tags on the game cursor atlas, apply only to room targets (not GUI buttons or inventory rows), and fall back to `activeAnimation` with a once-per-tag DEV warning when invalid. The Inspector exposes the override only while the target is hit-testable.
- **Walk**: **Left click** on empty space (no hit-test targets) moves the **player** character toward the click. **Right click** on empty space clears the runtime active verb (see **Verb system → Active verb** below). Clicks outside the mesh are **clamped** into **walkable regions** (`walkable.ts` — each **`WalkablePolygon`** is an outer ring minus optional **active** hole rings; union across polygons; point-in-polygon + closest-point clamping). Characters then **pathfind** around holes and concave parts of the mesh via `src/engine/pathfinding.ts` (see **Pathfinding** below).
- **Clickable targets** (props / hotspots / characters): **`pointerdown`** resolves through **`resolvePointerVerbForTarget`** (`src/engine/verbs/resolvePointerVerb.ts`) which considers the current **active verb** (runtime state on **`GameStateManager`**), the target's authored **`defaultVerb`**, and the effective **`inputProfile`**. Outcomes: dispatch a verb; walk to the target's stand point (when a slot resolves to the built-in `walkTo`); clear the active verb (right-click while one is set); or no-op. **Props** still dispatch immediately (no engine walk-to-before-verb). **Hotspots** use closed **`points`** polygons (≥3 vertices); optional **`onVerbFallback`** on the hotspot (and prop) JSON gates object-level fallback dispatch; per-verb handling is whatever **`*.room.ts`** registers on the **`EventBus`**. **Clickable characters** use a **polygon hit area** when **`CharacterData.collider.points`** has at least three vertices (coordinates in **sprite frame space**, origin top-left of the cel, consistent with **`feet`**); otherwise the **full sprite rectangle** is interactive.
- **GUI `inventoryPanel` (occupied slots)**: **`buildGuiOverlay`** gives each **filled** slot row a **`pointerdown`** handler that runs **`resolvePointerVerbForInventoryItem`** (`resolvePointerVerb.ts`), then **`dispatchInventoryVerbInteraction`** (`src/engine/verbs/dispatchInventoryVerb.ts`), then **`trySyncActiveInventoryAfterInventoryUseOrGiveRowDispatch`** (same module) when the row has **no** **`registerInventoryScript`** module — that synchronous path arms **`activeInventoryItemId`** for the effective **use** or **give** verb id only (**`resolveEffectiveUseVerbId`** / **`resolveEffectiveGiveVerbId`** in **`verbConfig.ts`**). **Active verb** and **left / right → `inputProfile`** match props/hotspots/characters, except (1) profile **`walkTo`** cannot mean “walk to a stand point” for a bag row — it is treated like **`defaultVerb`** on that item (**`InventoryItemData.defaultVerb`**, fallback **`look`**), and (2) when **`activeInventoryItemId`** is set, **`resolvePointerVerbForInventoryItem`** forces **`consumeActive: false`** on **`verb`** resolutions so the verb bar stays selected for **inventory-on-inventory** / **use-on-target** (**`shouldDispatchInventoryUsedOnVerbForGame`**); with **no** armed item, **`consumeActive`** matches **`resolvePointerVerbForTarget`**, and **`buildGuiOverlay`** **defers** **`clearActiveVerb`** with **`queueMicrotask`**: it **skips** the clear when **`activeInventoryItemId ===`** the clicked row (arming for combine / use-on-target after **`InventoryBenneScript`** **`afterInteractionTail`**, **`trySync`**, or any **`whenVerb`** that **`setActiveInventory`** for that row), otherwise clears like a room click. **`RoomScene`** supplies **`inventoryPanelPointerContext`** (current **`roomId`**, scripted-dialog suppression, dialog click-to-skip) on every in-game GUI overlay build; the VS Code **GUI preview** omits it, so preview inventory slots stay non-interactive and clicks still pass through like other non-button controls.
- **Context menu** disabled on mouse in `RoomScene`.

### Verb system

- **Config** (`src/game/game-config.json`, types **`src/types/game.ts`**): optional **`verbs`** (`{ id, label?, preposition? }` each — **`preposition`** is a short connector for composed verb + object UI, e.g. “Look **at** …”), optional **`inputProfile`** (flat **`primaryButtonVerb`** / **`secondaryButtonVerb`** — no `kind` field), optional **`defaultFallbackLine`** (used for **`verb:unhandled`**).
- **`inputProfile` slot grammar** — each slot accepts **any configured verb id** from **`verbs[]`**, or one of two reserved literal tokens:
  - **`"walkTo"`** — built-in universal walk verb (`WALK_TO_VERB_ID` in `verbs/verbConfig.ts`). Never authored in **`verbs[]`**, never shown as a verb chip in the Inspector. When a slot resolves to `walkTo` on a **room** clickable target, the engine walks the player to the target's stand point (prop `walkToPoint` / collider-closest / frame-center; hotspot `walkToPoint` / centroid; character `walkToPoint` / feet) — no verb dispatch for that click. On a **GUI `inventoryPanel`** occupied slot, there is no stand point: resolution uses **`resolvePointerVerbForInventoryItem`**, which substitutes the row item's **`defaultVerb`** (fallback **`look`**) and dispatches that verb. Empty-space clicks always walk, independent of slot configuration.
  - **`"defaultVerb"`** — substitute with the clicked target's authored **`defaultVerb`** field (per-prop / hotspot / character / inventory item). Falls back to **`"look"`** when the target omits the field. Shown in the Inspector as a "Default verb" dropdown on each clickable card (built from **`game-config.json`** `verbs`).
- **Defaults**: Omitting **`verbs`** implies ids **`look`** and **`use`**. Omitting **`inputProfile`** defaults to **left → `look`**, **right → `use`**. Typical 9-verb wiring: `primaryButtonVerb: "walkTo"`, `secondaryButtonVerb: "defaultVerb"` (paired with a verb GUI that calls `B.setActiveVerb(...)` per button).
- **Active verb** (runtime UI state on **`GameStateManager`**, not persisted in snapshots): a script-settable verb id that overrides the pointer resolution on the **next** target click.
  - **Bennescript**: **`B.setActiveVerb(verbId | null)`**, **`B.getActiveVerb()`**, **`B.clearActiveVerb()`** are available on every Bennescript facade (room / character / global / inventory / GUI) via the shared **`BenneScriptCore`**.
  - **Resolution rules — room clickables** (`resolvePointerVerbForTarget`):
    - Clickable + **left** click + active verb set → dispatch the active verb on the target; **clear** the active verb ( **`consumeActive`** ).
    - Clickable + **right** click + active verb set → clear the active verb (no dispatch).
    - Clickable + any button + no active verb → resolve the matching `inputProfile` slot (`walkTo` / `defaultVerb` / plain verb id).
    - Empty space + **right** click → clear the active verb (no dispatch, no walk).
  - **Resolution rules — GUI `inventoryPanel` rows** (`resolvePointerVerbForInventoryItem`): same active-verb / **`inputProfile`** / right-click clear semantics as above, plus **`walkTo` → item `defaultVerb` / `look`**. With **no** **`activeInventoryItemId`**, a left-click **`verb`** dispatch uses the same **`consumeActive`** as room clickables; **`buildGuiOverlay`** may clear the active verb on a **microtask** after dispatch unless the clicked row became **`activeInventoryItemId`** (any verb id that arms that row — built-in **use** / **give** tails, **`trySync`**, or **`setActiveInventory`** in **`whenVerb`**). When an item **is** armed, **`consumeActive`** is forced to **`false`** on **`verb`** resolutions so the selection stays for combine / use-on-target. If an inventory handler **queues** async work (`say`, **`wait`**, tweens) **before** arming on the same click, arm with **`setActiveInventory`** **synchronously** at handler start when the verb should combine; otherwise the deferred clear can run too early. The resolved **use** and **give** verb ids on a row arm **`activeInventoryItemId`** after the interaction queue drains by default (**`InventoryBenneScript`**, plus **`trySyncActiveInventoryAfterInventoryUseOrGiveRowDispatch`** for JSON-only items — see **Inventory System → Bennescript**). **`B.whenUse` / `B.whenGive`** add optional handler code **in addition**; **`B.whenUse.doNotActivate` / `B.whenGive.doNotActivate`** opt out of arming for that verb when **every** registered handler for that verb uses **`doNotActivate`**.
  - Event **`gameState:activeVerbChanged`** (`GAME_STATE_ACTIVE_VERB_CHANGED_EVENT`) fires on every change; handy for cursor / button-highlight wiring. **`applySnapshot`** also clears the active verb so loading a save never leaves a stray verb selected.
- **Per-object data**: **`RoomPropInstance`** and **`RoomHotspotData`** carry optional **`onVerbFallback`** (and **`defaultVerb`**) only; **`InventoryItemData`** may carry optional **`onVerb`** (verb id → **`true`**, authoring) plus **`onVerbFallback`**. **`CharacterData`** mirrors props/hotspots (no **`onVerb`**); optional **`onVerbFallback`** and **`defaultVerb`** behave like other clickables. **`defaultVerb`** controls what the `"defaultVerb"` slot substitutes in (omit to fall back to `"look"`); the Inspector shows it as a dropdown on each clickable card (the room-character card surfaces it read-only — edit from the character's own Inspector).
- **Dispatch** (`src/engine/verbs/dispatchVerb.ts`): **Before** emitting, **`interruptPlayerWalkForVerbInteraction`** runs (see **Game state → Active `Phaser.Game` handle**): if **`RoomScene`** is the active Phaser scene, **`RoomScene.interruptPlayerWalk()`** stops any in-progress **player** path tween, clears the live path / arrive callback, returns the player to **Idle**, and emits **`player:walk:stop`** (`PLAYER_WALK_STOP` in **`playerWalkEvents.ts`**) with **`reason: 'interrupted'`**. The same interrupt runs at the start of **`dispatchInventoryOnVerbTargetInteraction`**, **`dispatchInventoryOnInventoryItemInteraction`**, and **`dispatchInventoryVerbInteraction`** so inventory-on-world and **`inventoryPanel`** row verbs behave consistently. Superseding a walk by **starting another walk** still stops the prior tween inside **`RoomScene.movePlayerToward`**; this hook covers the case where the next interaction is **not** a new walk (e.g. **look** while crossing the room). **`RoomScene.tryBeginPropLook`** goes through **`dispatchVerbInteraction`**, so it participates in the same interrupt. **Emit order (listener-first)**: for **props** and **hotspots**, emit **`verb:room:<roomId>:<targetType>:<targetId>:<verbId>`** only when that channel has listeners; otherwise continue. For **characters**, try **`verb:room:<roomId>:character:<characterId>:<verbId>`** then **`verb:character:<characterId>:<verbId>`** the same way. If **`onVerbFallback`** is enabled on the target, try room-scoped then character-global fallback events **only when those channels have listeners**. Then **`verb:global:<verbId>`** (if listeners) → **`verb:global:fallback`** (if listeners) → **`verb:unhandled`**. In **Vite dev**, unhandled verbs also **`console.warn`**.
- **Payloads** (`propInteractionEvents.ts`): **`RoomPropInteractPayload`**, **`RoomHotspotInteractPayload`**, and **`CharacterVerbInteractPayload`** carry **`verbId`** and target ids; props also expose optional **`walkToPoint`** / **`lookAtPoint`** (room pixels). Characters may include optional **world** **`walkToPoint`** / **`talkPoint`** when the matching fields exist in **`CharacterData`** (converted from frame offsets at click time). Object fallback emissions add **`verbFallback: true`**.

### GUI verb status line (Bennescript)

LucasArts-style copy (**Walk to**, **Push pillar**, **Use item with …**) is authored as a normal **`text`** control plus **`registerGuiScript`**: subscribe to **`B.onVerbContextChanged`** (**`BENNE_VERB_CONTEXT_CHANGED_EVENT`**) inside **`onGuiBuilt`** and set **`control('…').text`** from **`B.activeVerb`**, **`B.activeInventory`**, **`B.currentHoverDescription`**, matching the pattern in **`src/game/guis/verbs/verbs.gui.ts`**. Helpers **`composeVerbLineText`**, **`resolveVerbLineDisplayLabel`**, and **`resolveVerbLineLeadingVerbWord`** in **`verbConfig.ts`** remain available when you prefer that exact string math in TS.

**Hover context for `B.currentHoverDescription`** — **`RoomScene`** walks Phaser **`hitTestPointer`** (sorted like dispatch) each **`pointermove`** and after **`gameState:inventoryChanged`**, skips GUI **`button`** hits, and publishes the short label plus structured **`B.currentHoverTarget`** (including optional authored **`defaultVerb`** when non-empty) through **`publishBenneVerbHoverContext`** (props/hotspots/clickable characters/occupied **`inventoryPanel`** rows). During **scripted dialog** input suppression (**`say`** lock), **`B.currentHoverDescription`** is cleared so HUD lines do not advertise room targets behind a blocking line.

### Character feet (walk / camera)

Optional **`feet`** on **`CharacterData`** (`src/types/character.ts`): **`{ "x", "y" }`** in **frame pixel space** from the cel’s **top-left** to the ground contact. The runtime places Aseprite sprites with **`origin (0,0)`** and offsets position so room spawn **`(x, y)`** is where the feet stand; walk tweens and camera follow use the same point. If **`feet`** is omitted, the engine uses the **bottom-centre** of the **current** frame (works best when cels share a consistent size). The VS Code **BENNE Character preview** webview (`npm run build:character-preview`) plays a default idle (prefers **`IdleD`**, then other **`Idle*`** tags), shows **Feet**, **Walk to**, and **Talk** handles plus the collider on one overlay, and **Save to JSON** writes **`feet`**, **`walkToPoint`**, **`talkPoint`**, and **`collider`** together via **`characterGeometryPatch.ts`**. In the preview, **Feet** and **collider** vertices are clamped to the cel; **Walk to** and **Talk** may be placed outside the sprite bounds (camera bounds grow to include them).

Optional **`walkToPoint`** on **`CharacterData`**: same **frame space** as **`feet`**; world stand = sprite position + offset. Used when **`RoomScene`** resolves script **`walkTo('<characterId>')`** to that character. If omitted, resolution uses the character’s **world feet** (same effective stand as when **`walkToPoint`** matches **`feet`**).

Optional **`talkPoint`** on **`CharacterData`**: same **frame space**; a script-facing **look / dialogue** hint. Verb payloads include **world** **`talkPoint`** when the field is set (like prop **`lookAtPoint`**, but stored per character in frame space).

**Click collider (authoring)** — Optional **`collider: { "points": [ { "x", "y" }, … ] }`** on **`CharacterData`**, same **frame space** as **`feet`**. The preview reuses **`PreviewPolygonOverlay`** with the same vertex / edge / Delete gestures as prop colliders; fewer than three points on save **removes** **`collider`** so the engine falls back to the full-sprite hit test. Verbs and scaffolding use **`CharacterVerbInteractPayload`** from **`propInteractionEvents.ts`**; **Create Character** and verb-handler insertion ensure that **import** is present in new **`*.character.ts`** files.

### Room regions (perspective character scale)

**Data** — **`regions`** on **`RoomData`** (`src/types/room.ts`, **`RoomRegionData`**): each entry is a closed **`points`** polygon in **room pixels** (same space as walkables and hotspots), with optional **`active`** (omit or non-**`false`** = used). Optional **`scaleEnabled`** (omit or not **`true`** = this region does not scale). When **`scaleEnabled`** is **`true`**, optional **`scaleTop`** and **`scaleBottom`** default to **`1`** (normal sprite size). **Top** means the **smaller** room **Y** (upper on screen); **bottom** means the **larger** **Y**. The runtime takes the axis-aligned **vertical span** of the polygon’s vertices (**min Y** … **max Y**) and linearly blends **`scaleTop` → `scaleBottom`** as the character’s **feet Y** moves down that span while the feet remain **inside** the polygon. Optional **`scaleWalkSpeed`** (default **`false`**) on that **scale winner**: when **`true`**, the character’s **authored walk speed** is multiplied each frame by **`max(minWalkScale, pow(linearScale, walkScalePower))`**, where **`linearScale`** is that same vertical blend (and **`minWalkScale` / `walkScalePower`** come from **`game-config.json`** — see **`perspective`** below). Optional **`tintEnabled`** (omit or not **`true`** = this region does not tint). When **`tintEnabled`** is **`true`**, optional **`tint`** (**`#rrggbb`**) and **`tintAlpha`** (**0–1**, default **`1`**) multiply-tint spawned character sprites while feet stay inside (applied by **`RoomScene.applyFeetWorldWithRegionScale`**). A missing or invalid hex, or **`tintAlpha`** **`0`**, clears tint for that tint winner.

**Runtime** — **`computeRoomRegionPerspective(feetX, feetY, regions, perspectiveSettings)`** (`src/engine/room/regionCharacterScale.ts`) walks **`regions`** in array order. Each active polygon with ≥3 points that contains the feet becomes **`winningRegion`** (last match — enter/exit only). Scale and tint are separate: only a region with **`scaleEnabled: true`** updates **`characterScale`** and, if that region’s **`scaleWalkSpeed`** is **`true`**, **`walkSpeedMultiplier`**; only a region with **`tintEnabled: true`** becomes **`tintRegion`**. A later region with the feature off does not reset an earlier scale or tint. If no containing region has scale enabled, **`characterScale`** and **`walkSpeedMultiplier`** stay **`1`**. If none has tint enabled, **`tintRegion`** is **`null`** (no tint). **`computeRoomRegionCharacterScale`** remains a thin wrapper that returns only **`characterScale`**. **`resolveWinningRoomRegionIdAtFeet`** / **`resolveWinningRoomRegionDataAtFeet`** return the enter/exit winner’s **`id`** or data (**`null`** outside) — shared by **`RoomScene.syncCharacterRegionEnterExit`** for **`B.region`…`whenEnter` / `whenExit`**, and independent of **`scaleEnabled`** / **`tintEnabled`**. **`RoomScene`** applies **`characterScale`** and **region character tint** (via **`packedTintFromWinningRegion`** on **`tintRegion`**) inside **`applyFeetWorldWithRegionScale`**: on spawn, on idle **`update`** (characters not in a walk tween), and along **walk legs** (interpolated feet). **Walk legs** advance **`u`** with **`u += (walkSpeed * walkSpeedMultiplier * dt) / legLength`**, then place feet and recompute scale + tint.

**Rendering (crisp downscale on screen)** — The **`characterScale`** math above drives **`sprite.setScale`**. How scaled character **sprites** stay **blocky / sharp** in the WebGL pipeline (custom quad batch, **`inPerspMag`**, texel bucketing while **`mag`** drifts) is separate; see **§3 → Rendering system → Perspective-scaled character batch** and **`src/engine/rendering/benneCharacterPerspectiveBatch.ts`**.

**Enter / exit hooks (Bennescript)** — Room scripts only: **`B.region('<regions[].id>').whenEnter(handler)`** / **`whenExit`**, or **`B.whenEnterRegion` / `whenExitRegion`** as flat sugar. Handlers register through **`BenneScript.subscribe`** (same queued interaction semantics as **`whenLookAt`**). After idle region scale/tint synchronization, the scene compares winning region ids every frame for all spawned characters, including mid-walk feet positions. The first frame after `create` seeds membership without emitting; when overlap priority changes, exit for the old winner emits before enter for the new winner. **`RegionEnterExitContext`** carries `roomId`, `regionId`, `characterId`, `isPlayer`, `feetX`, and `feetY`. Region handlers are not automatically cutscenes; wrap work in **`B.cutscene`** when full input suppression is required.

**Game config** — **`GameSettings.perspective`** (`src/types/game.ts`): optional **`minWalkScale`** (default **`0.3`**) and **`walkScalePower`** (default **`0.8`**). Merged by **`getPerspectiveSettings()`** in **`ConfigManager.ts`** (validated at load when the block is present).

**Feet / camera** — **`characterFeet.ts`** treats world feet as **`sprite.x + feetLocalX * scaleX`** (and **Y**), and **`placeSpriteByFeet`** backs out the same when positioning the top-left origin. The module-level **`getFeetFollowOffset`** used for **`cameras.main.startFollow`** scales the offset so follow still targets the feet when **`scale` ≠ 1**.

**Authoring** — **Add Region** (**`runAddRoomRegionWizard`**) still scaffolds a default square; edit the polygon in the **room preview** (**region polygon** mode). New regions omit **`scaleEnabled`** and **`tintEnabled`**, so both Inspector checkboxes start unchecked. In the **Inspector**, region cards expose **Scale** (checkbox, patch **`regionScaleEnabled`**, **`updateRegionScaleEnabled`**; checked writes **`true`**, unchecked deletes the key), **Scale top** / **Scale bottom** (patch **`regionScale`**, **`updateRegionScaleFields`**), **Scale walk speed** (checkbox, patch **`regionScaleWalkSpeed`**, **`updateRegionScaleWalkSpeed`**), **Tint** (checkbox, patch **`regionTintEnabled`**, **`updateRegionTintEnabled`**; same write/delete pattern), **Character tint** / **Tint alpha** (patch **`regionTint`**, **`updateRegionTintFields`**), or hand-edit **`*.room.json`**. The numeric and color fields stay editable while the feature checkboxes are off. Rebuild **`benne-editor/media/inspector/inspector.js`** after Inspector TS changes (**`npm run compile`** or **`npm run watch`** under **`benne-editor/`**).

**Limits (v1)** — Mapping is by the polygon’s **bounding Y extent**, not a custom “depth” axis through the floor. **`flipX`** on characters is separate from **`setScale`** (no negative scale for mirroring).

### Character directional animation (facing)

Directional clips use **Aseprite frame-tag names** built as **`<base><facing>`** (e.g. `IdleL`, `WalkDR`, `TalkUL`). Implementation lives in **`src/engine/directionalCharacterAnimation.ts`**; types for room JSON use **`CharacterFacingLetter`** in **`src/types/character.ts`**.

**Facings (eight-way)** — left, right, up, down, and diagonals: **`L`**, **`R`**, **`U`**, **`D`**, **`UL`**, **`UR`**, **`DL`**, **`DR`**. World space matches the rest of the engine (**y increases downward** on screen).

**Choosing facing from movement** — **`facingFromWorldDelta(dx, dy)`** normalizes the walk (or look) vector and picks the facing whose **unit direction** has the **largest dot product** with that vector, so purely horizontal or vertical motion maps to a **cardinal** (e.g. straight down → **`D`**), and diagonal motion maps to a **diagonal** when both components matter. A **zero** delta defaults to **`D`**.

**Playing a clip when some facings are missing** — **`playDirectionalAnimation(sprite, baseName, facing)`** first tries **`${baseName}${facing}`**. If that Phaser animation does not exist (or has no frames), it walks **other facings in order of smallest angular distance** from the requested facing, and for each candidate tries:

1. The **unflipped** tag for that facing.
2. If a **horizontal mirror partner** exists — **`L`↔`R`**, **`UL`↔`UR`**, **`DL`↔`DR`** — the partner’s tag with **`flipX`**, so a character can ship only **`WalkDL`** and still satisfy a **`DR`** request. **`U`** and **`D`** have **no** mirror pair in this scheme.

The sprite’s **`facing`** data stores the **logical** facing the gameplay asked for (walk end, look-at, spawn), not necessarily the suffix of the clip that ended up playing.

**Spawn and idle defaults** — **`resolveSpawnIdleFacing`** honors **`initialFacing`** on room character instances when it is one of the eight letters; otherwise it falls back like **`resolveInitialIdleFacing`**, which prefers an existing **`Idle*`** in a default order (**cardinals** `R`, `D`, `L`, `U`, then **diagonals** `DR`, `DL`, `UR`, `UL`), and finally **`D`** if nothing matches.

**RoomScene** uses this for **player walk**, **idle after walk**, and **NPC spawn** animation bases (`Idle`, `Walk`, etc.).

### Scripting / interaction system

- **Canonical scoped event ids** are emitted by **`dispatchVerbInteraction`** from runtime target context; JSON no longer stores ad-hoc event-id strings. Props/hotspots/room-scoped characters use `verb:room:...`, character-global uses `verb:character:...` (props still dispatch immediately; no engine **walk-to-then-verb** queue — but an **in-progress** player walk from empty space or **`walkTo`** resolution is **cancelled** when a verb dispatches; see **Verb system → Dispatch** and **Game state → Active `Phaser.Game` handle**).
- **`registerGameContent()`** (called before `createBenneGame`) **lazily** registers **`./rooms/**/*.room.ts`** (factories only — no module execution) and **eagerly** loads **`./characters/**/*.character.ts`**, **`./guis/**/*.gui.ts`**, **`./inventory/**/*.inventory.ts`**, **`./dialogs/**/*.dialog.ts`**, and **`./globalScript.ts`** so side-effect registrations run; it also registers **`./inventory/**/*.inventory.json`** and **`./dialogs/**/*.dialog.json`**. Room modules are executed on demand by **`ensureRoomScriptLoaded(roomId)`** (`src/engine/scripting/registerRoomScript.ts`), which is awaited in **`BootScene`** (after the Phaser asset loader completes, before `startInitialRoomFromBoot`) and in **`RoomTransitionOrchestrator`** (in parallel with `awaitLoaderComplete` during `changeTo`). Callbacks registered via **`registerRoomScript`** are stored in a **per-roomId map**; `RoomScene.create` calls **`getCallbacksForRoom(roomId)`** to run only that room's handlers with a fresh context. **`wireBenneGlobalScripts(game, gameEvents)`** runs immediately after **`createBenneGame`**, always constructs **`RoomTransitionHookRegistry` + `RoomTransitionOrchestrator`**, and (when at least one **`registerGlobalScript`** callback was recorded) runs those callbacks with **`GlobalBenneScript`** and **`setGlobalBenneScriptForRoomTransitions`** — enabling **`B.whenGlobalFallback`**, **`B.whenLeaveAnyRoom`**, **`B.whenEnterAnyRoom`**, etc. There is **no** exported `register*Script(events)` loader path.
- **Payloads**: Typed payloads for prop interaction (`propInteractionEvents.ts`), player walk start/stop, etc.
- **`BenneScript` movement — walk vs teleport**: **`B.player.walkTo(target)`** and **`B.character(id).walkTo(target)`** (and **`.now`**) use **`RoomScene`** pathfinding + **Walk** animation to a resolved room-space point — **unless** **`movable`** is **`false`** for that walker (**`CharacterData.movable`** / **`B.player.movable`** / **`B.character(id).movable`**), in which case the walk is a **no-op** (see **§7 → Sprite animation & persistence → Character movability**). **`B.player.moveTo` / `moveTo.now` / `moveToNow`** and **`B.character(id).moveTo` / …** **do not** pathfind: they call **`movePlayerToNow` / `moveCharacterToNow`** (feet **teleport** with walkable **clamp** and **Idle** facing) and are **not** gated by **`movable`**. The **same** resolution rules apply to **`Point2`** and string targets (first match): **prop** in the room → **hotspot** → **character** → **`room.points`**; props use **`walkToPoint`**, else closest point in/on the **collider** to the walker, else the prop frame **center**; hotspots use **`walkToPoint`** or polygon **centroid**; characters use **`CharacterData.walkToPoint`** or **feet** world position. Public **`RoomScene.resolveMovementTarget(target, walkerFeet)`** returns the room-space feet goal for any scripting use. Unknown ids **`console.warn`** once per id and fall back to the walker’s current feet (no move / no teleport offset). **`B.character(id)`** is implemented on **`BenneScriptCore`** (shared with room / character / inventory / **global / GUI / dialog** scripts): each call resolves the active **`RoomScene`** via the same hook as **`B.player`** (room-scoped facades pass **`() => this.roomScene`**; dialog / global / GUI pass **`game.scene.getScene(SCENE_ROOM)`**).
- **NPC track-facing**: **`B.character(observer).startFacingCharacter(targetId, minWaitSeconds?, maxWaitSeconds?)`** / `stopFacingCharacter()` are queued, NPC-only calls. The observer's Idle facing re-aims toward the target's world feet after a uniform random delay (defaults **0.2–0.4 seconds**) when either character moves; continued movement postpones the turn until motion settles. Stopping clears the lock and timer. Locks are per-room runtime state, are not saved, and update logical facing without replacing an active animation override.
- **Character follow (persisted)**: **`B.character(follower).startFollowingCharacter(targetId, options?)`** / `stopFollowingCharacter()` and the `B.player` equivalents persist the target plus merged `CharacterFollowOptions` (`minDistance`, `repathThreshold`, facing-relative `offset`, `speedMultiplier`, `faceTargetWhenIdle`, `pauseDuringCutscene`). The live driver runs only while both sprites are in the same room and normally pauses new walks during input-suppressed cutscenes. `"player"` is case-insensitive and resolves to the active player. Empty/self targets DEV-warn without persisting; stopping clears state and interrupts only follow-initiated movement.
- **`BenneScript` verb sugar** (**`whenLookAt`**, **`whenUse`**, **`whenPickUp`**, **`whenPush`**, **`whenPull`**, **`whenOpen`**, **`whenClose`**, **`whenVerb`**, **`whenTalkTo`**) registers handlers using the same **prop → hotspot → character** rule for the string id (room **`props`** / **`hotspots`** / spawned **`CharacterData.id`**). **`B.onProp`** and **`B.prop`** stay **prop-only**; **`whenGive(itemId, targetId, …)`** remains **prop-only** for **`targetId`** today. Armed-inventory **use** / **give** on props, hotspots, or characters (the usual combine flow) uses **`B.whenInventoryUsedOn(targetId, …)`** and **`payload.verbId`** / **`payload.itemId`** — see **§10 → `whenGive` on all target kinds**.
- **`B.region(regionId)`** (**`whenEnter`**, **`whenExit`**) and **`whenEnterRegion` / `whenExitRegion`** — room JSON **`regions[].id`** only; see **Room regions → Enter / exit hooks** above. **`RegionEnterExitContext`** payload; **`gameEvents`** ids **`roomRegionEnterEventId` / `roomRegionExitEventId`**.
- **`B.hotspot(hotspotId).active`** — room JSON **`hotspots[].id`** only; persists under `room:<roomId>:hotspot:<hotspotId>:active` and mounts/destroys the live polygon zone so inactive hotspots are not hit-tested. **`B.hotspot(id).clickable`** is an alias of **`.active`** (same persist key, immediate setter). **`B.hotspot(id).description`** is the hover / verb-line label; persists under `room:<roomId>:hotspot:<hotspotId>:description` (immediate setter).
- **Tagged dialogue (`B.say`)**: On every **`BenneScriptCore`** facade (**`BenneScript`**, **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, **`GuiBenneScript`**, **`DialogBenneScript`**), **`B.say`**…`` / **`B.say.now`**…``. Each non-blank line is **`Speaker: text`** (trimmed); **`Player`** in any case maps to `GameStateManager.activePlayerCharacterId`. Other labels match a spawned character definition id case-insensitively or `parseDialogueLines` throws with a short hint list. Blank lines and `//` comments are skipped. Tagged lines chain on the interaction tail in order; a single `B.say.now` line bypasses it, while multiple `.now` lines remain internally ordered without blocking later queued work. `B.player.say` / `B.character(id).say` scope plain lines to that speaker and reject a mismatched speaker prefix. A leading **`|number|`** voice id is removed from visible text and resolves the voice stem described under **Audio system**. Line timing, click-to-skip, `showText`, and `defaultTalkOffset` use **`getSpeechSettings(manager)`** / **`B.speechSettings`**. Without an active `RoomScene`, say calls no-op with a DEV warn-once.
- **Boundary**: Scenes should not embed game-specific puzzle logic; they **emit** and **listen** only through agreed event names and small shared types.

### Asset management / loading

- **Room & character JSON** for Aseprite: **eager globs** in `loadAsepriteAtlasData.ts` (and friends); **normalized** for Phaser frame indices (`normalizeAsepriteJson.ts`).
- **Binary assets**: **`resolveGameAssetUrl` / `resolveGameAssetJsonUrl` / `resolveGameAssetXmlUrl`** map paths under `src/game/assets/**` to **Vite-built URLs** (images, JSON, BMFont XML for GUI bitmap fonts). **Audio** uses additional globs on **`./assets/audio/sfx/**`**, **`./assets/audio/music/**`**, and **`./assets/audio/voice/**`** (.mp3 / .ogg / .wav / .m4a); **`getBenneAudioBootEntries()`** groups stems + URLs for **`queueBenneAudioForBootLoader`** (Phaser **`load.audio`** keys **`benne:sfx:<stem>`** / **`benne:music:<stem>`** / **`benne:voice:<stem>`** via **`benneAudioCacheKeys.ts`**).

### Audio system

**Goals**

- **`Phaser.Game#sound` only** (`SoundManager` never uses `scene.sound`) so playback survives **`RoomScene`** teardown — **music** can continue across **`B.room.changeTo`** without restarting.
- **Volumes**: **`applyBootAudioSettings`** (**`BootScene`**) sets the Phaser sound manager cap from **`game-config.json`** **`audio.masterVolume`**. Per-call playback multiplies **`getEffectiveSfxVolume`** / **`getEffectiveMusicVolume`** (**`applyAudioFromSettings.ts`**) with optional **`SoundPlayOptions.volume`** / **`MusicPlayOptions.volume`** (0–1) and with **`SoundManager`** session multipliers set by **`B.sound.setSfxVolume`** / **`setMusicVolume`** (persisted under **`settings:sfxVolume`** / **`settings:musicVolume`** in save snapshots via **`audioGameState.ts`**; **`applyPersistedAudioSessionVolumes`** on boot and **`GAME_STATE_REPLACED`**; **`applySnapshot`** preserves those keys when an incoming snapshot omits them unless **`initialGameState.variables`** seeds them). **Current music track** — **`settings:currentMusicId`** (stem or cleared on **`stopMusic`**); **`applyPersistedMusicTrack`** on boot and **`GAME_STATE_REPLACED`**; same merge/preserve rules via **`mergePreserveAudioVolumeVariables`** ( **`PERSISTED_AUDIO_STATE_VARIABLE_KEYS`** ). Playback position is **not** persisted. **Dialog prefs** use the same snapshot path for **`dialog:*`** variables via **`dialogGameState.ts`** (see **§3 → Dialog system**).

**Asset discovery**

- **`registerGameContent`** does **not** glob audio; **`resolveGameAssetUrl.ts`** holds **`import.meta.glob`** tables for **`assets/audio/sfx/**`**, **`assets/audio/music/**`**, and **`assets/audio/voice/**`**. **`getBenneAudioBootEntries()`** returns one boot row per **stem** (filename without extension); multiple formats for the same stem become a **fallback URL array** for **`load.audio`**.

**Runtime**

- **`SoundManager`** (**`src/engine/sound/SoundManager.ts`**) — **`playSfx` / `playSfxAndWait`**, **`playMusic`** (instant replace by default; optional **`fadeSeconds`** crossfade with **`sync`** alignment), **`stopSfx`**, **`stopAllSfx`**, **`stopMusic`**, **`destroy`**. **SFX** instances are tracked until **`complete`** / **`destroy`** or **`stop`**; **`playAndWait`** resolves when the sound finishes or is stopped.
- **Registry** — **`benneSoundRegistry.ts`**: **`BENNE_SOUND_MANAGER_KEY`**, **`tryGetBenneSoundManager`**, **`setBenneSoundManager`**; **`BENNE_AUDIO_SCRIPT_DISABLED_KEY`** (**`benneAudioScriptDisabled`**).
- **`Game.ts`** — constructs **`SoundManager`** after **`new Phaser.Game`**, registers it, **`applyPersistedAudioSessionVolumes`** + **`applyPersistedMusicTrack`**, **`wireBenneAudioGameState`** ( **`GAME_STATE_REPLACED`** ), **`destroy()`** on **`Phaser.Core.Events.DESTROY`** and removes the registry entry.

**Bennescript**

- **`createBenneScriptSoundFacade`** (**`benneScriptSoundApi.ts`**) wires **`B.sound`** on **`BenneScriptCore`** and exposes the **same object** on **`B.player.sound`**, **`B.character('…').sound`**, **`B.prop('…').sound`**.
- **Blocking `B.sound.play`** appends to **`interactionTail`** so it orders **after** **`walkToClicked`**, **`wait`**, etc.; **`B.sound.play.now`** plays immediately without tail sequencing. **`playAndWait`** chains **`SoundManager.playSfxAndWait`**; **`playAndWait.now`** starts playback without waiting on prior tail steps (same spirit as **`wait.now`**).
- **Author ids**: **`^[a-zA-Z0-9_-]+$`** map to loader keys **`benne:sfx:id`** / **`benne:music:id`**.
- **Voiced `say` lines** use this same manager rather than a separate dialogue API. `BenneScriptCore` recognizes a leading **`|number|`** marker in direct or tagged-template say text, removes it before logging/display, derives the stem **`<speakerId><number>`**, and plays `src/game/assets/audio/voice/<stem>.{mp3,ogg,wav,m4a}` at **`audio.dialogueVolume`**. The ordinary `say` promise still owns interaction-tail blocking, `.now`, Speaking Text visibility, Talk/Idle animation, and click-to-skip; skipping or tearing down the line stops its retained voice instance.

### Video system

- **Ownership and loading**: cinematic playback is a single hidden Phaser `Video` plus black letterbox backdrop owned by `RoomScene`, not by a game-scoped manager. Authors use basename-only ids under **`src/game/assets/videos/<stem>.{mp4,webm}`**. `resolveGameAssetUrl.ts` discovers them, `getBenneVideoBootEntries` groups formats, and `BootScene` calls `queueBenneVideoForBootLoader`. Preview games set **`benneVideoScriptDisabled`** in `preBoot` so authoring surfaces never start cinematics.
- **Composition**: the video is screen-fixed at **`ROOM_VIDEO_LAYER_DEPTH = 24_000`**, above room art and below the GUI band. It is letterboxed to internal resolution, registered with the runtime/editor UI camera, and forced to `FilterMode.NEAREST` when playback starts. Speaking Text and Display Text remain above it. Other HUD overlays and the dialog choice band are snapshot-hidden for playback and restored independently of dialog visibility snapshots when playback ends, stops, or tears down.
- **Bennescript**: `B.video` is shared by every `BenneScriptCore` surface and by `B.player`, `B.character(id)`, and `B.prop(id)`. It resolves the active `RoomScene`; missing-scene calls DEV-warn once. `play` queues after prior interaction steps but resolves immediately so later speech, fades, and character actions can run over the movie; `playAndWait` blocks until end/stop. `pause`, `resume`, `stop`, and `seek` follow the same `BlockingWithNow` convention. Completion invokes `options.onComplete` and emits **`benne:video:ended`**.
- **Input and lifecycle**: active video suppresses gameplay/GUI input and uses the cursor's busy state. Escape stops playback (or skips the enclosing cutscene when the video plays inside a skippable one); primary click/tap stops only when `clickToSkip` is true (default false). Room leave stops playback, scene shutdown destroys the objects, and video state is not saved. Volume is `audio.masterVolume × VideoPlayOptions.volume`.
- **VS Code codec caveat**: BENNE Play uses VS Code's webview browser, whose codec support differs from Chrome/Edge. MP4/H.264 with AAC may show frames but produce no sound. For editor testing, use a webview-supported audio codec (for example `ffmpeg -i Intro.mp4 -c:v copy -c:a libmp3lame -b:a 192k -movflags +faststart Intro-vscode.mp4`). When both MP4 and WebM exist, Phaser chooses one by container support and does not verify that the selected container's audio codec is decodable.

### Game state (v2)

- **Active `Phaser.Game` handle (engine bridge)** — not part of the saveable snapshot; complements **`game.registry`** + **`GameStateManager`** when APIs need the **game** or **active room scene** but only receive **`gameEvents`** (or other bus-only entry points). **`createBenneGame`** calls **`setActiveBenneGame(game)`** (`src/engine/gameState/activeBenneGame.ts`); the game’s **destroy** lifecycle clears it with **`setActiveBenneGame(null)`**. **`tryGetActiveBenneGame()`** returns **`null`** before boot or after destroy. **Primary use today**: **`interruptPlayerWalkForVerbInteraction`** (`src/engine/scenes/interruptPlayerWalkForVerbInteraction.ts`) resolves **`game.scene.getScene(SCENE_ROOM)`** (see **`SCENE_ROOM`** in **`src/game/boot/constants.ts`**) and, when that scene **`scene.isActive()`**, invokes **`RoomScene.interruptPlayerWalk()`** so verb and inventory-interaction dispatch does not run on top of an unfinished empty-space or **`walkTo`**-target move. **VS Code preview** bundles that build **`Phaser.Game`** without **`createBenneGame`** do not register this handle unless preview boot is updated — interrupt is then a no-op and preview walk + verb stacking may still occur.
- **`GameStateManager`** (`src/engine/gameState/GameStateManager.ts`): in-memory **flags** (`Record<string, boolean | number | string>`), **variables** (`Record<string, unknown>`), **`inventoryByCharacter`** (**`Record<string, Record<string, number>>`** — character definition id → item id → quantity), and **`activePlayerCharacterId`** (who **`B.inventory`** and default **`inventoryPanel`** rows target). Constructed in **`createBenneGame`** (`src/engine/Game.ts`) and stored on **`Phaser.Game.registry`** under **`benneGameState`** (`BENNE_GAME_STATE_REGISTRY_KEY`) so the same instance survives **`RoomScene`** teardown. **`getSnapshot` / `exportSnapshotJson`** emit **version 2** JSON. **`applySnapshot` / `importSnapshotJson`** accept **version 1** (flat **`inventory`** → starting player's bag) and **version 2**; v1 **`inventory`** arrays normalize to quantity maps (each id → **1**). **`getSnapshot()` runs `runSnapshotFlushHooks()` first** (unless `runFlushHooks: false`) so any **lazily-saved runtime state** (today: character feet positions and prop authoring positions on the active **`RoomScene`** — see **§7 → Sprite animation & persistence**) gets pulled into **`variables`** before the snapshot is cloned; this is what makes **`save`**, **`exportSnapshotJson`**, and **`B.state.exportJson`** capture positions without extra wiring. **`applySnapshot`** (including **`B.state.load`**) emits **`gameState:replaced`** with **`getSnapshot({ runFlushHooks: false })`** so the still-active pre-load scene does not overwrite restored position variables with the player's current feet before **`transitionToLoadedRoom`** restarts the room. **Runtime dialog settings** (**`B.dialogSettings`**) use **`variables`** keys **`dialog:*`** (eight persisted prefs — see **`dialogGameState.ts`**); writes are **eager** (not flush hooks). **`applySnapshot`** merges **`dialog:*`** like **`settings:sfxVolume`** / **`settings:musicVolume`**: omitted incoming keys keep prior in-memory values unless **`initialGameState.variables`** seeded them. **Bennescript sprite animation** also uses **`variables`** for reserved keys (see **§7 → Sprite animation & persistence**): `` `room:<roomId>:prop:<propId>:animation` `` (base prop tag), `` `character:<characterId>:animation` `` (character override), and **inventory** GUI/cursor tags `` `inventory:<itemId>:defaultAnimation` `` / `` `inventory:<itemId>:cursorAnimation` `` (override JSON **`defaultAnimation`** / **`cursorAnimation`**); **`playAnimation`** does not write these. **Per-room visit counter** — `` `room:<roomId>:visitCount` `` (non-negative integer; engine-maintained via **`roomVisitState.ts`**, surfaced as **`B.room.visitCount`**, **`B.room.isFirstVisit`**, and **`RoomTransitionContext.visitCount`**). **Per-room positions (lazily flushed)** — `` `room:<roomId>:character:<characterId>:position` `` (feet world coords) and `` `room:<roomId>:prop:<propId>:position` `` (authoring coords); see **§7 → Sprite animation & persistence → Snapshot flush hooks**. **Dialog options** persist via **`variables`** keys `` `dialog:<dialogId>:option:<optionId>:enabled` `` and `` `:used` `` (see **`dialogOptionVariables.ts`**); **`B.dialog(…).optionOn` / `optionOff`** write **`:enabled`**; picking a row sets **`:used`** and **`RoomScene`** refreshes the overlay on **`gameState:variableChanged`** for those keys and for **`__benne_active_dialog_id`**.
- **Active player and character switching**: `activePlayerCharacterId` defaults to `startingPlayerCharacter` and persists in v2 snapshots. **`B.player.id`** reads it; **`B.player.switchTo(characterId)`** / `.now` persist it, rebind `RoomScene.player`, refresh camera follow, and repaint inventory panels that follow the active player. `B.state.getActivePlayerCharacterId()` / `setActivePlayerCharacterId(id)` expose the saved id, but the player facade should be used when a live-room handoff is required. Tagged `B.say` labels named **`Player:`** and character-follow targets named **`"player"`** resolve to this active id.
- **Room context (persisted, not a variable bag entry):** optional **`currentRoom` / `lastRoom`** on **`SerializableBenneGameState`** (`src/types/gameState.ts`) — **`""`** and **`null`** when absent from JSON. **`getCurrentRoom` / `getLastRoom` / `setCurrentRoom` / `setLastRoom`**; **`B.state`** and **`B.room.current` / `B.room.last`** expose the same values. A cold **`createBenneGame`** leaves **`currentRoom` empty and **`lastRoom` null**; **`startInitialRoomFromBoot`** in **`BootScene`** sets **`lastRoom` to `null`** again before the first **`RoomScene`** (ensures a clean first **enter** context). Changes emit **`gameState:roomContextChanged`**; **`applySnapshot`** emits when loaded values differ from the previous in-memory pair. This is **separate** from the generic **`gameState:variableChanged`** stream. **`GameStateManager`**’s constructor accepts an optional slice that can seed these fields (`GameStateInitialSlice`); **`createBenneGame`** today only merges flags / variables / inventory from **`game-config.json`**. In-game **room loads** are driven by **`B.room.changeTo`** and **`RoomTransitionOrchestrator`** (not by mutating **`currentRoom` / `lastRoom`** alone — those fields track state for saves and hook context; see **§3 → Scene / room system → Room switching**).
- **Runtime “selection” UI state (verbs + use-on-target)**:
  - **Active verb** — see **Verb system → Active verb** (not part of save snapshots; cleared on **`applySnapshot`**).
  - **Active inventory item** (**`activeInventoryItemId`**, optional on **`SerializableBenneGameState`**): the item id “armed” for **use-on-target** clicks on room props / hotspots / characters. Persisted in **`getSnapshot` / `applySnapshot`** / **`exportSnapshotJson`**. Set/cleared with **`B.setActiveInventory` / `B.clearActiveInventory`** on room, character, global, and inventory Bennescript facades (**`GameStateManager.setActiveInventoryItem`**). Emits **`gameState:activeInventoryItemChanged`** (`GAME_STATE_ACTIVE_INVENTORY_ITEM_CHANGED_EVENT`). **`InventoryBenneScript`** arms the row after the interaction queue drains when the resolved **use** or **give** verb fires on that item — **without** requiring **`B.whenUse` / `B.whenGive`**. Optional **`B.whenUse` / `B.whenGive`** handlers run first, then the same **`afterTail`** activation unless **all** handlers for that verb used **`doNotActivate`**.
  - **Console**: the manager logs descriptive **`[Benne] …`** **`console.log`** lines when the active verb or active inventory item becomes active, inactive, or is overwritten by snapshot load (inventory lines include **display names** from **`inventoryDefinitionRegistry`** when available).
- **Data-first bootstrap**: optional **`initialGameState`** on **`game-config.json`** (merged at startup; validated in **`ConfigManager.ts`**). **`initialGameState.inventory`** (legacy) seeds the **starting player character** bag only (unique id list or quantity map). **`initialGameState.inventoryByCharacter`** seeds multiple bags (character id → list or quantity map).
- **EventBus**: incremental changes emit **`gameState:flagChanged`**, **`gameState:variableChanged`**, **`gameState:inventoryChanged`**; **room context** changes emit **`gameState:roomContextChanged`**; wholesale replace (**`applySnapshot`**, successful browser load) emits **`gameState:replaced`** only. Scripts listen with **`B.raw.on(...)`** (payload types in **`src/types/gameState.ts`**).
- **Bennescript**: **`B.state`** (set/get/has/clear flag and variable, **`getCurrentRoom` / `getLastRoom` / `setCurrentRoom` / `setLastRoom`**, named-save APIs **`getSaveList` / `save` / `load` / `deleteSave` / `renameSave`** with `.now` variants, **`exportJson` / `importJson`**, **`flush`** — pulls lazily-saved runtime state into **`variables`**; runs automatically inside **`getSnapshot`** and **`prepareForLeave`**) and **`B.inventory`** — **active player** bag quantity helpers: **`add` / `remove`** are **`BlockingWithNow`** (queue on each script facade’s **`interactionTail`** when **`createBenneScriptInventoryNamespace`** receives **`chain`**; **`.now`** applies immediately), plus **`has`**, **`quantityOf`**, **`items`**, and **`clearInventory`** (still synchronous). **`B.character(characterId).inventory`** / **`B.player.inventory`** expose the same quantity API for a **specific** character bag (no callable **`B.inventory(itemId)`** on those surfaces). **`B.inventory(itemId).animation`** / **`.cursorAnimation`** (**getters** return the effective tags used by the GUI cursor row and armed custom pointer; **setters queue** on the same tail as other blocking APIs; **`animationNow`** / **`cursorAnimationNow`** apply immediately; same **`variables`** keys as §7) on **`BenneScript`**, **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, **`DialogBenneScript`**, and **`GuiBenneScript`**. GUI scripts are still registered before `createBenneGame`, so pre-game calls no-op with a DEV warning until the active manager is published.
- **Persistence v1**: legacy slot snapshots stay at **`localStorage`** keys **`benne-save-<slot>`** (default slot **`0`**). Named saves are manifest-backed with **`benne-saves-manifest-v1`** and payload keys **`benne-save-v1-<sanitized-name>`**. `getSaveList()` migrates/merges legacy slot entries into the manifest view without breaking numbered-slot compatibility. **`exportSnapshotJson` / `importSnapshotJson`** remain the extension point for future file-based saves.

### Inventory System

- **Authoring layout**: Under **`src/game/inventory/<inventoryId>/`**, each inventory entry has **`<inventoryId>.inventory.json`** (source of truth, **`InventoryItemData`** in **`src/types/inventory.ts`**) and **`<inventoryId>.inventory.ts`** with top-level **`registerInventoryScript('inventoryId', ({ B }) => { … })`** from **`@engine/scripting`** (side effects only, mirroring characters). Optional **`defaultVerb`** on **`InventoryItemData`** is used when the player's click on that row in a GUI **`inventoryPanel`** resolves the effective **`inputProfile`** slot to **`"defaultVerb"`** or **`"walkTo"`** (both map to authored **`defaultVerb`**, else **`look`**). Plain verb ids in the profile (e.g. **`use`**) dispatch that verb on the item. Optional **`dropWhenUsed`** (boolean) overrides the global **`dropWhenInventoryUsed`** policy for this item only — see **Use-on-target (inventory × world) → Drop policy**. Optional **`cursorAnimation`** (string, Aseprite tag on **that item’s** sheet) drives the **optional** custom-game-cursor clip whenever this item is the **active inventory selection** — see **Input system → Custom pointer**; omit it to keep default cursor behavior only; at runtime **`B.inventory(itemId).cursorAnimation`** reads the **effective** tag (JSON ± **`GameStateManager`** override via **`inventory:<itemId>:cursorAnimation`** — see **`bennescript-api.md`** and §7 persistence).
- **Per-character bags**: `B.inventory` and `B.player.inventory` target the active player's bag; `B.character(id).inventory` targets a definition id explicitly. An `inventoryPanel` may set `characterId` to pin the displayed bag, or omit it to follow the active player and repaint after `B.player.switchTo`. Legacy flat inventory saves and `initialGameState.inventory` belong to the starting player's bag; `initialGameState.inventoryByCharacter` bootstraps multiple bags.
- **Use-on-target (inventory × world)**: With **`activeInventoryItemId`** set, **`RoomScene`** may route the next qualifying **left** click on a prop, hotspot, or clickable character to **inventory-on-target** dispatch (**`dispatchInventoryOnVerbTargetInteraction`**, events in **`inventoryOnVerbEvents.ts`**) instead of normal verb dispatch when **`shouldDispatchInventoryUsedOnVerbForGame`** is true (resolved verb is the configured **use** verb id **or** matches the current **active verb**). Room and character Bennescript register **`B.whenInventoryUsedOn('targetId', (payload) => { … })`**: in **room** scripts **`targetId`** is the prop id, hotspot id, or **character definition id**; in **character** scripts **`targetId`** must equal that character’s **`id`** (otherwise the handler is not registered). Handlers run through the usual interaction tail. A payload handler may **`return false`** to re-emit **`verb:global:inventoryOnVerbTarget:unhandled`** so **`B.whenInventoryOnVerbTargetUnhandled`** in **`globalScript.ts`** runs instead of inlining a fallback; in that case **`subscribeInventoryUsedOnTargetEvents`** does **not** apply drop-after-tail for the room callback—the global listener’s tail does.
- **Drop policy (“stay armed vs. drop after use”)**: whether the active inventory selection is “dropped” (active inventory + active verb both cleared) after a use-on-target click follows a layered policy resolved by **`shouldDropActiveInventoryOnUse`** (`src/engine/verbs/dispatchInventoryOnVerbTarget.ts`):
  1. Script-level **`B.whenInventoryUsedOn.doNotClear(...)`** (or **`{ doNotClear: true }`**) — hard per-handler opt-out; inventory stays armed.
  2. Per-item **`dropWhenUsed`** on **`*.inventory.json`** (**`InventoryItemData`**) — when present, wins.
  3. Global **`dropWhenInventoryUsed`** on **`game-config.json`** (**`GameSettings`**).
  4. Default **`false`** — inventory stays armed so the player can use the same item on several targets in a row (classic modern adventure behavior). Set the global or per-item flag to **`true`** for classic “drop after use”.

  When the policy resolves to **drop** **and** the **`whenInventoryUsedOn`** payload handler did **not** **`return false`**, **`BenneScriptCore.subscribeInventoryUsedOnTargetEvents`** clears **both** the active inventory and the runtime **active verb** after the handler’s queued steps so the verb HUD resets to idle (no stale "Use …" armed). **`RoomScene`** prop / hotspot / character pointer handlers and **`buildGuiOverlay`** inventory-on-inventory synchronously clear both when **`dispatchInventoryOnVerbTargetInteraction`** / **`dispatchInventoryOnInventoryItemInteraction`** is unhandled and **`shouldDropActiveInventoryOnUse`** is true. **`payload.verbId`** is captured at dispatch time, so handler bodies still see the verb that fired even after the post-tail clear. When the policy resolves to **don’t drop**, both the armed item **and** the active verb stay set across the click; clear them manually with **`B.clearActiveInventory()` / `B.clearActiveVerb()`**, verb GUI buttons, or right-click while armed.
- **Removal disarms depleted selections**: `GameStateManager.removeFromInventory` clears both `activeInventoryItemId` and the active verb when the removed id is armed and its quantity reaches zero, including non-stackable removal and stack depletion. This is independent of the post-use drop policy.
- **Right-click / empty-space clears while armed**: whenever **`activeInventoryItemId`** is set, a **right**-click on **anything** (prop, hotspot, clickable character, inventory row, or empty space) clears **both** the active inventory and the active verb. A **left**-click on empty space while armed also clears both instead of walking — the player must re-arm before the empty-space click walks again (`RoomScene.handleRoomPointerDown` + `resolution.kind === 'clearActive'` branches in the prop / hotspot / character pointer handlers and in **`buildGuiOverlay`** inventory rows).
- **Registry**: **`registerInventoryDefinitionsFromGame()`** (from **`registerGameContent`**) eager-loads **`./inventory/**/*.inventory.json`** into **`inventoryDefinitionRegistry`** so **`GameStateManager`** can read **`stackable`** when applying **`add` / `remove`**, and **`BootScene`** knows which Aseprite sheets to queue. JSON validation preserves optional fields such as **`cursorAnimation`**.
- **Shared Aseprite (PowerQuest-style)**: One export at **`src/game/assets/images/inventory/inventory.png`** + **`inventory.json`**. Each **frame tag** on the sheet is an inventory clip (and default animation name); entry-specific variants should use a root naming convention like **`<root>-*`** (for example **`lantern-glow`**, **`lantern-open`** for root **`lantern`**). The engine normalizes JSON for Phaser, then prefixes Phaser animation keys as **`inventory:<tag>`** so tags stay namespaced on a single texture (**`aseprite:inventory:shared`**). In JSON, set **`display.aseprite`** to **`"shared"`**. Optional **`defaultAnimation`** is the Aseprite frame tag used as the default clip in UI/cursor; when omitted, the inventory **`id`** is used (so the tag name normally matches the folder / inventory id).
- **Per-inventory-entry Aseprite**: **`display.aseprite: true`** loads **`images/inventory/<id>/<id>.png`** + **`.json`** (same pattern as characters). Authoring continues to use raw tag names, while normalized Phaser animation keys are namespaced as **`invitem:<itemId>:<tag>`** on texture **`aseprite:inventory:<id>`**. The **same soft `<root>-*` convention** as the shared sheet applies in tooling: roots are the inventory **`id`** plus optional **`defaultAnimation`**; a sheet tag is grouped with the entry when it equals a root or starts with **`root-`** (literal hyphen). The Inspector derives suggested animation rows from the per-item export the same way it does for **`"shared"`**; authored **`animations`** in JSON remains authoritative.
- **Bennescript**: **`InventoryBenneScript`** exposes the same **`B.player` / `B.character` / `B.state` / `B.inventory`** surface as character scripts, plus inventory-entry-scoped **`whenLookAt`**, **`whenUse`**, **`whenGive`**, … that subscribe to **`verb:room:<roomId>:inventory:<inventoryId>:<verbId>`** and **`verb:inventory:<inventoryId>:<verbId>`**. **`dispatchInventoryVerbInteraction`** ( **`src/engine/verbs/dispatchInventoryVerb.ts`** ) mirrors character precedence for inventory-authored handlers: emit **room-scoped** if that channel has listeners, else **global** if that channel has listeners, else the same global verb chain as **`dispatchVerbInteraction`** (**`verb:global:<verbId>`** → **`verb:global:fallback`** → **`verb:unhandled`**) so **`globalScript.ts`** fallbacks apply when no **`whenLookAt`** / **`whenVerb`** handler exists for that row. **`RoomScene`** runs every **`registerInventoryScript`** callback on each room load (inventory is not “spawned” like characters), then **`B.ensureDefaultInventoryUseAndGiveActivationAfterRegister()`** so empty scripts still subscribe the default **use** / **give** → **`setActiveInventory(thisId)`** path ( **`afterTail`**, same interaction tail as handler **`say` / `walkTo`**). **`B.whenUse` / `B.whenGive`** merge into that subscription — avoid redundant **`B.setActiveInventory(thisId)`** in the handler body unless you need activation **before** queued steps. **`trySyncActiveInventoryAfterInventoryUseOrGiveRowDispatch`** runs from **`buildGuiOverlay`** after dispatch for items with **no** **`registerInventoryScript`** module (JSON-only definitions). Room / character / global / inventory scripts may also use **`B.inventory(itemId)`** with **`animation`** / **`cursorAnimation`** to override **`defaultAnimation`** / **`cursorAnimation`** at runtime (**setters** queue on **`interactionTail`**; **`animationNow`** / **`cursorAnimationNow`** apply immediately — see **§7 → Sprite animation & persistence**), and **`B.inventory.add` / `remove`** (**`BlockingWithNow`**) for quantity changes in the same order as other tail steps.
- **VS Code extension**: Main tree **Inventory** group (with **Rooms**, **Characters**, **GUIs**, **Dialogs**). Tree selection opens **`*.inventory.json`** in the primary editor column and **`openBenneInventoryTypeScript`** (**`roomScriptNavigation.ts`**) for the companion **`*.inventory.ts`** in the Benne script row. Commands **`benne-editor.createInventoryItem`** (wizard: id + name → folder, minimal JSON with **`"aseprite": "shared"`**, stub **`.inventory.ts`**) and **`benne-editor.importInventoryItemsFromAsepriteTags`** (reads **`inventory.json`**, multi-select tags, writes/updates **`.inventory.json`** per tag and optionally **`.inventory.ts`**). **Inventory-on-target** authoring from the **room / character Inspectors** uses **`benne-editor.addRoomInventoryUsedOnStub`** / **`addCharacterInventoryUsedOnStub`** (see **§2 → BENNE — Inspector view**). In the Inspector, **both** **`display.aseprite: "shared"`** and **`display.aseprite: true`** entries derive animation cards from the relevant sheet using item-scoped roots (item **`id`** plus optional **`defaultAnimation`**) and only include matching tags (**`root`** and **`root-*`**); editing a derived row materializes that row into the entry JSON under **`animations`**. Tags outside that family can still be added manually in JSON (soft convention). Context menus follow the same pattern as **Characters** / **GUIs** (create on group/workspace; import from group or entry context where applicable).

### Dialog system (choice topics)

- **Authoring layout**: Under **`src/game/dialogs/<dialogId>/`**, each dialog has **`<dialogId>.dialog.json`** (**`Dialog`** in **`src/types/dialogue.ts`**: **`id`**, optional **`displayName`**, optional **`guiId`** defaulting to **`dialog`**, **`options[]`**) and **`<dialogId>.dialog.ts`** with top-level **`registerDialogScript('dialogId', ({ B }) => { … })`** from **`@engine/scripting`**. Each **`DialogOption`** has **`id`**, **`text`**, optional **`enabled`** (omit or **`true`** → option visible), optional **`used`** (authoring default **`false`**; runtime may persist **`true`** after the player picks that row), and optional **`say`** (omit or **`true`** → **`DialogBenneScript`** queues **`B.player.say`** with that option’s **`text`** before the matching **`whenChoice`** handler; **`false`** skips the automatic player line). Array **order** is the on-screen order; the Inspector can reorder rows (see **§2 → Dialogs**). The default choice GUI is **`guis/dialog/dialog.gui.json`** ( **`Option-Grid`**, **`scrollUp`**, **`scrollDown`**, template **`Dialog-Option`** / **`Bullet`** rows — the runtime hides templates and injects synthetic rows per option).

- **Registry**: **`registerDialogDefinitionsFromGame()`** (from **`registerGameContent`**) eager-loads **`./dialogs/**/*.dialog.json`** into **`dialogDefinitionRegistry`** (**`dialogDefinitionRegistry.ts`**). **`getRegisteredDialogChoiceGuiIds()`** returns **`'dialog'`** union every definition’s **`guiId`** so **`RoomScene`** can reserve those overlays from the generic GUI walk.

- **Runtime (`RoomScene`)**: Reserved choice GUIs are built **after** Speaking Text (**`speaking-text`**) at a higher depth band. **`wireDialogChoiceUi`** listens for **`benne:dialog:started`** / **`benne:dialog:stopped`** (**`DIALOG_STARTED_EVENT`**, **`DIALOG_STOPPED_EVENT`**), **`benne:dialog:optionEnabledChanged`**, **`gameState:variableChanged`** (**`GAME_STATE_VARIABLE_CHANGED_EVENT`**), per-GUI **`guiAllButtonsClickEventId`**, and **`guiButtonClickEventId`** for **`scrollUp` / `scrollDown`**. **`dialogChoiceGuiRuntime.ts`** owns **`DialogChoiceDynamicRowState`** (**`refresh`**, **`layoutDialogChoiceViewportSegments`**, **`getDialogChoiceAvailableHeightPx`**, **`DIALOG_CHOICE_GRID_ID`**). **`benne:dialog:started`** shows the overlay, calls **`pushScriptedDialogInputSuppression`** (same **`say`** line-lock path), and **`refresh`** fills the grid; **`benne:dialog:stopped`** hides it and **`popScriptedDialogInputSuppression`** when the session matches (**`dialogChoiceInputSuppressionActive`** guards double-pop). Each synthetic row is a real **`buildGuiButton`** hit target whose **`pointerup`** emits **`guiButtonClickEventId(guiId, dc__…)`** and **`guiAllButtonsClickEventId`**; **`RoomScene`**’s catch-all handler marks **`:used`**, then **`refresh`** applies **used** styling to picked rows — either tinting with **`dialog.usedColor`** from **`game-config.json`** (hex, e.g. `#888888`) or falling back to `setAlpha(0.45)` when omitted (**`B.whenChoice`** listeners run from the per-button emit). Scroll buttons page within **`Option-Grid`** by **viewport-sized pages** ( **`advanceDialogChoiceScrollTopPx`** / **`computeDialogChoiceScrollPageStarts`** — typically two pages when content slightly exceeds the cap); each page shows as much text as fits, including **partial** rows at the edges; bullets appear only when an option **starts** at the top of the slice (**`clipTopPx === 0`**). **`layoutDialogChoiceViewportSegments`** + **`getDialogChoiceScrollButtonState`** drive layout and arrow visibility. **`clearStateForRoomTransition`** and shutdown paths end orphan dialog sessions and end suppression if still active.
- **Choice options viewport height**: By default, how many option rows may stack is **`internalHeight − Option-Grid top − 4px`** (options grow toward the bottom of the canvas — fine for bottom bars). For **top strips** or other compact HUDs, cap stacking with optional **`choiceOptionsViewportHeightPx`** (pixels downward from **`Option-Grid`** top): **`game-config.json`** → **`dialog.choiceOptionsViewportHeightPx`**, or per choice GUI root in **`*.gui.json`** (GUI wins over game-config). Omitted = legacy behavior. Runtime: **`resolveDialogChoiceViewportHeightPx`** → **`getDialogChoiceAvailableHeightPx(..., maxViewportHeightPx)`** uses **`min(toScreenBottom, cap)`** when a cap is set. Example: 55px top strip with **`Option-Grid`** at **`y: 4`** → about **`47`** (`55 − 4 − 4` margin).
- **Used option color**: Optional **`usedColor`** in **`game-config.json`** → **`dialog.usedColor`** (hex string, e.g. **`"#888888"`**). When set, dialog options the player has already picked are tinted to this color (bullet sprite, label, label outlines, and background) instead of the legacy **`setAlpha(0.45)`** dimming. Omitted = legacy alpha behavior. Overridable at runtime via **`B.dialogSettings.usedColor`** (persisted under **`dialog:usedColor`** in **`GameStateManager`** variables; **`undefined`** clears override). Runtime: **`DialogChoiceDynamicRowState.refresh`** resolves the effective color from **`getDialogSettings(manager)`** and applies **`setTint`** / **`applyGuiBitmapTextFillTint`** on each sub-element when the option is **`used`** and `usedColor` is present.

- **Bennescript**: **`B.dialog(dialogId)`** is available on **`BenneScript`**, **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, **`GuiBenneScript`**, and **`DialogBenneScript`** (**`DialogBenneScript.ts`**, **`openDialogSessionForId`** in the same module to avoid circular imports). Methods **`start` / `stop` / `optionOn` / `optionOff`** ( **`BlockingWithNow`**, including **`.now`**) enqueue on each facade’s **`interactionTail`** except **`.now`** immediate variants. **`DialogBenneScript`** ( **`registerDialogScript`**) adds **`whenChoice(optionId, handler)`**, which registers **`guiButtonClickEventId(dialogGuiId, dialogChoiceSyntheticButtonId(optionId))`** so handlers fire when the player picks that row; unless the option’s JSON sets **`say`** to **`false`**, the engine first queues **`B.player.say`** with that row’s **`text`** (then runs the **`whenChoice`** body on the same interaction tail). **`B.player`** and **`B.character(id)`** are **not** dialog-specific — they come from **`BenneScriptCore`** (same active-room resolution as **`GlobalBenneScript`** / **`GuiBenneScript`**). **`B.prop(id)`**, **`B.hotspot(id)`**, and **`B.region(id).active`** are shared with room scripts (`benneScriptRoomEntityApi.ts`) and act on the **active** `RoomScene` (the room the dialog opened in), queued on the dialog session’s interaction tail where the room API queues. Region **`whenEnter` / `whenExit`** stay on **`*.room.ts`**. **`DialogScriptContext`** is documented briefly in **`src/engine/scripting/types.ts`**.

- **Events / variables**: Session helpers live in **`dialogSession.ts`**; **`dialogEvents.ts`** defines **`DIALOG_STARTED`**, **`DIALOG_STOPPED`**, **`dialogChoiceSyntheticButtonId`**, etc. Active dialog id is stored under **`BENNE_ACTIVE_DIALOG_ID_VARIABLE`** (**`__benne_active_dialog_id`**) for persistence and UI refresh.

- **Boot mirror**: **`game-templates/<name>/boot/registerDialogDefinitions.ts`** and the same globs in template **`boot/registerGameContent`** keep template games aligned.

- **VS Code extension**: **Dialogs** in the main tree, **Create Dialog**, Inspector + **Script…** workflow, and **`B.dialog(…).`** completions are documented under **§2 → BENNE — Inspector** (Dialogs bullet) and **§8**. Reserved Speaking Text (**`speaking-text`**) and choice-dialog **`*.gui.json`** / **`*.gui.ts`** authoring unchanged from the **GUIs** bullet above.

## 4. Data Flow

1. **Bootstrap**: `game-config.json` → resolution, start room id, **verbs / input profile / fallback line**, audio caps, debug flags, optional **`initialGameState`** for **`GameStateManager`**.
2. **Boot**: Manifest + glob pick **`RoomData`** → **`BootScene`** builds load list → loader completes → **`startInitialRoomFromBoot`** ( **`setLastRoom(null)`**, start kind **`'boot'`**) → **`RoomSceneStartData`** into **`RoomScene.create`**.
3. **Frame loop**: Phaser updates tweens / anims; **input** → hit tests → background **walk** on empty space, or **prop/hotspot/character** hit → **`dispatchVerbInteraction`** (stops an in-progress **player** walk first when applicable) → **`gameEvents.emit`** on the chosen event id.
4. **Scripts**: **`*.room.ts`** / **`*.character.ts`** / **`*.gui.ts`** / **`*.inventory.ts`** / **`*.dialog.ts`** / **`globalScript.ts`** register on **`gameEvents`** (or receive **`B`** from `@engine/scripting`) and run side effects when their lifecycle runs (per room load for room + character + inventory Bennescript; **`registerDialogScript`** bodies run when **`B.dialog(id).start`** / **`.start.now`** opens that dialog’s session via **`openDialogSessionForId`**; after game create for global; at content registration for GUI).

```
JSON + Aseprite  →  BootScene (Loader)  →  RoomScene (display + input)
                                              │
Pointer / keys ──────────────────────────────┤
                                              ▼
                                    gameEvents (EventBus)
                                              ▲
registerGameContent (*.room.ts factories [lazy], *.character.ts, *.gui.ts, *.inventory.ts, *.dialog.ts, globalScript)─┘
```

## 5. Key Design Decisions

| Decision | Why | Tradeoff |
|----------|-----|----------|
| **One `RoomScene` + boot + transition loader** | Keeps a single Phaser **room** scene; startup and in-room handoffs use the same **`RoomSceneStartData`** + loader queue helpers (`roomSceneBootstrap.ts`). | Each **`B.room.changeTo`** / **`changeToNow`** ( **`RoomTransitionOrchestrator`**) **restarts** **`RoomScene`** with a new start payload. **Cross-room data** (flags / variables / per-character **`inventoryByCharacter`**) stay on **`GameStateManager`**. **Teleport** helpers **`moveTo`** are unrelated (same room). |
| **Global `gameEvents` singleton** | Fast to wire; matches stringly event ids from JSON. | Global coupling; tests need discipline or indirection later. |
| **JSON string event ids** | Editable in data; matches classic adventure “verb” naming. | Typos fail at runtime; editor/tooling (e.g. VS Code extension) helps. |
| **Central verb dispatch** | One precedence chain (scoped per-verb listeners → object fallback → global → unhandled) and one place for future 9-verb / coin UIs to plug in. | Handlers must register **`verb:global:*`** if they rely on global overrides; listener counts drive whether each tier runs. |
| **Vite glob for assets** | Correct hashed URLs and tree-shaking. | **Editor preview** must use a **separate fetch/Webview path** (`src/editor/preview/`) — two loading strategies. |
| **Walkable polygons in JSON + visibility-graph pathfinding** | Designer-controlled navmesh; shortest-path routing around holes and concavities via reflex-vertex visibility graph + A\* (classical approach for polygons with holes; matches LucasArts feel). | No auto navmesh; bad polygons break movement visually (mitigated by debug draw of mesh + live path polyline). O(N²) visibility build per walk query — fine for hand-authored rooms, would need caching / triangulation for very large meshes. |
| **Aseprite tags = props / anims** | Single sheet per room/character, industry-standard tool. | Untagged cels are invisible to the engine; tag discipline required. |

## 6. Constraints and Rules

- **Engine vs game**: Do not put **game-specific narrative or room logic** under `src/engine/` except through **generic hooks** (events, helpers). Put reactions in **`src/game/`** (`*.room.ts`, future modules).
- **Config**: **`game-config.json`** is the **single source** for resolution, default character, start room override, **verbs**, **inputProfile**, **defaultFallbackLine**, audio, debug flags, optional **`initialGameState`** — read via **`getGameSettings()`**, not duplicated literals. Optional **`cursor`** (custom pointer) adds **`idleAnimation`** / **`activeAnimation`** (Aseprite tag names), optional **`cursor.animations`** (same per-tag shape as **`CharacterData.animations`**), and optional **`cursor.hotspot`** / **`cursor.hotspotPixel`** for pointer-tip placement.
- **Room data**: Follow **`RoomData`** / **`RoomPropInstance`** in **`src/types/room.ts`**; **`collider`** is required for **`clickable`** props. **`walkToPoint`** / **`lookAtPoint`** are optional script hints (not applied by the engine on click). Interactions are **`registerRoomScript`** listeners; optional **`onVerbFallback`** on a prop/hotspot enables fallback **`EventBus`** dispatch when no per-verb listener handled the verb. Optional **`defaultVerb`** (string verb id) feeds the `inputProfile` `"defaultVerb"` token (fallback `"look"`). **Room prop sheet placement**: **`spritePlacement`** defaults to **`"canvas"`** (authored `x`/`y` map to logical cel/sheet origin, full-canvas workflow); set **`"tight"`** when authoring against trimmed visible pixels (runtime uses `spriteSourceSize` and keeps placement synced across animated frames). In development, trim metadata that reports `trimmed: true` without `spriteSourceSize` produces a one-time warning so non-standard Aseprite exports are visible. Room-level **`points`** (**`RoomPointData[]`**, named **`x` / `y`**) are used by **`RoomScene`** when Bennescript resolves **`walkTo('pointId')`**. **`regions`** (**`RoomRegionData[]`**, closed polygons + `active`) drive perspective scale, optional walk-speed scaling, character tint, and enter/exit hooks. **Hotspot** polygons are separate **`hotspots[].points`**.
- **Room prop clip families (soft convention)**: Optional **`RoomPropInstance.defaultAnimation`** adds a second **root** alongside **`id`** for editor/Inspector grouping of tags on the room Aseprite sheet: a tag is suggested for that prop when it **equals** a root or matches **`root-*`** (literal hyphen after the root). **`RoomScene`** still uses **`tag`** for which clip is drawn; **`animations`** maps Aseprite tag names to optional **`loop`** / **`frameDuration`** overrides (same shape as character clip config). The Inspector merges **`meta.frameTags`** with **`animations`** using those roots; JSON stays the source of truth and arbitrary tags remain valid if added manually.
- **Character data**: Follow **`CharacterData`** in **`src/types/character.ts`**. Optional **`collider`** (≥3 **`points`** in frame space) restricts **click** hit-testing for **`clickable`** characters; omit it or save fewer than three points in the preview to use the **full sprite** bounds. Optional **`defaultVerb`** (string) feeds the `inputProfile` `"defaultVerb"` token for clicks on this character (fallback `"look"`). Optional **`onVerbFallback`** enables character-level fallback dispatch when no per-verb listener handled the click.
- **GUI data**: Follow **`GuiData`** in **`src/types/gui.ts`**. Optional **`controls`** describe screen-space widgets (**`text`**, **`inventoryPanel`**, **`image`**, **`nineSliceImage`**, **`button`**, **`trigger`**, **`grid`**). Optional top-level **`x`** / **`y`** set the initial screen-space offset of the packed **`gui.root`** (e.g. **`"y": -34`** to park a dropdown bar offscreen; fixed controls are not offset). Optional **`fixedControls`** is a string array of control **`id`** values: those controls are **not** parented under **`gui.root`**, so **`gui.root.tweenTo`** (and future whole-overlay moves) slide the rest of the HUD without moving them. Optional **`zIndex`** (default **0**) sets **overlay stack order** among all **`*.gui.json`** files (lower = behind); ties break on **`id`**. Distinct from per-control **`zIndex`** in **`controls[]`**, which only layers widgets inside one GUI. **`RoomScene`** assigns Phaser depth from **`sortGuisForOverlayStack`** (`src/engine/gui/guiStackOrder.ts`). Optional **`modal`** (default **`false`**) installs a full-screen invisible pointer catcher while the overlay is visible, blocking room input and any GUI with a **lower** overlay depth. The VS Code GUI Inspector exposes **`zIndex`** and **modal** in **GUI metadata**. Aseprite sheets use **`images/guis/<guiId>/<guiId>.png`** and **`.json`** when **`display.aseprite`** is true (same export pattern as characters). On **`image`** controls, **`tag`** and **`backgroundAnchor`** live on the control object (parallel to **`backgroundTag`** / **`backgroundAnchor`** on **`inventoryPanel`** and **`button`**); the GUI root **`display`** block is only for overlay-level options such as **`aseprite`**. **Trim-aware sheet placement**: `buildGuiOverlay` uses Aseprite trim metadata (`spriteSourceSize`) so both workflows are valid — **full-canvas** (`backgroundAnchor: "screen"`) and **trimmed-cel** (`top-left` / `center`). For grid-placed images, **`gridPlacement.align: "center"`** centers using visible packed frame size (`cutWidth`/`cutHeight`) rather than untrimmed source canvas size. **Bitmap fonts** for text controls: PNG atlas + BMFont **`.xml`** under **`src/game/assets/fonts/`**, logical ids and paths in **`fonts/fonts.json`** (Phaser **`load.bitmapFont`** key = id = GUI control **`font`**). **`RoomScene`** builds **one overlay per `*.gui.json`** (not a hard-coded id list), stacked by **`GuiData.zIndex`** then **`id`**: Speaking Text (**`speaking-text`**) is reserved for **`setDialogTextOverlay`** / **`say`** (starts hidden at boot); ids in **`getRegisteredDialogChoiceGuiIds()`** are reserved for **`B.dialog`…`start` / `stop`** (start hidden). Every other GUI is shown at room load unless **`"visible": false`**. The **GUI preview** uses the same **`buildGuiOverlay`** path for the selected GUI. **`nineSliceImage`** controls draw a tag from the GUI sheet using **`meta.slices`** (Aseprite slice names mapped per 3×3 cell in **`sliceNames`**) and nine cropped quads so panels scale on Canvas (see **`buildGuiOverlay`** / **`guiNineSliceImage.ts`**).
- **Walkable mesh**: **`walkable.polygons[]`** entries support optional **`holes[]`** (inner rings subtracted when **`active`** is not **`false`**). Each polygon and hole may set **`active`**; omitted or non-**`false`** means included in tests and debug draw. See **`walkable.ts`** and **`RoomScene`** debug overlays (outer vs hole stroke colors).
- **Registration**: New room scripts live under **`src/game/rooms/`** as **`*.room.ts`** with top-level **`registerRoomScript(({ B }) => { … })`**. Character scripts use **`registerCharacterScript('id', ({ B }) => { … })`** under **`src/game/characters/`**. GUI scripts use **`registerGuiScript('id', ({ B }) => { … })`** under **`src/game/guis/<id>/`**. Inventory scripts use **`registerInventoryScript('id', ({ B }) => { … })`** under **`src/game/inventory/<id>/`**. Dialog scripts use **`registerDialogScript('id', ({ B }) => { … })`** under **`src/game/dialogs/<id>/`**. Global hooks use **`registerGlobalScript(({ B, game }) => { … })`** in **`src/game/globalScript.ts`**. All are side-effect-only (no **`export function register*Script`**).
- **Strict TypeScript**: Project uses **strict** compiler options; new code should preserve typings for payloads and JSON-shaped types.

## 7. Scripting / interaction system (Bennescript)

BENNE uses a **two-layer scripting architecture** that keeps the engine data-first while giving authors a clean, modern, PowerQuest-inspired authoring experience.

**Layer 1 – Engine Core (unchanged)**  
- Verb dispatch still emits canonical scoped event IDs via `dispatchVerbInteraction` (`verb:room:office:prop:desk:look`, etc.).
- Raw `EventBus` (`gameEvents`) and typed payloads (`RoomPropInteractPayload`, etc.) remain the foundation.

**Layer 2 – Bennescript Facade (new authoring surface)**

Authors now write against a clean, discoverable facade. Handlers are **ordinary sync functions**; the engine registers `async` listeners and, for queued actions, awaits an internal **interaction tail** built from `Promise`s so linear scripts work **without** author `async`/`await` (see **Blocking interaction queue vs `.now`** below).

```ts
import { registerRoomScript } from '@engine/scripting';

// Sugar verbs (`whenLookAt`, `whenUse`, `whenTalkTo`, …) use one string id: `props[]` → `hotspots[]` → character in room.
// `walkTo('…')` pathfinds; `moveTo('…')` / `moveToNow('…')` teleports (same id / `{x,y}` resolution).
// `walkTo` / `moveTo` resolve prop → hotspot → character → `points[]`.
// `walkToClicked` / `walkToClicked.now` (also on `B.player`) walk to the clicked prop/hotspot/character id from the verb payload (same resolution as `walkTo` for that id), then face like `faceClicked` when the walk finishes.
// `faceClicked` / `faceClicked.now` alone use `lookAtPoint` from the room JSON when present; for NPCs, face their feet (`RoomScene.facePlayerTowardClicked`).
registerRoomScript(({ B }) => {
  B.whenLookAt('desk', () => {
    B.walkToClicked();
    B.player.say('Looks like an ordinary desk with some paperwork…');
  });

  B.whenUse('desk', () => {
    B.player.say("I don't know what to do with that yet.");
  });
});
```

### Generated game ID types (Bennescript IntelliSense)

**Purpose** — Give authors compile-time checking and autocomplete for content ids in **`*.room.ts`**, **`*.character.ts`**, **`globalScript.ts`**, and other Bennescript entrypoints without changing runtime behavior.

**Output** — [`src/types/generated/benne-game-ids.d.ts`](../src/types/generated/benne-game-ids.d.ts) exports unions such as **`CharacterId`**, **`PropId`**, **`DialogId`**, **`GuiId`**, **`InventoryItemId`**, **`RoomId`**, **`HotspotId`**, **`RegionId`**, **`PointId`**, **`DialogOptionId`**, **`GameVerbId`**, plus composite **`VerbTargetId`** (prop / hotspot / character verb targets) and **`ResolvableTargetId`** (walk / teleport string targets). Each type uses **`LooseString<'literal' | …>`** so known ids autocomplete while arbitrary strings still type-check (backward compatible).

**Scanner** — [`scripts/lib/scanGameContentIds.mjs`](../scripts/lib/scanGameContentIds.mjs) walks **`src/game/`**: folder names for rooms / characters / dialogs / guis / inventory; **`props[]` / `hotspots[]` / `regions[]` / `points[]`** across all **`*.room.json`** (props are a **global** namespace); **`options[].id`** in dialog JSON; **`game-config.json`** **`verbs[]`**.

**Regeneration** — **`npm run generate:game-ids`** (also **`predev`** / **`prebuild`** and the Vite plugin in [`vite.config.ts`](../vite.config.ts) during dev watch). The BENNE Editor runs the same script debounced when game JSON changes (see **§8**). The **`.d.ts` file is committed**; do not edit it by hand.

**Facades** — Bennescript APIs in **`src/engine/scripting/`** import these types for **`B.character('…')`**, **`B.prop('…')`**, **`B.room.changeTo('…')`**, **`registerCharacterScript('…')`**, etc. Domain barrels under **`src/types/`** re-export the same names for game scripts.

Character definition scripts use the same `B` movement/dialog primitives on the active `RoomScene`, but **self-only** verb sugar (no target id string — subscribes to `verb:character:<id>:<verb>` only):

```ts
import { registerCharacterScript } from '@engine/scripting';

registerCharacterScript('hank', ({ B }) => {
  B.whenLookAt(() => {
    B.player.say('Hank stares back.');
  });
});
```

**Blocking interaction queue vs `.now` (core Bennescript behavior)**  

Room and character verb handlers are written as **ordinary synchronous functions**, but several `B` methods represent **time** (movement tweens, short `say` pacing delays, `wait`, etc.). Those methods participate in an **internal interaction queue** (`interactionTail` in `BenneScriptCore`): each step is a `Promise` that must finish before the **next** queued step **starts**. That makes linear scripts read top-to-bottom while still driving real async engine work (e.g. `RoomScene.walkPlayerTo` resolves when the walk tween completes). The same queue backs **`BenneScript`** (room), **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, and **`GuiBenneScript`**. **`B.inventory.add` / `B.inventory.remove`** ( **`BlockingWithNow`**) and **`B.inventory(itemId).animation`** / **`.cursorAnimation`** setters on room, character, inventory, global, and dialog-session facades append through that tail (**`createBenneScriptInventoryNamespace`** in **`benneScriptGameStateApi.ts`** passes each script’s **`chain`**). **`GuiBenneScript`** has no **`B.inventory`** surface.

**`walkToClicked` / `walkToClicked.now`**: While a handler registered through `BenneScriptCore.subscribe` or `subscribeAfterInteractionTail` runs, the engine pushes a short-lived walk target derived from the event payload (`propId` / `hotspotId` / `characterId`, including global verbs and inventory use-on-target). `B.walkToClicked()` (room and global scripts) or `B.player.walkToClicked()` (character and inventory scripts) calls `RoomScene.walkPlayerTo` with that id so movement uses the same string resolution as `B.player.walkTo`, then applies `RoomScene.facePlayerTowardClicked` when the walk Promise settles — equivalent to chaining `faceClicked` after the walk (snapshot from the handler’s payload taken when `walkToClicked` runs). Pure inventory-row verbs (`dispatchInventoryVerbInteraction`) carry no world target — a one-time dev `console.warn` applies if authors call `walkToClicked` there anyway. Misuse outside any verb handler is also warned once in dev.

**`faceClicked` / `faceClicked.now`**: Uses the same payload-derived context stack. Facing prefers **`lookAtPoint`** from the verb payload (props, hotspots, global handlers — emitted from room JSON / `VerbInteractTarget`). **Characters** do not use `lookAtPoint`; the player faces the clicked character’s **feet** in room space. If there is no `lookAtPoint` and the target is not a character, facing falls back to the same stand/centroid point as **`walkToClicked`**. When the feet→target vector is ~0, facing is left unchanged (so the player does not snap to “down”). Same dev warnings as `walkToClicked` when there is no world target or no room scene.

**Important implementation detail:** queued steps are registered with **lazy factories** (`() => Promise<…>`), not pre-created promises. If the queue were fed eager promises, every `walkTo` / `say` in one handler body would **start immediately** in the same synchronous tick; only **completion** order would be serialized. Lazy registration ensures the **next** walk (or delay) does not begin until the previous step’s promise has settled.

**Methods that use the queue today (blocking by default)**  

These schedule work on the queue when called from a handler (or any code path using the same `BenneScript` instance). Not every facade method is queued; only ones that need ordering relative to time or prior steps. **Teleport** **`moveTo`** is queued the same way as **`walkTo`** (synchronous **`movePlayerToNow` / `moveCharacterToNow`** inside the tail step); **`moveTo.now`** / **`moveToNow`** fire immediately, like **`walkTo.now`**.

| API | Blocking call | Non-blocking (same effect, no queue) |
|-----|----------------|--------------------------------------|
| `B.player` / `B.character(id)` — walk | `walkTo(target)` | `walkTo.now(target)` |
| `B.player` / `B.character(id)` — feet teleport (not a walk) | `moveTo(target)` | `moveTo.now(target)` or `moveToNow(target)` |
| `B.player` / `B.character(id)` — line | `say(text)` | `say.now(text)` |

**`.now` semantics**  

- **`.now`** runs the **same** underlying behavior (walk tween, `delayedCall` for `say` / `wait`, sync animation or facing).  
- It does **not** append to `interactionTail`; later **blocking** lines in the same handler still run in source order, but **without waiting** for the `.now` action to finish.  
- Return type is **`void`** (same as the blocking form); the engine does not surface promises to authors for the default API.  
- TypeScript models blocking methods as **`BlockingWithNow<…>`** — the callable plus a **`now`** property with the same parameters (good autocomplete).

**Sprite animation & persistence (`Animation` vs `PlayAnimation`)**  

Bennescript separates a **saved** “what should this prop/character show by default?” from a **temporary** scripted clip (inventory row clips use **saved** overrides only — no **`playAnimation`** on **`B.inventory(id)`**):

- **`B.prop(id)`** (`BenneScriptPropFacade` in `src/engine/scripting/benneScriptFacades.ts`): **`animation`** get/set is the prop’s **base** Aseprite tag (JSON `tag` until a save overrides it). The **setter** is **queued** on the same **`interactionTail`** as **`walkTo`**, **`say`**, and **`playAnimation`**; **`animationNow(tag)`** writes game state and updates the sprite **immediately** (skips the tail). **`playAnimation` / `.now`** plays a tag once, then restores that persisted base clip. Room props register clips with **`scene.anims.createFromAseprite`** (global keys on the scene AnimationManager).

- **`B.player`** / **`B.character('id')`**: **`get animation`** returns the **effective** key (persisted **override** if any, else the live directional idle / walk / talk tag). **`set animation`** / **`animationNow`** accept **`string | null`** (`null` clears the override). **`stopAnimation()`** clears the saved override and returns to directional idle (always immediate — no **`.now`** variant). While an override is active, **`RoomScene`** avoids swapping to automatic directional **Idle / Walk / Talk** (movement tweens still run; **facing** data updates so that when the override ends, idle matches the current facing). **`BenneScriptCore.applySayLineDirectionalBase`** skips directional **Talk** when an override is active and restores via **`applyCharacterEffectiveAnimation`** after each line.

- **Character movability — `B.player.movable` / `B.character(id).movable`**: **`get movable`** returns whether pathfind walking is allowed (**`readSavedCharacterMovable`** vs **`CharacterData.movable`** default from the room’s first spawn row for that definition id). **`set movable`** queues like **`visible`** and persists to **`GameStateManager`** (see **Persistence**). When **`movable`** is **`false`**, **`RoomScene.movePlayerToward`**, **`walkPlayerToWorldPoint`**, **`walkCharacterTo`**, and **`walkCharacterToWorldPoint`** return without starting tweens ( **`walkTo`**, **`walkToClicked`**, click-to-walk, verb **`walkPlayerTo`** paths). **`movePlayerToNow` / `moveCharacterToNow`** still run.

- **Character clickability — `B.character(id).clickable`**: **`get clickable`** returns whether the NPC receives pointer hit-test (**`readSavedCharacterClickable`** vs **`CharacterData.clickable`** default from the room’s first spawn row). **`set clickable`** queues like **`movable`** and persists to **`GameStateManager`** (see **Persistence**). When **`clickable`** is **`false`**, **`RoomScene`** disables interactive input on the sprite (no hover, verbs, or inventory-on-target); **`resolveMovementTarget`** / **`walkTo('id')`** still resolve the character. Not on **`B.player`**.

- **Prop clickability — `B.prop(id).clickable`**: Same interaction gate as characters, room-scoped. **`get clickable`** is **`readSavedPropClickable`** vs JSON **`RoomPropInstance.clickable`** (`true` only when the field is explicitly **`true`**). **`set clickable`** queues like **`visible`** and persists (see **Persistence**). When **`false`**, **`RoomScene`** **`disableInteractive`**s the sprite; when **`true`**, it re-enables or attaches collider hit-test + **`pointerdown`**. Enabling needs an authored collider (≥3 points); missing collider is persisted but not attached (warn). **`resolveMovementTarget`** / **`walkTo('id')`** still resolve the prop.

- **Hover-line description — `B.prop(id).description` / `B.character(id).description` / `B.hotspot(id).description` / `B.inventory(id).description`**: Immediate (not queued) getters/setters for the verb-line / hover-text label. Each persists a string (including empty) to **`GameStateManager`** (see **Persistence**). Hover and verb / inventory-on payloads read the saved override over JSON; display still uses today’s trimmed fallbacks when the effective string is empty (prop id, character/item name, hotspot `null`). Setters refresh **`B.currentHoverDescription`** without requiring a pointer move.

- **Character follow — `B.player` / `B.character(id).startFollowingCharacter` / `stopFollowingCharacter`**: Persistent **trail** behavior (not the same as **`startFacingCharacter`**, which is runtime-only idle facing). **`startFollowingCharacter(targetId, options?)`** is idempotent for the same target (re-call updates saved options). **`stopFollowingCharacter()`** clears persisted keys and interrupts a walk that was started by the follow driver (sprite **`setData`** purpose **`benneFollowWalkPurpose`**). Follow walks apply **`benneFollowWalkSpeedMult`** on the sprite so **`beginPlayerWalkLeg` / `beginNpcWalkLeg`** multiply base **`walkSpeed`**. When **`faceTargetWhenIdle`** is **true** (default) and the follower is not walking and has no **`startFacingCharacter`** lock, **`RoomScene`** turns idle facing toward the target’s feet. **`B.player`** exposes the same API so the starting player can follow an NPC if authored.

- **`playAnimation`**: never touches **`GameStateManager`**; for **looping** clips (`loop: true` in `CharacterData.animations` → Phaser **`repeat: -1`**), completion is approximated by **one full cycle** (**`Animation.duration`**, with a frame-based fallback) before revert, so the interaction tail does not settle in the same tick as the play call. Character sheets use **`sprite.anims.createFromAseprite`**, so clips are **sprite-local**; **`promiseWhenSpriteAnimationFinishes`** (in `src/engine/benneAnimationRuntime.ts`) resolves completion using **`sprite.anims`** first, then **`scene.anims`** (props), and reads **`repeat`** from the resolved **`Animation`**.

- **`B.inventory('itemId')`** (`BenneScriptInventoryItemFacade`): **`animation`** / **`cursorAnimation`** get/set the effective **GUI icon** and **armed cursor** Aseprite tags (JSON defaults when no override; **`cursorAnimation`** getter is **`''`** when the armed pointer would fall back to the verb / global cursor). **Setters** are **queued** on the same **`interactionTail`** as **`walkTo`**, **`say`**, **`wait`**, and **`B.player.animation`** when used from **`BenneScript`**, **`CharacterBenneScript`**, **`InventoryBenneScript`**, **`GlobalBenneScript`**, or **`DialogBenneScript`**; **`animationNow(tag)`** / **`cursorAnimationNow(tag)`** write **`GameStateManager`** variables and refresh the active room scene **immediately** (skip the tail). Setter **empty string** clears that field’s variable so JSON applies again. **`description`** is **immediate** (not queued) and persists `` `inventory:<itemId>:description` `` over JSON; empty string is stored as empty (does **not** clear to JSON). **`RoomScene`** validates tags when a room is active; **`buildGuiOverlay`** / custom cursor read effective animation values; hover / verb payloads read **`readEffectiveInventoryDescription`** (`src/engine/inventory/inventoryScriptingAnimations.ts`).

- **Sprite alpha fade — `B.prop(id).fade` / `B.character(id).fade`** (room scripts for props; room + character scripts for characters): **`fade(fromAlpha, toAlpha, durationSeconds)`** tweens the prop/character sprite's `alpha` from **`fromAlpha`** to **`toAlpha`** over **`durationSeconds`** using a `Linear` ease. Both alphas clamp to `[0, 1]` and `durationSeconds` clamps to `>= 0` (a duration of `0` snaps to `toAlpha` synchronously). Each call **`tweens.killTweensOf`** the sprite first so back-to-back fades don't stack, then sets `alpha = fromAlpha` before the tween starts (so `fade(0, 1, 0.5)` always begins fully transparent regardless of prior state). The **blocking** form queues on the script's **`interactionTail`** and waits for the tween to complete; **`fade.now`** starts the same tween immediately without blocking subsequent script lines (later **blocking** lines still serialize through the tail behind any previously-queued steps). The **`toAlpha`** is **persisted to `GameStateManager`** the moment the call runs (room-scoped key for props, global per-character-id key for characters — see **Persistence** below) so saving mid-fade or reloading the room restores the **intended final** alpha rather than mid-tween state. Backed by **`RoomScene.fadePropScriptAlpha`** and **`RoomScene.fadeCharacterScriptAlpha`** (`src/engine/scenes/RoomScene.ts`).

- **Prop visibility — `B.prop(id).hide` / `show` / `visible = …` / `visibleNow(…)`**: Each setter call **persists** the boolean to **`GameStateManager`** (room-scoped key — see **Persistence**) and updates the live sprite. Spawn re-reads the saved value via **`readSavedPropVisible`** so a hidden prop stays hidden across **`B.room.changeTo`** and browser save/load. **`B.prop(id).visible`** getter prefers the live sprite when one is present (so it reflects what is on screen right now); when the prop is not yet spawned, it falls back to the saved value, then to the JSON default.

- **Character visibility — `B.character(id).hide` / `show` / `visible = …` / `visibleNow(…)`**: Same pattern as props, but the key is **global per character definition id** (see **Persistence**). Spawn re-applies via **`readSavedCharacterVisible`**. When there is no active **`RoomScene`**, setters still persist through **`writeSavedCharacterVisible`** if a **`GameStateManager`** is active (mirrors **`fadeCharacterScriptAlpha`** reachability from global / GUI scripts).

- **Prop position — `B.prop(id).moveTo` / `moveTo.now` / `moveToNow`**: Teleport the prop's **authoring** origin to a `Point2` in room space (no tween, no string-id resolution — props don't have feet / stand-points the way characters do). The **blocking** form queues on the script's **`interactionTail`** (same ordering as **`B.prop(id).visible`** / **`animation`**); **`.now`** / **`moveToNow`** apply immediately. Backed by **`RoomScene.movePropToNow`**, which routes the new origin to whichever placement model the prop uses: **tight** (`spritePlacement: "tight"`) updates **`benneRoomPropAuthoredX/Y`** then re-syncs via **`syncBenneRoomPropTightWorldPosition`**; **parallax** (`parallaxDepth !== 1`) updates the entry's **`baseX / baseY`** (the next parallax tick repositions the sprite); plain canvas placement sets **`sprite.x / y`** directly. Position is **not** eagerly persisted on the call — it goes to game state on the next snapshot flush (room-leave, **`getSnapshot`**, or **`B.state.flush`**), matching how character positions are tracked.

- **Character + prop position persistence (lazy)** — character feet (after walk / teleport) and prop authoring origin do **not** write to **`GameStateManager`** per-tick. Instead, **`RoomScene.create`** registers a **snapshot flush hook** (via **`registerSnapshotFlushHook`** in **`src/engine/gameState/snapshotFlushHooks.ts`**) that walks **`characterSpritesByDefId`** (writing **`getCharacterWorldFeet(sprite)`** to `` `room:<roomId>:character:<characterId>:position` ``) and **`propSpritesById`** (writing each prop's authoring position — tight → parallax `baseX/Y` → live `sprite.x/y` — to `` `room:<roomId>:prop:<propId>:position` ``). The hook fires from three trigger points: **`GameStateManager.getSnapshot`**, **`RoomTransitionOrchestrator.prepareForLeave`**, and **`B.state.flush`**. The hook is unregistered on **`Phaser.Scenes.Events.SHUTDOWN`** so torn-down rooms (and editor preview **`Phaser.Game`** instances that don't run `RoomScene.create`) never hold stale references. See **Persistence → Snapshot flush hooks** below.

**Persistence** ( **`GameStateManager` variables** — same snapshot pipe as other `B.state` keys):

- **Room visits** (room-scoped):
  - `` `room:<roomId>:visitCount` `` — integer **`>= 0`**; the engine increments this **once per room load** (before **`whenEnterRoom`** / **`whenEnterAnyRoom`**) and exposes it on **`B.room.visitCount`**, **`B.room.isFirstVisit`** (`visitCount === 1`), and **`RoomTransitionContext.visitCount`**. Survives **`exportJson` / `importJson`** / save slots like any other **`variables`** entry.
- **Props** (room-scoped):
  - `` `room:<roomId>:prop:<propId>:animation` `` — base tag string. Applied when **`RoomScene`** spawns props (after merged Aseprite clip setup).
  - `` `room:<roomId>:prop:<propId>:visible` `` — boolean override for **`B.prop(id).hide` / `show` / `visible = …` / `visibleNow(…)`**; spawn applies via **`readSavedPropVisible`** (JSON `RoomPropInstance.visible` is the fallback default).
  - `` `room:<roomId>:prop:<propId>:clickable` `` — boolean override for **`B.prop(id).clickable`**; spawn applies via **`readSavedPropClickable`** (JSON `RoomPropInstance.clickable === true` is the fallback default).
  - `` `room:<roomId>:prop:<propId>:description` `` — string override for **`B.prop(id).description`** (including empty); hover / verb payloads use **`readSavedPropDescription`** (JSON `RoomPropInstance.description` is the fallback default).
  - `` `room:<roomId>:prop:<propId>:alpha` `` — number `[0, 1]`; written as **`toAlpha`** by **`B.prop(id).fade(...)`** and **`fade.now`**; spawn applies via **`readSavedPropAlpha`** (JSON `RoomPropInstance.alpha` ?? `1` is the fallback default).
  - `` `room:<roomId>:prop:<propId>:position` `` — `{ x, y }` authoring world coords. **Lazily** written by the snapshot flush hook installed in **`RoomScene.create`** (see **Snapshot flush hooks** below) — written on **room-leave**, **`getSnapshot`**, and **`B.state.flush`**, never per-tick. Source is the prop's **authoring** position, not its live `sprite.x / y`: tight-placement uses `benneRoomPropAuthoredX/Y`; parallax uses the entry's **`baseX / baseY`**; otherwise the live sprite position. Spawn applies via **`readSavedPropPosition`** by overriding `RoomPropSpawn.x / y` before `add.sprite`, so tight + parallax + plain placement all round-trip. Authors mutate this through **`B.prop(id).moveTo` / `moveTo.now` / `moveToNow`** (see [bennescript-api.md → `B.prop(propId)`](bennescript-api.md#bproppropid-bennescriptpropfacade)).
- **Characters** (global, follows the definition id across rooms):
  - `` `character:<characterId>:animation` `` — override tag; cleared by **`stopAnimation()`** or **`animation = null`** / **`animationNow(null)`**.
  - `` `character:<characterId>:visible` `` — boolean override for **`B.character(id).hide` / `show` / `visible = …` / `visibleNow(…)`**; spawn applies via **`readSavedCharacterVisible`** (first **`RoomCharacterInstance.visible`** fold in the room JSON is the fallback default, same “first wins” rule as the sprite map for duplicate definition ids).
  - `` `character:<characterId>:movable` `` — boolean override for **`B.player.movable`** / **`B.character(id).movable`**; effective value via **`readSavedCharacterMovable`** (JSON **`CharacterData.movable`** from the first spawn row for that id in the active room is the fallback default — **`true`** when the field is omitted or anything other than **`false`**).
  - `` `character:<characterId>:clickable` `` — boolean override for **`B.character(id).clickable`**; effective value via **`readSavedCharacterClickable`** (JSON **`CharacterData.clickable`** from the first spawn row for that id in the active room is the fallback default).
  - `` `character:<characterId>:description` `` — string override for **`B.character(id).description`** (including empty); hover / verb payloads use **`readSavedCharacterDescription`** (JSON **`CharacterData.description`** is the fallback default).
  - `` `character:<characterId>:followingTarget` `` — non-empty string when **`B.character(id).startFollowingCharacter`** / **`B.player.startFollowingCharacter`** is active: a character definition id or the literal **`"player"`** (resolved at runtime to **`GameStateManager.activePlayerCharacterId`**). Cleared by **`stopFollowingCharacter()`**.
  - `` `character:<characterId>:followOptions` `` — plain object with merged follow tuning (**`minDistance`**, **`repathThreshold`**, **`offset` `{ x, y }`**, **`speedMultiplier`**, **`faceTargetWhenIdle`**, **`pauseDuringCutscene`**); written whenever follow starts or options change. Read via **`readSavedCharacterFollowEffectiveOptions`** (defaults applied when missing or partial).
  - `` `character:<characterId>:alpha` `` — number `[0, 1]`; written as **`toAlpha`** by **`B.character(id).fade(...)`** and **`fade.now`**; spawn applies via **`readSavedCharacterAlpha`** to both image-only and Aseprite character spawn paths (default `1`).
  - `` `character:<characterId>:speechPosition` `` — `{ x, y }` absolute **world/room** coords for the speaking-text GUI bottom-center when this character speaks; written by **`B.character(id).setSpeechPosition`** / **`B.player.setSpeechPosition`**; cleared by **`resetSpeechPosition()`**. Read on demand in **`RoomScene.resolveSpeechOverlayScreenPosition`** (bypasses **`talkPoint`** and **`defaultTalkOffset`** when set).
  - `` `character:<characterId>:speechOffset` `` — `{ x, y }` canvas-pixel offset applied after default talk anchor projection + **`speech.defaultTalkOffset`** when no **`speechPosition`** override is set; written by **`setSpeechOffset`**; cleared by **`resetSpeechPosition()`**.
  - `` `room:<roomId>:character:<characterId>:position` `` — `{ x, y }` **feet world** coords (matches **`getCharacterWorldFeet`**). **Per-room** (so the same character id appearing in two rooms never clobbers across rooms) and **lazily** written by the same snapshot flush hook as prop positions; source is the live sprite's feet, walked or teleported during gameplay. Spawn (image and Aseprite paths) applies via **`readSavedCharacterPosition`** by overriding the `RoomCharacterSpawn` `x / y` fed to **`applyFeetWorldWithRegionScale`**. Rooms with a `whenEnterRoom` that calls **`B.player.moveTo.now('entry-point')`** still work — spawn applies the saved feet, the enter hook teleports the player to the entry, and the next flush records the new spot.
- **Hotspots** (room-scoped):
  - `` `room:<roomId>:hotspot:<hotspotId>:description` `` — string override for **`B.hotspot(id).description`** (including empty); hover / verb payloads use **`readSavedHotspotDescription`** (JSON `hotspots[].description` is the fallback default).
- **Inventory** (per item id, global): `` `inventory:<itemId>:defaultAnimation` ``, `` `inventory:<itemId>:cursorAnimation` ``, and `` `inventory:<itemId>:description` `` — optional overrides for **`InventoryItemData.defaultAnimation`** / **`cursorAnimation`** / **`description`** (see **Inventory System**). Description empty string persists as empty (unlike animation tags, which treat empty as “clear to JSON”).

**Snapshot flush hooks** ( **`src/engine/gameState/snapshotFlushHooks.ts`** ): a small registry — **`registerSnapshotFlushHook(fn)`** returns an unregister fn; **`runSnapshotFlushHooks()`** invokes every hook in registration order with per-hook **`try / catch`** (a buggy hook can never break **`getSnapshot`** — saves are sacred). Used as a **pull-up** for state that is too noisy to write eagerly per-tick (today: **character feet positions** and **prop authoring positions**; everything else — visibility, alpha, animation overrides, flags, variables, inventory — is still written eagerly on every change). **Trigger points** (all funnel into the same hook): (1) **`GameStateManager.getSnapshot`** runs hooks **before** cloning state, so **`save`**, **`exportSnapshotJson`**, and **`B.state.exportJson`** automatically pick everything up; (2) **`RoomTransitionOrchestrator.prepareForLeave`** calls **`roomScene.flushRuntimeStateToGameState()`** as its first step before the scene tears down; (3) **`B.state.flush()`** for explicit script save points. **`RoomScene.create`** registers the flush hook and stores the unregister fn in **`snapshotFlushHookUnregister`**, called on **`Phaser.Scenes.Events.SHUTDOWN`** so editor previews and torn-down rooms never hold stale hooks. The **scene method** **`flushRuntimeStateToGameState`** walks **`characterSpritesByDefId`** + **`propSpritesById`**; the prop helper **`getPropAuthoringPosition`** picks tight authored coords → parallax `baseX/Y` → live `sprite.x / y` in that order so values round-trip across spawn.

**Runtime wiring**  
- Room scripts run **after** props, characters, the player, and the camera are set up in `RoomScene.create()` (so `B.prop` / `B.player` resolve real scene objects).  
- Character scripts for a given id run in the same phase **only if** that character is spawned in the room; each gets its own `CharacterBenneScript` and `B.dispose()` on scene shutdown.  
- **`registerDialogScript`** callbacks run **when** a matching dialog session opens (**`openDialogSessionForId`** after **`B.dialog(id).start`** / **`.start.now`**); **`endDialogSessionIfMatches`** calls **`dispose()`** on that session’s **`DialogBenneScript`** so **`whenChoice`** and other subscriptions clear when the dialog stops or another dialog replaces it.  
- On scene shutdown, each room/character `B.dispose()` removes listeners that instance registered (avoids duplicate handlers if the room scene is recreated).  
- Optional payload-typed handlers use `(p: any)` for unified **`when*`** methods (runtime shape depends on prop vs hotspot vs character), or import specific payload types from `propInteractionEvents.ts` when wiring **`onProp`** / raw events.

**Key Design Decisions**  
- Single `B.` namespace → excellent Cursor IntelliSense and discoverability (better than multiple `C.`, `H.`, `P.` prefixes for a modern TS codebase).  
- `registerRoomScript(({ B }) => { ... })` → natural, minimal boilerplate; **blocking** timing is internal (`async` listener + `await` on the tail after the sync handler body); **`.now`** opts out per call.  
- Side-effect registration via module-level array → works reliably with Vite `import.meta.glob` (avoids marker propagation issues).  
- All real work still flows through the existing `EventBus` and verb dispatch system — zero runtime cost for the facade.

**Multi-room scripts:** `registerGameContent` records one lazy module loader per room id. `BootScene` and `RoomTransitionOrchestrator` call `ensureRoomScriptLoaded(roomId)` for the target room; the imported `registerRoomScript` callback is cached by room id and only that room's callback runs with a fresh context when its `RoomScene` is created. Room-local scripts therefore need no `ctx.roomId` guard. **Room changes** at runtime use **`B.room.changeTo` / `changeToNow`**; the **first** room starts through **`BootScene.startInitialRoomFromBoot`** (see the API table, **`RoomTransitionOrchestrator`**, and **§3 → Scene / room system → Room switching**). Per-room **`whenLeaveRoom`**, **`whenLoadedRoom`**, **`whenEnterRoom`**, **`whenEnterRoomAfterFade`** hooks and global **`whenLeaveAnyRoom`**, **`whenLoadedAnyRoom`**, **`whenEnterAnyRoom`**, **`whenEnterAnyRoomAfterFade`** hooks receive **`RoomTransitionContext`**.

**Future extensions** (easy to add under `B.`):  
- `B.sequence(...)` for parallel/cutscene actions on top of the existing queue and **`B.room`**
- Richer branching on top of **`B.dialog`…`start` / `stop`**, **`B.whenChoice`**, and persisted **`:enabled` / `:used`** option state (see **§3 → Dialog system**)

This layer turns BENNE from "wiring events" into "telling a story" while keeping the engine clean and data-driven.

### Speech settings and character speech presentation

- **Runtime preferences**: `game-config.json` `speech` provides defaults; **`B.speechSettings`** on every `BenneScriptCore` surface synchronously reads/writes session overrides (these accessors do not use `interactionTail`). `getSpeechSettings(manager)` and `computeSpeechLineDurationMs` resolve variable override → config default for `clickToSkip`, `showText`, `msPerCharacter`, `durationMultiplier`, `minDurationMs`, `maxDurationMs`, and `defaultTalkOffset`.
- **Persistence and events**: overrides are eagerly stored in `GameStateManager.variables` under corresponding **`speech:*`** keys by `speechGameState.ts`. Snapshot replacement preserves omitted speech keys unless `initialGameState.variables` explicitly seeded them. Setters emit **`benne:speechSettingsChanged`**; GUI scripts subscribe with **`B.onSpeechSettingsChanged`**. Per-line `say(..., { clickToSkip })` remains the highest-precedence override. Choice-dialog viewport preferences are separate under `dialog:choiceOptionsViewportHeightPx`.
- **Character color**: optional `CharacterData.speechColor` supplies the speaker's Speaking Text tint. `RoomScene` builds a first-wins color map by character definition id and `setDialogTextOverlay` applies it through `GuiOverlayHandle.setPrimaryTextColor`; hiding the line or speaking without a color restores the GUI's authored default. The Character Inspector owns the color field and omits white (`#ffffff`) as the engine default.
- **Character position overrides**: `B.player` and `B.character(id)` expose queued `setSpeechPosition(x, y)`, `setSpeechOffset(x, y)`, and `resetSpeechPosition()` calls with `.now` variants. Absolute world `speechPosition` has highest precedence and bypasses `talkPoint` plus the global offset. Otherwise canvas-pixel `speechOffset` is added after the projected default anchor and `defaultTalkOffset`. Both persist under `character:<id>:speechPosition|speechOffset`; `RoomScene.resolveSpeechOverlayScreenPosition` reads them whenever a line opens.

### Cutscene mode

BENNE supports **scripted sequences** that suppress all player input for the duration of the sequence. They are **skippable with ESC** by default — see **Skipping cutscenes** below.

**Automatic activation** — the following handlers are always wrapped in a cutscene block with no author changes required:

| Handler | When active |
|---------|-------------|
| `B.whenLoadedAnyRoom(…)` | Save-load restarts; runs before room-local loaded handlers |
| `B.whenLoadedRoom(…)` | Save-load room restarts, after global loaded handlers |
| `B.whenEnterRoom(…)` | Before fade-in; non-load starts only |
| `B.whenEnterRoomAfterFade(…)` | After fade-in; non-load starts only |
| `B.whenEnterAnyRoom(…)` | Same timing as `whenEnterRoom` (global script, non-load only) |
| `B.whenEnterAnyRoomAfterFade(…)` | Same timing as `whenEnterRoomAfterFade` (global script, non-load only) |
| `B.whenChoice(optionId, …)` | Full `say` + interaction-tail drain after the player picks an option |

**Explicit API** — `B.cutscene(callback, options?)` / `B.cutscene.now(callback, options?)` is available on every Bennescript surface (room, character, inventory, global, GUI, dialog):

```ts
B.cutscene(() => {
  B.walkToClicked();
  B.player.say('I'll do it!');
  B.wait(0.5);
  B.character('guard').say('Stop right there.');
});
```

- **Blocking form**: waits for any previously-queued steps to drain, pushes the cutscene flag, runs `callback` synchronously (which may queue further `B.*` steps), then pops after all those steps complete.
- **`.now` form**: pushes the cutscene flag immediately, runs the callback, then pops after any steps the callback queued finish.

Both forms use the interaction tail so they chain correctly with `walkTo`, `say`, `wait`, fades, etc.

**What is suppressed** — push/pop are reference-counted so nested cutscenes are safe:

| Input | During cutscene | During `say`-line only |
|-------|:---------------:|:----------------------:|
| Background empty-floor walks | ✗ | ✗ |
| Prop / hotspot / character clicks | ✗ | ✗ |
| Inventory row clicks | ✗ | ✗ |
| GUI button clicks | ✗ | **✓ live** |
| Hover descriptions (`B.currentHoverDescription`) | suppressed (null) | suppressed (null) |
| Click-to-skip scripted `say` lines | **✓ always live** | ✓ live |

**Walk promise contract** — inside a cutscene, if a scripted walk is interrupted (e.g. a new `walkTo` starts before the prior one finishes), the pending `walkPlayerTo` promise resolves immediately so the interaction chain does not hang. Outside cutscene mode, interrupting a walk drops the arrive callback (existing behaviour).

**Custom cursor** — when the Aseprite cursor is enabled, `game-config.json`'s `cursor.busyAnimation` controls the appearance during a cutscene:

- Non-empty string and the animation key exists → cursor plays that tag.
- Missing, blank, or clip not found → cursor sprite is hidden entirely.

Both `idle` and `active` animations are fully restored when the cutscene ends.

**`B.state.isCutsceneActive`** — read-only `boolean` on every `B.state`, true while any cutscene block is active on the current `RoomScene`. Safe to read from GUI / global scripts.

#### Skipping cutscenes

Pressing **ESC** during a cutscene **fast-forwards** it. The cutscene is never aborted: every step still queued on the interaction tail runs, in order, with the same conditional logic — only the *time* is removed. That is what guarantees a skipped cutscene ends in exactly the state it would have produced had it played out (characters at their final positions and facings, props at their final animation / alpha, flags and inventory applied, room transition performed, camera restored).

Each timed primitive checks `RoomScene.isCutsceneSkipFastForwarding()` and takes an instant branch:

| Step | Skipped behavior |
|------|------------------|
| `B.wait(n)` | Resolves immediately |
| `say` / `display` | No overlay, no voice; resolves immediately |
| `walkTo` (player and NPC) | Teleports to the end of the pathfound route with the arrival facing; still emits the walk start / stop pair |
| `fadeIn` / `fadeOut`, prop / character `fade` | Jumps to the target alpha |
| `B.camera.*` transitions | Applied with a zero-second transition |
| `playAnimation` one-shots | Lands on the base / effective animation without playing the clip |
| `B.sound.playAndWait` and `B.sound.play` | Skipped (one-shot SFX leave no lasting state) |
| `B.sound.playMusic` | Track still changes, without the crossfade |
| `B.video.play` / `playAndWait` | Video never starts; `onComplete` and `benne:video:ended` still fire |
| Flags, variables, inventory, `moveTo`, prop / character setters | Unchanged — already instant |

The step that is *in flight* when ESC is pressed is finished separately: blocking steps register a finisher via `RoomScene.registerCutsceneSkipFinisher` while they run, and `requestCutsceneSkip()` drains those finishers (plus snapping the active player walk and stopping any playing video) before the queue drains at full speed.

**Opting out** — two levels, mirroring `say`'s `clickToSkip`:

- **Global**: `game-config.json` → `"cutscenesSkippable": false` disables ESC skipping for the whole game (default `true`).
- **Per cutscene**: `{ skippable: false }` on `B.cutscene(fn, opts)` / `B.cutscene.now`, `B.whenEnterRoom`, `B.whenEnterRoomAfterFade`, `B.whenEnterAnyRoom`, `B.whenEnterAnyRoomAfterFade`, and `B.whenChoice(optionId, fn, opts)`. One unskippable entry anywhere on the cutscene stack locks the whole nest; for the enter / after-fade phases, one unskippable handler locks that phase's batch.

**ESC and video** — ESC still stops a standalone `B.video` playback. When the video plays *inside* a skippable cutscene, one ESC press skips the whole cutscene, video included.

**Key modules:** `src/engine/scenes/RoomScene.ts` (`pushCutscene` / `popCutscene` / `isCutsceneActive`, `canSkipActiveCutscene` / `requestCutsceneSkip` / `registerCutsceneSkipFinisher`, `onRoomKeyDown`), `src/engine/scripting/BenneScriptCore.ts` (`cutscene` / `cutscene.now`, `wait`, say / display promises), `src/engine/scenes/RoomTransitionOrchestrator.ts` (automatic enter / after-fade wrapping + queue drain), `src/engine/scenes/RoomTransitionHookRegistry.ts` (per-hook `skippable`), `src/engine/scripting/DialogBenneScript.ts` (automatic `whenChoice` wrapping), `src/engine/gui/buildGuiOverlay.ts` (`isButtonClickSuppressed` callback), `src/engine/scripting/benneScriptGameStateApi.ts` (`B.state.isCutsceneActive`), `src/types/cutscene.ts` (`CutsceneOptions`), `src/types/game.ts` (`GameSettings.cutscenesSkippable`, `GameSettingsCursor.busyAnimation`).

### GUI behavior runtime (`GuiRuntime`, `B.onGuiBuilt`, `B.onGuiShow`, `B.onGuiHide`)

After **`buildGuiOverlay`** composes a GUI in **`RoomScene`**, the engine constructs a **`GuiRuntime`** for that overlay and invokes every **`B.onGuiBuilt((gui) => { … })`** callback registered in the matching **`registerGuiScript('guiId', …)`** facade. The same path runs for the reserved Speaking Text (**`speaking-text`**) overlay. Authors use this for **low-level, composable** UI behavior (slide panels, fades, hover bands, etc.) without adding opinionated helpers to the engine core.

**`B.onGuiShow((gui) => { … })`** and **`B.onGuiHide((gui) => { … })`** complement **`onGuiBuilt`**: they run when **`B.gui('thatGuiId').show()`** or **`.hide()`** toggles overlay visibility (including calls from another GUI script, e.g. **`game-menu`** opening **`save-menu`** / **`load-menu`**). Use **`onGuiShow`** to refresh UI that reads live persisted data (**`B.state.getSaveList()`**, etc.) on every open — **`onGuiBuilt`** alone only runs once per room load when the overlay is first composed. **`onGuiShow`** does **not** run for overlays that start **`visible: true`** at room load (initial sync still belongs in **`onGuiBuilt`**) or for engine-internal visibility restores (e.g. dialog temporarily hiding all HUD overlays). The engine invokes **`notifyGuiShown` / `notifyGuiHidden`** on the target **`GuiBenneScript`** from **`GuiBenneScript.gui(overlayId).show()` / `.hide()`** after **`GuiOverlayHandle.setVisible`**.

- **`gui.root`** — **`ControlFacade`** for the **`Phaser.GameObjects.Container`** that parents every authored control **except** those whose **`id`** appears in **`fixedControls`** on the GUI JSON. **`gui.root.tweenTo`** / **`setY`**, etc. move or fade only that packed subtree (same Bennescript interaction queue as per-control facades). Fixed controls keep their own scene objects; tween them via **`gui.getControl(id)`** if needed. **`GuiOverlayHandle.gameObjects`** lists the packed container **plus** each fixed control’s top-level object(s) so editor UI-camera routing stays correct. Optional **`GuiData.x`** / **`GuiData.y`** set the **initial** position of the packed root at build time — e.g. **`"y": -34`** parks a dropdown bar just offscreen so a **`tweenTo({ y: 0 })`** in **`onGuiBuilt`** reveals it without any setup call. Fixed controls ignore **`GuiData.x`/`y`** (that is the whole point — keep the reveal trigger pinned in screen space while the rest slides).
- **`B.gui('overlayId').show()` / `.hide()`** — available on GUI scripts to toggle another overlay’s whole visibility at runtime (not just a control subtree). This routes through the overlay handle path used by the scene (`GuiOverlayHandle.setVisible`), so modal blocker interactivity and fixed-control visibility stay in sync, then notifies the target overlay’s **`GuiBenneScript`** (**`onGuiShow`** / **`onGuiHide`**). Missing or inactive overlays are a no-op (DEV warns).
- **`gui.getControl(controlId)`** returns **`ControlFacade | null`** — use when a control may be absent and you branch. **`gui.getControlOrThrow(controlId)`** returns **`ControlFacade`** and throws with **`guiId`** + control id if missing; **prefer this** when a missing id means bad JSON so TypeScript stays strict without local guards. Controls need a stable **`id`** in **`*.gui.json`** (`text`, **`button`** `id`, **`inventoryPanel`** optional `id`, **`image`** optional `id`, **`trigger`** `id`). Each facade exposes **`gameObject`**, immediate setters (**`setY`**, **`setVisible`**, **`setAlpha`**, …), **`enabled`** on **`button`** and **`textInput`** hits (runtime toggle of hit-testing + disabled chrome; mirrors JSON **`enabled`**), **`setVisualState`** on **`button`** hits ( **`'normal'`** / **`'hover'`** / **`'pressed'`** / **`'disabled'`** — visual-only while **`enabled === true`**; drives **`states.*`** + **`textColorStates`**, **`'normal'`** re-enables pointer-driven chrome), and **`tweenTo(props, duration?, easing?)`** / **`tweenTo.now(...)`** — tweens use the **same interaction queue** as other Bennescript (`say`, **`B.wait`**, …) on that GUI’s **`GuiBenneScript`** instance.
- **Pointer hover events**: **`B.whenMouseEnter(controlId, handler)`** / **`B.whenMouseLeave(controlId, handler)`** fire when the pointer enters / leaves any GUI control with that **`id`**. They work uniformly for **`button`** (while enabled, via Phaser's native `pointerover` / `pointerout` since buttons already need `setInteractive` for clicks) and for **`image`**, **`inventoryPanel`**, **`text`**, and **`trigger`** — all of which use a **non-blocking scene-level `pointermove` observer** (**`installGuiControlPointerHoverObserver`**) that tests the pointer against the control's current world bounds without calling `setInteractive`. Events emit on `gameEvents` as **`gui:<guiId>:control:<controlId>:mouseenter` / `:mouseleave`** (see **`guiControlHoverEvents.ts`**). **The observer is critical to keep HUD overlays from eating room clicks**: because non-button GUI controls are not hit-tested by Phaser, the `RoomScene` pointer pipeline (prop / hotspot / character `pointerdown`, and the walk-on-empty-space path that calls `hitTestPointer`) still receives events for pixels covered by an `inventoryBar` backdrop or `image` control.
- **`trigger` control** — **`GuiTriggerControl`** in **`src/types/gui.ts`** (fields: **`id` / `name?` / `x` / `y` / `width` / `height` / `active?` / `visible?`**). It is **never drawn** (a `debug.showGuiOutlines` overlay still traces it for layout). Triggers use the same non-blocking observer as the other non-button controls. Multiple overlapping triggers all fire independently (each is its own rect-containment test). When **`active: false`** no events emit; hiding the rect flushes a synthetic **`mouseleave`** so subscribers always see a clean exit. Authored via the **Add Control** wizard in the Inspector as **“Trigger”**.
- **Dropdown / slide-in HUD pattern**: combine **`GuiData.y`** for the parked position with **two triggers** — a small reveal rect at the top of the screen plus a larger keep-alive rect covering the bar footprint, both listed in **`fixedControls`** so they stay in place while **`gui.root`** slides. Wire reveal on **`whenMouseEnter('hoverZone')`** and hide on **`whenMouseLeave('hideZone')`**. Because triggers are non-blocking, moving the pointer from the reveal zone down onto a button inside the bar keeps **`hideZone`** "inside" and the bar stays open while the click is processed; see **`src/game/guis/inventoryBar/inventoryBar.gui.json`** + **`.gui.ts`** for the canonical example.

```ts
B.onGuiBuilt((gui) => {
  const root = gui.root;

  B.whenMouseEnter('hoverZone', () => {
    root.tweenTo({ y: 0 }, 300, 'Sine.easeOut');
  });

  B.whenMouseLeave('hideZone', () => {
    root.tweenTo({ y: -34 }, 250, 'Sine.easeIn');
  });
});
```

- **Teardown**: **`GuiRuntime.dispose`** (from overlay **`destroy`**) kills tweens on **`gui.root`** and per-control facades; **`buildGuiOverlay`** destroys the packed content container **and** any **`fixedControls`** scene objects, and detaches every hover-forwarder listener it installed. **`GuiBenneScript`** subscriptions (button click, mouseenter/leave) and **`onGuiBuilt` / `onGuiShow` / `onGuiHide`** registrations remain on the facade for the next room load; **`onGuiBuilt`** handlers run again whenever the overlay is rebuilt.

Core modules: **`src/engine/scripting/GuiRuntime.ts`**, **`GuiBenneScript.ts`**, and **`buildGuiOverlay`** (`BuiltGuiOverlay` / **`createGuiRuntime`**).

### High-DPI editor overlay

The editor preview uses **`Scale.RESIZE`** (not `Scale.FIT`) so the Phaser canvas always fills the VS Code panel. **Navigate mode** simulates the exact in-game view by computing `scale = min(panelW/gameW, panelH/gameH)` and using `cameras.main.setViewport(centreX, centreY, gameW*scale, gameH*scale)` — the viewport box is letterboxed inside the panel using the game background colour. **Edit mode** expands the viewport to the full panel (`setViewport(0,0,panelW,panelH)`), zooms to fit the room art, and enables mouse-wheel zoom (around the cursor) and middle-mouse pan. Pressing **F** resets to the fit-room zoom. The camera re-applies its mode automatically via `scale.on('resize')`. The DOM overlay canvas is sized to fill the full panel in both modes; all handle drawing uses `worldToCanvasCss(p, cam)` which accounts for the active camera zoom, scroll, and viewport origin (`cam.x`, `cam.y`). **Pointer capture** on the overlay handles drags; **`pointer-events: none`** in Navigate so `RoomScene` receives clicks. **Zoom formula** (Phaser 4-accurate): `scrollX = worldX - originX - (screenX - originX - cam.x) / newZoom` keeps the world point under the cursor fixed across zoom steps.

**Editor UI camera** (`RoomScene.ensureEditorUiCamera`): because the editor main camera uses `setZoom(scale)` while the shipped game keeps `cameras.main.zoom = 1`, Phaser 4's origin-aware zoom math pushes `scrollFactor: 0` overlays off the viewport by `origin × (1 − zoom)` pixels (hundreds of px at typical editor scales) — this is why the first "Show GUIs" attempt produced no visible pixels even with `visible: true` and correct bounds. `RoomScene` creates a second camera (`name: 'editor-ui'`) with the same viewport + zoom as `cameras.main` but `origin = (0, 0)` and `scroll = (0, 0)`, so GUI overlays render at `(x × zoom, y × zoom)` relative to the viewport top-left — matching the runtime placement. `GuiOverlayHandle.gameObjects` enumerates each overlay's top-level objects so the main camera can `ignore` them and the UI camera can `ignore` everything else; a `Phaser.Scenes.Events.ADDED_TO_SCENE` listener keeps the split correct for objects added after scene boot (tween sprites, debug overlays). The UI camera is torn down on `Phaser.Scenes.Events.SHUTDOWN`. The shipped game never calls `setEditorCameraMode`, so this camera is editor-only and has **zero** runtime cost.

### Pathfinding (engine)

- **`src/engine/pathfinding.ts`** — `findWalkPath(start, goal, polygons) -> Point2[]` returns an ordered polyline of waypoints (goal last) routing the character around **holes** and **concave** parts of the walkable union. Used by both the player and NPCs.
- **Algorithm**: classical **reduced visibility graph + A\***, the canonical shortest-path approach for *simple polygons with holes* and what most modern 2D adventure engines use under the hood (Adventure Creator, Wintermute-family, PowerQuest polygon mode). Result is the **exact Euclidean shortest path** — a polyline that bends only at polygon corners, giving the classic LucasArts "walk around the obstacle" look.
- **Graph nodes**:
  - **Reflex** outer-ring vertices of each **active** polygon (convex outer corners are never on a shortest path and are omitted).
  - **All** vertices of each **active** hole ring (holes poke into the walkable region, so every hole vertex is reflex as seen from the walk side).
  - Each node is offset **~1 px inward along the interior angle bisector** so waypoints sit just inside the mesh rather than exactly on the boundary pixel. This both matches the classic LucasArts corner-radius feel and keeps segment-midpoint-in-walkable tests numerically robust at vertices.
- **Edges**: two points are connected iff the straight segment between them lies entirely inside the walkable region. Tested by (1) sampling the segment at t = 0.25 / 0.5 / 0.75 and checking each is in the walkable union, plus (2) a proper-crossing test against every ring edge (outer + active hole) that ignores shared-endpoint touches and collinear overlap.
- **Start / goal**:
  - Goal is first clamped to the walkable union (reuses `clampWalkDestinationTowardClick`).
  - If the **start** point is outside the walkable region (spawn / cutscene placement off the mesh), pathfinding is skipped and a **direct line** to the clamped goal is returned — preserves the pre-pathfinding behavior where off-mesh characters glide to the floor.
  - If start and goal are in **disconnected components** of the walkable union, A\* returns no path and the engine falls back to a direct line to the clamped goal.
  - If the straight segment from start to clamped goal is already inside the mesh, `findWalkPath` short-circuits to `[goal]` without running A\* (common case: clicking nearby open floor).
- **Complexity**: O((N+2)²) visibility edges per query, where N is the number of candidate nodes (typically tens for hand-authored rooms). Each visibility test is O(E) across all ring edges. Cheap in practice; invoked once per walk command (click-to-walk, `B.player.walkTo(…)`, or `B.character(id).walkTo(…)`), not per frame. No cross-query caching yet — future work if rooms ever grow to hundreds of vertices.
- **Integration in `RoomScene`**:
  - `walkPlayerToWorldPoint` / `walkCharacterToWorldPoint` (and the empty-space click handler) call `findWalkPath` and then chain **one Phaser tween per path leg** via `beginPlayerWalkLeg` / `beginNpcWalkLeg`. Facing is recomputed per leg with `facingFromWorldDelta` so the sprite turns into each new direction (`Walk` base animation swaps accordingly); `Idle` plays on final leg completion.
  - `PLAYER_WALK_START` fires **once** with the final clamped target; `PLAYER_WALK_STOP` fires **once** on `complete` (final leg) or `interrupted` (new walk pre-empts the chain, scene shuts down, etc.). Leg boundaries themselves do not emit events.
  - `stopPlayerMoveTween(emitStop)` cancels the current leg and clears `currentPlayerPath`; in-flight `onComplete` guards against advancing a superseded chain by comparing tween identity with `playerMoveTween`.

## 9. Game content templates and switch script

The repo can hold **multiple authored game layouts** (e.g. a two-button verb game vs. a nine-verb SCUMM-style shell) while keeping **`src/engine/`** shared and **`src/game/`** as the **single live slot** Vite and the editor target.

Each mirror builds a **plan** (new / modified / unchanged / orphan deletes), prints a summary, and asks for confirmation unless **`--yes`** / **`-y`** is passed (e.g. **`npm run set-template:9-verb -- --yes`**).

**What counts as “bootstrap” vs “template”**

- **Boot**: everything under **`src/game/boot/`** (loaders, registration helpers, asset URL resolution, Aseprite helpers, constants). These files are shared across all templates and synced to every **`game-templates/<name>/boot/`** by **`sync-boot-down`**. New engine helpers added to `boot/` are synced automatically.
- **Template**: everything else in **`src/game/`** — **`game-config.json`**, **`globalScript.ts`**, and all content subdirectories (rooms, assets, characters, guis, inventory, dialogs, pdcs, …).

**Special cases the script handles**

- **`.gitkeep`** under template folders is ignored by the mirror so empty directories can stay in git without being deleted when **`src/game/`** has no matching file.
- **Editor / OS duplicate names** are ignored and dropped as orphans on sync (never copied into templates): e.g. **`game-config copy.json`**, Windows **`… - Copy.ext`**, Explorer **`… (1).ext`**, **`.DS_Store`**, Office **`~$…`** lockfiles.

**Authoring pitfall**

Empty templates still need a **`src/game/rooms/rooms.manifest.json`** (and usually manifest **room entries**) because **`boot/loadStartRoom.ts`** imports the manifest statically; the **Create New Room** wizard only **appends** to an existing manifest — it does not create the file if missing.

For packaging, distribution, and VSIX publishing, see **[publishing.md](publishing.md)**.

## 10. Future Considerations

- **Room transitions (extensions)**: The shipped path **restarts `RoomScene`** with new **`RoomSceneStartData`** via **`RoomTransitionOrchestrator`**. Deeper work might add **preloading**, **shared caches**, or **non-black cutscene transitions**; **global narrative state** should remain on **`GameStateManager`** unless a game explicitly resets it.
- **Post-processing**: `PostEffects.ts` is ready for **camera filter** composition (CRT, dither, etc.).
- **Audio**: **`B.sound`** covers **SFX + music** from authored assets and **`BlockingWithNow`** sequencing; further work might add **spatial audio**, **voice/dialogue bus mixing**, or **event-driven triggers** outside scripts.
- **Dialogue / inventory UI**: **`say`** shows the **Speaking Text** overlay (**`speaking-text`**). **`inventoryPanel`** GUIs render a carried-items grid with optional **paged scroll** (`scrollDirection`, `backButton`, `forwardButton` in **`*.gui.json`**) and **reactive rebuild** on **`gameState:inventoryChanged`** / **`gameState:replaced`** when scroll is configured. **Richer dialogue** (choices, portraits) and **full inventory UX** (drag-reorder, cursor) remain **future work** — **`B.inventory`** is available for wiring.
- **`whenGive` on all target kinds** (planned, not implemented): Room **`B.whenGive(itemId, targetId, …)`** is documented as **prop-only** sugar, but **armed-inventory give** (player selects an item, clicks **Give** on a world target) already routes through **`dispatchInventoryOnVerbTargetInteraction`** and **`inventoryOnVerbEvents.ts`** — including **characters** and hotspots. Authors handle that today with **`B.whenInventoryUsedOn(targetId, (payload) => { … })`**, branching on **`payload.itemId`** and **`payload.verbId === 'give'`** (see sample **`apartment.room.ts`**). A future change would reimplement **`whenGive`** as sugar over the **item-scoped** inventory-on-target channels (**`roomInventoryOnCharacterEventId`**, **`roomInventoryOnPropEventId`**, etc.) with the same **prop → hotspot → character** **`targetId`** resolution as **`whenInventoryUsedOn`**, interaction-tail / drop-policy behavior aligned with **`subscribeInventoryUsedOnTargetEvents`**, and a generalized give payload (not only **`GivePropInteractPayload`**). That would subsume the common **`whenInventoryUsedOn` + give filter** pattern for fixed item+target pairs; broad “any item on this NPC” handlers would stay on **`whenInventoryUsedOn`**. **`InventoryBenneScript.whenGive`** (row-level **Give** on the inventory panel) is unrelated.
- **Editor**: VS Code extension + **`build:room-preview`** ship a **live `RoomScene` preview** in a webview with **polygon editing** (walkable, prop colliders, **hotspots**, **regions**, and **room points**) via **`RoomPolygonEditScene`**. **`build:character-preview`** adds a separate webview for **feet** + **click collider** polygons. **`build:benne-play`** ships the **BENNE Play** full-runtime panel (same boot as **`main.ts`**, not the preview loader) — see **§8**.
- **HMR script registry hygiene:** During dev hot reload, side-effect `register*Script` calls can accumulate stale handlers (e.g. room enter hooks) if registries are append-only. Add HMR-safe registry reset/dedupe behavior (`import.meta.hot.dispose` and/or module-keyed maps) to prevent duplicate/stale hook execution without requiring full page reloads.
